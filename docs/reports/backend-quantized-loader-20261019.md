# 模型加载配置所有权收敛（2026-10-19）

基线：`323c9e51bdd4b2616fdda717d89940f91904ab0b`。服务器先修改、验证及部署，再同步本地。

## 调用链与问题

训练任务经配置校验调用 `LoRATrainer._load_model`，然后进入库的权重加载和必要的低位训练准备。旧实现先检测量化类型，再分别读取同一配置重建 AWQ/GPTQ 参数；读取失败会吞掉错误，AWQ 构造发生 TypeError 时还会删除 version 重试。库随后又自行读取配置，形成多份参数解释与默认值。

全仓检索确认类型检测方法只有本加载器一个调用方。

## 修改

- 一次读取本地 config.json，按明确的 model_type 构造库的配置对象，将完整对象交给原生模型加载器。缺文件、非法 JSON、缺架构或未知架构直接失败，不按目录名称猜测。
- 已量化权重保留自身完整 quantization_config，由库处理相应格式；不再手工重建 AWQ/GPTQ 配置、强行改变后端或在异常后删除 version 重试。
- 未量化模型仍可按原配置启用 NF4/INT8；原有精度参数和已加载低位标记的处理保留。低位训练准备成功后才发布模型对象，加载或准备失败保留原异常。
- 模型加载限制为现有本地资产；缺配置不下载模型来代替。没有新增依赖、模式、包装层或重试。

生产代码净减少 **90 行**。其他训练方法、数据准备、身份边界、API 及 DeepSeek 推理链路未改变。

## 验证

- **12 项直接相关检查首次通过**：新增 9 个配置交接、缺失/损坏配置及原异常传播案例；原 2 个低位权重准备案例和精度案例通过。旧低位夹具只补齐明确的 model_type，原断言保持不变。
- **12 个前后链路对照**：普通、AWQ、GPTQ、已有 bitsandbytes、运行时低位标记、新 NF4/INT8，以及配置读取、加载和准备故障。量化权重加载使用明确受控接口，完整配置交接和准备次数受检。
- 7 条正常路径的配置读取总次数从 **16 次降到 7 次**；每条均为一次。坏配置在权重加载前停止，原加载/准备故障不被包装或伪装成成功。
- 本地创建的随机微型 Qwen3 模型进行了**真实 CPU 保存、加载和前向计算**。修改前后精度、输出形状和 logits 哈希一致。没有下载生产模型或调用付费模型。
- 收尾时发现最初探针引用的 Transformers 导出模块在导入期间被替换，构造次数计数不可靠；仅用原方法备份和当前实际模块做了 3 个局部对照，确认两种正常构造及旧 TypeError 删 version 重试。未修改功能测试预期，未重跑整套测试。
- 差异、限定静态检查和仓库完整性检查通过；部署后后端就绪和前端登录 200，受保护接口 401，配置及其他进程保持一致。

没有运行真实 GPU 量化内核、量化微调或完整后端回归。CPU 模型成功与配置交接测试不能证明 AWQ/GPTQ 在所有硬件和依赖组合上可训练；必需依赖不可用时由原生加载器明确失败。

接口依据为安装环境的 Transformers 4.57.6，以及对应的[架构配置工厂](https://github.com/huggingface/transformers/blob/v4.57.6/src/transformers/models/auto/configuration_auto.py)、[模型加载工厂](https://github.com/huggingface/transformers/blob/v4.57.6/src/transformers/models/auto/auto_factory.py)和[量化配置处理](https://github.com/huggingface/transformers/blob/v4.57.6/src/transformers/quantizers/auto.py)。

整体优化目标继续。
