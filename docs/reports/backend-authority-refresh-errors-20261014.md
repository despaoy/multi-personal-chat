# 资料持续变化时明确失败，删除固定回复回退（2026-10-14）

## 实际问题与修改

生成链路在最终来源/私人上下文再校验发现变化后，允许用当前资料重新生成一次。旧 refresh_answer 在第二次变化时构造带固定提示语的正常 GenerationResult，并通过 authority_fallback 让 API 把它显示为弃答；这把未完成可靠生成包装成一条成功回复。

重试耗尽现在抛出 ContextAuthorityChangedError，明确停止，不返回任何旧答案或固定生成结果。API 对该错误统一返回 HTTP 503，带 context_authority 阶段和 repeated_authority_change 原因；错误链保留，失败调用记录正常生成，回复不保存。不同提供商得到同样明确的上下文故障结果，不切换模型。

删除 GenerationResult.authority_fallback 字段、API 中的回退结果转换和部分回答条件中的重复状态判断。refresh_answer 不再接收已弃用答案参数；仍仅从当前授权资料重建一次，旧答案不作为历史、证据或修复输入。两份生产代码合计净减少 4 行，无新增意图规则、配置、重试次数或降级框架。

正常资料撤销/内容改变仍按现有权限机制精确剔除受影响来源，保留独立公共来源和私人内容。单次变化后用剩余资料完成回答保持；持续变化不无限重试。数据库读取故障继续直接传播，不被当成合法撤销或用其他来源代替故障。

## 定向验证

服务器 14 项直接相关测试全部通过（1.78 秒），23 项其他测试未运行。两组实际持久化 SQLite 控制分别在主回答期间、引用标注期间连续撤销两份独立完整资料，均在两次主回答后抛出明确异常，标注最多两次，没有第三次生成，两个已删除来源均不返回。

成功控制继续验证一次公共来源删除后的独立来源回答、标注期间原作变化后只使用剩余来源重生成、私人原话擦除后不返回被擦除内容。完整原文包含费用、否定、原件条件、例外、年度范围及私人自述，测试没有缺省完成前提。

六组统一 API 故障测试覆盖 vLLM 与当前兼容 API 两种传输的提供商失败、回复校验失败、上下文持续变化。上下文故障均返回 503 和具体阶段/原因，原异常保留，失败记录一次，启用持久化时也不调用回复保存，不切换提供商。

移除一项过旧测试：其要求原文读取故障后丢掉该来源并继续生成，与当前明确失败要求冲突。已有 test_source_read_error_aborts_without_replacement_answer 在生成前/后两种时机验证同一真实 SQLite 原文读取入口，要求原始 OSError 和对应模型调用数量；本阶段实际执行这两项有效检查，覆盖未削弱。其他成功测试只移除对已删除内部字段的断言，保留内容、调用次数、擦除和来源可见性检查。

语法、增量静态和差异检查通过，无新增静态问题。付费模型调用 0；所有模型输出为明确注入的控制响应，不是新的模型质量实测。未重复全量回归，未修改生产资料、索引、用户数据、凭据或运行配置。整体后端精简优化目标继续。
