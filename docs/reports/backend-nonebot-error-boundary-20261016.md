# NoneBot 消息入口统一报告失败

本地基线：`73670dd262f2b99a82b2ca1152d0608b242fe408`。当前先本地修改，服务器同步待连接恢复。

## 实际问题

会话回复开关读取异常后原来仍按私聊/群聊条件继续回复。生成函数则把限流、队列故障及模型异常转成普通字符串，随后执行正常回复的日志和延迟；最外层遇到其他故障只写日志，没有明确通知。模型异常日志及若干消息日志还记录了错误原文或对话片段。

## 修改

- 会话设置读取失败保留原因，使用具体异常交给入口报告数据库故障，停止后续去重及生成；正常关闭和开启的语义不变。
- 生成函数只返回真实生成结果，故障直接传播。入口统一区分限流、队列已满、处理超时及一般消息处理失败；失败不再经过正常回复的延迟和分段流程。
- 一般错误日志保留异常类型及代码堆栈位置，不输出异常文本或运行变量。对话和工具生成日志只记录字符数，不截取原文。
- 删除无调用方的旧消息保存函数及其专用导入。正在使用的统一生成服务保存路径保持不变。

生产代码净减少 32 行；没有新增依赖、自动重试、模型切换或规则判断。

## 定向验证

4 项基线失败用例确认原行为：会话读取故障、限流、队列故障及模型故障均没有向调用方抛出异常。修改后共 16 项不同检查通过：

- 上述 4 项失败行为修复，生成失败不写入内存历史。
- 会话设置的开启和关闭、真实生成结果的请求身份与多轮历史传递、取消传播。
- 实际注册的处理函数分别报告 5 类故障，仅通知一次，不泄露合成错误内容；真实成功回复仍正常发送。
- 调整完整事件夹具后，关联去重失败及未选中消息两项仍符合原约定。

其中超时控制首次误用了 Redis 专用超时异常，已将夹具改为调度器实际使用的 `asyncio.TimeoutError`，只重跑该失败用例后通过；没有扩大生产捕获范围或放宽断言。

新增及修改测试 Ruff、生产文件语法和增量静态检查、补丁空白检查通过。测试使用真实机器人模块和完整合成 OneBot 事件，服务边界由明确控制对象替代；未连接真实平台、Redis、DeepSeek 或服务器，没有付费请求或全量回归。这不代表所有旧机器人配置与历史管理分支已完成清理。
