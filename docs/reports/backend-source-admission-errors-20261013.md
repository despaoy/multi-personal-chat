# 历史原话注入失败与后续阶段目标（2026-10-13）

## 本阶段问题与修改

真实调用链是 SourceMemoryService.recall → attach_sources → build_generation_request → admit_deferred_sources → 模型输入。此前延迟原话包格式损坏会被清空并标记 retrieval_error，容量不足会被清空并标记 budget_omitted，之后仍允许生成。移除已选原话可能丢失条件或否定，诊断状态不能代替请求失败。

现在格式损坏抛出明确 ValueError；容量不足保留原始上下文预算错误，要求缩短输入或证据。删除清空后重建请求与按错误文案捕获的分支，生产代码净减少 14 行。完整原话仍先确定容量，再分配公共证据预算；输入对象不会修改。

## 验证

服务器直接相关测试文件 10 项通过，0.37 秒。覆盖完整长原话和末尾限制进入模型、超容量及四类格式错误在模型调用前失败、公共证据容量分配、授权撤销、来源读取和生成后逻辑使用同一上下文。合成资料完整，未运行全量回归，付费模型调用为 0。语法、差异和新增静态问题检查通过。

这验证了输入链路，不代表真实模型的语义质量已经验证。保留来源检索阶段的正常无匹配以及尚未进行最终容量判定的候选状态；本阶段不修改历史数据。

## 后续目标与收尾标准

1. 证据与缓存：沿实际入口核对证据归属、完整性和缓存失效。只修复能说明触发条件与实际影响的问题；对应成功、错误传播与隔离用例通过后收尾。
2. 长期记忆与动态上下文：检查否定、条件、人物、时间和多项事实在读取、选择、预算分配及生成输入中是否保留。完整合成资料验证链路；需要判断模型理解时才使用当前 DeepSeek 作小规模真实测试，并区分模型限制与链路故障。
3. 代码精简：仅删除已确认无使用方的兼容代码、重复状态及重复规则。优先缩短实际调用链，不为假设问题增加防御层，也不以删除行数作为质量标准。

各阶段均按服务器先改与定向验证、有效后同步本地、提交 GitHub 的流程推进。不重复全量回归，不提交密钥、运行数据和私有测试原文。达到可用标准后结束该项；记录剩余限制，不追求无法保证的 100%。按用户要求，账户可用额度剩余 20% 时停止继续工作，额度不是需要消耗的目标。
