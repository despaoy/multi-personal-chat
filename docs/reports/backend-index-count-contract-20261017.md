# 缺失计数结果不得被当作空库

基线：`dacdaf83f87a2b11cb2892db83c2e94149839395`。

检查 SQLite 查询、PostgreSQL 查询及同步适配器后确认，该无分组 `COUNT(*)` 查询在真实空库也应返回一行、计数为零。原 `_get_expected_chunk_count` 把缺失结果行转换为零，混淆了正常空库与异常响应。

在有完整来源及旧索引的隔离数据库中注入缺失结果行，复现旧逻辑清空非空索引并写入 `complete:0`。这是适配器异常响应的故障注入，未在生产环境观察到该适配器故障。来源正文仍在，测试没有操作生产索引。

删除这一处 `if rows else 0`，直接读取查询约定的计数。缺失结果会在清理索引前经已有安全错误边界返回 503，保留原因；没有新增检查框架、猜测默认值或重试。源码一行替换，净增 0 行，SQL 与数据库适配器保持原样。

3 项定向测试首轮通过：新增用例确认缺失结果不会清理已有元数据或标记完成，来源和修订仍保留；现有最后一份文档删除用例确认真实空库仍会清理旧索引并完成；现有孤儿分块用例确认计数继续排除已删除文档的分块。未重复全量回归，旧测试及断言未修改。
