# 生成链路复用历史和模型预算

基线：`7c5a0dbd8d305b8a8a87c5682667d64afbe6ae6d`。审查聊天生成入口、检索规划、问题绑定、证据审核、通用资料扩展、原始来源补充，以及请求上下文和模型预算定义。

## 修改

- 生成入口只解析一次有效历史，供规划、绑定和最终生成共同使用。非空现场历史优先，否则使用按用户范围准备的服务端历史。
- 在各自作用域复用不可变的模型预算。生成入口原来解析二至六次，现在一次；通用检索扩展和来源补充原来两次，现在一次。保留知识库开启时的检索错误转换边界，以及关闭时的原始预算错误。
- 两条检索结果分支共享十个相同字段，分别保留证据充足与证据不足时的状态、正文及引用处理。修改前逐项比较公共字段表达式，确认完全一致。

仅修改 `backend/api/generate.py`，生产代码净减少七行。没有增加错误类、重试、配置、语义规则或测试矩阵；没有调整模型、权限、检索算法和证据准入。

## 验证

- 54 项直接相关检查全部通过，覆盖历史选择、知识库开关、云端预算、编译输入、无效证据、公开审核失败、部分证据状态及来源版本变化。
- 19 组前后对照使用实际请求编译器和两种实际预算配置，覆盖关闭检索、个人上下文、公开检索、证据不足、现场和服务端历史、预算错误、检索错误，以及通用资料扩展。完整请求、消息、生成参数、阶段参数和响应摘要一致，异常状态和原始原因一致。
- 对照中，服务端历史属性读取由两次变为一次。这是内存数据复用，不代表数据库查询减少。通用检索和生成编排分别持有自己的预算作用域。
- 其他模块级代码 AST 一致，语法、名称、差异空白及服务器仓库完整性检查通过。部署后就绪与登录页均为 200，匿名受保护接口为 401；运行配置与前端进程保持不变。
