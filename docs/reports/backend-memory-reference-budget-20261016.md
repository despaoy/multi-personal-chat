# 长期记忆参考区使用完整文本预算

本地基线：`ca2af47374315dc6d144a743012828adddd2a1ab`。用户已授权服务器断线期间先在本地修改。

## 复现和原因

`CharacterContextService` 将参考区预算交给 `compile_reference_context`，但旧的私有挑选函数只统计记忆包及称呼预留量。后加的固定安全声明没有计入，称呼换行还有两处计算，只有称呼时则没有最终超限检查。原话观察和普通记忆使用的声明长度也不同。

完整合成证据在 659 字符预算下实际返回 660 字符；只有称呼、预算为 1 时仍返回 117 字符。该复现不依赖模型，也没有读取真实用户记录。

## 修改

挑选和编译合为一个参考区编译入口，共用同一预算。实际声明、称呼、换行及完整证据都计入；诊断 `used_chars` 等于最终输出字符数。后出现的有效原话观察可选择对应声明，已撤销或未注入观察不影响声明。

完整入选集合超限时保留 `MemoryContextBudgetError`，不返回部分成功。普通候选召回原有的按排序、条数和预算整包选择仍保留，并通过诊断标明未入选项；它不代表已经审核为必需的完整集合。无可用参考仍正常返回空文本。生命周期、原话主体和信任边界、称呼长度上限及模型调用数量保持原有职责。

删除没有其他调用方的 `_select_memory_lines` 和从未参与执行的 `MAX_SINGLE_MEMORY_CHARS` 常量/导出，生产代码净减少 44 行。
