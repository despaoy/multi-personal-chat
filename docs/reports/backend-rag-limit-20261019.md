# 显式检索数量不再隐式变为默认值

基线：`402fdecd00d89c816f5a2207012eae341067478a`。重新梳理生成编排、私有来源准入、通用检索、任务视图、缓存和评测命令的实际调用关系。

## 问题与修改

通用检索把 `top_k=0` 按真值表达式替换成默认数量，缓存键也随之使用默认数量。普通查询和多任务查询的两个公开入口都能成功返回默认检索结果。评测命令接受零值，造成声明的数量与实际检索不一致。

- 只有 None 使用默认数量；显式数量必须是正整数，布尔值不能成为数量 1。普通检索在缓存和索引访问前校验；任务视图沿用既有收集器的校验，保留显式值。
- 解析后的数量直接用于缓存键和召回，删除同一方法中的重复默认值计算与局部别名。
- 评测命令在提示词、检索器和模型加载前拒绝非法数量，不写出错误配置的评测结果。

生产代码净增加四行，没有新错误类、配置项、抽象层或语义规则。未调整模型、查询、范围、排序、证据或引用策略。审查中的内部来源包校验虽返回 None，但调用方会明确抛错，因此没有仅根据返回值形状把它误判为业务降级。
