# 通用生成入口数据库归属修复（2026-10-24）

generate_reply_core 接收指定的 message_db，却调用预先绑定全局数据库的默认 ChatGenerationService。指定数据库只通过参数进入生成处理器，服务前置的 Web 消息来源检查仍读取全局数据库，可能产生错误冲突、错误放行或错误故障原因。

现在显式注入数据库或角色服务时，复用现有服务构造器，在来源检查之前绑定依赖。来源检查和生成使用同一数据库，未指定依赖的调用方继续使用默认服务。删除了生成调用中的重复依赖参数传递；净增加 3 行生产代码，没有新增校验、回退或抽象层。

验证先在服务器执行：

- 三个隔离案例在旧代码中均失败，确认访问了错误的全局数据库。
- 修复后成功路径返回结果；来源冲突返回 409；指定数据库故障返回 503 并保留原始 OSError。后两种情况均不进入生成处理器。
- 共 67 项相关测试通过，无跳过，覆盖通用生成服务、应用容器、角色生成、来源身份和预约。
- 除 generate_reply_core 外，生产文件其余 AST 未变；静态检查、仓库完整性和差异检查通过。
- 重启后后端就绪和前端登录返回 200，未授权接口返回 401，运行配置未改变。

未重复全套回归，没有真实模型调用。此处修复的是进程内通用入口显式注入依赖时的归属问题；不宣称所有线上请求此前都会触发该问题。
