# 上下文策略按完整结果验证

服务器隔离复现确认：模型遗漏明确任务、返回两个其他策略时，后端会插入
必做任务，再截掉最后一个模型策略，最终仍标为语义选择成功。本阶段删除
这段改写，让模型获得完整约束，后台验证其实际返回结果。

## 修改

- 模型输入显式提供 `required_strategies`，要求按给定顺序置于输出前缀，
  完整列表仍为 1 或 2 项。
- 漏任务或顺序错误明确报错，不再自动插入、去重并截断策略。
- 合法完整选择原样保留；兼容性只检查一次。安全保护和两个明确任务
  已经占满槽位时跳过策略模型的逻辑保持不变。

仅调整现有输入协议和校验，产品代码净增 1 行。没有新增意图规则、策略
词表、分类器、重试或框架，也没有改动记忆选择、状态估计和权限。

## 验证

- **38 项直接相关检查通过**。首轮 37 项有一项仍期待“补齐后不兼容”的
  旧原因；明确缺失任务后，仅复测受改动的两项错误路径，再补一项受提示
  长度影响的长查询预算检查，没有重跑整组。
- 进程内 API 路径的受控检查确认：错误返回 503，回答模型不被调用，
  对话及模型调用记录不写入。原有断言全部保留，只精确区分错误原因。
- 使用实际应用上下文工厂及当前 **DeepSeek Flash** 新发出 **1 次策略
  HTTP 请求**。模型把必做任务放在首位，应用保留完整返回列表，完整来源
  继续保留为原话，没有提升为已确认事实。
- 前置状态审核原样复用一条输入及参数完全相同的旧响应，不计为新模型
  验证；最终回答模型没有重测。此次不声称重新验证完整 HTTP 登录鉴权。
- 定向静态、语法和差异检查通过，保护分支及固定策略词表未修改。
- 已部署服务器，后端就绪和前端登录页均为 200；配置及其他服务未改动，
  验证后按摘要同步本地。

单次模型抽查只验证当前完整策略协议，不保证所有表达均被正确分类。模型
违反任务约束时会明确失败，而不是由后台改写成成功。原始交换、运行数据、
隔离数据库及密钥不进入提交。
