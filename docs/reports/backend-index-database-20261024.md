# 索引就绪状态的依赖归属修复（2026-10-24）

上一阶段沿索引管理与生成调用链审计后，使用两个隔离 SQLite 数据库复现了相同修订号下的依赖串用。甲乙库各有完整课程规则，文档数量、ID 和修订号相同，但停课条件和确认人不同。

旧实现仅用版本号命中就绪状态：切换数据库后，共享索引仍返回甲库原文；同时更换为空索引时，准备函数返回成功但索引没有数据。这两例均已在旧代码上失败。

就绪缓存现在保留数据库和向量索引的实例归属。只有两个实例身份与已提交版本都匹配，才可复用就绪状态；任一实例变化就清除本地版本并进入既有内容核对与重建流程。归属和版本检查统一放在现有重建锁中，删除锁外重复快速判断，生产代码净减少 2 行。没有恢复已删除的冗余布尔状态，没有新增策略层、关键词规则或降级。

服务器验证后同步本地：

- 两个旧失败场景均返回正确数据库的完整原文，并确认当前数据库的重建完成状态。
- 补验数据库不变、仅替换索引实例，空索引会得到正确内容。
- 首轮 155 项检查通过；新增独立场景后只重跑归属测试文件的 3 项。按最终用例去重，共 156 项相关检查通过，无跳过。
- 保留并验证原有跨进程版本新鲜度、并发更新、事务提交、数据库故障、索引损坏及知识库隔离行为。
- 静态检查、仓库完整性及差异检查通过。部署后后端就绪、前端登录返回 200，未授权接口返回 401，配置未改变。

范围与限制：修复的是索引依赖被重新绑定后的就绪缓存归属。模块级数据库仍是现有接口的主要依赖，本轮未将全部知识接口改造成多应用、多数据库并发隔离，也没有承诺运行中可以并发修改全局数据库。索引管理的职责拆分仍需在统一调用方依赖注入时推进。

没有真实模型调用，没有重复全套回归，也未修改知识数据或数据库结构。
