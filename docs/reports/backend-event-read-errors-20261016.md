# 已选事件记录损坏时明确失败

本地基线：`616ea91d6b98972ad92eca7696c57850099886ff`。用户已授权服务器断线期间先本地修改。

## 实际问题

记忆召回在构造最终 `MemoryItem` 时调用 `event_reference_content`，判断当前计划是否逾期。旧逻辑把日期解析失败设为“未过期”，继续返回普通计划；布尔日期和非对象事件还会因真假值默认处理被当成缺失。

三类完整合成复现均返回正常内容：不可能的日期、`scheduled_date=False`、`event=False`。读取没有报错，但并未成功解释存储状态。

## 修改

明确区分可选事件缺失、日期尚未确定和无法解析的已存字段。需解释当前计划日期时，非法日期不再生成“未过期”结论；事件字段为非对象时不再当作不存在。

使用具体 `EventMemoryReadError` 保留异常原因和安全字段名。API 角色上下文准备返回 503，包含 `stage=memory_read`、`reason=invalid_event_record` 及字段，提示修复数据后重试；回执不含原文或损坏值。没有重试、丢弃错误后继续或改写存储记录。

合法未定日期保持原内容；逾期计划仍只描述结果未知；已完成和历史记录不被重新解释为当前待办。没有新增事件语法规则、分类器或写入逻辑。
