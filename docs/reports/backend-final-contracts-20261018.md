## 架构判断与修改

保留模块化单体及现有来源边界：问题规划、对象绑定、检索、原作快照、证据审核、生成预算和引用绑定各自承担明确职责。本阶段围绕真实链路失败精简实现，没有增加策略层、语义关键词规则、模型替换或隐式降级。

真实原作检索取到三份来源后，旧审核目录将每个短行都展开为一条记录。1490 条记录触发固定的 256 条上限，模型尚未审核证据，请求便返回 503。其中一份完整来源只有 26856 字符，条数限制不能代表实际模型容量。

`knowledge/curated_task_evidence.py` 改为对连续原文按既有的 512 字符粒度生成块，保留全部字符、来源身份、精确偏移和起始行号。删除逐行展开及固定目录条数限制，仍由完整审核请求的实际 token 预算决定是否可发送。原文不截断，超预算明确失败。运行时代码净减少 7 行。

`app/main.py` 将启动配置与记忆写入配置检查移到资源获取之前。配置不合法时直接报告配置错误，不进入尚未接管资源的关闭流程，避免旧事件循环中的全局回写实例掩盖原始错误。成功启动、资源获取后的失败及正常关闭继续使用原有清理顺序和错误传播机制，没有新增兜底分支。
