# 记忆证据边界及无变化回执

移除模型证据被后台改写后接受的分支，并让可检测的长度协议错误明确失败。
修改前服务器隔离复现确认：历史引文可以被替换为当前原话后入库；超过
120 字的模型引文则会被静默过滤。产品代码净减 **11 行**。

## 修改及验证

- 模型提交的短引文超过 120 字，业务筛选前报告 `MemoryResponseError`，
  回执定位 `evidence`。低置信度不能掩盖协议错误，整批校验仍先于写入。
- 删除历史引文自动替换。模型应引用当前原话；有效当前引文仍可用用户
  历史消歧，assistant 历史不能提供用户事实。
- 完整原话观察仍保留全部来源及末尾限定；120 字限制只作用于模型提供
  的短引文，不截断后续派生的完整原话证据。
- 无变化回执区分 `no_new_information` 与 `no_eligible_memory`，明确是否
  有模型候选未通过准入。后者不表示已经理解并保存。
- 定向测试最终 **88 项通过**：75 项主检查，失败后只复测 2 项；另做
  9 项输入预算检查，其中过期历史输入控制修正后仅验证受影响的 5 项。
  没有重跑完整组或全量回归，保留了原始失败结果。
- 历史格式测试遵守已有的严格输入协议：有效角色保持原文和权限标记；
  外部对象、非标准角色、system/tool 输入明确报错，不静默丢弃。
- 语法、定向静态及差异检查通过。证据准入之外的值消歧、权限、持久化和
  生命周期函数未变；原有真实模型记录未修改。

## 真实抽查及仍有限制

使用实际记忆客户端和已有 **DeepSeek Flash** 配置共新调用 **4 次**。
原提示和一次合并说明的尝试各检查两条相同输入：历史消歧均成功，模型均
引用当前原话；长计划均未形成结构化记忆。

长计划的原始输入完整。模型的限定条件都来自完整原话，但未被它提供的
短引文覆盖，因此被原有准入检查拒绝。该检查实现未变，新增长度错误检查
也未触发。合并提示词没有改善结果，已撤回；未通过修改预期或放宽证据
校验将这项抽查改称成功。

两次长计划的完整原话都已保存，末尾“尚未收到录取、不要声称已经出发”
保持完整，仓储检索能返回完整原话。这里只验证来源保存及检索，不宣称
结构化提取或最终回答已经通过；该案例作为后续优化任务保留。

每次抽查还做四种受控记录检查，共 8 次、4 种不同情形：超长引文、低
置信度的超长引文、历史引文、显式空提取，结果均符合错误或无变化约定。
这些记录复用不计为新的模型验证。

已部署服务器，后端就绪及前端登录页均为 200；配置和其他服务未改动。
验证后按摘要同步本地。原始交换和隔离数据库仅保留服务器运行目录，提交
不包含密钥、运行数据或真实用户原文。
