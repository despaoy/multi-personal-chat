日期：2026-10-16。基线：`aaf6ba4a211fbbf2cf32b71424a2a1a36333f1d4`。

## 问题与修复

默认角色服务首次构建后一直保留当时的历史、来源、记忆参考区、审核预算和原话观察语义。主聊天的自定义数据库路径还在 HTTP 请求排队前构建角色服务，早于实际生成绑定提供方。

服务器隔离预检实测：本地提供方切换为 65536 工作窗口的兼容提供方后，当前历史预算为 65536，默认服务和排队前服务仍为 16000。完整 SQLite 原文、关联记忆、角色画像和真实上下文准备链进一步确认：当前参考区预算应为 32768，实际仍为 6000，且原话观察标记仍被隐藏。

默认服务现在仅在完整 `ProviderContextBudget` 相同时复用，保留已有记忆向量缓存的收益；预算变化时创建新实例，不修改正在处理其他请求的实例。工厂接受已经解析的预算，避免重复解析。HTTP 依赖只绑定容器数据库与运行时，在排队执行、绑定实际模型配置之后构建角色服务。准备与回写复用同一局部实例，消息、记忆和关系仍读写同一数据库。无角色请求不构建角色服务。

无效的当前预算立即报错，不返回旧实例。没有增加模型切换、重试、分类规则、依赖或缓存框架。
