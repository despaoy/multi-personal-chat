# 向量状态接口的真实依赖与明确失败

日期：2026-10-17。基线：`76b7decebd4460a06857f64cb96826b9a6460435`。

## 问题与修改

`app.config` 通过捕获 ImportError 设置向量模块的“可用”标记，并转发 `get_vector_db`。它没有独立配置入口，唯一生产消费者是向量状态接口；检索已经直接检查真实依赖。该标记会阻止接口重新检查依赖，初始化或统计失败还会通过 HTTP 500 和异常日志暴露原始内部错误内容。

删除旧标记和配置层转发，状态接口在使用时直接导入向量数据库。依赖导入、初始化或统计失败返回 HTTP 503 和安全的检查说明，保留原始异常作为 cause，日志记录失败环节及异常类型。合法空索引仍是成功结果，请求取消保持原有取消语义；接口路径与管理员依赖不变。

清理九处失效的测试开关，删除测试中伪造的配置模块和配置层 getter。文档更新、创建和导入测试改为观察实际的向量 getter，继续检查写入不会触发额外索引发布。生产代码增加 7 行、删除 20 行，净减少 13 行。

## 验证

服务器隔离环境复现了旧标记阻断真实依赖检查，以及接口和日志暴露内部异常内容的问题。随后完成 46 项定向检查，全部通过，没有真实模型调用，没有全量回归。

新增检查覆盖依赖、初始化及统计失败的安全说明和异常来源，合法空索引，请求取消，以及实际 HTTP 路由的匿名 401、普通用户 403、管理员成功和服务失败 503。关联检查保留真实 FAISS 快照的 flat/ivf/hnsw 类型、索引修订与跨实例一致性、CRUD 后统一发布和发布失败不返回成功的行为。

首次测试选择包含一个不存在的用例名称，收集阶段未执行任何用例；修正名称后才执行上述 46 项。未反复运行已通过测试。静态比较确认除此接口和旧配置块以外的配置及 API 业务语法树不变，未发现新增静态诊断。

服务器部署后，后端就绪与前端登录页均返回 200，匿名向量状态接口与其他受保护接口返回 401，安全响应头存在。源文件哈希与部署记录一致，运行配置、前端和其他服务进程均未改变。
