# 查询规划失败明确传播，移除部分成功路径（2026-10-13）

## 问题与修改

聊天实际链路为意图检测 → plan_retrieval_views → 问题绑定 → 检索/证据审核 → 生成。此前调用方已把完全失败的规划状态转换为 HTTP 503，但规划器内部仍接受缺少依赖或业务切分字段的旧结构，非法检索词或非法切分还会生成“仅依赖”或“粗粒度”可用计划；异常原因也会在状态转换中丢失。

现在规划结果必须完整包含 search_views、dependencies、public_partitions，并通过原文片段、全段依赖覆盖及公共任务切分检查。删除旧输出兼容、非法片段保留部分计划、非法切分改用粗任务的分支。已启用规划的模型故障、超时和非法输出直接抛出 QueryPlanReviewError，保留原始异常链；输入容量错误保留原类型。聊天入口使用现有统一处理返回 HTTP 503，在检索或回答调用前停止，删掉重复的状态转异常判断。

功能开关复用项目现有显式布尔解析；超时须在 [0.1,30] 秒内，非法值不自动压回范围。显式关闭、独立原文读取和 Corrective RAG 的既有独立路径保留。生产代码净减少 9 行，没有新增依赖、配置项或处理层。
