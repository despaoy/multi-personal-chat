# 知识创建和导入共用一次索引发布

真实隔离 SQLite/FAISS 预检确认：创建文档会先增量向量化一次，但 SQL 原子提交已把索引修订标记为 dirty，随后首次检索仍完整重建，单个样例执行两批相同来源的嵌入。

本阶段删除创建、ZIP 导入、目录子文件夹及根目录导入的四处增量向量化、临时向量文档和重复路径拼接，沿用更新/删除已经使用的统一发布入口。文档、完整分块及修订号仍原子提交，写入后只清除当前进程的加速状态；检索入口完成索引重建和完整性检查后才提供证据。

同时删除创建文档时仅供旧索引拼接使用的一次知识库查询，保留实际决定分类的文件夹读取。三个导入分支不再保存未使用的数据库返回值，原始保存调用及参数保持不变。生产代码净减少 111 行。

完整用例使用已有文件夹，暴露 SQLite 重复知识库/文件夹插入捕获冲突后未结束事务的问题，后续原子文档提交会报嵌套事务错误。各补一处回滚修复收尾，没有移除已有父级这个正常使用前提。新增重复父级后继续提交及自动重用同名知识库的验证。

17 个有效场景通过。首次 14 项中 10 项通过，定位四个失败同属上述事务问题；修复后只运行四个失败和三个新增场景，共七项，全部通过。既有业务断言保持原样，删除一个已无作用的测试开关，未重复全量回归。

使用真实 FAISS 快照和受控嵌入验证四条路径：原文、否定条件、时间、分类和知识库归属完整；写入阶段无向量化，首次检索仅一批，后续有效索引不重建；落盘重载、BM25/向量/元数据数量一致。索引 flush 故障时原文仍完整保存，索引不标记完成，实际搜索返回 503，错误响应不暴露私有细节。

静态核对确认源数据原子提交参数、统一重建和 RAG 逻辑、PostgreSQL 持久化实现均未改变；SQLite 只增加两处冲突回滚。静态检查无新增问题，语法兼容 Python 3.10。未调用真实大模型，未进行新的模型理解质量评测，也未重复既有 PostgreSQL 事务回归。

服务器先修改、定向验证和部署，后端就绪与前端登录页为 200，匿名保护接口为 401，安全响应头正常；运行配置、其他服务及现有知识数据未改。随后同步本地及 GitHub。

范围限制：保留既有导入接口输出格式，批量导入含 errors 时的整体完成状态仍需结合实际前端消费单独检查。向量依赖可用标记也仍有独立审计项。总体优化目标继续进行。
