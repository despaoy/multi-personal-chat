# 输入校验直接作为 API 必需依赖

服务器隔离复现确认：生成组件能在校验模块导入失败后继续加载，并通过
INPUT_VALIDATOR_AVAILABLE=false 跳过校验。完整应用的其他路由又直接依赖
对应模式，最终可能变成另一个导入错误，依赖职责与原始失败原因不清晰。
正式应用没有用于关闭这些请求校验的用户配置。

## 修改

- 生成、配置、知识文档和训练 API 直接导入所需校验器与模式，缺依赖时
  原始错误立即传播，不再依赖可用性标记或按请求延迟导入。
- 删除配置模块的可选校验转发、四个入口的跳过分支及全局标记；增强
  状态接口保留原 JSON 字段和正常值，表明正常构建所必需的组件已存在。
- 校验器实现、全部内容规则、长度限制及 Pydantic 模型均未修改。没有
  通过删除额外安全检查来声称它们与结构模型完全重复。
- 清理 19 个测试文件中 21 处全局关闭校验的设置；受影响测试现在实际
  执行原有校验。产品代码净减少 24 行，没有增加替代开关或兼容分支。
