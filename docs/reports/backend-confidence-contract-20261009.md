## 问题与修改

character/memory_llm.py 的候选解析原来把缺失置信度默认成 0，字符串强制转换为数值，转换失败与越界值则静默丢弃。布尔值 true 还能转换成 1。这会把不符合模型输出协议的结果解释成合法候选或“没有新增记忆”。

现在在候选进入业务判断前，要求 confidence 为 0 到 1 的 JSON 数值；缺失、布尔值、字符串、容器和越界值明确抛出不含原文的 ValueError。删除原有默认值、强制转换及异常吞掉逻辑，业务代码净减少 1 行。

保持正常业务规则：0 与合法低置信度不写入，整数 1 和合法小数可以通过置信度准入；最终是否写入仍受证据、主体和权限校验约束。整个响应解析成功后才进入写入，混合合法与非法候选不会部分保存。原始来源仍按既有流程保存。
