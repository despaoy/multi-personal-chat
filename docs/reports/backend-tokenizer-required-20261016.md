# 必要 tokenizer 不再静默回退（2026-10-16）

## 问题与契约

共享计数器用于主回答编译、审核预算和后台记忆消息构建。服务器原代码在已识别的官方 DeepSeek Flash 配置下，将指定 tokenizer 文件指向隔离的缺失文件：没有抛错，改为 UTF-8 字节上界估算，并返回 utf8_byte_upper_bound。原分支同样掩盖缺库、读取失败与 hash 不符，并把不可用结果作为正常缓存项。

字节上界原意是保守预算，不能说它必然导致超窗口或错误事实；实际问题是必要依赖故障被转成另一个计算方式，可能额外拒绝输入或减少历史，线上也没有说明故障。本次遵循必要依赖失败应报错的约定，收紧这一契约。

## 精简修改

只改一个生产文件 token_counting.py，净减少 13 行。移除捕获异常后返回空 tokenizer、错误原因元组和字节回退。loader 直接返回通过固定 hash 校验的本地 Tokenizer；文件、依赖、UTF-8 和解析错误保留其原异常，hash 不符明确报 asset integrity 并提示恢复随包数据。失败不再被缓存为可用估算。

元数据入口也要求必要加载成功，只报告实际 BPE 来源，删除始终为空的 unavailable_reason；仓库、版本、资产 hash 和零网络请求来源字段保留。已审查真实消费者，没有外部使用方解开私有 loader 元组。无需新增异常体系、配置、兼容分支、网络下载或重试层。

替换五项断言字节回退的过时用例，以两模型完整故障和恢复行为验证新契约。保留健康 BPE、其他模型既有估计、完整来源和历史轮次预算测试，没有通过放宽有效检查换取通过。

## 定向验证

服务器 22 项测试通过，7.22 秒。新增 16 项：两模型分别验证缺文件、缺库、hash 不符、匹配 hash 后无效 UTF-8、匹配 hash 后真实 tokenizer 解析失败；计数和元数据入口均报对应错误。恢复真实文件后不清理失败缓存也能取得与独立 Tokenizer 一致的结果。

真实 ReviewContextBudget、build_generation_request 和 generate_character_response 缺资产时都失败，模型 spy 没有调用。真实 SQLite、记忆调度器、complete_turn 和持久 worker 链路启用 8192 token 预算后，缺资产产生不可重试的 failed 回执，worker blocked，原文、原来源 ID、原接收时间和原回复保留；零 claim、零模型调用。

六项关联健康验证核对真实两款 BPE、数字输入预算、完整近期轮次、否定及多项证据原文，以及切换模型不混用资产。没有运行全量回归。语法、差异和增量静态检查通过；所有模型输出控制均显式隔离，付费模型调用为零。

## 部署与限制

按服务器验证、仅重启后端、就绪 200、运行配置和其他服务不变、SHA 清单同步本地及阶段提交 GitHub 的流程收尾，实际证据保留在阶段目录。未执行 PostgreSQL、真实模型语义质量或吞吐测试。

本阶段只移除已识别 DeepSeek 所需 tokenizer 的故障回退，不改变其他模型原本标明的估计方式。模型识别仍使用现有环境配置；数据库请求快照、审核客户端与独立记忆配置之间的计数来源一致性留在下一阶段，不能据此声称所有调用都已经使用实际模型的计数器。整体优化目标继续。
