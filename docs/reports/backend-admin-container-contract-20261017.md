# 管理员鉴权不回退到全局数据库

服务器隔离请求复现确认：应用缺少运行容器时，管理员鉴权捕获配置错误，
转而使用全局数据库；全局库中同名用户为管理员便可返回授权成功。这条
为最小测试保留的兼容逻辑也会作用于真实 HTTP 请求。

## 修改

管理员 JWT 的当前角色只在当前应用绑定的数据库中复核。容器缺失、类型
错误或数据库故障直接返回 503，不切换数据库，并保留异常原因。

删除嵌套捕获与延迟导入，产品代码净减少 6 行。已验证 API 密钥的独立权限
来源、角色降权检查、背压状态与 Retry-After 保持原实现。没有增加配置项
或新的权限框架。旧测试改为提供真实调用所需的应用容器，原有断言未放宽。

## 验证

- 17 项相关检查通过，未运行全量回归或重复整组检查。
- 使用合成签名令牌发出真实 ASGI 请求：缺失或无效容器返回 503，全局
  数据库访问次数为零；当前库中用户已不存在仍按权限不足返回 403。
- 数据库异常返回 503 且保留原始原因；容量不足保留可重试响应。正常
  管理员、已降权用户及三种已验证密钥身份的既有语义通过检查。
- 静态逐段比较确认普通用户解析、密钥分支、最终角色判断、背压处理
  和旧测试断言未改变。语法、静态与差异检查通过。
- 已重启服务器后端，就绪与前端登录页均为 200；未登录资料和生成
  请求均为 401，配置及其他服务未改变，再按摘要同步本地。
- 此阶段没有调用付费模型，也没有向生产数据库创建用户或读取真实账号。
  ASGI 探针验证应用路由和依赖，部署后检查验证实际服务健康及未登录拒绝。

原始测试令牌、隔离数据库和运行日志保留服务器，不进入提交。
