# 修复空用户 ID 的排队身份

## 问题与修改

认证依赖会返回含 `user_id`、`username`、`role` 的字典；无数值用户 ID 的认证结果中，`user_id` 可以为 `None`。排队服务原先使用 `dict.get(key, default)`，只有键不存在时才读取用户名。因此键存在但值为空时，不同用户名均转换成字符串 `None`，共用限流身份及默认 `manual:None` 会话。

改为先读取用户 ID，非 `None` 时使用该 ID，否则使用认证结果中的用户名。保留数值 ID（包括 0）的优先级，移除缺失身份时的 `unknown` 默认值，不新增校验层、包装或重试。生产代码减少 4 行。

此修改仅修正已有认证身份到排队身份的映射，不改变身份认证、消息历史范围或显式指定会话的语义，也不声称将同一认证用户名下的不同 API 密钥区分开。

## 证据与验证

服务器使用两个完整的合成认证结果执行同一排队服务：修复前两者的限流身份均为 `None`、默认会话均为 `manual:None`；修复后分别为各自用户名及对应默认会话。测试未访问真实用户记录或模型。

扩展现有排队测试，覆盖正常 ID、0、两个空 ID 用户名及旧式缺少 ID 键的用户名。聊天服务和 Web 来源身份两个测试文件共 15 项全部通过，无跳过，原有业务断言保留。

静态检查、仓库完整性及差异检查通过。后端重启后就绪和前端登录返回 200，未登录访问受保护接口返回 401；配置及前端进程未改变。服务器验证后按内容哈希同步本地。

本阶段未调用真实大模型，未重复运行全部回归测试。
