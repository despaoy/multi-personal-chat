# 共享模型 API 依赖归属

整体审查确认：聊天、独立知识问答和知识库搜索的检索策略存在合理差异。聊天支持独立公共资料来源组合；独立问答限制角色知识域；搜索返回片段而非生成答案。本次保留这些业务边界。

发现知识问答在初始化模型适配器时，从聊天 API 导入共享 vLLM 客户端的 API 包装函数。这使同级接口依赖聊天路由模块，同时把应用依赖装配留在聊天接口中。

将原函数完整移至既有 app.providers，由聊天和问答共用。底层客户端的实例、连接池和生命周期仍由 inference.vllm_client 管理；应用依赖层负责启用判断和 HTTP 错误转换。没有新增转发包装、兼容入口或处理阶段。移动前后函数 AST 一致，现有函数内的初始化异常转换及取消传播行为保留。生产代码净增加 4 行，来自导入及分隔调整。

## 验证

- 五个直接相关测试文件共 172 项通过，无跳过。覆盖问答惰性初始化、云端选择不调用本地服务、流式与取消行为、初始化失败、客户端重建和共享运行时。
- 原先通过聊天模块替换问答依赖的测试，改为在实际应用依赖所有者上替换；业务断言保留。
- 静态检查、仓库完整性和差异检查通过。没有运行全部回归，没有真实模型调用。
- 部署后后端就绪和前端登录返回 200，未登录受保护接口返回 401；配置及前端进程保持一致。服务器修改按内容哈希同步本地。

本次收敛一个明确的接口依赖倒置，不代表生成入口的全部业务编排职责已经拆分完成。
