# 每轮云端主答固定连接配置，避免跨模型缓存污染（2026-10-15—16）

## 实际问题与复现

缓存查询先读取提供商配置生成标识，模型调用又读取一次实时配置，最后根据共享提供商状态生成来源标签。配置在这些步骤之间改变时，缓存和真正调用的模型可能不同。

服务器在原代码上用实际主答入口及隔离 HTTP transport 复现：按模型 A 查询缓存后，管理设置切换到 B，实际发送的是 B；该回复写入 A 的缓存。恢复 A 后直接复用了 B 的结果。输入包含完整金额、时间或否定/条件资料，所有回答和传输均为明确的测试控制，没有真实用户记录和真实模型调用。

## 单轮快照与职责

OpenAICompatProvider 增加请求快照能力，复制配置并解析连接字段，继续使用现有协议校验和 HTTP 连接池。管理用提供商保留实时刷新；已绑定本轮的提供商不再在每次模型调用前刷新配置。同一轮若需要多次模型调用，使用同一实例，不混合更新前后的模型、连接地址或凭据。

主答有缓存时先取得快照，用其生成缓存标识，未命中时继续使用该快照发送请求；不启用缓存时，在第一次实际模型分派时获取快照。模型标签、计量和消息归档也使用本轮实例的真实模型名称，不从其他请求刚更新的共享状态猜测来源。缓存查询期间的提供商类型变化也不会改写本轮缓存标识。模型分派前若类型已变化仍明确失败，不自动切换。

保留确定性结果和显式内部模式语义；缓存复用仍明确 modelInvoked=false。没有新增模型回退、重试、规则或分类器，没有改变资料权限、记忆持久化与独立审核/检索规划的配置策略。移除同一提供商值的两层局部别名，只使用一个本轮来源变量。
