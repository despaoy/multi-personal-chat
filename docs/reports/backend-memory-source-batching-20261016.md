## 问题和修改

生成前的结构化记忆校验逐条查询来源指纹和原文回执，同一发送内已有绑定也会重复查询。隔离 SQLite 基线证明，两条完整记忆分别执行两次指纹读取和两次回执读取。

复用仓储已有的精确“记忆—来源”配对读取：每类来源先去重，再按接口上限每批 200 对读取，最后分别核对各记忆原有版本。两条记忆的来源查询由四次降至两次；共有 N 条记忆时，不再固定执行 2N 次来源查询。唯一存储记录仍逐条读取，没有增加仓储接口或跨发送缓存。

指纹与原文保持各自的授权接口，不混合其跨会话权限。返回重复或未请求配对时报错；数据库读取失败向上传递，模型不会收到无法核验的请求。明确撤销或删除导致合法缺失时，仅移除对应证据，保留独立有效记录及公共来源；这不是把读取异常当成空结果。

所有异步读取结束后再检查有效时间，仍按本轮原预算重新编译剩余证据。没有新增关键词规则、分类器、重试或数据写入。

另修正一项过期测试：原测试要求来源读取抛错后继续生成，违背当前失败必须明确的要求和现有实现；现验证异常保留且模型未调用。
