# 统一分支入口检查，消除接口循环依赖

## 问题与修改

普通生成入口为了检查分支功能开关，需要导入 `api.narrative`；分支接口又调用 `api.generate`，形成双向接口依赖。原检查还将除 `true`、`1` 外的任意配置当作关闭，拼写错误也返回 404，隐藏配置问题。

将同一检查移至已有的 `app.dependencies.require_narrative_enabled`，供分支路由依赖和普通生成入口共同使用。删除旧位置实现及无用导入，不保留别名或转发函数，不新建模块。

复用现有 `read_bool`：缺省仍关闭，标准 true/false、1/0、yes/no、on/off 按统一规则解析；空值、拼写错误及其他无效值明确抛出配置异常，错误信息包含配置名而不泄露其值。生产代码净增加 2 行。

## 验证

服务器上分支业务与聊天生成服务两个测试文件共 43 项全部通过，无跳过。新增参数化检查覆盖启用、关闭、缺省及无效配置；保留现有路由、所有权、分支状态与生成断言。

静态检查、仓库完整性和差异检查通过。后端重启后就绪接口及前端登录返回 200，未登录访问受保护接口返回 401；配置内容与前端进程未变化。服务器通过验证后按内容哈希同步本地。

此阶段消除了普通生成到分支 API 的反向导入，不宣称整个生成模块已完成分层。未调用真实大模型，未重复运行全部回归测试。
