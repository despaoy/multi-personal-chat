# 令牌撤销归属与有效期修复（2026-10-24）

认证中间件和应用依赖原先反向导入 api.auth 的撤销状态。该 API 同时持有令牌撤销字典，超过 10000 条时删除一半记录，其中包括尚未过期的撤销记录；这会使已注销令牌重新被接受。注销保存过程的宽泛异常捕获也会把内部失败当作成功。

将撤销状态和操作迁移到 infra.token_revocation，API、中间件和依赖校验共同使用该实现，移除反向 API 依赖。只清理已过期记录，删除未过期淘汰分支及闲置上限；仅捕获 JWT 无效异常，内部保存或清理错误正常抛出。生产代码净减少 3 行。

服务器先验证后同步本地：

- 三个完整隔离案例中，旧代码在记录保留和异常传播两例失败，合法无效/过期令牌处理原本通过。
- 修复后 10001 条未过期撤销记录全部有效，已过期记录清除；注入的内部保存异常保留原始异常对象。
- 38 项认证、数据库归属、并发、背压及架构相关测试通过。原有注册、查询、注销后拒绝访问的流程继续通过，断言未放宽。
- 静态检查曾指出三个测试旧导入无用，已删除后通过；仓库完整性及差异检查通过。
- 部署后就绪及前端登录返回 200，未授权接口返回 401，配置未改变。

边界：撤销存储仍沿用进程内 TTL 字典，重启清空，不提供多进程一致性；本轮未迁移数据库。有效记录现在保留到令牌到期，内存随有效期内撤销数量增长，不再通过恢复已注销令牌换取内存上限。没有真实模型调用，未重复全套回归。
