# 数据库选择不再隐藏配置与依赖错误（2026-10-15）

## 实际问题与根因

应用默认 RuntimeContainer 从 db.adapter 导入数据库实例和模式；API 的兼容导入也使用这个组合入口。旧选择器把未知布尔值解释为 false，把未完成的 PostgreSQL 组件配置解释为未配置，再在开发环境捕获 PostgreSQL ImportError 后导入 SQLite，可能让实例启动成功却使用另一份数据。

服务器在修改前保存原源码；隔离复现以 git 原版本和备份 SHA 一致为前提。确认 flase 开关会选择 SQLite、只有 PG_HOST 会选择 SQLite、开发环境缺少 PostgreSQL 模块会依次导入 PostgreSQL 和 SQLite。首次复现的隔离 os 对象缺少 getenv 接口，脚本失败；补齐接口后对保存的原源码完成复现，没有改变生产配置，也没有把首次脚本错误归因为产品缺陷。

## 修改后的唯一选择入口

明确的 USE_POSTGRESQL 使用已有 read_bool 校验，不再复制宽松布尔解析；拼写错误和显式空值会直接失败。优先级仍为明确开关、DATABASE_URL、完整 PG_HOST/PG_USER/PG_PASSWORD/PG_DATABASE 组件、无数据库配置时的本地 SQLite。开关明确为 false 的开发和测试配置继续支持 SQLite；生产环境的部署要求仍由既有校验控制。

DATABASE_URL 既不是支持的 PostgreSQL URL、也不是 SQLite URL 时失败；组件只配置一部分时失败，错误只列所需字段，不包含实际连接串或密码。明确开关的优先级仍高于其他配置，不引入冲突策略或新配置项。

选择 PostgreSQL 后，任何环境缺少依赖都保留原因为 RuntimeError 并说明安装依赖和重启，不再改用 SQLite。其他配置/初始化异常保留原异常，不宽泛捕获、返回空实例或修改模式。没有新增依赖、重试、mock、数据迁移或数据库文件操作，也没有改变查询与业务数据语义。

## 定向验证与限制

24 项相关测试首轮全部通过（1.86 秒），包括显式布尔错误、未知 URL、部分组件、开关优先级、两种环境只导入选定后端、缺依赖明确失败且不导入 SQLite、配置异常保留、无效开关在任何后端导入前失败；关联检查覆盖既有选择语义、生产部署校验和应用正常装配。测试输入中的连接串及口令均为合成数据，不连接实际 PostgreSQL。

组合入口测试执行真实模块源码，以隔离 SQLite 对象作为明确的测试依赖，验证导入选择与错误传播；不宣称这些控制就是实际 PostgreSQL 驱动连接成功或 SQL 事务验收。生产部署后的就绪检查单独验证现有数据库服务。未运行全量回归，未改变 DeepSeek、检索意图、长期记忆或模型选择，付费模型调用为零。

语法、增量静态检查和差异检查通过；导入排序只整理本次两个 Python 文件。服务器先修改和验证，再只重启后端；部署要求就绪 200、配置及其他服务进程不变，随后按哈希同步本地、服务器提交与 GitHub。整体精简目标继续；模型调用记录吞错等其他问题尚未在本阶段修改。
