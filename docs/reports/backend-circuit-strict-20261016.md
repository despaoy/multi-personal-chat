# 熔断器移除隐式降级并统一状态处理

日期：2026-10-16。基线：`c7713fc4d2867904dbb1af5ca53b33a3d44bd8d3`。

## 实际问题与使用方

服务器预检使用真实聊天入口、CircuitBreakerRegistry 和隔离 SQLite 调用记录：前 5 次受控模型故障正常抛出，第 6 次熔断拒绝未调用模型，却返回默认 `None`，随后元组解包抛出 `TypeError`。数据库也把这次拒绝记录为无关的 TypeError，掩盖了实际熔断原因；没有生成或归档成功回复。

调用方审计确认生产使用只有主聊天的 `call`、vLLM 非流式 `call`、vLLM 流式状态/手工记账、管理接口的统计/重置及应用生命周期清理。缓存回复、默认值、fallback 回调和排队降级没有业务使用方，仅旧测试还主动选择默认值路径。其他推理队列、限流队列和记忆任务队列不属于该模块，不受影响。

另一个确定问题是半开探测被取消后没有归还名额：唯一名额占用时后续请求一直无法恢复。

## 修改

- 完全移除 `DegradationMode`、fallback、缓存回复、默认值、排队等待和对应配置/统计字段。熔断打开或半开名额已满时只抛 `CircuitOpenError`，不返回替代结果。vLLM 调用方同步移除已经无意义的模式参数。
- `call` 复用同一上下文管理器完成准入、结果记账和取消清理，消除两套近似状态机。保留 CLOSED/OPEN/HALF_OPEN、恢复时间、并发限制、原始业务异常、统计、观察回调、手工记账和注册表生命周期。
- 半开取消归还本轮名额，不伪造调用失败或成功。旧在途成功不能关闭新熔断；同轮半开先成功后失败仍重新熔断，保留既有恢复失败语义。显式 reset/trip 会使旧结果失去修改新状态的权限。
- 主聊天对熔断拒绝返回 HTTP 503，明确 `stage=model_circuit`、`reason=circuit_open`、`modelInvoked=false`，保留原异常链和失败记录。必需调用记录自身失败时继续保留其主错误信息。
- 熔断器由 597 行精简至约 297 行。旧“返回 fallback 即成功”的测试改为验证拒绝且上游只执行一次，其余核心测试保留。

## 验证

服务器定向测试 20 项通过（2.47 秒），没有重跑此前作品证据投影的 44 项。

新增 6 项使用真实聊天编译、隔离 SQLite 记录/归档、真实熔断器和事件协调：正常成功、5 次故障后的第 6 次拒绝及恢复、半开并发名额、取消后的清理与恢复、旧成功不能覆盖新故障、同轮晚失败重新打开熔断。模型边界仅接收完整虚构题设并返回受控结果，不连接 HTTP、不产生模型费用。

关联验证包括核心熔断状态机、跨事件循环生命周期、管理接口重置、架构拒绝成功伪装，以及原有调用记录失败行为。语法、补丁和增量静态检查无新增问题；未运行全量回归。

交付沿用服务器先改和测试、有效后同步本地、阶段同步 GitHub 的流程。部署检查只重启后端，要求 `/ready` 为 200、配置哈希和其他服务进程不变，逐文件核对 SHA-256。

## 当前限制

本阶段不改变 vLLM 流式现有手工准入方案，不声称其并发探测已切换到新上下文管理器。DeepSeek 的真实认证仍为上一阶段确认的 401，凭据更新前没有再次发起真实模型请求；健康检查不代表云端认证恢复。后续继续检查模型故障在普通问答、流式问答和聊天审核中的一致、安全展示，不以本阶段代替那项工作。
