# 批量读取适配器最近检查结果

基线：`a5e08aa41ed9eeef3f45daf6f67b6413b3293a9c`。先审查适配器检查页面、客户端、接口、检查结果写入与两种数据库适配，再在服务器修改和验证。

## 问题与实现

适配器列表对每个目录单独查询一次最近兼容性报告，造成重复数据库往返。改为一次参数化查询，仅查询当前目录中的适配器，通过窗口排序选择各自最近报告，再按原目录顺序组装响应。检查时间相同时按自增 ID 选择最近写入的记录；没有报告仍明确显示未检查。

目录名称始终作为绑定参数传入，不拼入 SQL 值。报告 JSON 的原有类型检查、数据库和解析失败返回 503、取消传播、管理员权限均保留。删除接口模块中没有调用方的 `_execute_sql_insert` 和 `_now`；其他函数 AST 保持一致。生产代码净减少 1 行，没有新增异常捕获或回退策略。

线上角色选择已经使用显式角色/适配器，旧关键词路由只服务离线研究；本阶段未改变这项业务边界，也未删除研究评测实现。

## 验证

- SQLite 隔离数据包含 65 个目录、每个已检查适配器的 8 个历史版本，以及带引号名称的未检查目录。列表查询从 65 次降为 1 次，完整 JSON 响应 SHA-256 保持 `72b50b3b9b46bc6a963f4c5162c798877a7e39f1fd1754388ff35d699e59a1e1`。
- 对照验证正常历史、空目录、数据库异常、取消和最新报告 JSON 损坏五种场景。空目录不查询数据库，失败没有变成成功或旧报告。
- 在已有隔离 PostgreSQL 实例中新建独立测试数据库，经原生 `PgDatabase` 和 `SyncPgAdapter` 执行同样五种场景，得到相同完整响应及一次查询。未连接生产数据库。
- 只执行适配器及相关数据接口的三个测试模块，35 项全部通过；新增一个组合用例覆盖最近报告、相同时间戳、带引号名称及未检查状态。
- 修改文件语法、未定义/重复/未用名称检查及服务器仓库完整性检查通过。服务器启用修改后，后端就绪和前端登录页为 200，匿名受保护接口为 401 并保留 `nosniff`，配置及前端进程不变。

没有执行全量回归或调用模型。数据库往返次数是本阶段的效率证据，未据单次耗时声称所有数据规模均获得固定倍数加速。
