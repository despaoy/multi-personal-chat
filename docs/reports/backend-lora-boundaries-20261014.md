# LoRA 必要检查失败不得继续，删除默认适配器降级工具（2026-10-14）

## 实际调用链

检查显式/激活适配器选择 → vLLM 可用目录 → 共享上下文/提示词 → 生成，确认 list_loras 将 HTTP、连接、解析失败以及无实例统一返回 None，聊天入口又忽略这个未知状态继续调用模型。API 的提示词包装还吞掉读取异常返回空串；注册角色字段缺失也被当作没有附加提示词。两个 safe_resolve 工具没有实际调用方，只彼此连接，仍包含退到 default 或忽略兼容性检查故障的逻辑。

## 修改与正常语义

vLLM 目录查询必须成功并返回完整 data 列表和文本 id，HTTP/传输/解析及配置故障保留原因向外传播，不返回 None 或猜测空目录。合法空目录/只有基础模型代表确实没有可用附加适配器。各配置实例独立并行查询，返回共同已加载的适配器集合；生成可能分配到任一实例，因此不能以首台机器的状态代替整个池。任一查询失败或调用取消，会取消并等待其余查询退出，不遗留后台探测。采用现有请求时限，无重试或默认适配器切换。

聊天入口在有附加 LoRA 时要求服务及查询成功，故障返回 503，合法没有所选适配器返回 409；不能忽略故障继续生成。基础模型请求无需适配器目录查询。原显式提供商、激活/手选适配器、未映射自定义适配器及人物映射语义保留。

提示词直接引用现有注册表函数，删除吞错的转发包装。已注册角色的 system_prompt 必须存在、是非空文本；读取故障或非法字段不能丢弃人物指令继续。基础模型及未注册自定义适配器本来没有附加提示词，继续允许空串；没有强行猜测或补全人物画像。真实角色提示词及冻结训练提示词不改。

删除无调用方的 safe_resolve_lora_served_name 和 safe_resolve_lora，以及因此无用的日志状态。保留正常名称映射、适配器检查报告和激活检查。五个生产模块合计净减少 59 行，未新增依赖、框架、关键词判断或分类器。

旧规则路由还存在管理页、配置 API 和独立历史评测脚本，本阶段未把它改成新的语义路由或删除半套接口；它们需要连同界面和实验记录统一整理。现有 DeepSeek 检索/意图链路未改，本阶段不声称所有路由及适配器降级均已清除。
