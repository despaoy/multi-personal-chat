# 回复缓存去掉无界查询锁与重复状态（2026-10-14）

## 实际证据与范围

检查生产调用方确认，生成入口已统一构建完整请求/模型身份；旧 compute_prompt_hash/build_cache_key 仅用于一个生命周期测试，没有生产调用方。管理接口只依赖 stats/invalidate，缓存条目的访问次数没有使用方。每个查询的独立锁仅包围缓存读取，未覆盖模型调用或缓存回填，不能合并生成请求。

服务器独立内存实例验证：max_size=4、缓存条目为 0 时，2,000 个不同查询未命中保留了 2,000 把锁，容量限制只约束响应条目，没有约束这些查询资源。探针不读生产缓存、不调用模型、不写数据。

## 精简与行为

缓存改为一份有界 OrderedDict，键直接为 (prompt_hash, cache_key)，同一应用事件循环内只有一把操作锁。删除查询锁表、提示哈希辅助索引、字符串键拼装/解析、无用访问计数与旧独立哈希方法；生命周期更换事件循环时仍重建操作锁。保留 LRU 命中及覆盖顺序、合法未命中、按提示身份失效、全量失效、过期清理、管理接口及原统计字段。不声称线程间共享或模型请求合并。

没有生产写入 None 响应的调用方，旧空值标记的调用者也无法区分空值命中与未命中，不能发挥所称的穿透防护。移除该模式：None 写入明确失败，合法查询未命中继续返回 None；原样保存其他合法值，字面 __NULL__ 不再被误当作空值。完整响应仍由生成入口的协议负责，未增加重复的回复内容检查。

容量必须为正整数；默认及覆盖 TTL 必须有限、非负，非法选项在改变已有数据前失败，不能替换为缺省值。TTL=0 明确不保存新数据并移除同项旧值；这是显式关闭该项缓存，不是故障降级。过期改为单调时钟期限，保留原 ±10% 抖动及命中不续期，避免墙上时钟校正影响有效期。计算出的非有限期限也拒绝。

应用配置直接导入和构造所需缓存，模块故障不能隐藏为 LLM_OPTIMIZER_AVAILABLE=false 后正常启动；健康情况下既有能力标志和管理 API 保持。缓存组件与应用装配两处生产代码合计净减少 187 行（组件 184 行、装配 3 行），未添加依赖或策略框架。
