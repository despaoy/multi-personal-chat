# 生成请求按实际选择读取 LoRA

基线：`3b1f0c3f041c507396d91586d11d3ae51704f24d`。

## 问题与修改

`backend/api/generate.py` 原先对每个请求并行读取配置和完整 LoRA 列表，先查激活项，再按请求清除或覆盖。明确使用基础模型、角色或已有分支上下文的请求，也会被无关的 LoRA 读取故障阻断。隔离复现确认：显式 `default` 请求因该读取返回 503，尚未进行模型生成。

现在先确定是否需要选择激活适配器。只有显式选择自定义 LoRA，或没有指定基础模型、角色及已准备上下文而需要选择激活项时，才读取列表；需要两类数据时仍并行读取。选择过程直接处理显式、激活或基础模型三种情况，删除“先选激活项再清除/覆盖”的重复工作。业务源码增加 13 行、删除 13 行，净增 0 行，无新依赖。

配置仍来自请求所属数据库，读取失败保留原因并返回安全的 503。需要的 LoRA 列表读取失败同样明确失败；指定项不存在返回原有 422，不选择另一适配器或基础模型。提供商能力、适配器目录、人物映射和分支一致性检查继续保留。已准备上下文按 `is None` 判断；没有用对象真假值代替。

前一阶段的云模型参数提前校验保持不变。适配器读取和选择之外的生成流程逐段核对一致，检索、记忆、缓存、持久化和授权实现没有改动。没有新增意图规则、分类器或运行时降级。

## 验证

服务器完成 29 项不同的相关检查：18 项新增检查覆盖无关列表不读取、所属数据库配置失败、必要适配器读取失败、未知显式项不切换及实际适配器选择；11 项现有检查覆盖不支持 LoRA 的提供商、目录不可用、人物不匹配和无效配置不能命中旧缓存。

首轮 28 项通过。旧人物不匹配测试在进入被测代码前缺少语义策略的隔离配置，真实模型访问被测试保护拦截。为这一机制测试显式关闭语义策略选择后，仅重跑该失败项，通过；原业务断言经 AST 对比未修改。没有重复完整测试集，没有真实模型请求，也没有改动生产语义配置。

修改文件通过 Python 3.10 语法解析、差异空白检查和 Ruff E9/F 增量检查，无新增诊断。服务器更新后 `/ready` 和前端登录页面返回 200；匿名受保护接口返回 401，安全响应头正常。运行配置与其他服务进程保持不变。

本阶段验证数据读取、选择及失败边界；生成输出由受控测试替身提供，不作为新的 DeepSeek 回答质量证据。没有运行全量回归、生产模型下载或实际适配器推理；此前真实模型链路记录继续作为独立证据。整体优化目标保持进行中。
