# 备份创建统一流程与真实失败传播

基线：`5ed11426f4b7f38491937dbfc29dedadf27684ba`。重新审查应用生命周期、手动与定时备份、列表和正式停机恢复的调用关系，再以隔离合成 SQLite 数据库复现问题。

## 实际问题

- 两套相同的创建流程吞掉文件和数据库错误并返回 None，管理接口只能产生一个没有原始原因的 500。
- 目标数据库连接创建失败时，已打开的源连接没有关闭。
- 同秒连续两次备份共用文件名：成功调用两次，实际只留下一个文件。
- 列表读取某个文件失败时，接口仍返回 success=true 和其余文件，不能辨别不完整结果。

## 修改

合并为一条完整快照创建流程。公开 `backup` 在执行前解析类型，成功返回 `BackupInfo`，失败传播真实异常。HTTP 边界只转换文件和 SQLite 操作错误，保留原始原因并记录错误；不再通过 None 表示故障。

使用标准库管理连接和临时目录。快照和压缩均在私有临时目录完成，压缩成功后原子发布最终文件；失败不遗留半成品或增加成功统计。文件名加入唯一标识，保留现有文件名的读取能力，两次同秒备份可以分别恢复对应版本。

列表读取错误直接抛出；不属于备份的文件名仍按原有解析规则忽略，空目录仍是正常空结果。完整和历史 incremental 类型继续生成完整 SQLite 快照，本次不声称实现差分存储。

生产代码净减少 117 行，没有新增错误类、重试或配置。待单独确认删除的七个旧恢复与安全方法未动；其余业务代码 AST 保持一致，加密与访问控制源码没有修改。

## 验证

- 初次 13 项定向检查全部通过。发现列表问题后，仅新增一项行为检查并复查两项受影响检查，三项通过；累计 14 个不同检查，没有重跑其余用例或全量回归。
- 九组原生前后观察覆盖两种类型的正常创建、源文件缺失、压缩故障、目标连接故障，以及同秒重复创建。正常场景读回数据库和 SQL 导出摘要一致；六组故障保留原始原因且没有成功统计和遗留文件，目标连接失败时源连接正确关闭。
- 同秒场景由一个实际文件变为两个；行为测试还验证两个不同数据版本均被保留，旧文件名可列出，压缩未完成时列表不可见。
- 独立 SQLite、真实签名 JWT 和 ASGI HTTP 的八项检查覆盖匿名 401、普通用户 403、非法类型 422、两种备份创建 200、两种创建故障 500，以及列表读取故障 500。列表问题修改前的原生观察保留了“实际两个、成功返回一个”的记录。
- 初始检查工具曾因重复记录字段和跨线程测试连接清理失败，保留两次原始文件；修正工具后完成基线，未将工具故障归为产品缺陷。
- 语法、名称、差异空白及服务器仓库完整性检查通过。部署后后端就绪、前端登录页均为 200，匿名受保护接口为 401；运行配置和前端进程不变。

所有数据库和文件均为隔离合成资料，没有触碰真实业务数据或密钥。模型调用为零；本阶段未执行 PostgreSQL、前端构建或全量回归，也未扩展为进程强杀后的任务恢复保证。
