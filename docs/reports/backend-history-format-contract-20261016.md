# 统一历史格式契约，保留上下文原文

## 问题与修改

最终生成原来会将非文本历史强制转成字符串、去掉首尾空白，并静默丢弃非法角色。记忆审核则使用另一套“跳过错误条目”逻辑。用户前提被跳过后，助手回答仍可能单独留下，使错误上下文看起来可用。

使用一个独立且不依赖模型或数据库的历史契约替换这些不一致判断：只接受 user/assistant 角色和非空白文本；错误包含安全字段位置，不包含原文。API、角色历史读取、内部审核和最终生成共享该契约。删除原生成历史转换包装；规划器直接使用已校验历史的长度计算裁剪数量，不重复筛选条目。

读取历史后先校验，再用于记忆召回。生成入口在访问回复缓存前也校验现场历史，不能用旧缓存掩盖错误。存储或内部历史错误通过 503 明确报告 `conversation_history / invalid_history` 和字段位置；客户端输入仍遵守原有 API 长度及字段限制。

合法历史不再自动去除空白。SQLite/PostgreSQL 共用的装配函数也保留保存的原文，预算按原文全长计算。完整问答后缀、合法空历史和单边旧记录的处理保留；仅空白的存储字段仍不形成消息。此变更可能使预算保留的历史略少，但不删除存储记录或截取必要前提。

- 原始否定、条件、代码缩进和首尾空白在生成及审核视图中保持一致，不修改调用方数据。
- 错误历史结构、规划及上下文错误的字段报告正确，不输出合成私有内容。
- 实际生成入口在启用检索、关闭检索及存在可命中旧缓存的配置下，均先拒绝错误历史，不调用模型、不保存回复或伪造模型调用记录。
- 实际角色服务拒绝错误数据库历史和现场历史，尚未把错误历史用于记忆召回或审核；正常现场历史优先和空存储行为仍通过。
- API 原有历史大小限制、审核完整问答边界、最终模型窗口的前提保留、规划器裁剪数量通过必要关联检查。
