# 生成前批量复核选中的长期记忆

基线：`1c54c9ee5bb3db22e9b3387af42462ee74301a7e`。先在服务器修改和验证，再同步本地。

## 问题与修改

长期记忆的来源指纹和原文回执已按精确配对批量读取，但生成前仍逐条读取声明版本。同一数字 ID 的不同文本写法还会重复查询。真实 SQLite 和 PostgreSQL 隔离库均复现：201 条选中记忆加一项相同 ID 的文本别名需要 202 次声明查询。

复用现有列表读取接口，增加可选的精确 ID 过滤。生成前先规范化、去重存储 ID，每批最多读取 200 条，再按原有版本逐项核对。201 条记忆现在只需两次声明查询。SQL 在原有所有者、角色和会话范围内筛选指定 ID，不先读取全部记录再过滤；继续读取历史状态，以便核对已经审核的历史记忆。

两种数据库共用各自现有的过滤构建流程处理记忆键和 ID，避免再复制一套列表方法。生产代码净增 19 行，没有新增服务层、配置、锁、重试、语义规则或跨发送缓存。单条读取仍有实际调用方，予以保留。

合法缺失只撤销对应证据；数据库故障、重复或未请求的返回 ID 明确报错，保留原始异常。原有来源复核、所有异步读取完成后的到期检查、参考预算及剩余证据重编译保持原实现。

## 验证与范围

- 80 项不同的定向检查最终全部通过，覆盖精确批次、重复 ID、下次发送的新版本、第二批故障与恢复、模型调用前中止、历史状态、所有者范围、来源撤销、预算及读取后到期。
- 首次 79 项通过；一项新测试误将带 `persisted=True` 的写入回执视作持久化读取结果。改为与单条读取的完整字段比较，只重测该项并通过，原始失败记录保留。
- 真实 SQLite 和 PostgreSQL 各执行三组前后对照：201 条未变记忆及 ID 别名、其他用户与不存在的记录、一个审核版本过期。声明 SQL 次数分别由 `202 / 204 / 202` 降为 `2 / 2 / 2`，完整生成消息、参数、参考文本和选中 ID 一致。
- 两种数据库额外核对精确过滤、空 ID 集、其他所有者隔离、历史记录与原始读取异常；SQLite 的定向测试还核对作用域与记忆键过滤的交集。
- 未涉及的数据库和仓储方法通过语法树对照，来源复核及版本比较后的处理保持原文一致。静态检查、补丁空白和仓库完整性检查通过。

本阶段不改变模型输入的语义，不进行付费模型质量评测，不重复全量回归。原有两项测试的故障和时钟挂钩改为批量读取入口，保留有效业务断言。服务器部署后就绪及登录接口均为 200，未登录访问受保护接口为 401，运行配置及前端进程保持不变。
