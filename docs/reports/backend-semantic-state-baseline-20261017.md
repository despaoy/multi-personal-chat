# 完整语义判断跳过未采用的常规规则评分

服务器隔离复现确认：正常问题加两条用户历史会先执行三次完整规则评分，
随后完整语义模型覆盖这些常规结果。审核输入没有使用这份规则状态，
它只影响待审核基线及诊断中的规则置信度。

## 调整

正式工厂在完整语义审核实际启用时，为普通非安全轮次只准备待完成基线，
由已配置模型返回完整状态，再执行既有严格校验、证据选择和上下文编译。
失败直接传播，不能把空基线当成成功结果，也不重新启动规则评分。

- 复用现有即时安全和含混风险检查，没有增加词表、关键词或意图规则。
- 安全相关消息保留完整旧估计结果，继续受原有安全审核与策略保护。
- 空输入、默认直接调用及明确关闭语义审核的路径保留旧估计器。
- 正式路径的常规规则置信度为零，表示没有进行这次评分；模型置信度仍
  来自实际通过校验的结果。基线不会作为模型验证结果返回。
- 只由实际审核组件是否存在选择路径，没有增加环境设置或用户配置。

产品代码净增 12 行，用少量路由保留必要旧调用，移除正常生产路径中的
重复工作。没有声称延迟降低了某个比例。

## 验证

- 28 项定向检查通过：先运行 27 项，再只运行新增的缺字段回复检查。
  未重复整组或全部分类回归。
- 六类完整题设检查确认：新旧基线下的审核消息和最终状态一致，覆盖
  数值任务、引用中的告别、多人归属、条件与否定、第三人称和回应边界。
  这些比较使用受控结果，不作为新的模型质量验证。
- 现有安全结果逐项保持一致；模型异常、非法结果及超时停止准备。
  空输入和显式关闭路径保持旧行为，正式启用路径的完整评分调用为零。

  为零，两个模型结果均被采用。
- 实际来源召回保留完整用户原话、排除其他用户来源，原话没有提升为

- 静态逐函数比较确认旧评分、安全辅助函数、语义输入与解析、来源检索
