# 消息归档必须取得回执，失败不得返回整体成功（2026-10-14）

## 实际问题与调用链

沿聊天入口 → 共享生成 → 消息归档 → 角色完成/交付快照检查，确认普通生成在 _save_message 返回 False 后仍返回正常回复，只跳过记忆回写，没有保存失败提示。上一阶段缓存路径有独立布尔检查，形成两个不一致的失败入口。SQLite 和 PostgreSQL 的实际 add_message 均在提交后返回含 id 的完整回执；原调用层却把无回执也当作保存成功。

共享归档函数现在只在有效字典回执含 id 时返回 True；数据库异常、超时、无效回执统一抛出 503/message_archive 并保留原异常原因。清空旧输出回执后执行实际写入，只有成功才回填，不能沿用旧记录。日志保留故障计数、请求和错误类型，去掉原始异常文本。

新生成与缓存复用都传入实际 modelInvoked 状态，不再各自解释 False。新生成在归档确认后设置 message_saved=True，重复的保存成功条件删除；归档失败先退出，不会返回回复、写入新的回复缓存、完成角色记忆或冻结交付快照。包装层继续释放已预留的完成容量。缓存命中不新增模型调用，失败也按共享写入契约退出。
