# 通用 RAG 失败传播与缓存精简（2026-10-09）

## 问题和调用链

`RAGHelper.retrieve_with_citations → retrieve_context → vector_db.hybrid_search / CrossEncoderReranker` 中存在两个宽泛捕获：检索失败变成空列表，重排序失败变成原召回结果并可进入缓存。依赖导入失败还会设置可用性状态，后续静默跳过检索或精排。

## 修改

- 必需依赖直接导入，删除模块可用性标记、未使用的数据库全局变量及 `use_vector_db` 镜像状态。删除五处测试中的无效赋值；其他模块自己的功能标记不受影响。
- 启用重排序后初始化失败直接传播；检索和精排失败不返回结果、不写缓存，非空候选被重排为空明确报错。
- 单候选也经过已启用的重排序。重排结果按 `rerank_score` 归一化，未重排结果使用 `final_score`。
- 每次查询只获取一次数据库对象，合并成功结果的返回和缓存路径；缓存键反映实际是否启用重排序，缓存命中日志不再记录查询原文。
- 显式禁用重排序、合法无匹配、证据不足及资料过滤保持正常业务语义。

业务代码净减少 52 行；未增加依赖或配置项，未修改生产运行配置。
