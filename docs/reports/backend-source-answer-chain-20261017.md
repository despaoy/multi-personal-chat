# 完整原话进入检索和回答链路

针对此前结构化提取未通过限定覆盖的长计划，验证独立启用的原话召回能力。
没有修改产品代码或放宽提取校验，没有重启服务，也没有重跑已有单元回归。

## 验证范围

使用服务器当前代码、实际应用上下文工厂、来源检索、动态语义审核、上下文
编译、生成入口及生成前后来源权限复核。测试数据库隔离，保留同一条完整
合成原话，另放入另一用户的相反记录，且两个用户使用相同来源 ID。
生产数据库仅以只读事务读取当前模型及采样配置。

问题要求只核对原话记载，以 JSON 返回年份、地点、活动、录取及出发状态、
逐字条件、来源 ID，并区分历史记载与现实中的最新状态。所有回答检查通过：

- 完整原话及末尾限定进入实际模型输入，未混入另一用户的相反记录。
- 保持零结构化事实，来源标记仍为历史原话，人物归属和当前有效性没有被
  自动提升为已确认状态。
- DeepSeek Flash 正确读出年份、地点和活动；原话里的“未收到录取”和
  “尚未出发”保持否定，出发条件完整包含录取与预算，均可逐字追溯来源。
- 返回正确来源 ID，明确仅凭历史原话不能确认现实最新状态。
- 检索和生成均未改变保存的原话或新增事实条目。

## 调用计数及限制

本阶段实际新增 **3 次模型 HTTP 请求**：2 次审核、1 次回答。最初抽查脚本
使用了通用 `top_p=0.9`，回答尝试被 DeepSeek 适配器在发送 HTTP 前明确拒绝；
该尝试不计作真实模型调用。补齐正式入口的 `top_p=1.0` 配置后，仅补测回答，
前两次审核的输入及参数完全相同，原样复用已有结果，并明确记录为回放。

这次验证覆盖实际服务及生成链路，**未经过 HTTP 登录鉴权入口**，不能据此
声称端到端 API 鉴权已重新验证。也只证明这条信息完整的原话检索案例达到
本轮可用标准，不保证所有自然语言输入的模型质量。

此前长计划的结构化提取错误继续作为失败保留。本次成功的是正常配置下的
独立原话检索与回答能力，不把结构化提取改称成功，也不为通过测试自动启用
其他模式。后续转向其他实际问题，不继续围绕同一案例增加规则或反复调用。

原始模型交换、回答和隔离数据库仅留在服务器运行目录；本报告和同步摘要
不包含密钥、真实用户原文或模型原始响应。验证时前后端均返回 200，运行
代码及配置未改动。
