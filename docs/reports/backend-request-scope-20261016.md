# 请求内共享模型快照与分支仓库修复（2026-10-16）

## 已复现的问题

主聊天在准备角色上下文、调用默认语义审核后，才为主回答取得云端配置快照。审核客户端自行刷新数据库配置，token 计数和元数据又使用聊天环境；同一请求可能使用不同的实际模型及计数器。

服务器在修改前运行真实 API 内部入口、默认审核适配器、OpenAICompatibleProvider 和 HTTP 编码，使用隔离测试配置及明确的 httpx.MockTransport：审核实际发送 deepseek-flash，随后修改隔离设置，主答实际发送 deepseek-v4-pro，而两次计数元数据均标 Flash。没有访问外部模型、读取真实用户对话或支付模型费用。

## 修改

新增一个请求上下文，保存已经解析的提供商、云端连接快照及对应计数器。生成入口在角色准备前取得一次配置；默认审核、上下文预算、计数元数据、缓存身份和全部主答调用共享该快照。嵌套生成复用现有上下文，结束、异常和取消均恢复原绑定；下一独立请求才读取新配置。

删除生成过程中较晚取得快照的重复逻辑。实际审核和主答发送前，提供商种类变化仍明确报错；已经完成的请求和缓存命中保持其真实来源标记，不增加结束时重新检查或把成功改成失败的规则。必需配置读取失败在入口报告 503 并保留原因，没有默认模型、空快照或通用计数回退。

长期存活的记忆写入任务、闲置触发器、交付记忆所有者、排队工作者和维护任务仅清除新增请求绑定，保留日志等其他上下文。每项排队生成自行建立请求范围；请求内短任务和线程调用仍继承这一份有效绑定。

关联检查还暴露了原有假想分支缺陷：关系状态包装对象没有当前上下文服务必需的关系笔记等数据库读取接口。将其改为完整数据库记忆仓库的子类，仅覆盖分支关系状态，并让上下文服务与记忆服务共享实例。服务端派生的 canonical 证据范围、分支历史和事实包、禁止普通归档、分支事务提交与 revision 校验保持原语义，没有用空列表掩盖读取失败。

旧云端测试补全实际连接快照字段，公共合成连接在意外调用时明确失败。原先所谓模型失败用例实际在更早的假仓库接口处失败；现在使用隔离真实 SQLite，并在实际 async_complete 注入故障，检查 500、原始原因、唯一实际调用和零归档。移除该用例无关的 vLLM 配置；另一个旧编译器替身改用正式 GenerationResult。没有放宽有效断言。

## 定向验证

服务器首组 48 项中 45 项通过、3 项失败。补齐两个测试前提并修复分支仓库后，仅重测这 3 项及 4 项直接关联分支行为，7 项通过。另一组受影响旧测试为 54 项通过、1 项前提失败、6 项 PostgreSQL 参数未运行；补齐隔离仓库后仅重测该失败项，1 项通过。最终 107 项不同测试通过，没有重跑已经通过的整组。

新增请求范围检查覆盖真实云端编码与默认审核的同快照、下一请求新配置、两个并发请求隔离、实际 BPE 与元数据一致、线程继承、嵌套复用、异常和取消恢复，以及实际 SQLite 记忆、交付和排队长期任务的请求解绑与其他上下文保留。生成关联检查覆盖缓存来源、配置故障、发送前提供商变化、发送中变化、原生并发、归档与完成任务容量。分支检查覆盖真实 Web 生成后回到 canonical、权限和角色边界、可信来源、归档时竞争以及不写 canonical 记忆。

语法、差异及相对原文件的增量静态检查通过。测试使用完整合成输入、明确模型控制输出及隔离数据库；付费模型调用为零。未运行全量回归、PostgreSQL、真实 DeepSeek 语义质量或吞吐测试。保留一项依赖中的 AnyIO 弃用提示。

## 部署与后续

按服务器验证、仅重启后端并检查就绪 200、运行配置与其他服务不变、逐文件 SHA 同步本地、阶段提交及 GitHub 同步流程收尾。阶段目录保存首次结果和逐项复查日志，不覆盖失败记录，也不将合成模型控制宣称为真实大模型质量验证。

这一阶段完成主聊天入口及其派生任务。独立 /api/ask 入口仍有先固定模型标识、稍后重新读取实际云端配置的风险，可能影响答案来源和缓存键；下一阶段单独处理普通回答和流式生成的真实生命周期。整体精简优化目标继续进行，未新增关键词规则或分类器。
