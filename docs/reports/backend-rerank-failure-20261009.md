# 重排序失败契约精简（2026-10-09）

## 实际问题与修改

角色检索链路 `RoutedMultiScaleService → PipelineReranker → CrossEncoderReranker` 存在两层失败伪装：入口捕获初始化和推理异常后自动改用确定性排序；底层加载或推理失败后返回原顺序或空列表。入口还用虚构查询探测底层是否真正打分；单候选却跳过模型，无法得到用于证据门控的分数。

- 删除入口降级、虚构探针、不可用粘滞状态以及没有生产调用者的 `uses_cross_encoder` 最近一次状态。结果自身的 `rerank_method` 继续记录来源。
- 删除 `fallback_to_original` 配置及回退分支；同步唯一脚本使用者。模型加载保留异常原因，初始化失败清理半成品；下次独立请求可在问题修复后重新加载。
- 推理、必要预热失败直接传播，不记录可能包含私有内容的异常字符串。预热完成后才标记模型加载成功。
- 空候选仍是合法空结果；单候选也进行真实打分。非法候选不再被静默跳过，分数数量不完整或包含 NaN/Infinity 明确失败。
- 显式关闭模型重排时仍采用配置指定的确定性排序。未改变生产配置或扩大公网访问。

两份业务模块净减少 77 行，关联评测脚本减少 2 行。未新增框架或依赖。
