# 实际模型用量记录

原 OpenAI 兼容适配器丢弃响应中的 usage，生成记录按当前消息和最终回答的字符数估算 token。完整提示、历史、证据和追加生成均未纳入实际计量；生成失败时还会将输出用量写成零。服务器隔离复现中，两次合成响应报告 2,200 tokens，而旧记录逻辑只保存 10。

本次删除字符长度估算。生成请求拥有独立的用量收集上下文，OpenAI 兼容适配器在校验回答完成状态之前保存服务返回的计数，因此截断回答仍保留已消耗用量。多次响应累计；无法确认的调用不估算，已有计数标为部分实测。独立后台任务不继承前台计量上下文。

SQLite、PostgreSQL 和 ORM 增加 usageSource，区分 provider、partial、unavailable、legacy_unverified。未知计数保存 NULL。增量迁移保留历史 token 原值，不把历史估算重新标记为实测；重复升级不重复增加字段。必要计量字段缺失、非法或加总不一致时明确失败。

## 验证与部署

- 汇总相关测试的最新结果，共 214 个不同用例通过，无跳过；没有重复运行完整回归。
- 实际适配器使用隔离 HTTP 响应验证两次调用精确累计 2,200 tokens；生成入口到 SQLite 验证两次调用累计 240 tokens，截断回答保留单次 120 tokens。
- 验证失败后的部分计量、并发与嵌套请求隔离、后台任务分离、非法计数及旧记录迁移。
- 在实际隔离 SQLite 和 PostgreSQL 中验证完整、部分和未知计数。初次 PostgreSQL 测试查询用了不支持的问号占位符，修正为命名参数后仅复测相关用例；没有修改计数断言。
- 一个旧 HTTP 测试缺少 usage，确认失败原因后补齐合成响应，并保留请求所有权断言。绕过实际提供商的模拟生成不会凭空产生计数，相关测试明确验证未知值。
- 静态检查、仓库完整性和差异检查通过。生产代码净增加 78 行，新增部分用于计量收集、来源字段与迁移；移除了旧估算及无用导入。
- 后端部署后就绪和前端登录均为 200，未登录受保护接口为 401；配置及前端进程未变化。按内容哈希同步本地。

本轮真实模型调用为零。验证使用完整合成响应，不能称为新的 DeepSeek 实测。本次覆盖普通生成入口内 OpenAI 兼容调用的用量，不是全系统账单：独立后台任务、其他模型适配器和其他接口的独立调用尚未统一计量。未接入计量的提供商明确记为未知，不使用估算替代。当前统计页面也没有基于这些字段计算费用；价格、缓存折扣及平台账单核对不在本次实现范围。
