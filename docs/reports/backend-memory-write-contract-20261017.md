# 长期记忆写入字段及目标关联

本阶段修复写入候选的协议错误被当成无变化或被旧记录补猜的问题。修改前
在服务器隔离复现：未知类型、空值和 49 字值均被静默过滤；未知类型配合
合法旧专业目标时，反而可以补猜成旧目标类型并产生替换提议。

## 修改

- 新增内容的操作必须显式给出受支持的 `kind`，以及不超过 48 字的非空
  `value`。检查在置信度、证据和目标的业务筛选之前完成。
- 错误使用上一阶段的 `MemoryResponseError` 和固定字段回执，不增加
  错误框架、重试、模型切换或关键词分类器。
- 旧目标不再为未知写入类型补猜。目标类型推导仅用于已有的明确输入契约，
  以及无需新事实值的授权撤回、删除。通用 `user_fact` 输入继续接受独立
  证据校验；派生索引的既有长度约束保留。
- 整批候选通过解析后才持久化。第二条候选无效时，不会先保存第一条。
  低置信度、证据不支持仍可正常不保存。

产品代码净增 7 行，主要是两项早期协议检查及对原有分支的整理。证据、权限、
持久化、时间解析及生命周期实现未变；未修改历史数据。

## 验证

- 直接相关测试最终 **153 项通过**。首次有 23 项失败，保留了原始结果；
  修正后只复测失败项及受测试输入修正影响的 **32 项**，没有重复整组。
- 修正了两种过期控制：缺少必需的用户归属；仍在替换不参与调度调用的旧
  解析入口。部分成功、冲突、不重复执行的原断言全部保留；真实数据库
  冲突用例改用完整响应走实际解析，不再绕过解析。
- 新撤回正例改为明确的本人撤回授权；修改前模块对比证明原测试表达本来
  就未通过现有授权判断。未增加同义词规则，也不声称撤回表达已全面覆盖。
- 使用实际记忆客户端、实际向量检索和已有 **DeepSeek Flash** 配置新调用
  **2 次**：新增专业成功，随后根据真实旧目标完成 `SUPERSEDE` 更正；旧
  版本和两条原始来源均保留。
- 对上述记录进行缺失类型、未知类型、空值、超长值四种受控故障注入，均
  明确失败且零部分写入。这四次记录复用不计为新的模型验证。
- 定向静态检查、语法及差异检查通过。服务器部署后，就绪与前端登录页
  均为 200，配置及其他服务未改动；随后按摘要同步本地。

两次合成抽查只验证这条新增、更正链路，不保证模型对所有表达的理解质量。
本次未改动 120 字证据限制及其已有处理，后续可独立审计。

原始模型交换与隔离数据库留在服务器运行目录；提交仅包含源码、合成测试
和本报告，不包含密钥、运行数据或真实用户原文。
