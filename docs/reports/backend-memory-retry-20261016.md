# 已投递记忆任务的有限重试与明确失败（2026-10-16）

## 已复现的问题

投递确认后的持久任务经 DeliveryMemoryWorker、真实 complete_turn 和记忆调度器执行。服务器原代码在隔离 SQLite 中对同一份无效模型 JSON 连续处理四次，模型控制调用四次，回执仍 pending；没有执行次数上限。永久认证失败、部分写入、已执行但结果未知等状态也统一回到 pending。由于语义提议没有逐条幂等键，重放部分成功的 ADD 可能重复已提交修改。

续租还有两个独立的实际故障。状态更新已经把数据库从 A 改为 B、但协程尚未发布内存 response 时，heartbeat 使用旧 A 续租会误报失去所有权；真实 SQLite 固定交错已复现。续租数据库抛出 OSError 时，任务异常原先被清理阶段吞掉，之后仍能记为 completed；独立故障控制同样先复现再修复。

## 根因修改

只修改两个生产代码文件。调度器在回执中明确标记能否重试及 HTTP 状态，仅生成阶段的暂时网络故障或明确的 408/429/500/502/503/504 可重试。模型 JSON、预算和证据校验错误、冲突、写失败、部分写入与活动任务取消不通过重放掩盖。

持久 worker 在执行前保存次数和 execution_started，最多三次执行；更换进程和重新打开数据库不会重置预算。容量满、调度器关闭、确定未执行的队列取消，以及运行时在任务受理前关闭，不消耗执行次数；它们继续按既有等待流程恢复。已开始但结果未知的旧 running 任务明确 blocked。旧 pending 的回执也在清除前核对，部分写入、永久失败及缺乏安全重试证据的状态保留原回执并 blocked，不能先再执行一次才停止。正常无记忆、原文观察和明确业务跳过保留其完成语义。

新旧回执共用两个小谓词判定可重试与未开始，不新增模型切换、关键词意图规则、分类器或策略框架。原来源 ID、原接收时间和回复不变；turn_finished 保持一次性交互更新，后续只补记忆。

同一任务的一把异步锁保护状态 CAS 与内存 response 发布，也保护 heartbeat 读取和续租；数据库所有权校验仍有效。保存前取回已经失败的续租任务并传播原异常，续租失败不能被后续完成覆盖。清理正常取消不报错；同时已有主异常时保留该异常，另外仅记录续租异常类型，不泄露用户原文或凭据。已经提交的 claim 不会被伪称回滚，结果不明确时留待核对。

## 定向验证与证据边界

初轮服务器 35 项定向测试通过（3.74 秒）。审查补出旧 pending 恢复入口后，仅重跑该入口及相关重试、排队恢复路径，18 项通过（2.18 秒），其中五项是新增的旧回执案例。真实两提议测试先保存一条、第二条写失败，再模拟旧 pending 升级恢复，确认原 claim 和部分写入回执保留、没有第二次模型调用。

续租交错修复后两项新案例和四项关联 CAS 检查共 6 项通过（1.36 秒）；补续租数据库异常后直接关联的 7 项通过（1.40 秒）。最后的 9 项定向检查通过（1.54 秒），包含真实默认 OpenAICompatibleMemoryCompletion 经 MockTransport 的三种 HTTP 路径、相关取消/受理路径和三个续租案例。429 后实际保存、503 到三次停止、401 一次停止均核对真实 HTTP 编码、完整当前消息、回执、原时钟与交互计数。仅 HTTP 交通被隔离，语义内容为合成模型结果，没有声称经过真实大模型理解验证。

另以真实 provider 入口事件固定主任务取消与续租故障并发：最初测试未等待 provider 真正开始，修正执行前提后只重跑这一失败用例，1 项通过（1.18 秒），保持原有效断言。上述批次有重叠，不把重复执行累计成独立覆盖量。

语法、差异与增量静态检查通过，独立只读审查参与发现并复核修复。没有全量回归，未执行 PostgreSQL 联动、真实 DeepSeek 语义质量或吞吐测试；付费模型调用为零。原有部分写入取消测试的注入点更新为当前在线解析入口，保留已提交数量和实际结果断言，没有放宽预期。

## 部署与适用范围

按服务器先修改和验证的流程，仅重启后端并检查就绪 200、运行配置和其他服务不变，再通过 SHA 清单同步本地、服务器提交与 GitHub；阶段目录保存实际部署与同步证据。没有批量改写历史用户数据、创建额外提议幂等体系或改变当前模型配置。结果不明的历史任务停止自动重放，是本阶段有意的失败行为变更；需要核对实际已提交内容后处理。整体精简与记忆、RAG、上下文优化目标继续。
