私聊身份按用户规范化，单纯换前端会话不会清除服务端历史。因此本例经真实记忆写入器创建资料来源和结构化记录，再进入聊天读取，避免把过去聊天内容误算为长期记忆召回。实际上下文历史为零，完整来源在该用户范围内被检索，并进入与最终回答匹配的真实提供方请求。来源、账号、数据库、消息和作品检索资料均隔离；模型、语义审核、记忆选择及上下文策略沿用当前配置，重排保持当前关闭状态。

人工对照实际来源和完整回答，10 个语义核对点均正确：别名对应用户；预约事项；否定事项；具体日期时间；地点；书面确认付款前提；改期截止；无通知维持原安排；出差顺延；未提供的细节明确未知。回答在无确认时明确不可付款，在无通知时保留原安排，没有将公开角色身份混入用户资料。该结果达到本用例可用标准，没有为措辞继续调用模型或追加规则。
