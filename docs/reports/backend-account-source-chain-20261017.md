# 登录账号到私有来源回答的完整路由验证

本阶段验证近期的认证和完整语义链路能否一起工作，没有修改产品代码。
服务器使用隔离 SQLite、正常注册的普通用户、实际应用工厂、中间件、
Cookie 登录及生成路由；模型请求通过真实 DeepSeek HTTP 服务完成。

## 完整前提与结果

同一来源标识分别保存两份归属不同用户、内容互相冲突的合成记录。目标
用户原话完整描述 2030 年去泉州学习陶艺的计划，明确尚未录取、尚未出发，
并保留书面录取与预算落实的条件。另一个用户的记录声称事情已经完成。

登录后生成请求故意传入其他用户的 senderId、userId 和伪造的浏览器历史。
实际结果证明：

- 后端使用登录用户归属读取和保存，伪造身份没有改变消息归属。
- 完整本人来源进入回答输入，其他用户记录和浏览器伪造历史未进入输入。
- 回答正确保留年份、地点、活动、两项未完成状态、原文条件和来源标识，
  明确历史原话不能证明现实中的最新状态。
- 原始来源保持完整，问题没有变成新的结构化事实；回写队列排空，失败为
  零，记忆结果为 no_change，没有把回复内容当作新证据。
- 匿名生成及错误密码均返回 401；补充检查确认退出后显式重用旧 Bearer
  令牌也返回 401，实际应用包含认证、输入校验、限流及 CORS 中间件。

## 测试准备问题与调用计数

首次探针用了不存在的归属列，修正前没有模型请求。随后种子直接使用浏览器
会话编号保存来源，而正式私聊边界会把会话范围规范化为用户身份，因此
来源在该请求中不可见，模型返回未知。这个失败属于测试前提不完整，
没有据此放宽隔离规则或修改未知结果。

补齐数据时使用项目正式的范围构建及来源写入接口，普通用户重新注册到
独立范围。前两段状态与策略审核逐项比较完整输入和调用参数，完全一致
才复用既有真实响应；新来源在之后进入回答输入。复用没有计作新模型验证。

本阶段累计 **6 次真实模型 HTTP 请求**：原先不完整种子消耗 4 次，修正后
新增回答和回写 2 次。原始交换及失败记录保留，未重复整套回归。

实际生成请求使用兼容模型名 deepseek-chat，记忆写入请求使用 deepseek-flash；
上游六次响应均报告 deepseek-flash。隔离数据库含自己的默认配置，不能把
本次结果当作所有生产配置均已逐项复制和验证。

本次通过 ASGI 传输调用完整应用路由，外部模型调用是真实 HTTP；未启动

明确关闭公开知识路由，没有重测作品 RAG 或长计划的结构化提取质量。

生产后端进程未重启，配置及源码保持不变；就绪与前端登录页均为 200。
