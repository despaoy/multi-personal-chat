# AstrBot 网关明确失败与回执边界精简（2026-10-14）

## 问题与调用链

沿接入插件 POST /api/integrations/astrbot/messages → 平台配置 → 回执认领 → 限流/会话状态 → 排队生成 → 结果回执逐层检查，发现配置读取异常被转成空配置，数据库/队列/模型故障被 _degraded_response 转成 HTTP 200：私聊发送固定繁忙文本，群聊跳过。内外两层同时转换生成异常，原有 HTTP 错误和失败原因被掩盖。

配置读取现在要求真实字典，读取失败或非法结构直接失败。删除 _degraded_response 和处理层大段重复异常转换，接入边界在尝试释放失败回执后统一处理：限流 429 并保留 Retry-After，超时 504，排队满和其他处理故障 503；配置、回执和会话读取失败明确标识阶段。已有生成 HTTPException 的状态、详情和响应头保持不变，取消继续传播。安全策略拒绝明确 403，回执所有权变更明确 409，均不创建可发送的降级答复。没有新增关键词/意图规则，既有凭据保护未放宽。

生产 api/integrations.py 净减少 99 行。删除四项旧降级断言及不再使用的测试故障数据库/运行时状态，改由真实隔离 SQLite 回执检查覆盖失败行为；保留原成功用例。未引入异常策略框架或新的依赖。会话存储故障原有的 db_write_failures 告警计数保留。

## 回执、送达与正常业务语义

显式平台/会话关闭仍跳过生成。正在处理的重复事件仍返回 processing，已生成未确认回复仍复用，已送达重复事件仍不再生成。失败尝试将回执置 failed，不把故障文本存成成功生成；若清理本身也失败，保留主错误，由既有租约到期恢复。所有权被替换时，旧请求不能返回待交付答复，也不能覆盖新 owner 的状态。

没有改动回执 SQL、数据库迁移、历史数据或交付记忆任务。插件已有 HTTP 非成功响应处理：记录错误，私聊可显示明确的系统故障提示，不标记事件完成或确认送达；这是故障通知，不是后端模型答复。无需插件代码变更。可选诊断事件日志的记录失败仍有日志，不改变生成结果；本阶段没有把非关键观测写入升级为业务前提。

服务器隔离数据库上 49 项直接相关测试通过（3.04 秒），26 项其他测试未运行，没有重复全量回归。补回既有数据库告警计数后，仅重测直接相关的两项存储故障控制，均通过。覆盖 QQ/Telegram/微信正常生成、回执复用与送达确认、并发去重、所有权 fencing、鉴权/签名和输入边界；新增/更新控制核对私聊与群聊的队列满、超时、生成异常、既有 HTTP 错误保留，限流，配置读取失败/非法结构，认领/会话/结果持久化失败，清理失败保留主错误，取消和显式关闭。
