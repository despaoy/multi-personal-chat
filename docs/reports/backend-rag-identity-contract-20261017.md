# 检索合并只使用已校验的片段 ID

基线：`853b2c68de01c52a7171bb904318fa40f65251a7`。

## 调用链与修改

先核对实际生产者：`api.knowledge._vector_chunk_document` 为每个片段生成 `doc_{documentId}_chunk_{chunkIndex}`；向量入库、索引重建及快照校验都要求有效且唯一的 `id`。向量查询保留元数据，重排器复制完整候选。因此，真实通用检索不会输出只有 `chunk_id`、`document_id` 或正文而没有 `id` 的记录；同文档不同片段也已有独立 ID，本阶段未发现原主链路存在片段误合并。

`rag_helper._stable_result_key` 原先仍逐项尝试别名，并在缺少 ID 时计算正文摘要。删除这些没有实际调用来源的分支和无用的 `hashlib` 导入，直接使用索引已验证的 ID。所有合法结果保留原有 `id:` 前缀和排序方式，检索、缓存、来源权限、重排、置信度与引用实现未改动。

这个私有辅助函数不再替不符合索引契约的数据生成标识；缺失 `id` 明确失败。没有改变索引格式、重建生产索引或迁移历史数据。业务源码增加 2 行、删除 15 行，净减少 13 行，无新依赖、意图规则或分类器。
