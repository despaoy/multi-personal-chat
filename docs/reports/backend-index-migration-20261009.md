# 索引迁移统一与实际类型判断（2026-10-09）

## 问题与修改

自动迁移原先把按新文档数计算的目标类型当作当前类型，因此跨过阈值后可能跳过应发生的迁移；显式 flat 配置却可能被迁移。两套迁移函数重复备份、清空和恢复状态，且先清空 metadata 再创建 IVF，使聚类数计算总是看到零条文档。

改为仅 auto 配置触发迁移，对比 FAISS 原生索引类型与目标类型；合并为一个 _migrate_index。创建目标索引时保留当前文档数量，失败恢复原索引、元数据和 ID 映射并抛出原异常。移除重复状态清空，原有完整快照发布机制保留。

新增文档后的缓存失效提前到迁移之前：文档可能已提交，迁移失败也不能继续使用旧查询缓存。失败会明确抛出；不宣称回滚之前已提交的新增文档。

## 验证

服务器 7 项定向测试通过，1.92 秒；四条已有 jieba/pkg_resources 依赖警告。

真实 FAISS、临时磁盘快照和完整合成文档覆盖：跨阈值 auto 从 Flat 迁移 IVF，显式 flat 保持；底层 nlist/nprobe 有效；HNSW 迁移及快照重载；创建、编码、保存故障时原索引/元数据/映射恢复、原快照字节不变；新增已提交后迁移失败仍使查询缓存失效。

使用固定合成向量，无模型调用，无全量回归；未运行十万条规模的真实性能测试或验证生产历史索引迁移。没有触发生产索引重建。部署、代码规范及同版本同步记录保存在服务器本阶段备份目录。
