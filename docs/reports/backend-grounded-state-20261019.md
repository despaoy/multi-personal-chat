# 知识回答的结果状态收敛

基线：33f62fa9e62ce99ffc2233faedcab0c382fcf778。

## 问题

沿知识问答入口、检索、模式判定、证据包、普通及流式回答检查后，确认私有 _answer_from_bundle 只有 answer 一个调用方。未命中知识域时，它仍为已不存在的聊天回退调用方构造空回答、NO_RAG、abstained=false 的中间结果；answer 随即重新构造明确弃答的最终结果。

公开接口原本已经正确处理此情况，问题是多余的中间状态和重复组装。服务器前置记录确认，一次无域请求会构造两次结果，第一份为空，第二份才是实际返回值。

普通和流式生成还各自判断一次“无文档”，而统一证据包构建已负责将无文档结果转为弃答，重复判断没有独立职责。

## 修改

无域分支直接构造最终弃答结果，删除外层再次包装，保留原回答、模式、置信度、告警、失败原因、来源标记和检索元数据。NO_RAG 仍保留为模式与证据包的内部无域状态，没有删除有效枚举。

删除两处重复的无文档判断，继续由 _build_packet 执行唯一权威转换；流式事件顺序和其他分支保持原有行为。模式判定注释同步去掉过时的回退描述。

生产代码净减少 22 行，没有新增检查、抽象、配置、依赖或测试，也未修改既有测试断言。

## 验证

- 154 项关联测试首次全部通过，覆盖回答状态、普通及流式错误、依赖故障、单次检索、来源范围及必要缓存行为。未改动的纯缓存构造、LRU 和并发测试不重复执行。
- 七种场景分别经过普通和流式路径，共 14 项前后对照：无域、已匹配但零证据、低置信度、完整成功、检索故障、模型故障、未知指定域。
- 使用三个真实索引分区、正式运行时、原文读取、证据包、提示词、引用和缓存。资料完整包含日期、时段、否定、条件及例外；零命中和低置信度为明确的检索边界控制，嵌入、排序及模型输出为测试控制。
- 排除耗时和 costTime 这类运行观测字段后，全部功能字段及来源依赖快照前后一致；无域普通结果从两次构造降为一次，不再产生空回答中间结果。
- 合法证据不足继续明确弃答；检索和模型故障保留原异常对象，未知指定域继续报错，不会转换为弃答或成功。失败的流式路径没有正文、引用或完成事件。
- 代码复核确认统一证据包构建、来源检查、缓存、模型连接、API 和测试文件未改动；模式判定仅调整注释。Python 检查、仓库完整性及差异检查通过。
- 部署后后端就绪、前端登录为 200，受保护消息接口为 401；前端、其他服务和配置保持不变。

本阶段无付费模型调用，没有重新执行全量回归或前端构建；不将确定性链路对照解释为真实模型理解质量验证。
