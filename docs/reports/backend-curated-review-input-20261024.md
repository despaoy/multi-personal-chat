# 原作证据审核只传输一份完整正文

在当前 DeepSeek Flash 上执行一次私人记忆与公共 RAG 组合抽查：隔离 SQLite 中预置两条完整合成个人事实，以及另一用户的干扰记录；公共资料使用实际 1,098 文档角色索引。正式生成编排执行语义审核、记忆选择、行为策略、公共问题规划、证据审核和最终回答。

基线中，两条个人事实及否定进入最终输入，另一用户的原话未进入；回答区分个人记录与原作人物，正确说明专业、研究方向和兄妹关系。原作引语及说话人与原文核对一致。七次真实模型请求均成功，共 76,506 tokens，与隔离调用记录逐项累计一致。这是读取预置记忆的测试，不包含模型提取并写入记忆的流程，也不覆盖登录和队列。

## 问题与修改

该抽查暴露出证据审核的重复输入：curated_payload 同时携带 sources.excerpt.text 和由同一正文完整分块生成的 source_spans.source_quote。审核模型收到两份相同原文；该请求输入达到 47,621 tokens。

审核发送前投影来源元数据，移除其中重复的 excerpt.text，原文仍按既有顺序完整保留于 source_spans。来源身份、行号、位置、文件及正文哈希、索引声明、叙事标注、完整问题和对象任务全部保留。后台完整 payload、回执摘要和原文重新核验逻辑保持原样；没有通过截短原文或减少候选换取体积下降。生产代码净增加 4 行，没有新增运行步骤或语义关键词规则。

## 修改后验证

- 针对受影响审核环节，再执行一次真实 DeepSeek 请求。复用同一次检索的相同资料，不重复检索，不重跑前面的动态上下文和记忆审核；响应为新生成。
- 发送前逐项确认：所有原文可从 source_spans 按来源完整还原，恢复后与原先 sources 完全一致，其他输入字段完全一致。审核后后台完整 payload 与原 payload 一致，输出通过现有证据、任务及对象绑定解析。
- 实际审核输入从 47,621 降至 28,382 tokens，减少 19,239 tokens，约 40.4%；输入字符从 77,818 降至 48,954。新审核仍选出支持问题的真实原文位置，并保留 limited_context 范围。
- 新审核输出消耗 178 tokens，本次新增请求总计 28,560 tokens。整个阶段包括七次基线请求及一次修改后验证，共八次真实调用、105,066 tokens。没有计算价格折扣或宣称整体账单下降相同比例。
- 五个相关测试文件最终 90 个不同用例通过，无跳过。首次八个失败均为模拟审核仍从旧字段读取正文；改为从位置表核对同一完整正文后，只复测这八个用例。完整原文、来源变更、回执绑定、对象范围及证据接纳断言保留。
- 静态、仓库完整性和差异检查通过。部署后就绪、登录页及未登录受保护接口状态为 200、200、401；配置与前端进程保持一致。按内容哈希同步本地。

测试使用在线 PostgreSQL 的只读模型配置快照，所有合成数据及调用记录写入隔离数据库。原始请求、模型响应和作品片段留在服务器运行目录，没有进入源码提交。修改后的真实验证只覆盖证据审核环节，不能称为修改后再次完成了整条组合链路，也不能由此保证所有问题的模型理解正确。
