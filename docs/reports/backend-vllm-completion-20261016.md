# vLLM 完整响应与流式终态检查

日期：2026-10-16。基线：`bd473044d0f773798c380091da76f58928704d56`。

审计 `/api/ask/stream` → GroundedAnswerService → vLLM adapter → VLLMClient 的实际调用链。原传输层吞掉畸形 JSON，忽略上游 error、非正常 finish_reason 和缺失的 `[DONE]`，正常退出后实例及熔断器均记成功；服务层随后可能把已收到的正文作为完整答案。服务器隔离 HTTP 预检复现了畸形 JSON、length、提前 EOF，以及非流式 length 四种情况，均返回文本并记录一次成功、零失败。

流式响应现在必须有正常 stop、`[DONE]` 和可用正文。损坏 JSON、错误事件、结构错误、非正常终态及提前 EOF 明确传播失败；正常 role、独立 reasoning 字段、分片 think 标签和 usage-only 事件继续支持。只在验证完成后刷新过滤器尾部并记录成功，原始推理不进入回复。问答服务原有整段校验和缓冲保持不变，传输失败不会发出 delta、citations 或 done 成功事件。

非流式复用已有 completed_chat_content，拒绝截断等未正常完成的响应，并在过滤推理后拒绝空正文。HTTP 拒绝复用既有 ProviderResponseError，不再把上游正文拼进异常。流式准入、半开限制和结果记账改用已有熔断器上下文，删除重复的状态检查与手工成功/失败记录；用 aclosing 明确拥有内部流，外层提前关闭会立即关闭上游并释放连接，不记录部分输出为成功。协议和 HTTP 失败各计一次，流式不重试；非流式既有有限暂时故障重试保持。

服务器 18 项定向测试通过（1.84 秒）：真实 VLLMClient/熔断器/httpx MockTransport 的正常与失败 SSE、13 字节切分的 Unicode/分片推理过滤、消费者提前关闭、真实 ask API/service 串联、非流式健康/length/仅推理，以及流式与非流式 HTTP 401 的安全错误和单次记账；另保留并验证三项受影响的既有过滤检查。旧的“截断响应返回空串成功”预期改为必须报错；旧流式过滤样本补齐正常终态，纯推理成功预期由严格失败测试覆盖，没有放宽断言。

预检曾因未显式提供进程 JWT 配置而触发开发模式自动写入：核实仅 JWT 行变化后，从已有备份精确恢复原文件，SHA 与阶段开始前一致，服务未重启且仍就绪。后续隔离测试显式提供测试配置；该意外及恢复证明仅存运行目录，不提交配置内容。

语法、增量静态及差异检查通过；部署只重启后端并核对配置与其他服务，再按 SHA 同步本地、服务器 Git 和 GitHub。当前 DeepSeek 主对话使用独立的严格完整响应链，本阶段未改变其模型或配置。全部 HTTP 响应为合成替身，没有调用真实模型、下载权重或提交密钥、运行数据及私有对话；这些验证不证明真实模型回答质量。
