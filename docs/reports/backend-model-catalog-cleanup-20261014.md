# 模型目录状态单一实现，移除无消费者缓存（2026-10-14）

## 实际问题与修改

模型管理器初始化读取 model_cache.json，下载和删除后写入其中的时间/路径。但仓库内没有读取这些缓存条目来执行功能的调用方；list_available_models 和 check_model_exists 一直从实际目录、必需文件和权重文件判断状态。重复缓存增加启动读盘、写盘、过期状态和吞掉缓存错误的代码，同时列表与完成检查分别实现了相同判断。

删除 cache_file、cache、_load_cache、_save_cache 及下载/删除后的无用途缓存维护，移除失效导入。已有模型文件和历史 model_cache.json 均保留，生产数据未删除。列表统一调用既有 check_model_exists，让真实文件状态成为单一实现；数据库配置 TTL 缓存及提供商选择没有改变。

另一个实际失败问题是 snapshot_download 返回后直接宣称下载成功。现在用同一文件检查核对配置要求：缺少任何必需文件，或没有 safetensors/bin 权重文件时返回明确失败，不编造完成状态。现有 API 对下载失败返回稳定错误的协议保持；残留部分文件可供下次明确请求续传，不自动切换模型或重复下载。

生产代码净减少 38 行，无新增规则、分类器、框架、配置或降级。本次文件检查复用原有存在性标准，不声明已经验证权重内容、哈希或实际加载质量。

## 定向验证

服务器 13 项直接相关测试通过（1.33 秒），12 项其他测试未运行。九组模型管理器初始化控制继续验证环境与数据库选择优先级、明确开发 mock 和生产 mock/无效配置拒绝。

扩展已有实际 ModelManager 目录测试：事先放置历史缓存，实际模型目录仅有部分文件时，检查和列表均未完成；受控下载补齐必需文件及权重后两者均完成。再次请求已完成模型不重复下载，删除测试目录后检查和列表同步变为未完成。整个过程中历史缓存字节保持不变。并发下载仍通过同一目录锁串行执行。

两组新增不完整下载控制分别缺少必需文件、缺少权重；模拟下载调用恰好一次，返回 success=false 及具体错误，列表和完成检查均为 false，不生成缓存文件。仅使用临时目录内的受控小文件，未下载真实模型、未触碰生产模型目录、未执行真实推理或付费调用。

语法、增量静态、差异检查通过，无新增静态问题。初次静态检查指出缓存移除后 json 导入失效，修正后才首次执行上述测试，未重跑已通过的测试或全量回归。测试输出包含 Starlette 对 AnyIO 别名的依赖弃用提示，未影响执行结果，本阶段未扩展到依赖升级。
