# 记忆重新核权沿用本轮预算并保留独立证据（2026-10-16）

## 分离后的实际问题

主生成入口从 PreparedCharacterTurn 建立私有核权回调。正常云端准备已经根据实际工作窗口编译记忆，并在 memory_budget 中记录生效预算；两个核权模块重建时却都传 max_chars=None。这会恢复完整证据编译器的 6000 字符默认值，而不是延续本轮预算；重建还把全部 remaining 记录包留下，可能与新 used_ids 和实际文本不一致。

服务器基线 2a5df2d 上，真实 SQLite 保存 24 条完整、独立、带条件的合成记录及来源，经过实际 scoped recall、ContextualEvidenceSelector、CharacterContextService.prepare_turn。选择器分类和最终答复均为明确的本地控制。65536 工作窗口实际给予 32768 字符参考预算，准备出的完整参考区为 18447 字符。每条记录和原始输入很短，没有单条超长或缺少前提的测试。

一次真实生成中，在 structured 核验前删除一条，最终 23 条独立记录全部丢失；在 structured 核验后、private 首次读取来源时删除，最终仅 7 条进入参考区，正文 5451 字符，却仍留下 23 个记录包，16 条有效记录缺失。

分层诊断还确认另一个实际原因：明确删除会按既有隐私机制推进 owner 级原话屏障，因此旧原话访问全部撤销，独立规范化记录本身仍有效。private 核权发现这些原话正文出现在仍有记录依据的 evidence 中时，旧分支会整块清空参考区，误把独立证据一并删除。诊断过程中重复调用旧 request 的观察单独保留，不把它当作单次生成；最终预检为两条路径各一次真实生成记录。

## 修改

核权闭包只捕获本轮已有 memory_budget['budget_chars']，显式传给两个核权函数。不重新读取模型设置、不猜测文本长度、不加大常数，也不新增请求或上下文字段。正式 PreparedCharacterTurn 的空诊断默认仍允许独立构建工具使用编译器原有默认入口；线上准备会提供真实预算，没有为不完整替身增加 getattr 容错。

将两段重建逻辑合并到一个实际共用函数。它仅从剩余已授权记录编译，沿用现有完整证据和 observation 渲染语义，按返回 used_ids 统一生成记录包与状态；调用方各自保留来源、复核文本、字段存在性、历史和分支引用的失效处理。

原话访问撤销后，如果参考块包含相关正文且仍有核验有效的记录包，重新从这些包构建参考区，保留独立规范化事实并丢弃所有未绑定的拼接文本。没有记录包的未知来源复制内容仍清除。owner 级原话屏障、记录撤回和版本检查、作用域、时间检查及读取错误传播保持原语义，没有恢复原话访问或用新资料替代本轮已选内容。

本阶段没有改变 compact 与 complete 两种初始渲染策略；只延续既有核权渲染契约并修复预算传递和来源分层。最终 GenerationRequest 的 token 预算仍然生效。
