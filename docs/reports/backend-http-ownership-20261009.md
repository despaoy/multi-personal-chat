## 问题与修改

BaseProvider 的 _fallback_async_client 从未被赋值，却保留跨事件循环关闭、异常吞没和四个仅转发 super().close() 的子类方法。配置导入异常又会被吞掉后创建独立连接。三个 HTTP 提供方重复捕获并记录原始异常再抛出，OpenAI 兼容 HTTP 错误还携带部分响应正文。

- 删除未使用客户端字段、跨循环关闭分支与四个空转关闭方法。BaseProvider 保留资源关闭合同，本地 Transformers 提供方仍执行真正的模型资源释放。
- 共享连接由连接池管理，独立脚本在没有池时使用调用级客户端，并在创建它的事件循环内关闭。已有池获取失败或配置导入失败直接传播，不创建替代客户端。
- 删除三个只记日志再抛出的宽泛异常包装，让现有上层统一处理。OpenAI 兼容 HTTP 错误只包含状态码，不包含响应正文。
- 没有改变模型选择、请求正文、请求超时、生成参数或提供方错误的传播行为；不新增依赖、配置或模型调用。

业务代码净减少 69 行。
