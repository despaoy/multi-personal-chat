## 问题与修改

实验权限在当前应用数据库复核，六个业务入口却仍读写全局数据库。列表、详情和报告各自吞掉结果 JSON 解析错误。量化模块缺失且请求为 mock 时，接口还会另外拼出一张固定指标表并标记完成。

更深的 RAG 路径中，API 的 `formal=true` 只是由 mock 取反得出，构造实验器却未启用已有的正式条件。实验器内部把检索异常换成空命中并计算零分；缺少 questions 字段也被换成空题集，最终仍能返回完成。

- 六个数据入口复用 `get_request_database`；记录创建显式接收同一存储。删除全局数据库导入及一个 SQL 转发函数，直接保留原有线程卸载和参数化查询。
- 三个结果读取入口共用小型解析函数，保留对象、历史数组及 SQL NULL 的契约；损坏 JSON、空文本及契约外结构明确失败，不再使用空对象掩盖。
- 删除量化模块缺失后的替代指标，两个请求模式均记录失败并返回 503。正常显式 mock 仍由指定实验器执行，并如实标记。
- 真实 RAG 消融显式设置正式模式，执行已有冻结资料和重排器条件；条件不足按现有约定返回 409。实验器删除检索异常转空结果的分支，直接传播原始错误；题集字段必须存在。真实没有命中仍是正常零分。
- 日志保留阶段、实验 ID 和异常类型，避免输出原始异常内容。共享测试客户端删除最后的全局数据库修补，关闭资源使用直接的 finally。

生产代码净减 22 行，没有新增错误类、重试或语义规则。指标七项聚合计算的 AST 一致，除本次 run_variant 修改外的整个 RAG 实验模块 AST 一致；SQL 语句集合和成功响应契约保持不变。
