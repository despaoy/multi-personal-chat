# 请求内模型资源归属收敛（2026-10-19）

本阶段从生成入口、角色上下文审核、知识问答、令牌预算和模型管理器的实际调用链出发，修正默认提供商切换对已开始请求的影响。服务器先修改并验证，再同步本地和 GitHub；现用 DeepSeek 配置不变。

## 问题与处理

- `resolve_request_context` 原先只为云模型保存实例，本地模型只有名称。生成代码在等待熔断器准入后重新经过管理器选择提供商，因此能够调用新的默认实例，却仍将回答标记为旧模型。现在请求上下文一次取得选中实例，云模型保留原有配置快照，本地模型保留原实例。
- 聊天审核和知识问答原先回查全局默认值，将仍然有效的已有请求拒绝。审核、问答、生成、缓存身份和模型标记现在使用本轮归属的资源，默认值只影响后续请求。删除这些重复检查，没有改成捕获错误后继续，也没有调用替代提供商。
- LoRA 的能力判断原先由管理器动态检查方法是否存在。基础提供商现在明确支持选择基础模型，并拒绝非空适配器；已有支持 LoRA 的实现继续覆盖该方法。管理器只委托一次，聊天直接操作本轮实例，保留原有本地选择与生成串行锁。
- 令牌计数按提供商类别读取云端连接字段，避免本地实例绑定后被误当作云连接。

六个生产文件合计减少 21 行，没有新增防御分支、语义规则、分类器或依赖。保留真实模型错误、配置错误、超时、取消、熔断、准入容量、权限和记忆回写机制。

## 验证与测试整理

修改前，五个完整隔离用例分别复现云审核误拒绝、云生成误拒绝、等待后使用错误本地实例、知识问答身份漂移和 vLLM 审核误拒绝。修改后全部成功；补充知识问答非流式和流式调用的两条路径，共七个归属用例。

关联检查覆盖 648 个不同测试，其中 605 个首次通过；43 个失败项中，知识问答存在一处尚未移除的重复检查，其余主要是旧夹具没有提供实例，或声明本地选择却返回云实例。移除重复检查并补全夹具后，43 项全部通过。只复查夹具修改涉及的另外 197 项，没有重跑全部回归。与七个归属用例合计 655 个不同测试最终全部通过，无跳过；197 项是关联复查，不能重复累计为新增覆盖。

删除两个要求默认切换后必报错的过期重复用例，由完整归属用例覆盖其连接、容量、调用次数、标记及上下文释放行为。改动涉及的旧测试保留 398 条有效断言，未放宽预期。静态检查、仓库完整性和差异空白检查通过。

使用真实管理器、提供商及消息编排接口，云传输使用隔离 HTTP，其他模型资源使用明确的合成测试实现。真实模型调用和外部 HTTP 调用均为零，不将其表述为模型内容准确率或真实本地权重评估。测试输入完整包含金额、时间、否定及条件。

## 运行与范围

服务器后端重启后就绪接口 200，前端登录页 200，受保护消息接口 401 且保留 nosniff；运行配置和其他服务进程不变。保持本地端口映射，不开放公网。

本阶段保证默认选择切换时资源归属一致；不冻结本地权重重载，也不保证资源在运行中永远可用。资源真实失败仍上报原有错误。长期记忆、RAG 和上下文整体优化目标继续进行，不将本阶段通过视为整个目标完成。
