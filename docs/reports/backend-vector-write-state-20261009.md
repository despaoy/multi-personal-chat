# 向量写入状态与失效入口清理（2026-10-09）

## 修改

add_documents 原先在保存成功后才清除查询缓存，FAISS 添加、关键词索引更新或保存失败时可能继续复用旧查询结果；某些失败发生在 dirty 标记之前。

现在在首次添加向量之前设置 dirty 并清除查询缓存。后续失败仍抛出原异常，不把发生过修改的内存状态视为已保存。正常立即保存和明确配置的延迟保存/flush 行为保留，不新增状态或恢复层。

仓库引用检查确认无调用方后，移除 rebuild_index 和 _save_bm25 两个旧入口；保留实际使用的 clear_all、统一版本重建、完整快照保存和 flush。

## 验证

服务器 6 项定向测试通过（1.63 秒），四条现有 jieba/pkg_resources 依赖警告。

真实 FAISS 和临时磁盘快照、固定合成向量：注入向量添加、关键词更新、保存失败，确认原异常向上传递、dirty 与缓存代次正确、旧查询缓存清除、旧磁盘快照不变且可重载；正常立即保存和显式延迟保存再 flush 均正确。仅附加运行直接相关的既有迁移失败缓存测试，未运行全量回归。

无模型调用。故障通过明确替身注入，不声称模拟所有磁盘故障。本阶段不提供内存修改整体回滚；失败后统一知识重建入口仍负责恢复完整索引。未改动生产索引数据。

部署健康、代码规范及同版本同步记录保存在服务器本阶段备份目录。
