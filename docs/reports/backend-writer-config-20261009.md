## 问题和修改

`character/memory_llm.py:MemoryLlmConfig.from_env` 原先把“启用但地址或模型缺失”自动转换为 disabled，随后交互写回可能走规则模式；非法数值被 max/min 截断，拼错布尔值也会关闭模型。实际配置错误因此难以发现。

- 启用但缺少完整地址或模型时明确抛出配置错误，提示应配置相关变量或显式关闭，不自动换用规则写入。
- 布尔值只接受明确的 true/false、1/0、yes/no、on/off；数字必须满足原有边界且为有限值。解析错误显示变量名，不回显原始配置内容。
- 删除重复数值截断，外部环境读取集中进行转换和校验。内部直接构造的类型化配置保持原有接口。
- `app/main.py` 在数据库初始化前校验启动环境快照，错误配置阻止启动；正常配置继续既有启动流程。
- 文档明确说明错误行为，修正输入预算超限仍写为“跳过”的过期描述。

保留有文档和使用方的配置继承：非空 MEMORY_LLM 地址/模型/API key 优先；否则地址依次取 VLLM_BASE_URLS 的首项、VLLM_BASE_URL，模型依次取 VLLM_SERVED_MODEL_NAME、VLLM_MODEL，密钥取 VLLM_API_KEY。上下文窗口优先 MEMORY_LLM_CONTEXT_WINDOW_TOKENS，其次 VLLM_MAX_MODEL_LEN，默认 8192。显式窗口 0 保留完整输入字符预算模式。这里是启动时确定的配置来源，不是在调用失败后切换服务。
