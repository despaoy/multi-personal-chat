## 问题与修改

隔离复现确认：数据库查询和配置读取失败会被替换为空数据，统计接口仍返回 HTTP 200 和零值；一次采集读取配置 16 次；不同应用忽略各自数据库并共享全局缓存。此外，原有日统计最多读取 10,000 条完整记录，活动分组丢弃奇数小时，模型负载来自每日回复数，模型与数据库服务又固定显示运行中。

新增一个由应用持有的 `StatsService`，明确绑定当前数据库、推理调度器和启动配置。敏感统计缓存随应用隔离，同一轮请求合并刷新并返回独立副本；刷新失败不会使用过期数据。采集使用现有有界数据库执行器。API 保留管理员校验并负责安全的 HTTP 503 转换，原始异常保留为 cause，日志只记录环节和异常类型。

配置每轮读取一次，保留缺失设置的正常默认值，显式无效值及不符合约定的数据形状报错。查询改为数据库聚合和窗口排序，不读取整条对话与模型记录，不再截断到 10,000 条。活动按完整两小时区间汇总，范围为当天开始至下一天开始。响应时间分位数保留原有有效数据算法，模型调用记录仍优先于消息记录。

公开路径和统计响应字段保留。`modelLoad` 改为当前调度器活动任务占工作线程数的百分比，不代表远端供应商硬件利用率。服务列表复用现有应用就绪探测，明确呈现未就绪状态，并使用实际数据库类型名称。宿主硬件缓存保留进程作用域；原有进程级观测计数继续保留该作用域。

删除全局数据库、推理调度器引用和旧的业务缓存状态，移除无调用方的数字容错助手。相关现有测试迁移到真实应用接口或采集器，不保留只服务于旧测试的兼容入口。生产代码增加 359 行、删除 339 行，净增加 20 行，用于上述完整职责与查询变化。
