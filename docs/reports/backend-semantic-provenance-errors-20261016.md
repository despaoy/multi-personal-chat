## 问题与修改

语义记忆投影在来源版本、生产者、有效性声明或观察时间无法解释时直接返回原始记录。特别是坏日期和无时区时间，会使模型摘要绕过观察视图。真实 SQLite 隔离基线证明，坏的语义观察时间未使读取失败。

在现有时间来源模块集中定义校验：已声明的来源记录必须为对象，使用整数版本 1 和已支持的生产者；语义模型及来源删除投影只能携带尚未核实或未指定的有效性声明，并提供有时区的实际观察时间。布尔版本不再因等于整数 1 而被接受。

普通无此声明的旧记录，以及已定义的规则来源，保留原有语义。无法解释的语义声明明确报错，不当作旧记录或已核实事实。读、写和投影共享同一校验，写入先于数据库操作拒绝错误输入；没有增加数据库查询、模型请求或缓存。

将已有字段异常移到纯业务契约模块，仓储、时间来源和 API 使用同一类型。事件异常复用该字段实现，同时保留原有专用 API 原因。API 仍提供安全字段路径和修复提示。没有改写历史数据，也没有增加意图、归属或时间关键词规则。

## 定向验证

30 个不同相关用例分批通过：

- 7 项完整 SQLite 故障控制：坏日期、无时区时间、错误来源容器、不支持/布尔版本、未知生产者、模型擅自声明已核实。在精确读取、实际召回及真实生成前校验入口失败，模型未调用，坏值不出现在安全错误中，原记录不变。
- 3 项写入拒绝：缺少实际时钟、坏时钟、不支持版本均在持久化前失败。已有来源描述中的时间不能替代缺失的记录时钟。
- 1 项正常写入：完整来源已捕获并显式绑定，语义记录保留原证据、实际时钟、来源描述及实际来源读取权限。
- 3 项旧记录/规则来源保持原对象；3 项原先误期待返回原摘要的组件检查改为验证明确拒绝，覆盖不支持版本及非法有效性声明。
- 5 项原有 API 字段映射、4 项真实事件 API 错误继续正确，专用错误原因及隐私检查保持有效。
- 4 项正常关联链路：调度器保存应用来源描述、片段删除后保留独立证据、零宽模型日期不丢原话、观察记录不成为当前字段值或已证明缺失。
