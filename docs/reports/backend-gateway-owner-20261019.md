## 问题与修改

旧代码的配置与事件记录使用全局数据库，其他步骤又可能使用应用容器数据库。容器缺失、数据库或调度器为空时会选择全局对象；对合法但布尔值为假的数据库使用 `or db`，还会把回执写到另一数据库。网关另行提前构建角色上下文，与共享生成核心及送达工作器的既有职责重复。

现在请求入口只解析一次应用容器，保存本次数据库与调度器引用。配置、事件、回执、会话与生成始终使用这份数据库，送达确认也绑定当前应用数据库。缺少依赖返回带恢复提示的 503，在事件、回执或生成之前停止；明确关闭的平台仍能正常跳过，不要求未使用的调度器。合法的假值对象保持其身份。

删除三个历史兼容 getter 及全局数据库/调度器导入。网关只把数据库传入共享生成核心，由核心在实际提供方作用域内构建角色上下文；送达工作器在自己的数据库上惰性构建完成服务。没有再增加一个服务工厂或包装层，生产代码净减少 23 行。认证、签名、输入检查、会话标识、回执所有权与投递语义保留。
