# PostgreSQL 关闭错误与资源所有权

基线：`2fbe2be5305640d1572b093bfe7d19cd3bfb13c4`。审查同步数据库适配器、读取快照、启动初始化和应用退出链路后，在服务器复现并修复。

## 问题与修改

`SyncPgAdapter.close` 原先把引擎关闭异常和超时仅记为警告，调用方收到成功；读取器关闭异常会跳过后续引擎释放；线程未退出时也会丢弃句柄。超时直接停止事件循环还可能留下尚未处理取消的任务。应用层已有的关闭错误机制因此无法收到真实失败。

改用标准库 `AsyncExitStack` 依次退出读取器，通过 `finally` 尝试释放引擎、停止线程和关闭事件循环，失败明确传播。异步生成器的 `GeneratorExit` 会占据其原生上下文，因此给连续的读取器关闭错误保留显式因果关系，所有原始错误仍可沿 `__cause__` 和 `__context__` 追溯。

关闭超时先取消任务，再有界等待任务清理完成的信号，随后继续退出线程和循环；这次等待用于确认取消完成，不重试数据库操作。线程未停止时明确报错并保留句柄，已关闭实例仍拒绝新业务请求。正常关闭继续幂等。

生产代码净增 17 行，没有新增错误类型或重试策略。数据库 SQL、持久化方法和适配器其他方法 AST 保持一致，没有修改运行配置或切换数据库。
