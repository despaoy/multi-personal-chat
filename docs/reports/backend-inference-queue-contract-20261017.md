# 推理队列配置与提交超时契约

日期：2026-10-17。基线：`25ea46b086a3eb1206c4506624160158940a7891`。

## 问题与修改

推理队列直接读取容量，配置为 0 或负数时会进入无界队列模式；工作线程数和本地模型并发数则将零或负数强制改成 1。队列超时允许非有限值，单次提交的 `timeout=0` 又会被 `or` 替换成默认超时。这些行为隐藏了显式配置或调用错误。

复用已有的正整数和有限正浮点数读取器，要求队列容量、工作线程数、队列超时和本地并发配置有效。缺失设置继续使用原有默认值。工作线程优先级保持 `INFERENCE_WORKERS`、`LLM_MAX_CONCURRENCY`、`MODEL_MAX_CONCURRENCY`；本地并发保持自身设置优先于旧键，选择旧键时仍有弃用提示。优先键显式配置为空时直接报错，不再跳到次级设置。

提交入口在启动工作线程前解析有效超时，拒绝零、负数和非有限值，不创建任务、占用队列或改变提交计数。未传超时才使用队列默认值。生产代码净增加 8 行，用于现有入口的明确配置和失败行为，没有增加策略层或依赖。
