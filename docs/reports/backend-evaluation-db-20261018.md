# 评测任务和反馈使用当前应用数据库

基线：`a090b1b680d076808118614b0487d13ce7539370`。审查评测、反馈五个数据入口、鉴权、后台调度器及回写函数、数据库契约和现有调用方，再在服务器复现存储错配。

## 问题与实现

评测创建、历史列表、详情和反馈读写仍使用模块导入的全局数据库；管理员权限已在当前应用存储中复核。后台调度函数本来支持显式数据库，但入口仍把全局对象传给它。结果是权限与数据属于不同存储，当前应用数据库故障也可能被另一份数据的成功响应掩盖。

五个数据入口复用现有 `get_request_database`，并将该存储直接传给现有后台任务。删除全局数据库导入，生产代码净增 9 行，用于明确依赖参数；没有增加判断、错误类、重试或转发层。归一依赖参数和数据库变量后，所有原有业务函数 AST 一致，SQL、评测计算及调度器代码保持不变。

现有测试客户端提供完整应用容器，删除对已移除全局属性的修补及两个无用 fixture 参数。共享分页测试仅保留仍依赖全局对象的实验模块修补。

## 验证

- 原生 SQLite 与真实 JWT 下，从完整评测记录、带事实的反馈开始，执行五个入口的七次请求，包括排队、现有调度器创建实际异步任务、数据库回写完成、读取结果和反馈。任务的计算部分明确使用测试控制，没有调用模型。
- 修改前六次管理员复核读取当前库，但十一项业务操作全部落在全局库，后台任务也收到全局对象；修改后业务操作全部进入当前库，全局访问为零，任务回写完成并释放。
- 应用数据库三种读取、评测插入和反馈插入故障，修改前均为 200，修改后依次为 500、500、500、503、500。调度失败仍写入同一应用的失败记录，并向调用者报告 500。
- 匿名访问仍为 401；数据库降权后的旧管理员令牌不能读管理数据或创建评测，返回 403；普通登录用户仍可以提交反馈。
- 原有同库场景的完整响应 SHA-256 保持 `41eb06e31068cd9b85c74d4e7c85df061a324e7d68d9486fd9e2c18a825a1a87`。修正后的独立应用场景为 `a5e740009102eb0c5036a31d25d212d7bce33cf56830484c801fb2667c802c80`。
- 独立 PostgreSQL 测试库通过相同流程、五种故障及调度失败；完整正确响应与 SQLite 一致，原生适配器释放。
- 只运行新增绑定测试、评测生命周期测试和共享分页/SQL 关联检查，19 项首次执行全部通过，其中新增五项；没有重跑完整回归或无关向量索引测试。
- 语法、名称、差异空白和服务器仓库完整性检查通过。

部署后第一次连续探测曾在就绪响应之后遇到连接拒绝，部署检查明确失败，未当作成功。随后检查确认同一后端进程存活，未再次重启；五次连续就绪、登录页和权限探测均为 200、200、401。配置和其他进程记录不变，再完成阶段同步。该瞬时连接拒绝的根因尚未确定，原始失败记录保留。

本阶段没有模型调用，不作为生成或评分质量的新证据，也没有修改生产业务数据、数据库结构或运行配置。其余评测 JSON 读取、依赖缺失处理和实验模块的历史问题继续单独审查。
