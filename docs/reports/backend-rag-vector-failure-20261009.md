# RAG 必需向量检索失败显式传播（2026-10-09）

## 问题与调用链

`MultiScaleRagRuntime.retrieve_with_citations → RoutedMultiScaleService.retrieve → HybridRetriever.search → _vector_channel` 中，查询向量计算失败曾被宽泛捕获，转成空向量结果。混合检索随后仍可能返回关键词结果，调用者无法区分成功和必要检索步骤失败。

## 修改

- 删除 `_vector_channel` 的异常吞掉逻辑及无用日志对象；保留原始异常向调用方传播。业务代码净减少 8 行。
- 显式选择 sparse 模式仍不调用向量提供方；合法查询无匹配仍可返回空列表。
- 未修改模型、生产配置、数据或权限规则。

## 验证

服务器仅执行新增的 `backend/tests/test_rag_vector_failure.py`：9 项通过，86.65 秒。覆盖 OSError、ValueError 在混合检索、向量检索及运行时入口传播；异常对象保持一致、调用一次、不记录私有错误标记；同时覆盖显式 sparse 模式、合法无匹配、正常运行时结果及证据信任标签。

测试使用已有真实索引，显式注入测试向量提供方，并显式关闭重排序。初次运行因测试环境缺少向量模型路径在初始化阶段失败；将注入时机移到构造之前后通过，未修改生产逻辑或放宽断言。存在 4 项已有 jieba/pkg_resources 警告。

修改文件语法、增量 Ruff 和差异空白检查通过。本阶段新增付费模型调用 0 次；未重复全量回归。

## 范围和限制

这是检索故障传播的组件与运行时验证，不代表真实模型回答质量验证。重排序器和索引初始化中的其他容错路径仍需独立梳理，不能据此声称整条 RAG 链路已消除全部隐式降级。
