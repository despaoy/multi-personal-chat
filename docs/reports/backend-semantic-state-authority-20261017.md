# 动态语义结果与记忆来源继承

日期：2026-10-17。基线：`a1c37b1ca922f368caadf2fe9f99661073dfac63`。

## 问题和结果

动态上下文的语义审核结果仍会被规则假设修改。完整的语法题明确说明引号内的告别不是当前用户意图，旧分析器却识别为结束对话；即使模型纠正了状态，结果合并仍会重新加入告别。正式服务装配器还默认使用选择性审核，因此部分简单轮次会跳过语义模型。

正式装配现在明确使用全量非安全语义审核。该模式只使用完整审核原因，不再计算关键词歧义原因；解析与结构、数值校验独立完成，已校验的模型状态直接进入后续策略和上下文编译。历史选择性模式的保护逻辑移到独立函数，仍供明确使用它的评测脚本调用。安全入口、信号白名单和有限数值校验保持原样。审核失败继续直接传播。

关联检查又定位到记忆写入中的实际缺陷：补充条件合成的新版本声明了前后两条来源，但数据库只关联当前来源。来源列表不能提供授权，发送前核验因此正确撤销了不完整的新记忆。单纯补齐测试原话或指定正确数据库仍无法解决这一缺陷。

SQLite 和 PostgreSQL 现在在原有写入事务、所有者锁及目标版本校验之内，共用一份来源继承计划：

- 只有本次声明继续使用、且已与已校验目标实际关联的来源才能继承。
- 保留原始来源键和作用域，不复制原文，也不按来源编号重新授予访问权限。
- 未继续使用的旧来源不继承。缺失、歧义、撤销或不属于前版的来源明确报错，新版本及目标状态变更一起回滚。
- 继续使用原有发送前快照核验和精确来源读取器。历史记录不自动修补、迁移或重新授权。

同时给非法记忆元数据增加明确的结构错误，避免暴露无关的属性错误；清理一个原有的未使用查询结果变量，保留原 SQL 调用与等待。生产代码增加 95 行、删除 47 行，净增 48 行；本阶段优先纠正数据流与授权链，未以减少行数替代正确性。

## 定向验证

401 个不同测试身份的最终结果通过。按每项最新结果汇总，失败复测不重复计数；已通过部分未重复运行，未运行全部回归。单元测试进程禁止接触实际审核客户端。

覆盖语义状态、服务装配、动态提示、审核错误、历史角色边界和直接使用装配器的记忆、分支路径。完整性前提补齐包括独立策略控制、合成原话记录、正确的隔离数据库和显式的私人来源规划；没有取消来源核验或放宽“不得执行外部检索和回答生成”的有效断言。

来源继承新增 SQLite、真实 PostgreSQL 各 8 项检查，验证替代与合并、无关旧来源不继承、同所有者未关联来源、其他所有者来源、缺失来源、撤销来源和重复编号歧义。确认失败时不留下新版本或改动旧版本状态。跨会话的来源指纹可以随授权事实核验，但新会话不能因此读取旧会话原话。另检查了直接相关的来源变更、撤销及发送前授权行为。

旧历史测试混入 `system`、`tool` 角色的成功预期改为两项明确拒绝检查，原有六条合法历史完整性检查保留。旧的非法限定信息返回空值预期改为明确报错，合法缺少限定信息的结果保持为空。一个旧测试未计入现有的可信参考时间参数，现按完整参数核对；对应生产读取函数与基线一致。

静态检查、语法和差异空白检查通过。历史选择性保护语句逐项比对保持一致；安全门、数值及信号解析函数体保持一致；精确来源读取器和发送前授权函数没有修改。

## 实际模型和运行验证

使用服务器当前的 `deepseek-flash`、正式服务装配器和隔离 SQLite 完成 4 次新的实际调用：两次状态审核、一次真实人物策略审核、一次语法回答生成，没有复用旧模型结果。

模型纠正了引用材料造成的假告别，状态原样进入后续处理，最终系统提示没有告别指令，原始问题仍在用户数据区，回答完成第三人称转述。真正的告别仍被正常识别。该抽查证明当前完整案例可用，不保证所有语义判断都准确。

启用语义审核的正常非安全轮次现在均使用一次状态模型审核；此前跳过审核的简单轮次会增加这一次调用。没有新增模型阶段或修改提供商配置。来源继承测试使用专用 PostgreSQL 测试库，未修改生产数据库或历史数据；原始模型交换和数据库留在服务器。
