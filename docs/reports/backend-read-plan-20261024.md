# 不可变读取计划复用派生选择条件

`SourceReadPlan.matches` 原先每次匹配一条记录都会重新创建全部 `SourceReadAtom`，`selectors` 也重复展开同一计划。调用链中的计划以不可变元组保存分组及匹配模式，派生结果无须随每条记录重建。

将这两个属性改用标准库 `cached_property`，只在所属计划内保存派生结果；计划对象结束使用后一起释放。没有跨请求缓存原文、数据库结果或来源授权，原有新鲜度、撤销与版本校验保留。生产代码净增加一行导入。

验证四种计划的 24 组匹配结果及分组、选择条件与旧实现一致，检查同一计划重复读取时复用派生对象。合成计划重复匹配一万次，本次耗时约 0.055 秒降至 0.012 秒；仅反映该函数场景，不代表完整问答性能。

服务器上布尔组合、混合来源、标识符、跨领域依赖及用途范围五个文件共 120 项测试全部通过，无跳过。静态、仓库完整性及差异检查通过。后端重启后就绪与前端登录返回 200，未登录受保护接口返回 401；配置及前端进程未变。验证后按内容哈希同步本地。

未调用真实模型，未重复运行全部回归测试，未增加语义规则或修改匹配语义。
