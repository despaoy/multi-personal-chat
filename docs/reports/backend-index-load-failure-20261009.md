# 索引加载失败不再伪装为空库（2026-10-09）

## 实际问题

`VectorDatabase.__init__ → _ensure_index → _load_index / _load_bm25` 会在快照或旧索引损坏时吞掉异常，并创建空索引或空 BM25，导致调用者把加载失败当成无数据。只有元数据或 BM25 文件残留时，也会被误判为新库。

## 修改

- 删除索引和 BM25 加载的宽泛捕获以及失败后创建空状态的分支。
- 任意已有索引组件都触发加载；旧格式必须能读到向量索引、元数据及非空库的 BM25。缺失或损坏直接报错。
- 保留正常新建空库、合法空快照覆盖旧数据、完整旧格式读取及其不能授权数据库复用的规则。
- 不删除、重建或覆盖损坏数据；恢复操作交给明确的数据维护流程。

业务代码净减少 15 行，无新增配置或依赖。

## 验证

服务器仅执行 `test_vector_snapshot_integrity.py`：20 项通过，1.88 秒，4 项既有 jieba/pkg_resources 警告。

使用真实 FAISS 和本地临时索引，不调用模型。覆盖完整快照往返、原子发布失败保留旧文件、读者固定快照、校验和错误、损坏快照不得读取旧文件、三个旧组件缺失或损坏时失败且剩余文件哈希不变、新建空库、合法空快照。

原先验证损坏索引变为空库的断言已按明确失败契约改为异常断言；完整性、文件保留及正常读取检查保留。语法、增量 Ruff、差异检查通过。未执行全量回归，新增 API 调用 0 次。

## 限制

本阶段只覆盖持久索引加载边界。角色索引运行时、模型设备选择及上层索引重建入口仍需继续审查；不代表全部检索故障均已处理。未改变生产数据和模型配置。
