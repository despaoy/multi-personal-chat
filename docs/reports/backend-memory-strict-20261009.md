# 结构化长期记忆召回：第九阶段（2026-10-09）

基线 fe8f983b4a5aba7f0f2d058ab049db43317bf98c。先在服务器修改并完成定向验证，部署后按哈希同步本地与 GitHub。

## 实际问题

`character/memory_service.py` 在召回入口把任何异常转换成空记忆和诊断状态；来源版本读取失败后清空版本映射，原文凭据失败后清空凭据继续；语义排序失败又会改用词面排名。另有按 TypeError 文本猜测旧仓库接口并少传参数重试、在缺少精确凭据接口时改用较宽的来源关联读取等兼容逻辑。

这些行为会让准备流程完成，即使必要的读取或排序没有成功。语义失败还写入共享的 `_semantic_failure_logged` 状态，评测脚本依靠这个内部字段事后判断是否发生回退。

## 修改

- 必要的结构化记录、来源版本和精确原文凭据读取失败时传播原始异常，由已有聊天 API 边界转换为脱敏 503；取消继续正常传播。召回函数不会返回部分成功结果。
- 删除按错误文本重试旧参数和宽泛来源接口的回退。仓库协议补充来源版本接口，测试替身使用明确的当前接口。必要接口缺失直接失败。
- 已启用语义排序发生超时、模型/依赖错误或无效向量时失败，不替换成词面排序。保留显式关闭语义排序的配置路径；正常无记录、无匹配及证据不足保持原有业务语义。
- 向量返回形状错误、非有限数值、范数溢出、零向量或空向量均拒绝。已有记忆向量缓存不能代替失败的当前查询计算。
- 删除共享失败标志、重复的评测后验检查和相应日志包装。来源读取继续按精确配对、最多 200 对分批执行；未取消作用域、版本和最终权限校验。
- 每条候选的来源版本与绑定结果各计算一次，再拆分赋值，去掉重复序列化和哈希计算。

召回主模块净减少 49 行，仓库协议增加 3 行，评测入口减少 2 行；没有引入依赖或通用异常框架。现行架构说明与历史实验说明补充了新旧行为的区别。
