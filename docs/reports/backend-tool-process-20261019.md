# 工具执行的进程归属和失败行为修正

基线：9b466914d93dbb90366b89a247cc00085360d7f1。范围为管理员工具执行 API，不包括 bot/tools.py 的其他工具实现。

## 实际问题

原执行器先等待 worker 结束，再读取结果管道。服务器多线程父进程下，单独 16000 字符输出或返回值均正常，但 40001 字符 stdout 加 40000 字符返回值会因管道背压被误判为超时；两项各自都未超限。

另外，64001 字符输出或返回值被截成 64000 后仍报告成功；无效内存限制被忽略后仍执行成功。worker 通过 fork 继承父进程环境，合成哨兵测试能读取到专门设置的父进程标记。没有读取真实凭据。

旧代码选择 POSIX fork 的注释把原因归于 spawn 重导入测试入口，这不能解决 Web 多线程进程及 API 依赖继承问题。

## 修改

执行逻辑归到轻量 services/tool_execution.py，API 只处理管理员依赖、生产启用开关及响应映射。公共准入规则、允许模块、受限内置函数、源代码包装和实际权限均保留；专用 ToolCodeError 保持 ValueError 契约，并区分代码拒绝的 403 与配置失败的 503。

执行器以独立解释器运行自己的标准库入口，使用 -I、-S、UTF-8、独立临时工作目录和最小环境，通过 JSON 传输请求及结果。进程接口持续收发结果，避免先 join 后读取；无需导入 API、数据库、模型或测试运行时。没有 multiprocessing 启动方式回退。

CPU、内存、时间及结果大小限制继续生效：无效配置明确失败，资源限制无法设置时停止执行，超限内容不再伪装为完整成功。超时返回明确失败；子进程退出异常保留退出码和有界诊断。成功结果仍保留原来的四个字段。

生产代码净减少五行，新增一个承载实际逻辑的模块。原有三个用例只迁移私有函数的导入位置，断言完整保留；新增八个直接覆盖本次行为的参数案例。没有新增语义规则、未训练分类器、依赖或模型调用。

## 验证

- 多线程父进程原生前后对照：组合 80001 字符结果由假超时变为完整成功；超限改为明确失败；无效内存配置停止执行；父进程合成标记不再进入 worker。单独较大输出、代码错误和超时控制均保持相应语义。
- 11 项相关测试全部通过，其中初始十项及追加的一项资源设置失败检查分别执行一次；将 multiprocessing 多线程 fork 警告提升为错误，未屏蔽该警告。没有重跑全量回归。
- 真实 ASGI、受管合成 API Key 及 SQLite 检查：未登录 401、普通用户 403、生产开关关闭 403、危险代码 403；管理员得到完整中文结果；无效配置返回 503。前三类拒绝及危险代码均未创建子进程，实际成功 worker 和全部流句柄已关闭。
- 资源失败检查使用受控 OSError，未改变测试父进程的实际资源上限；失败时未执行代码。
- 原准入策略、允许集和内置函数 AST 相同；权限依赖、CRUD、生产开关及模型生成源码未变。静态检查、仓库完整性及差异检查通过。
- 服务器先修改验证并重启，再按哈希同步本地。后端就绪 200、前端登录页 200、受保护接口 401 且保留 nosniff；运行配置及其他服务进程未变。

原生执行验证限于当前 POSIX 服务器；缺少资源限制支持的平台会明确失败，不能继续无上限执行。本执行器仍不是容器或虚拟机安全边界，也不构成其他工具入口的安全验收。较小任务的一次测量约增加到 0.05 秒，不作为整体吞吐或延迟承诺。
