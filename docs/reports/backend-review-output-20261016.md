# 动态语义审核拒绝含糊的重复字段（2026-10-16）

## 真实问题

动态审核已启用且非安全消息需要审核时，解析器原先直接 json.loads，重复字段被后一个值覆盖。服务器在原代码上使用完整合成前情、完整本轮请求和隔离审核结果复现：confidence 先返回越界 9、再返回 0.72，先前错误在验证前消失，诊断仍为 applied；真实角色准备入口继续编译。列表形式的同一信号先为 0、再为 0.8 时也被静默合并。

这不是审核模型正常地改变判断，而是同一份结构化输出含有冲突的字段，程序擅自选取一个值后声称审核成功。

## 修改

语义状态解析复用现有 evidence_selector._unique_object，拒绝任意层级的重复 JSON 键。信号解析使用既有 scores 字典登记所有分值，包括零分；重复 ID 立即失败，正常零分仅在排序前过滤。没有增加第二份去重集合，也不再用 max 猜测模型的冲突输出。

只改一个生产文件。正常的模型状态与受保护信号之间合并逻辑保持原样；Mapping、直接状态对象、完整 JSON、带或不带 json 标记的完整代码围栏、唯一信号列表继续支持。没有新增意图规则、关键词、分类器、回退或重试。

异常沿已有角色准备边界明确报告 503，失败不再得到 applied，也不会替换为未经审核的状态继续生成。审核递归守卫仍由 finally 释放。

## 定向验证

服务器 50 项测试全部通过，2.02 秒。新增用例覆盖根级 state、状态标量、嵌套信号与列表项内的重复 JSON 键，包含错误值在前而合法值在后；覆盖三个信号字段的重复 ID，以及零分在前/后的两种顺序；保留六种有效输出形式与合法零分过滤。API 联动验证两类错误均返回 503 并保留 ValueError 原因，然后同一审核器在提供健康结果后重试成功。

关联用例仅验证受影响的状态解析、范围检查、排序/数量限制、诊断无原文、正常受保护信号、明确关闭及安全跳过、服务准备与编译。没有全量回归，也没有重跑上阶段已通过的记忆和 RAG 用例。

语法、差异及增量静态检查通过，独立只读审查未发现明确问题。所有模型返回均为明确的隔离控制，付费模型调用为零；未执行新的真实 DeepSeek 输出格式频率、语义质量或吞吐验收，不以这些测试保证模型理解始终正确。
