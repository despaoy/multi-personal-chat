## 依据与修改

角色记忆的正式版本化写入已经直接使用 `append_claim`。旧 `add_or_update_memory` 仓储方法只剩测试造数调用，协议也重复保留了这一入口。删除这两个无业务调用方的声明及实现，生产代码净减少 40 行。

这些造数中有真实的 revision=0 历史兼容场景。测试专用工厂通过现有数据库旧格式写入创建记录，并明确检查 revision=0；不把旧数据悄悄变成新版，也不引入生产回退。数据库方法、历史数据、SQL 和正常版本化写入保持。

过期测试仍要求缺少版本化接口时成功退回旧 upsert，与已完成的禁止回退契约冲突。基线执行确认这一矛盾后，删除该旧文件，将其中 15 类生命周期、作用域和关联场景并入当前“必须有版本化接口、旧写入未调用”的契约。正常 NOOP 独立检查，增加真实 SQLite 的新版写入、原文关联和读回检查。没有删除有效权限检查或放宽业务断言。
