# 独立问答与后台记忆的实际用量记录

基线为 `986b98890b5fde32363a1f1dd722b2cab4a87248`。本阶段整体核对普通生成、独立问答、后台记忆、调用记录和聊天统计的关系，在服务器隔离环境复现后修改，再验证和部署。

## 问题与职责

真实适配器收到完整合成响应后，独立问答和后台记忆都没有调用记录；两项隔离复现均为零条。现有调用表还参与聊天耗时和失败率统计，因此不能直接混入不同用途而改变原指标。

新增purpose区分chat、knowledge_answer和memory_judgement，历史行与未显式标注的普通生成保持chat；不改历史token或usageSource。SQLite、PostgreSQL、ORM及增量迁移016保持一致。聊天统计与分位数仅使用chat记录，独立问答和后台记录仍可按用途查询。

记录写入收敛到services/model_usage.py，普通生成继续保留自己的HTTP回执转换。独立操作使用已有请求计量上下文收集提供商计数，正常、失败和取消都会记录已知用量；未知值保持NULL，不估算。没有实际调用的缓存命中、合法弃答和模型调用前拒绝不新增用量。后台任务仍与前台计量分离；记忆客户端接收并校验usage，判断及授权审核的实际调用累计在该任务中。

问答使用当前应用的数据库，后台记忆使用原仓储的数据库。记忆判断记录确认后才进入事实修改，失败回执明确指出记录阶段；不会把记账失败伪装成保存成功。数据库写入超时可能稍后提交，状态保持未确认，且同一操作不再次写入。

## 发布顺序

初版接入后进一步复现：记录失败时答案可能已经放入缓存。现已将确认放在缓存发布前；确认是当前调用方的实际提交步骤，不是另一个模型审核。确认期间存在异步等待，故其后重新核验原文来源，来源变化则不发布旧答案或缓存。流式问答只有在记录确认后才发送done；记录失败以error结束。客户端取消继续按取消结束，即使记录也失败仍保留错误链。

## 验证与部署

- 按用例身份合并各轮最新结果，共289项通过、零跳过、零未解决失败。其中19项新增检查覆盖实际适配器、SQLite和PostgreSQL、精确累计、缓存复用、应用数据库归属、流式完成顺序、失败与取消、前后台隔离、用途统计、迁移、确认期间来源变化及超时后单次延迟提交。
- 首组79项有一项新测试错误地预期底层JSONDecodeError，实际边界明确转换为MemoryResponseError；核对原有契约后检查准确的领域错误及response字段，没有改变失败条件。关联组234项有三项旧API案例未配置应用数据库或完整登录身份；补齐前提并保留原断言。另为原先可能因缺少依赖而提前返回500的提供商失败案例增加实际模型调用断言。修正后只复测23项相关案例，再复核4项直接相关的实际传输案例，没有重复整套后端检查。
- 静态、语法、仓库完整性、文件哈希、差异及Alembic head检查通过。业务源码净增加130行，用于实际计量、用途字段和发布衔接，没有新增模型、配置开关、语义关键词或分类器。
- 服务器后端已更新，就绪200，前端登录200，未登录受保护接口401且保留nosniff。在线PostgreSQL确认purpose为非空且默认chat；按部署前的ID范围核对历史记录数量、非空计数数量及token总量保持一致。运行配置、前端及其他服务进程不变。

本阶段真实模型调用为零，合成用量不代表付费消耗；未做新的DeepSeek语义评测、浏览器交互或长期负载验收。提供商未返回完整计数时不补造数据；用途记录也不是价格、折扣及平台账单核算。其他独立工具、训练及平台专用调用仍须沿实际调用方继续审查，不能称为全系统账单已经闭环。原始首次失败、复测、迁移和部署证据保存在服务器运行目录operation-usage-20261025，不进入源码提交。
