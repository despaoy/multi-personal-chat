# 全文向量编码与索引版本

基线：`8c2131460d3f282d95167b370b2ed14a74c1d24c`。服务器先修改、使用真实本地模型验证并启用，再按摘要同步本地。没有调用付费 API。

## 问题与修改

长期记忆共用编码器、通用向量库、角色知识编码器的有效输入窗口均为 128 token。真实模型测试提供了共同前文和相反的尾部说明，完整输入分别为 235、236 token（含特殊 token）；旧路径得到完全相同的向量。问题来自实际编码截断，和 DeepSeek 回答模型的大小无关。

现在使用分词器原生的全部溢出窗口：每窗保留模型原有的 128 token 配置，正文连续分段，逐项核对还原后的 token 与原输入完全一致。全部窗口完成编码后，按正文 token 数加权汇总并归一化，仍输出每份来源一个 384 维向量。空文本保持独立表示；空集合不调用模型。没有增加语义关键词规则、分类器、模型切换或重试路径。

三条入口共用分窗、完整性检查、超时和向量校验逻辑。移除两处原有的独立批量编码实现、均值池化的静默分母修正，以及配置参数的静默转换和最小值纠正。通用向量库继续校验写入边界的整批结果，失败不会发布部分索引或缓存。SentenceTransformer 仍运行完整模块链；角色编码器保留原有的均值池化。推理范围不改变调用线程的梯度模式。

新增编码标识 `complete-token-windows-weighted-v1`，纳入模型指纹、角色索引 manifest 和通用快照 schema 2。版本缺失或不符时明确要求重建，不将旧向量重新标记为新版本。删除无版本 FAISS／pickle／BM25 三文件的直接读取分支；旧文件保持原样，不能授权检索。

## 使用范围与限制

已有部署升级时，必须用当前编码器重建索引。角色索引使用 `backend/scripts/build_character_rag_index.py`，先备份旧产物，再显式重建。通用旧索引应保留备份并改用空索引目录，由现有数据库 chunks 重建流程生成新快照；不得只改 manifest 版本。

全文进入编码不等于模型必然理解所有细节。多窗口仍汇总为一个向量，不能保证每条分散事实均有相同检索权重。本阶段没有调用回答模型，也没有全面验收最终回答质量。整体优化目标继续进行，下一步核查独立知识问答的历史拼接和关键词纠正路径。
