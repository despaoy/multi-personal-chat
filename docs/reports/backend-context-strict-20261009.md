# 动态上下文审核失败链：第七阶段（2026-10-09）

## 实际问题

状态审核器在超时、提供商异常、非法输出和完整输入超预算时返回原规则状态；递归审核也直接跳过。上下文策略审核同样把失败替换成基线决策。角色服务另有一层异常处理，把分析失败替换成中性状态、把策略失败改为更少参数重试。生成入口最终还可能返回空角色上下文，使绑定角色的 LoRA 请求继续普通聊天。

这是一条由多层回退共同掩盖失败的链路，而不只是一个异常捕获点。

## 修改

- 必须执行的状态/策略审核发生超时、上游异常、结构错误或输入预算不足时直接失败；保留原始异常原因和取消传播，不返回未经审核的替代结果。递归审核明确拒绝，并确保释放上下文标记。
- 删除中性状态、旧参数决策重试和丢弃角色继续聊天的分支。聊天 API 将准备失败转换为脱敏 503，无回答生成、消息归档和后续写入，预留的并发名额释放。
- 显式关闭、无需语义审核、已命中安全保护规则属于正常路径，继续保留。未调用审核时不处理无关的审核历史预算；调用时历史只整理一次。语义审核超时配置非法或超出支持范围时明确报错，不改成默认值或截断到边界。
- 删除失效的回退状态字段和对应调用方。状态/策略评测遇到失败直接终止，不把规则结果统计成模型结果；回复评测保留失败分组和失败阶段，不进入生成。
- 显式遗忘可能先执行、上下文后失败。新增一个具体的部分完成异常，携带现有脱敏操作回执；API 报告回复未生成及已确认的操作数，保留内部异常链，避免让用户误以为之前的记忆操作未发生。

5 个核心业务文件合计净减少 114 行。没有增加依赖或通用错误框架；回退诊断字段的调用方和文档同步清理，历史评测文件未修改。
