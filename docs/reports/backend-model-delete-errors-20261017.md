## 问题与修改

服务器隔离复现确认：删除目录的异常被转换成 `False`，管理员接口据此返回 400，与未知模型混淆，原始错误原因丢失。目录为损坏符号链接时，`exists()` 返回假，接口甚至会报告删除成功而保留链接。

底层使用 `lstat()` 确认目录入口，只把目标本身的 `FileNotFoundError` 视为已经不存在；检查权限、递归删除和子项错误直接传播，不再转换成普通布尔结果。保留目录操作锁、线程适配和未知目录名称的业务结果。删除正常完成或目标确实已不存在时仍返回原有成功响应。

管理员 API 统一在边界记录安全异常类型，返回带原因类型和恢复提示的 503，并明确可能已删除部分文件，要求刷新列表后检查目录权限。原始错误通过异常链保留，不把底层错误原文或路径放进普通错误日志和响应。取消仍传播，未知模型保留原有 400 及提示。

删除旧的宽泛吞错和重复成功分支，生产代码增加 16 行、删除 27 行，净减少 11 行。没有新增依赖、回退、自动重试或回滚伪装。
