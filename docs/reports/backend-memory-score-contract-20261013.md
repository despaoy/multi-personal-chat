# 版本化记忆分数读写契约（2026-10-13）

## 问题与修改

CharacterMemoryService 排序原先通过 _safe_float 把非法置信度替换为 1.0、非有限数替换为 0，再夹取到 0–1。仓储与 SQLite/PostgreSQL 版本化 claim 写入也会夹取分数，NaN 可能成为最高置信度。损坏数值因此可能被提升为可信记忆，或伪装成正常低置信度过滤。

读入排序和两个数据库的版本化写入边界现在复用现有 parse_unit_interval：显式值必须是有限的 0–1 分数，布尔、None、非法文本及越界值报错。删除 _safe_float、无用 math 导入和仓储提前夹取；仓储原样传递置信度，由数据库写入边界负责校验。未提供的旧轻量记录仍沿用 MemoryItem 已定义的重要性 0、置信度 1；显式错误值不会取默认值。合法低置信度过滤保持正常业务结果。生产代码净减少 9 行。
