# 角色包入口取消隐式功能加载

日期：2026-10-24。基线：`a5e845ec9617fd31b1faf5b075bcc695b6e8dfda`。

审查数据库与角色模块的依赖时发现：即使调用者只导入不可变数据模型 `character.models`，Python 也会先执行包入口，连带导入上下文编译、人物注册、情景判断及语义复核。纯数据模块声明的独立性因此没有落实。

移除 `character/__init__.py` 中 30 个集中导出及对应导入，只保留包说明。全仓库 Python AST 检索确认，生产与评测调用方没有使用这些包级符号；三个测试已改为从实际所属模块导入。`from character import memory_llm` 等子模块导入仍由 Python 正常处理。未增加惰性导出映射、兼容包装或新模块，生产代码净减少 70 行。

这是导入入口调整：原来 `from character import CharacterProfile` 的写法改为 `from character.models import CharacterProfile`。具体功能实现和原有规则均未删除。仓库外未知调用者未做兼容承诺。

服务器两个独立进程对比仅执行 `import character.models`：角色子模块从 9 个降至 1 个，该次进程的 `sys.modules` 总数从 171 降至 86。测量证明隐式依赖减少，不代表整个服务启动时间或内存按同样比例改善。

117 项相关测试全部通过，无跳过，覆盖角色数据、编译、人物注册、生成集成、后台记忆、Web 历史归属及提供方预算。静态、仓库完整性及差异检查通过。部署后后端就绪和前端登录页面返回 200，未认证受保护接口返回 401；配置及前端进程不变。验证后同步本地。

未调用真实模型，未重复运行全部回归。数据库到具体角色业务函数的其他依赖仍需逐项审查，本阶段不宣称全部消除。
