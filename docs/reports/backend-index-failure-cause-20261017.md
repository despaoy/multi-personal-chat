# 保留知识索引异常的原始原因

基线：`b91273bbc0ab9234b0e3f026f7c5b17a5b4a42e3`。

服务器与本地基线一致。隔离复现确认 `_ensure_vector_index` 会把修订号读取、索引持久化等异常转换为 `False`，上层虽返回失败，却丢失原始原因。知识搜索接口及对话检索已有安全错误边界，无需增加包装层。

仅将这两个异常处理中的 `return False` 改为裸 `raise`，保留异常类型诊断。业务源码两行替换，净增 0 行；并发修订号变化、提交 CAS 失败、数量未完成等现有返回值保持原样，锁、文档发布、缓存、空库完成语义均未改变。

19 项定向测试首轮通过：四种新增/导入成功路径、四种持久化失败的安全 HTTP 响应与完整来源保留、对话检索的修订号读取/持久化异常原样上抛、更新/删除成功与失败、三种不可读取/非法修订号，以及并发修改和最后一份文档删除。原失败返回值断言升级为异常断言，原有业务、状态和数据完整性检查保留；没有放宽有效断言或重复全量回归。

通过 Python 3.10 语法、差异空白及 Ruff E9/F 增量检查。完整业务源码对比确认只改两处异常返回。测试使用临时 SQLite、真实 FAISS/BM25 和受控向量，不访问真实大模型或嵌入服务；仅下载源码及汇总证据，没有下载用户日志或模型原文。最初复现辅助脚本误导入临时目录中的同名旧测试，已改为按当前源码绝对路径加载；该准备问题没有触发产品调用，修正后复现完成。

部署后就绪与前端登录页面返回 200；匿名受保护接口返回 401，安全响应头正常。运行配置、其他服务进程及生产索引数据没有改变。本阶段验证失败链路与对应索引行为，不宣称完成真实模型质量验收。没有新增意图规则、分类器、依赖或重试。整体优化目标继续进行。
