# 无效索引行统一报错

基线：3a2570b。审查上下文编排后，沿实际 RAG 检索链定位到文档读取契约问题。

## 原因与修复

`DomainIndex.get_document` 对不存在的行返回 None，关键词、向量、实体及单通道结果组装共四处将其静默跳过。这使损坏索引的结果与正常无匹配混淆，生成链还可能继续调用模型。

现在文档读取入口对越界行统一抛出已有的 `RetrievalIndexError`，检索端删除四处重复的空值跳过判断。通过原有 API 错误转换返回 503，说明文档索引引用不存在的行，并提示加载或重建完整索引。错误不包含查询原文。没有新错误包装层、自动重建、回退通道或新增语义规则。

正常空索引、过滤无匹配、向量阈值、FAISS 未命中标记和正常排名保持原行为。仅三个生产文件修改，净减少 2 行。

## 验证

- 修改前七项复现全部失败：三个通道各自的负数与越界行都未报错，另一个生成链案例继续调用回答模型。
- 修复后六个相关测试文件共 109 项全部通过，无跳过。包含新增七项以及正常结果、正常空结果、单通道依赖、修复后重新检索、联合召回和排序测试。
- API 案例验证 503、原始错误因果关系、安全公开详情，并确认回答模型没有被调用。
- 使用完整两文档索引和合成 embedding，在通道边界注入无效行；未使用真实模型或付费接口。没有改变旧断言以取得通过，未重复全量回归。
- 静态检查、仓库完整性和差异检查通过。重启后端后就绪接口和前端登录页为 200，受保护接口为 401，运行配置不变。
