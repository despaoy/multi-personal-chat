# 原文请求的提取故障不再降级（2026-10-13）

## 问题与修改

RoutedMultiScaleService.retrieve 在原文/出处请求中，提取器缺失或文件缺失、解码与解析失败时，原先标记 extractor_unavailable/source_unavailable 并继续返回摘要或尝试下一候选。实际文件故障因此可能被“未取得原文”掩盖。

现在发现可见的原文候选后，必须具备提取器；配置缺失明确 RuntimeError，提取异常原样向上传播，不尝试另一候选换取成功。正常没有可见来源仍是 no_visible_source，不读取被知识边界排除的证据。删除异常吞掉和候选回退分支，生产代码净减少 2 行。

## 验证

服务器 10 项直接关联测试通过（0.79 秒），46 项无关测试未运行。五种原文请求表达均使用真实临时 UTF-8 文件验证原文成功、完整条件与例外保留、共享场景不重复；同一场景确认提取器缺失及文件删除明确失败。另三种故障注入验证只尝试第一候选且不调用回答模型；两个可见性场景确认隐藏原文不会被读取。

修正了旧测试仅提供 extract 方法却未满足后续来源目录契约的简化对象，采用真实 OriginalTextExtractor 和完整卡片字段。原错误输入与拒绝要求保留，未通过宽松断言绕过验证。语法、差异检查通过，无新增静态问题。未运行全量回归，付费模型调用 0。

本阶段处理明确原文请求的必需提取失败，不宣称所有来源审核路径已完成；普通索引证据与可选来源目录审核仍需各自核对。后续检查截断原文的完整性标记是否始终送达模型，整体优化目标继续。
