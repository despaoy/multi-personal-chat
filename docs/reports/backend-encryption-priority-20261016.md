# Resolve encryption key sources only when selected

The encryption constructor's candidate tuple eagerly read the canonical key file before checking the explicit environment key. A valid environment key could therefore be blocked by an unused file read. Normal application startup already loads its configuration file before constructing this manager, so this is a constructor priority defect and redundant read rather than evidence of a current production outage.

The loader now selects the explicit environment value first and only reads the canonical file when that value is absent. The existing decode, error handling, environment publication, legacy migration, development provisioning and explicit rotation behavior remain unchanged. An invalid explicit environment key fails immediately; it cannot switch to a file key. A selected file read failure still propagates with its cause and cannot trigger legacy migration or generation. No real key was read into test output, changed or rotated; database encryption integration was not added or claimed.

Four focused tests passed in 0.20 seconds: three new priority/error cases and the existing invalid-persisted-key case. A synthetic baseline reproduced one unused source read blocking a valid explicit key. The success case decrypts ciphertext produced with the same synthetic existing key and verifies new encryption round trips, without touching any configuration file. Failure tests check that files remain byte-for-byte unchanged and that the selected-file PermissionError cause is retained. Syntax, incremental lint and whitespace checks passed. No full encryption suite or unrelated regression suite was rerun. Server configuration hashes remain the deployment invariant.
