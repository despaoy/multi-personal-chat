# 独立问答的连接快照与缓存来源（2026-10-16）

## 真实问题

/api/ask 在检索前记录提供商和模型名，但保留可变云端对象，实际 async_complete 又读取数据库配置。检索期间修改配置可能使响应标记、缓存键和真实请求不一致。答案缓存原先只有模型标识，没有同模型不同连接的身份。

服务器基线 c8424ac 上使用真实隔离 SQLite 配置、真实 ask 入口、GroundedAnswerService、缓存和 OpenAICompatProvider/HTTP 编码，明确控制检索边界和 httpx.MockTransport。第一项复现响应 model 为 Flash、实际 wire 为 Pro；第二项保持模型名、修改地址和合成凭据，仍命中旧连接缓存，新的 HTTP 调用为零。资料包含完整开放时间、暴雨例外与人物尚未入馆等事实，模型响应明确为合成控制，付费调用为零。

## 修改

普通和 SSE 问答入口复用现有 InferenceRequestContext，在检索前解析一次云端连接快照。适配器明确接收该上下文，删除对私有刷新方法的探测及同步刷新；来源标签、实际调用保持同一快照。实际发送前检查所选提供商种类，变化时直接失败；延迟 vLLM 客户端解析及其单次初始化语义保持不变，不因合法无证据结果初始化推理客户端。

普通回答在真实服务调用期间绑定上下文。SSE 在事件生成器实际迭代的任务中绑定，覆盖检索、生成、所有事件和关闭过程；返回 StreamingResponse 时不留下绑定。保留现有错误事件、超时、客户端断开、取消传播和关闭语义，没有增加重试或替代模型。

由解析后的连接状态、地址及凭据 SHA 摘要构建内部 cache_identity，再显式传给服务和缓存键；公开 model 字段保持原含义。服务和公开响应不接收凭据原文。保持模型名但修改云端地址或凭据时，旧连接答案不再命中；恢复同一连接仍能正常复用缓存，并明确标记 cacheHit 和 modelInvoked。服务的独立注入式调用保留现有默认入口，不强迫离线工具获取在线提供商。

两个旧测试文件补齐明确连接快照与新适配器返回值，原有禁止本地切换、参数与角色消息、取消、错误和缓存断言保持不变。没有为了兼容不完整测试替身给产品增加默认连接。

同步纠正上阶段报告的预检措辞：配置来源实际是隔离设置替身，不是 SQLite 配置读取；当时记忆和交付检查确实使用真实 SQLite。本阶段新增用例的连接配置和完整证据均实际持久化到隔离 SQLite，未将两类验证混称。
