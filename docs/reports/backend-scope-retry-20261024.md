# 记忆范围审核的有限重试修复（2026-10-24）

记忆写入器对 scope_review 和 proposal_generation 两个写入前阶段的临时网络/服务故障均产生 retryable=true 回执，但交付记忆执行器只接受后者。需要范围审核的消息因此在第一次临时故障后直接被阻断，无法使用已有恢复机制。

将交付执行器的阶段条件与写入器对齐。仅修改一行生产代码，仍要求 failed 状态及明确 retryable=true；沿用持久化的最多三次尝试和等待时间，不增加重试器、不切换模型、不吞掉错误。结构化写入阶段和不确定结果不进入该重试路径。

验证先在服务器执行：

- 新增完整原文、跨角色授权及真实数据库回执的三个隔离案例；旧代码在恢复及重试耗尽两例失败，认证失败停止案例原本通过。
- 修复后 66 项记忆重试、交付及队列相关测试全部通过，无跳过。
- 503 后恢复只保存一次；连续 503 在第三次停止；401 第一次即停止。每次重试间重建数据库连接和执行器，检查持久化次数、原始回复及交互统计不重复。
- 静态、仓库完整性和差异检查通过。重启后就绪与前端登录返回 200，未授权接口返回 401，配置未改变。

未调用真实模型，未重复全套测试。没有自动恢复此前已标记 blocked 的历史任务，以免重放未经本阶段核对的历史操作。
