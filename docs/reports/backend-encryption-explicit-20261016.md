# Require an existing encryption key in every environment

The loader previously generated and persisted a new key when no configured source existed in development or when ENVIRONMENT was unset. A fully isolated baseline reproduced successful initialization, a newly written dotenv file and a newly populated environment value despite the missing prerequisite. No real key or deployment configuration was involved in that probe.

All environments now require an existing key. The loader reports a specific KeyManagementError after env, canonical and legacy sources have no key; it never generates a replacement during initialization. Its private name is now `_load_key`, and the obsolete production-only environment branch was removed. Deployment validation applies its existing key validity check in every environment instead of warning that development would generate one. The sample configuration documents this requirement and retains the explicit manual generation command.

Explicit constructor keys, source priority, existing ciphertext, legacy migration and the explicitly requested rotation API are preserved. Migration still copies the same existing key, rather than generating a different one. The application's single startup snapshot is taken after configuration initialization publishes that verified/migrated key; otherwise a first legacy-only development start would be rejected by its earlier incomplete snapshot. The snapshot still stays frozen after construction. Test bootstrap supplies a process-local explicit synthetic encryption key before application imports and never writes workspace credentials.

Ten directly relevant checks passed in 4.28 seconds: existing canonical key and ciphertext across a restart; missing keys with unset/development/production environment; invalid persisted key; a real isolated first app.main import using only the legacy key, with actual deployment validation and frozen-snapshot checks; a test-bootstrap import without dotenv writes; and missing/invalid/valid development deployment configurations. The legacy app-import test blocks outbound socket connections and decrypts pre-existing synthetic ciphertext through the public API. No live provider or real key was used. The old JWT matrix and unrelated regressions were not rerun. Syntax, incremental lint and whitespace checks passed.

The former automatic development provisioning behavior intentionally ends here. New installations must set ENCRYPTION_KEY explicitly using the documented command before starting. Existing configured keys and server configuration bytes remain unchanged. This phase does not change encryption algorithms, rotate stored data, remove legacy plaintext compatibility or add database encryption middleware.
