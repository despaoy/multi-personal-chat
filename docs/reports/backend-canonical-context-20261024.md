# 正史上下文与生成共享同一模型连接

## 问题与修改

普通生成会先确定本轮模型连接，再按该连接构建角色上下文。正史入口此前先构建上下文服务并读取历史，再进入生成入口确定模型。期间模型配置变化时，历史和证据预算可能取自先前全局配置，与实际生成连接不一致。

正史排队任务现在先检查已有请求回执；需要实际生成时，确定本轮模型连接，并在现有请求上下文作用域内构建服务、准备角色上下文及调用生成。生成入口复用已经绑定的连接。请求回执命中不额外构建上下文服务，配置读取失败返回 503 并保留异常原因。

复用现有连接快照及上下文管理机制，没有新增包装模块、重试或备用模型。生产代码净增加 7 行。

## 验证

新增三个隔离场景：连接确定后改变全局提供商选择，验证上下文准备和生成仍共享连接及云端预算；连接快照失败时不准备上下文、不生成；准备失败时不生成。所有路径检查请求上下文在结束后恢复。

分支业务、请求上下文和提供商归属三个相关测试文件共 49 项全部通过，无跳过。既有正史与分支历史隔离、真实服务调用流程测试保持通过。模型质量未参与此次测试。

静态检查、仓库完整性和差异检查通过。服务器后端重启后就绪及前端登录返回 200，未登录受保护接口返回 401；配置及前端进程未变化。验证后按内容哈希同步本地。

未调用真实大模型，未重复运行全部回归测试。本次未调整正史入口其他错误映射或分支业务语义。
