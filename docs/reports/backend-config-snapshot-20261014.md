# 配置缓存收敛与失效竞态修复（2026-10-14）

## 调用链和架构取舍

沿配置 GET/PUT、模型配置读取、旧 bot 配置属性和共享缓存追踪，发现配置总是先读 Redis，Redis 读取错误被当成未命中，再转用本地缓存；删除失败返回 false 但上层忽略，后续可能继续取旧 Redis 值。API 和模型还分别执行“读取数据库→填充缓存”，配置更新期间旧读取可在失效后回填。旧 bot 在数据库和缓存错误时还会返回空配置。

当前部署强制 BACKEND_WORKERS=1，因此配置缓存收敛为一份进程内 TTL 快照，彻底移除配置的 Redis/本地切换及分离 get/set 入口。read_config(database) 统一持有一把锁完成命中检查、必要数据库读取、值转换和回填，返回数据副本及命中标志。快照绑定数据库实例，另一个实例不能获得其数据；过期或换实例先清掉旧引用，读取失败直接传播，不返回过期值或空字典。

invalidate_config_cache 与加载使用同一把锁，设置保存后的失效会等待旧加载结束再清空，防止旧快照回填。模型删除额外配置锁和重复转换；API 返回准确 cached 标志，读取失败为 503；旧 bot 删除三处吞异常和空配置行为，统一读取同一快照。公开失效函数保留，既有评测调用无需修改。

TTL 仍为 60 秒加既有少量抖动。主后端设置保存立即失效；独立旧 bot 进程在自己的 TTL 到期后观察外部更新，约一分钟，不再宣称跨进程即时失效。该取舍已在修改前说明并写入运行文档。没有增加 Redis 必需依赖、新配置项或缓存策略框架。其他知识统计/列表缓存仍有独立用途，知识统计相关函数保持原样；本阶段不声称其他 Redis 故障行为已全部清理。

四份生产模块合计净减少 49 行；未迁移或删除生产配置、用户数据或历史评测，也没有清理 Redis 中的运行数据。已退休配置键按其既有 TTL 自然到期，当前配置读取不再访问它。

## 定向验证

服务器隔离环境中 23 项直接相关测试通过（1.44 秒），未运行全量回归或重复旧成功集合。新增控制验证副本隔离、准确 TTL 过期、数据库实例隔离、非法数据库返回不入缓存、到期后读取故障不使用旧值或默认配置、配置 API 明确错误。

并发控制使用两条真实线程和事件：第一条捕获旧值后阻塞，另一条请求失效；失效必须等待旧加载结束，完成后下一次读取获取新值。测试校验实际返回值和数据库读取次数，不检查锁的实现类型。真实隔离 SQLite 的设置 API 与模型读取共享实际缓存，验证更新后的模型名、API 值一致且凭据仍脱敏。

既有三项配置数据库/缓存控制改为验证真实读写行为，不再通过替换缓存 get/set 函数验证内部调用。提供商刷新测试继续使用明确的无缓存数据库读取替身，保留其完整参数、异常和连接快照断言；没有放宽标准。配置快照控制禁止调用 Redis 客户端，证明这一链路不依赖 Redis 可用性。

旧 bot 的受改配置函数只做调用方核对和语法检查，未启动旧 NoneBot SDK 或真实平台链路。知识统计函数与修改前逐字对照一致，未扩大其回归范围。静态、语法、差异与退休入口引用检查通过，无新增问题。付费模型调用 0，没有真实模型质量或跨进程即时同步结论。

部署仅重启后端并核对实际就绪、配置哈希和其他服务进程，之后同步本地和 GitHub。整体后端优化目标继续，本阶段完成配置缓存根因治理，不作为全项目降级已消除的结论。
