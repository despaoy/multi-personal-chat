## 问题与修改

问答服务在读取缓存、构造检索问题前没有验证历史结构，无效历史可能直接命中缓存并返回成功。`AskRequest` 也缺少聊天入口已有的角色及非空正文校验。提示词层随后又自行删除控制字符、去除首尾空白、字符串化、过滤记录、截取最后 20 条，并裁剪每条至 2000 字符；换行、缩进和末尾否定可能因此丢失。

- 服务的普通及流式入口复用现有 `validate_history`，在缓存、版本解析、检索和任何流事件前拒绝无效结构；明确区分合法 `None`/空历史与错误类型。
- 问答 API 保留最多 20 条历史的既有外部限制，复用角色和正文校验。原来提示词内的每条 2000 字符静默裁剪改为接口显式 422；不会接纳后仅传递前半段。
- 提示词只投影已接纳历史的角色和完整正文，移除重复过滤、改写及裁剪。内部服务收到更长或更多的合法历史时完整传递，模型容量错误仍交给对应供应商明确报告。
- 当前问题同样保留换行和原始格式，继续通过 HTML 转义封闭资料边界，不将文本标签当作系统指令。
- 提示词契约升为 v4，避免沿用旧提示词语义的缓存身份。

三份生产文件合计增加 16 行、删除 18 行，净减少 2 行。没有新增意图规则、分类器、配置项、模型调用或降级分支。
