# 所选模型的就绪检查：第六阶段（2026-10-08 至 10-09）

基线 b15112173d09bd2eb6cda04c4cd61afa82f97e3c。服务器先修改、定向验证，再同步本地和 GitHub。

## 问题与修改

app/main.py 原本另行按启动环境中的 vLLM 标记决定是否检查模型。DeepSeek 路径会直接得到 model=true / not_required；运行时切换模型后检查对象也可能不一致。

删除这套重复选择逻辑。就绪检查读取与聊天相同的模型管理器当前提供商，不把远程提供商初始化时写入的 loaded=true 当成连通证据。协议检查集中在 inference/model_readiness.py；现有 ReadinessProbe 继续负责错误边界、超时、缓存及并发合并。应用容器只增加一个可注入的模型检查依赖，用于应用隔离与测试，没有新增配置体系。

OpenAI 兼容服务刷新与生成相同的有效配置，通过鉴权模型列表确认所选模型；Ollama 查询指定模型详情；llama.cpp 查询健康端点；vLLM 复用聊天初始化入口和共享客户端。mock 不代表真实聊天可用，Transformers 必须已完成加载；探测不自动加载权重。连接、鉴权、解析、配置失败不会被当成就绪。

协议依据：[DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models/)、[Ollama 模型详情](https://docs.ollama.com/api/show)、[llama.cpp 健康接口](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md#get-health-returns-health-check-result)。

## 验证与同步

服务器使用正在运行的后端环境执行一次 DeepSeek Flash 模型列表检查，鉴权和所选模型检查成功；没有调用聊天生成，没有发送对话内容。该检查只验证模型依赖，数据库与部署后 /ready 另行确认。

Ruff 与同配置基线比较无新增问题，Git 差异检查通过。部署流程检查后端就绪、其余服务进程和配置哈希；同步仅包含本阶段代码、测试与本文档。

## 限制和下一步

/health 仅表示进程响应；/ready 的成功是本阶段定义的依赖检查结果，不能证明账户余额、回答质量、全部 LoRA、可选 RAG 或每次生成必然成功。成功缓存 5 秒、失败缓存 1 秒，模型切换也遵守这个过期窗口。Transformers 使用前需要先完成预热。

没有全量回归或付费生成验证。并未变更账号、密钥、运行配置、历史数据或公网访问。上游记忆/互动状态审核降级、模型设置更新原子性等问题仍待后续阶段处理，持续目标尚未完成。
