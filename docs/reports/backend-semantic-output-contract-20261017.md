# 语义审核协议与任务定义

日期：2026-10-17。基线：`d09d354b0524cc89bd755b675a9a70bb097c1fa6`。

## 问题与修改

动态审核提示要求顶层为 `state`、三个信号字段为对象，解析器却会将缺少封装的平铺状态、额外字段及信号列表识别为成功。这会隐藏模型协议错误，也保留了没有实际协议调用方需要的结构转换。

现在顶层只能有 `state`，状态恰好包含已声明的十个字段，信号只接受对象。缺失封装、字段不全、额外字段和列表形式直接报错，不猜字段或伪造默认值。原有 JSON 重复键拒绝、数值及枚举检查继续执行。已有真实 DeepSeek 记录使用的完整 JSON 围栏格式保留，原记录没有修改。

首次真实抽查中，两次输出结构均符合协议，但一个前提完整的“区分已知与未知、暂时不需要建议”请求漏掉了信息请求行为。原输出包含 `factual` 情景、信息需求和交互边界，却没有相应任务行为；没有在程序中补标或放宽检查。

现有审核提示改用通用定义区分背景、明确任务和独立边界，说明处理用户已给出的材料也属于信息请求，单纯分享本身不构成请求。删除一段针对特定短语的解释示例，保留整体语境、反讽及引用归属要求，没有增加关键词分类器。生产代码增加 14 行、删除 24 行，净减少 10 行。

## 验证与范围

184 项相关测试通过，首次运行均通过。提示调整后仅复查直接受影响的 5 项预算边界；它们已包含在 184 个不同测试身份中，不重复计数。没有运行全部回归。

验证包含两种审核模式下的结构错误、HTTP 503、健康重试恢复、数值和枚举边界、重复 JSON 键、合法对象的零分过滤，以及历史真实围栏格式。旧的“额外字段被丢弃仍成功”预期改为明确拒绝；平铺结果和信号列表的成功预期改为协议错误。合法对象及安全、权限相关断言保留。

静态和语法检查通过。只有状态、信号两个解析函数的逻辑改变；安全门和历史选择性保护函数体保持一致。提示调整后的其他函数体与测试版本一致；重复键解码器及历史真实记录文件摘要未变。

本阶段共进行 5 次新的 `deepseek-flash` 审核调用。前两次的任务遗漏及原始交换完整保留。提示修正后，对输入逐字一致的两个原案例和一个新增“仅分享进度”对照进行三次审核：信息请求及不接受建议的边界同时保留，引述告别语没有变成告别意图，纯分享没有被增加信息任务。三个当前提示案例均满足检查，没有复用结果或修改原案例输入。

这些是协议及限定案例的证据，不能保证所有交互语义都正确，也没有执行新的回答质量全量评测。模型结构错误现在失败；无法可靠检测的语义质量问题仍需实际抽查。
