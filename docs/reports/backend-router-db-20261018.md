# 适配器管理与鉴权共用应用数据库

基线：`1144947bdced7016a229389dd0f2ab4e94060efc`。审查应用容器、管理员复核、认证与适配器接口及其调用方，在服务器先复现、修改和验证，再同步本地。

## 问题与修改

管理员权限在当前应用的数据库中复核，但适配器配置、检查记录读写仍使用模块导入的全局数据库。两个应用数据库不同时，授权和实际数据操作会落在不同存储；当前应用存储故障也可能被另一个数据库的正常响应掩盖。

统一通过 `app.dependencies.get_request_database` 读取当前应用容器：认证、管理员复核和适配器配置/检查的四个接口共用这一入口。删除认证私有数据库辅助函数和适配器 SQL 转发辅助函数，接口直接向注入的数据库提交原有查询。直接调用接口函数的测试显式提供自己的数据库。

查询内容、请求响应、权限复核、兼容性检查与保存失败语义保持不变。生产代码净增 4 行，其中末尾 3 行仅用于调用排版；没有新增业务判断、错误类型、重试或数据库回退。对依赖来源做归一后，原有业务函数 AST 一致。

## 验证

- 两个隔离 SQLite 数据库配备独立配置、检查记录和管理员；经真实 JWT 验证及管理员数据库复核，修改前四个接口的 5 次操作全部落在全局库，当前应用库没有被访问，其故障仍返回 200。
- 修改后 5 次操作全部进入当前应用库，全局访问为 0。配置及检查记录只修改所属库，存储故障返回 503；匿名请求为 401，数据库中已被降权的用户为 403。
- 原有应用库与全局库相同的对照场景，完整响应 SHA-256 保持 `90c559204cf4509532f3ee987bf3d4977b1f279dc48df2fa3f8af4bff9ddfce6`。
