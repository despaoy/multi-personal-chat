# 对话原文契约与重复清洗收敛

基线：aff73aeb6ceb6c663d28125db52026c592b8df9a。

## 问题与实际影响

通用对话服务改写当前消息和历史用户消息，去掉首尾空白并删除控制字符；叙事页面、原作对话接口、AstrBot 接口又分别执行清洗。结果是代码首行缩进和尾部格式丢失，归档也只能保存改写后的正文。历史助手消息却没有相同的清洗行为。

服务器隔离复现使用包含时间、否定、条件及缩进代码的完整虚构题设，经过真实生成服务、请求编译器和 SQLite 归档。修改前，当前消息、历史用户消息、模型边界收到的正文和归档均未保留原文。真实来源准入与预留还会把同一来源标识下裁剪前后的不同正文视为相同；三类含不支持控制字符的 HTTP 请求返回 200，并实际到达受控模型边界。

## 修改

当前消息共用 MessageText 请求契约，历史消息复用同一文本判定。正常文字、缩进、空格、TAB、LF、CR 原样保留；纯空白以及原先会被静默删除的 C0 控制字符、DEL 明确拒绝。原有长度、历史条数、角色及总预算约束保留。

通用生成、知识问答、原作对话、AstrBot 四个请求入口复用该契约。生成服务删除正文改写、历史逐条复制及清洗回调；叙事前端仅用 trim 判断空白，发送和展示原始输入；网关删除重复长度检查、清洗函数和只转发安全判断的包装。已无调用方的 strip_control_chars 一并删除，控制字符判定只有一处实现。

安全检查使用只读的派生视图，不覆盖正文。鉴权、签名、原始事件大小限制、队列准入、来源事务及服务器掌握的分支历史保持现有职责。

生产代码净减少 20 行；没有新增应用模块、依赖、语义关键词规则、分类器、重试或降级机制。

## 验证

- 140 项直接相关测试首次全部通过，覆盖对话服务、来源状态、叙事分支、知识问答历史、网关、安全及投递契约。没有运行全量回归。
- 真实服务、编译器和归档前后对照：修改后当前消息、用户及助手历史、提示词封装反转义后的正文与归档均保留原文。模型输出边界受控，没有真实 DeepSeek HTTP 请求或费用。
- 真实 SQLite 来源准入：原文重试允许，不同原文使用同一标识返回 409，预留摘要对应完整原文，不同登录用户相互隔离。该项替换生成处理器，只验证来源准入，没有冒充模型验证。
- 实际 ASGI 接口：正文、用户历史、助手历史中不支持的控制字符均返回 422，模型边界调用次数为零。
- 四个请求契约均验证保留完整中文、缩进、CR/LF/TAB，并拒绝纯空白、NUL、ESC；两种历史请求契约均验证双方角色的非法控制字符。
- 叙事页面类型检查、定向 ESLint、生产构建通过；Python 未使用及未定义符号检查、仓库完整性和差异检查通过。
- 部署后后端就绪与前端登录均为 200，受保护消息接口为 401；现有配置及其他服务保持一致。

## 兼容范围与限制

没有重写历史消息、来源记录或数据库结构。来源比较继续采用完整正文的精确身份规则；旧记录若保存的是裁剪后的正文，携带不同原文重放将明确返回冲突，应使用新的来源标识，不会猜测旧正文或自动回退。

原先接受并清除不支持控制字符的请求，现在会在请求校验处返回 422。历史记录出现这些字符也会明确失败，需要定位其写入来源。本阶段证明输入链路和失败行为，不声称验证了真实模型的理解质量。
