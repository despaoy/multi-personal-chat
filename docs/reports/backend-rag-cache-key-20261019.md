# RAG 缓存快照与锁范围精简

## 问题与修改

缓存读写把整份结果深拷贝放在 LRU 锁内，其他查询会等待复制结束。受控并发复现中，分别暂停一次读取复制和一次写入复制，已开始执行的独立读取均被阻塞。

读取在锁内取得自有快照并更新 LRU，之后在锁外复制；写入先复制调用方数据，再在锁内计算过期时间、发布快照和处理淘汰。存储快照从不向调用方直接暴露，也不原地修改，因此缩小锁范围仍保留数据隔离。没有新增锁、重试或配置。

缓存键改为一次结构化 JSON 序列化，保留问题、数量、重排序状态、阈值、召回倍数、过滤范围和索引修订号七个维度。删除单独的过滤器编码和多段字符串拼接，生产代码净减少三行。这是进程内键格式整理，没有引入兼容分支或宣称修复未复现的键碰撞。
