# 记忆证据字段契约（2026-10-09）

## 问题与修改

`backend/character/memory_llm.py::_candidate_to_proposal` 曾通过 `str(raw.get("evidence") or "")` 把任意结构转换成文本，并静默跳过空证据。模型协议错误可能被当作正常无记忆处理。

现在要求 evidence 为非空字符串，错误抛出带字段名的 ValueError。保留已有空白规范化；移除后续重复的空值判断。有效字符串但不受原始输入支持的证据仍按业务规则拒绝；IGNORE 仍按公开协议忽略，不要求证据。没有新增依赖、配置或抽象层。

## 验证

服务器运行新增证据契约测试与直接关联 test_character_memory_llm.py：19 passed，0.77 秒。

覆盖缺失、null、布尔、数值、列表、对象、空白证据；有效证据正常解析；原话不支持的证据不写入。调度器测试使用真实 SQLite 仓储及明确的模型响应替身，确认错误发生于 proposal_validation，失败回执记录 ValueError，accepted/persisted 均为 0，仓储无 claim 写入。

本阶段没有运行全量回归，没有付费模型调用。格式判断是确定性边界验证，未将替身测试声称为真实模型验证。

## 范围

仅处理证据字段结构，未声称解决其他字段、全部语义质量或全部记忆链路。超长、未被原话支持的字符串继续使用既有业务拒绝规则。测试仅使用合成资料，不提交运行数据或私有原文。

部署与版本同步的校验记录保存在服务器本阶段备份目录。
