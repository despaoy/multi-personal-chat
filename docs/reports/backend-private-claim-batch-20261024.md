# 批量复核受撤回来源影响的记忆

审查长期记忆准备、来源检索和生成前复核后，确认 revalidate_private_sources 在发现原话撤回时，会对每条受影响记忆调用 get_memory_record。该读取与生成前的来源新鲜度检查有明确用途，不能直接删除；但仓储已支持带相同用户和角色范围的按 ID 批量读取。

本次将逐条读取改为复用 list_memory_records：只读取受撤回来源影响的记忆 ID，每批最多 200 条，显式取消数量截断并保留非活动历史读取语义。返回结果按 ID 对应原来的记忆，再执行原有正文及 evidence 比对。未返回的记录仍视为失效；独立有效事实继续保留。没有复用旧快照、增加缓存、重新召回或重新询问模型，也没有修改数据库接口或权限条件。生产代码净增加 7 行。

## 验证

- 来源最终权限、记忆预算、结构化记忆有效性、有效时间和来源继承五个相关文件共 69 项测试通过，无跳过；包含真实隔离 SQLite/PostgreSQL 的范围读取及来源继承检查。
- 使用原函数与新函数进行 20 组隔离对比，覆盖 0、1、24、201、401 条受影响记忆，以及记录保留、记录缺失、正文变更、证据变更，输出完全一致。测试还将批量返回顺序倒置，确认不依赖返回顺序。
- 上述对比中，24 条受影响记忆的复核仓储调用从 24 次降至 1 次；201、401 条分别使用 2、3 批。该结果证明调用次数减少，不是实际部署延迟的基准测试。
- 静态、仓库完整性和差异检查通过。没有新增重复业务测试，没有运行全量回归，没有真实模型调用。
- 部署后后端就绪、前端登录返回 200，未登录受保护接口返回 401；配置及前端进程保持一致。按文件哈希同步本地。

本次只优化来源撤回分支的数据库访问。仍保留生成前重新读取来源和事实的必要边界，不代表整个记忆链路或模型回答已经获得全面验收。
