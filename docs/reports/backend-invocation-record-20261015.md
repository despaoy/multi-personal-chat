# 模型调用记录失败明确终止本轮成功（2026-10-15）

## 实际问题与修改

主答在真实模型输出后、消息归档前写 model_invocations，异常路径也会记录失败计量。原 helper 捕获数据库错误后仅警告并返回，让必需记录失败伪装为成功；警告还会输出原异常文本。服务器基于原函数的隔离控制已复现：写入抛出 OSError、失败计数增加，但调用正常返回。未访问真实用户记录或调用模型。

现在保存异常或超时返回 503，stage=model_invocation_record，保留具体异常原因，日志只写错误类型。成功模型已经完成时 modelInvoked=true；失败路径无法确定是否实际发送到模型时为 null，不猜测。invocationRecorded=null 表示状态未确认，messageSaved=false 表示本轮尚未进入归档；线程超时后仍可能提交，不声称回滚，也不自动补写。

模型失败计数和原故障事件先记录，之后才保存失败计量。模型和数据库同时失败时，响应明确两种错误类型，异常 cause 保留原模型错误，context 另保留计量异常及数据库原因；不会让第二个故障抹去第一个。计量失败后的 HTTP 错误直接传播，不再重复记录失败、不误加模型失败计数，也不会继续归档和记忆回写。

保留原数据库提交方法的正常 void 契约，不伪造回执或猜测默认值。确定性回复、缓存复用、显式关闭记录的内部模式仍遵循实际来源，不新增计量或真实模型验证。没有修改数据库 schema、模型选择、角色权限、检索意图或数据留存。
