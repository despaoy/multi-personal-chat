## 调用链与修改

检查了聊天生成、知识问答普通/SSE 响应、语义依赖规划、对象与事实审核、发送前来源校验，以及角色索引和向量模型加载。

规划器成功时已经通过唯一解析器生成完整依赖，但结果类型仍允许省略依赖并默认标为 `not_needed`。结果现在必须显式携带依赖，默认状态与实际成功状态一致；生成 API 复用依赖分组，删除重复空值分支。规划器的模型请求、原始输入处理及响应解析函数 AST 均未改变。

同时定位并修复了一个真实资源生命周期问题：查询服务或选择冷启动预算会自动启动 `character-rag-warmup` 守护线程。该线程没有等待或关闭入口，还会吞掉预热异常。本阶段两轮相关测试出现 `-6` 异常终止；第二轮 229 项断言全部通过，退出时预热线程仍存活。删除该线程后，同范围及扩展检查均不再出现原生异常终止。

删除自动预热线程、状态标记及吞异常代码。索引和向量模型由实际检索按需加载，继续使用既有冷启动预算和共享模型锁。获取服务不再触发后台模型加载。首次检索承担一次加载耗时。

四个生产文件净减少 **20 行**，其中向量运行时仅调整锁用途注释。没有新增语义规则、模型降级或生产防御分支。
