# 训练模式与实际执行一致性

基线：`30b59e633f73525716b01b435b2ff1e094bc1296`。

## 问题与修改

整体核对了训练界面、配置导入/导出、任务配置映射、异步任务执行和训练器。仓库中的 `use_deepspeed` 仅有界面选项、数据字段和警告日志，没有 DeepSpeed 执行实现。启用该选项后，旧实现仍创建普通训练执行器，并可以将任务标记为完成。

- 删除未实现的界面选项、默认值和提交字段，以及任务管理器中的警告后继续执行分支。
- 复用现有训练配置校验，拒绝非 `false` 的旧字段值。保留关闭状态字段，使历史普通训练配置仍可加载；启用请求在创建执行器和保存自动配置之前失败。
- 导入配置先检查旧模式，再更新表单。合法的旧 `false` 字段被移除，普通参数保持原值；不支持的模式明确报错，不发生部分导入。

生产代码净减少 15 行。没有增加校验层、重试、依赖或语义规则。本次移除的是未实现的入口，没有新增 DeepSpeed 功能。历史研究记录未修改。
