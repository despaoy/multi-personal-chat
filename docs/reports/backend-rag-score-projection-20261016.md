# 检索分数只由生产环节计算一次

本地基线：`7dc26c5b33e52422b4b4530d2a787ac20c88dc23`。用户已授权服务器断线期间先在本地优化。

## 实际问题

CrossEncoder 已对完整候选计算 `rerank_normalized_score`，RAGHelper 又对截取后的 `rerank_score` 做一次最小最大归一化。这使同一来源的展示/引用分数随 `top_k` 改变，也覆盖重排器明确关闭归一化的设置。无重排时，已经融合的分数同样再次被拉伸。

旧版本对照使用实际 CrossEncoder 适配器和受控张量输出 `4、2、0`，只返回前两条时，第二条的生产分数为 `0.5`，RAG 结果和引用却变成 `0`。该对照执行一次，不加载真实模型、不联网。

## 修改

删除 RAGHelper 的重复归一化函数。重排结果直接投影既有 `rerank_normalized_score`，未重排结果使用既有融合分数；原始模型分数、检索置信度、排序及引用字段保留各自职责。缺少必需的重排投影字段会明确失败，不再通过零默认值构造结果，也不写入成功缓存。

测试中的重排替身补齐实际适配器原本就返回的两个分数字段，没有放宽业务断言或增加错误吞并逻辑。

## 验证

本地 11 项定向检查通过（2.32 秒）：分数跨返回条数稳定且与引用一致、只计算一次、显式归一化设置不被覆盖、混合分数不被再次拉伸、缺字段报错且不缓存；关联失败恢复、重排模式缓存、单候选、独立任务排序和实际适配器的三类非有限输出校验。

Python 语法、增量静态及补丁空白检查通过。未运行全部检索测试或全量回归，未改依赖、配置、数据或模型调用数量。受控 logits 只验证分数协议，不能声称真实语义质量已通过。服务器同步和真实模型抽查仍待 aTrust 恢复。
