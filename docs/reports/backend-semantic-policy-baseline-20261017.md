# 语义策略路径跳过未采用的可选评分

服务器隔离复现确认：正常轮次先运行完整可选策略评分，语义模型随后覆盖
这些选择；既有角色 `response_preferences` 却没有进入策略模型输入。决策器
直接入口还会把无效主状态默认成日常。

## 调整后的职责

生产工厂在实际启用语义策略时，让常规轮次只准备必要基线，由模型选择
可选行为，再经过现有完整输出校验和最终上下文约束。

- 中间基线标记 `pending_semantic`，不作为成功的模型选择。模型错误继续
  直接传播，不转回规则评分，不生成默认回复。
- 安全相关信号仍经过原有确定性评分和保护；硬安全门保持最高优先级。
- 默认直接调用、没有软状态或显式关闭语义策略的路径保留既有实现。
  新路由由实际策略组件是否存在决定，没有新增环境设置或用户配置项。
- 无效的非安全主状态直接报错；不会用日常计划掩盖错误。
- 已有角色回应偏好作为数据传入模型，仅为可选倾向，不能挤掉必做任务、
  安全或用户边界。最终编译器的独立保护未移除。

中间诊断不再为常规语义轮次列出未采用的可选评分；最终采用已校验的模型
策略。为保留必要路径而增加了少量路由代码，产品代码净增 **10 行**，正常
生产路径减少一次完整可选评分。没有增加词表、关键词规则或策略框架。

## 验证

- **69 项直接相关检查通过**，没有重复整组或全量分类回归。验证了正常
  语义选择不依赖可选评分器、模型失败不回退、旧调用及安全路径保留。
- 一次性比较 **160 组受控状态**：相同模型选择下，两种基线的模型输入、
  最终策略和编译上下文一致，覆盖普通、明确任务、混合情绪、元问题、
  收束、关系阶段及安全澄清强度。这是受控等价性检查，不是模型质量评测。
- 实际应用工厂使用 **DeepSeek Flash 新发出 1 次策略 HTTP 请求**：常规
  可选评分调用为 0，角色已有两项偏好到达模型，必做任务保持首位，完整
  模型选择被采用，原始来源仍未提升为结构化事实。
- 前置状态复用一条输入和参数完全相同的真实记录，不计为新模型验证；
  最终回答模型和完整 HTTP 登录鉴权未重测。
- 定向静态、语法及差异检查通过，旧评分实现、安全辅助函数、输出校验、
  画像加载和最终上下文编译器保持原样。
- 已部署服务器，后端就绪和前端登录页均为 200；配置及其他服务未改动，
  随后按摘要同步本地。

单次策略抽查不证明所有角色风格都达到一致质量，也没有解决此前长计划
结构化提取的限制。原始模型交换、运行数据、隔离数据库和密钥不进入提交。
