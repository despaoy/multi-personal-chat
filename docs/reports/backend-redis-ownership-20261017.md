# 删除闲置同步 Redis 资源

全仓跟踪的 Python 调用核对表明，同步 Redis 客户端及连接池只有后端启动探测使用，没有业务读写调用。其故障被转换为布尔值后输出“数据库直连模式”日志，实际并不存在对应的业务缓存切换。

本阶段删除同步连接池、客户端、健康探测及对应启动/关闭代码，移除旧测试中的两个模拟入口。Web 后端不再为闲置探测建立 Redis 连接；NoneBot 消息去重仍使用原来的异步共享连接，连接或原子预留失败继续阻止消息生成。异步池、客户端发布和关闭函数的实现逐项 AST 比对一致。

只运行直接相关的 11 项测试：SQLite/PostgreSQL 生命周期、新增的 Web 启动不连接无关 Redis、配置快照无需 Redis，以及消息去重正常/重复/失败路径。全部一次通过，未重复上一阶段的全部测试，未调用真实模型。静态检查无新增问题，既有测试函数及断言保持不变，生产代码净减少 88 行。

服务器先修改并验证后重启部署；后端就绪及前端登录页为 200，受保护接口匿名访问为 401，安全响应头正常。配置和其他服务未改变。随后同步本地及 GitHub。

本阶段未改变去重规则、配置缓存、模型、记忆、RAG 或 Redis 的异步关闭错误处理；其余统一错误报告仍按后续实际调用链继续检查。总体优化目标保持进行中。
