# 记忆预算绑定实际 writer 配置（2026-10-16）

## 实际配置分裂

MemoryLlmConfig 已独立解析真实记忆客户端的 base_url/model，但最终完整请求和删除来源候选的 token 预算原先都读取全局聊天环境。聊天与后台记忆使用不同模型或地址时，实际请求与计数器可能不一致；只修最后的完整请求还会遗漏提前筛选来源的预算。

服务器在原代码中以独立真实 Flash tokenizer 验证：满足 MessageRequest 8000 字符上限的完整 7236 字符合成资料，实际正文 5889 token，错误通用估计 4070，窗口 5350 还须容纳输出及余量，但旧构建器仍接受。另一个 7836 字符完整数字资料也复现了误判。较早的大输入直接构建检查只是辅助诊断，未用作声称已通过 HTTP 验证的依据；实际记忆联动用例通过完整 MessageRequest 校验。

## 修改

把现有模型识别改为纯函数，增加 text_token_counter(provider, base_url, model)，只依据已经解析的连接选择计数函数。官方两模型使用既有固定 BPE；其他连接继续使用原本明确的通用估计。没有新增配置优先级、数据库查询、资产下载或计数时重新读取设置。

MemoryEnrichmentScheduler 构造时从自身 MemoryLlmConfig 选择一次计数器，显式传入完整模型消息与 source_erasure_selection.candidates；两处共用同一个来源。客户端和计数器随这一份配置保持一致，不受随后修改聊天环境影响。选择计数器时不读取资产，实际需要计数时仍执行严格加载与完整性检查，因此不改变明确关闭、source_only 或无需 token 预算的合法路径。

直接构建工具仍有实际测试和离线调用方，保留其原默认入口；在线 writer 显式传参。旧缺资产的记忆联动测试现在创建明确的真实 DeepSeek writer 配置，避免仅改变聊天环境却使用 unused/fixture writer。来源预算的直接测试也明确提供本地连接计数器，继续断言完整来源或整条遗漏，没有放宽有效预期。

## 定向验证

服务器 17 项测试通过，7.13 秒。新增六项验证：两模型的显式计数与独立真实 BPE 一致，随后切换聊天环境并使另一个模型资产缺失也不改变既有计数；实际本地 writer 在全局 DeepSeek 资产故障时仍完成一次真实保存；实际 Flash writer 拒绝错误通用估计本会接受的合法完整输入，保持原文且模型调用为零。

两项真实 SQLite 来源删除测试分别使用本地/Flash writer 与相冲突的聊天配置。来源候选与最终消息中只保留完整允许条目，过长来源整条遗漏并报告未覆盖；模型控制选择 pet 后实际只删除这一来源，其他来源及其完整正文和时间保留，没有新增结构化 claim。模型结果均为明确的合成控制，未宣称已做真实大模型语义验证。

11 项关联检查覆盖最终完整请求预算、合法长输入与历史、显式窗口关闭、两模型必要资产故障不可重试、原来源完整保留、直接来源筛选与正常实际删除，以及旧环境入口的真实 BPE 和模型切换。没有运行全量回归，也没有重跑上阶段所有错误或记忆重试测试。语法、差异和增量静态检查通过；付费模型调用为零。
