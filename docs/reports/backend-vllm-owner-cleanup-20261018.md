# 推理客户端所有权与显式生成依赖

日期：2026-10-18。基线：`80f63fd15cc6d8b613884f8882f1671da26c762d`。

## 问题与调整

整体检查了生成 API、模型管理器、共享 vLLM 客户端、应用生命周期、LoRA 状态入口和评测调用方。

共享适配层已经持有客户端及其创建、关闭锁，生成 API 又维护了第二份状态和锁。检索生成函数同时隐式读取 API 的全局客户端，使调用依赖和资源所有权分散。

- 客户端只由 `inference.vllm_client` 创建、缓存和关闭。API 保留启用配置及 HTTP 错误转换职责，删除重复缓存、初始化锁和关闭转发函数。
- 应用生命周期及真实回放工具直接调用适配层的关闭入口。
- 检索生成函数必须显式接收选定的 `model_generate`，云端及 vLLM 都从调用方传入；不再隐式读取全局模型。
- 本地可变适配器仍由一个明确的本地模型锁串行访问，删除按名称选择锁的分支。

三个生产文件净减少 **40 行**。未新增语义规则、回退模型、默认回答或生产防御分支。当前 DeepSeek 配置未改变。

## 测试整理

测试替身改为注入当前真实入口。删除只检查已退出 API 缓存状态的重复测试；并发复用和关闭后重建由实际共享客户端的生命周期测试覆盖，保留初始化失败、取消、健康检查失败及清理失败的业务检查。

补全旧测试缺少的前提：显式语义规划及已审核合成检索包、引用来源标识、引用审核响应、本地模型身份以及隔离 PostgreSQL 配置。模型替身和审核控制仅用于协议及传输契约测试，不作为真实语义质量证据。

旧 Web 用例把虚构引语的来源留存等同于个人事实写入。当前契约保留获准来源以便追溯，因此改为检查来源身份完整、**个人记忆记录为空**；拒绝记忆的输入仍检查来源不被保存。检索复用用例保留检索一次、证据传递和引用结果断言，并提供有效来源及完整审核响应。没有修改生产语义来迁就旧用例。
