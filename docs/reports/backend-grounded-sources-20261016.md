# 问答缓存与输出复核真实来源快照（2026-10-16）

## 修改前的实际证据

独立问答使用进程内加载的角色作品索引。通用知识库的 SQL revision 属于另一条链路，本阶段没有把它当作角色索引版本，也没有声称已支持热重建。实际可变依赖是每次检索都会重新读取的原作文件。

服务器基线 385aee1 上，用真实临时 card/scene/evidence 三分区向量文件、MultiScaleRagRuntime、RoutedMultiScaleService、OriginalTextExtractor 和默认 GroundedAnswerService 复现：完整两行合成原文首次生成成功并写缓存，随后只删除该原文件，同问仍缓存命中并返回旧成功；在同一实例明确关闭缓存后，同问立即抛 FileNotFoundError，模型调用总数仍为一。不是缺少领域、证据或模型前提的失败。

另一项受控交错在首次原文读取 A 后立即写入完整 B。旧检索返回 raw_excerpt=A、curated_source_catalog 的证明=B，实际提取发生两次。单纯给缓存增加证明校验仍会认可错误正文，因此必须同时消除重复读取。

所有源文件、日期、否定、条件及例外均为明确合成资料。embedding、排序和最终答复是本地控制，真实检索和来源处理未替换；没有加载模型资产或访问付费模型。

## 修改

原文摘录直接复用该 evidence 在来源目录中的同一份 excerpt。目录仍执行既有完整文件快照及前后读取一致性检查；不再另读一次原文形成 A/B 错配。可见性边界、缺少提取器的明确错误及完整片段限制保持原语义。

成功结果内部保留本次实际来源证明，字段不进入 repr。缓存命中、实际调用模型前和成功发布前共同复用既有 validate_curated_source；校验在线程中完成。SSE 正文原本会缓冲到引用等检查结束，现在也在发送最终正文 delta 前复核来源。

仅缓存命中时的 CuratedSourceChangedError 被解释为正常缓存未命中，重新检索、生成并在成功后更新原缓存键。未变来源仍正常复用缓存。文件不存在、权限/读取故障、非法证明和生成期间变化均直接传播，不使用旧答案、替换模型或伪造成功。

未提供文件来源目录的注入式文档服务继续使用原有缓存契约；已经提供目录却形状错误时明确失败，不把非法目录视作可选空依赖。没有新增配置、缓存框架、重试层或索引版本猜测。普通 API、引用白名单和 SSE 最终字段仍由原有明确映射构造，没有加入内部来源证明。

## 定向验证

服务器 47 项测试一次通过，4.14 秒。其中 9 项新增用例覆盖：未变来源缓存命中；相同路径和两行范围合法修订后真实未命中、完整新原文进入提示并再次可缓存；删除和仅目标源读取权限故障不得返回缓存成功及恢复；普通/SSE 模型执行时改源不能结束成功或写缓存；原文与证明读取交错失败；准备提示后改源在模型调用前失败；已提供但非法的目录不被当作空依赖。

新增用例实际写入三分区索引和完整原文，走真实 runtime、检索、文件提取、证据包、提示词、引用校验和缓存。控制的最终模型只有在完整日期、时段、否定及例外实际进入提示后才作答。普通和流式生成期间变化都只调用一次控制模型，流式没有正文 delta 或 done；恢复后能够重新成功。

其余 38 项直接关联检查覆盖可选依赖的正常与失败路径、无领域合法弃答、检索/生成/结构/引用故障、流式关闭与取消、HTTP 和 SSE 错误、精确缓存身份与过期、真实知识边界、原文身份及不可见来源。没有全量回归或重跑此前整个阶段；语法、差异及增量静态检查通过。

保留依赖 jieba 的三个转义提示及一个 pkg_resources 弃用提示。未执行 PostgreSQL、真实 DeepSeek 语义质量或吞吐评估，付费模型调用为零。本阶段确保来源快照和失败行为，不将来源存在性等同于索引声明已被独立验证，也不声称保证模型理解完全正确。
