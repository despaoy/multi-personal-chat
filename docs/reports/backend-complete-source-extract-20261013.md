# 原文提取只返回完整声明范围（2026-10-13）

## 问题与修改

OriginalTextExtractor.extract 原先把声明末行夹到文件长度、把行数夹到 max_lines，再按 max_chars 截断文本，返回 truncated=true。检索原文块没有完整传递该标记，末尾条件可能丢失；tighten_to_evidence 又会吞掉读取错误，使索引构建继续。

现在来源行号必须是有效整数范围；超过文件范围、行数上限或字符上限明确报错，要求修正声明范围或显式调整限制，不返回截断成功。配置也必须是合法整数，删除自动夹取。完整片段仍保留原文及精确行号，RawExcerpt 的兼容字段继续保留，正常提取不再产生 truncated=true。tighten_to_evidence 的读取异常传播，合法但无法精确匹配的证据只保留原批准范围，不扩大来源，也不声称已经匹配。生产代码净减少 5 行。
