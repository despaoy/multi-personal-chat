# 偏好数据读取不再掩盖损坏内容

基线：`86275f6a5ef3a4f98a82e23a30a05b8e82632a69`。审查偏好接口、数据库可空 TEXT 列、请求与前端对象契约，以及训练导出消费关系，再在服务器隔离数据库中复现。

## 问题与修改

列表接口捕获评分、元数据解析异常并替换为空对象，空字符串也被当作缺省值；合法 JSON 的数组、null 等非对象值会被成功返回。导出对评分采用另一套解析，错误结构仍可进入导出结果。六个入口的日志还直接输出异常文本，可能包含数据库参数或原始内容。

列表与导出共用一个对象解析函数：数据库 SQL NULL 代表可选字段未填写，保留原有空对象；其他值必须能解析为 JSON 对象。损坏文本或错误结构交给现有 HTTP 错误边界，返回失败并保留原始异常原因。没有新增错误类、重试或外部依赖，也未对历史记录重新套用创建请求的长度限制。

删除两处捕获后默认成功的逻辑、三处查询结果替换为空列表和一处计数缺省值；使用数据库现有返回契约。六个错误日志只记录操作及异常类型，不输出异常原文。生产代码净增 1 行。

## 验证

- 原生 SQLite、真实签名及管理员复核下，分别向评分和元数据写入损坏 JSON、空文本、数组、JSON null，共八种完整测试记录。修改前列表全部返回 200，修改后全部返回 500；评分导出相应场景也全部明确失败。
- 正常嵌套对象、SQL NULL、空对象和真实无记录共四组成功场景，列表、导出、空历史采样的完整响应 SHA-256 保持 `4fe1b8adec8a5db30243e782cd528fafcd89b9bb7c5f5f141978f40a1e9f3683`。JSON null 与 SQL NULL 的语义保持区分。
- 写入故障仍返回 500，原始异常对象保留在原因链中；合成私有标记从错误日志消失。匿名读取仍为 401。
- 仅运行数据库绑定、研究数据完整性和数据库兼容三个相关模块，54 项全部通过，其中新增 11 项覆盖上述失败、合法空值及错误日志行为，没有重跑全量回归。
- SQL 字面量未变；语法、名称检查、差异空白检查和服务器仓库完整性检查通过。
- 部署后后端就绪、前端登录页和本地两个映射均为 200；匿名受保护接口为 401 并保留响应头。运行配置及前端进程不变。

本阶段没有模型调用。未重跑 PostgreSQL 或前端构建：SQL、数据库结构、请求协议和前端代码未变，前一阶段已通过两种数据库的完整工作流验证。本阶段只验证存储 JSON 的对象边界，不声称完成所有历史训练样本或模型质量审核。
