# 重排器资源初始化收敛

基线：77f4430。

## 问题与修改

重排器将 tokenizer、model、已加载标记和已预热标记作为四份关联状态维护。加载过程中先发布半成品，失败再捕获异常清空资源；预热方法只有加载流程一个调用方。

现在在原有加载锁内用局部变量完成分词器加载、模型加载、设备设置、推理模式和可选预热，全部成功后才发布资源。以实际模型对象作为就绪依据，删除两个布尔标记、无消费者使用的布尔返回值、单独预热方法和异常清理包装。原始异常自然传播，后续请求可在资源修复后重新加载，不切换模型或设备。

一个生产文件净减少 18 行。并发加载锁、离线加载配置和显式设备选择保留；评分、排序、归一化及候选复制函数的 AST 均保持原样。

## 验证

- 七个直接相关测试文件共 120 项全部通过，无跳过，未重复全量回归。
- 并发首次使用仍仅加载一个分词器和模型；加载失败、预热失败保留原异常且不发布半成品，后续请求恢复路径通过。
- 删除仅检查旧布尔标记和返回值的断言，改为检查实际资源；预热测试额外检查真实夹具调用顺序及次数，原有失败、评分和输入保护断言保留。没有增加测试数量。
- 静态检查、仓库完整性和差异检查通过；后端重启就绪 200、前端登录页 200、受保护接口 401，配置不变。
