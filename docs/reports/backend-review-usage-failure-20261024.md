# 审核失败后保留实际用量记录

上一阶段隔离复现确认：上下文审核收到带 120 tokens 用量的模拟提供商响应后，结构解析失败，接口正确返回 503，但调用记录为零。用量收集已覆盖该调用，遗漏发生在记录时机：准备阶段及部分 RAG 错误未经过原有主生成记账路径。

本次在请求计量状态中加入“记录写入已经开始”的状态，复用现有数据库写入函数。准备、RAG 审核或取消离开请求时，只补记尚未开始写入的实际调用；写入开始前即标记，数据库超时或取消不触发第二次写入。保留原始异常；记账也失败时，同时保留原请求回执和记账错误。取消仍以取消结束。

成功路径同时覆盖已有审核、但直接返回存储结果的情况：在消息归档前记录审核用量，回复仍明确标记没有调用主生成。记账失败的回执也使用这一明确状态。模型调用前拒绝不创建计量；显式 record_invocation=False 仍跳过记录。未使用字符估算、固定零值或另一模型补齐数据。

生产代码净增加 31 行，包含请求自身的计量状态及错误记录衔接，没有新增审核环节或语义关键词规则。

## 验证

- 146 个不同的相关用例全部通过，无跳过；首次 69 项、关联 76 项，以及回执字段修改后的定向检查按最新用例结果去重汇总。没有重跑后端整体检查。
- 真实 OpenAI 兼容适配器配合隔离 HTTP 响应和实际 SQLite，确认审核后 JSON 解析失败仍记录准确的 100 输入、20 输出、120 合计 tokens，并保留原 503 及 JSONDecodeError。
- 覆盖 RAG 审核 HTTP 错误、仅审核直接返回、主生成失败、取消、记账关闭及模型调用前拒绝；没有凭空创建调用记录或将审核标记为主回复生成。
- 数据库写入失败只尝试一次，并保留原 HTTP 回执；超时写入稍后提交时最终仍只有一条记录。取消发生后记账失败也不会将取消改写为普通成功或 HTTP 响应。
- 原有并发及嵌套计量、后台任务隔离、部分与未知用量、数据库保存、模型身份、熔断及记忆操作测试通过。
- 静态检查、仓库完整性和差异检查通过。部署后就绪、登录和未登录受保护接口状态为 200、200、401；配置及前端进程保持一致。按内容哈希同步本地。

本轮没有真实模型请求，所有提供商响应均为完整合成测试输入；120 tokens 是复现及验证数据，不是实际付费消耗。此次仍针对普通生成入口中的已收集调用，独立问答、独立后台任务及其他尚未接入用量收集的提供商不构成全系统账单。上一轮完整检查发生在本次生产修改之前，不能写成当前版本重新通过了全部测试。
