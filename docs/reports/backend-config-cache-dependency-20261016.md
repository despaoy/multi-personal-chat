# 配置快照解除无关 Redis 依赖

本地基线：`b1bc04a0348c7720a1b2488fba26e851b03085d3`。继续按当前指示先本地优化。

## 实际问题

进程内配置快照模块同时保留了 3 个已无调用方的 Redis 知识库统计包装。读取模型配置或 API 配置时，模块导入也会加载 Redis，即使该读取只依赖当前数据库与本地快照。隔离子进程基线证明，无关 Redis 模块不可导入时，配置读取也被阻止。

引用核对进一步确认，7 个通用 Redis JSON/增删查包装只被上述死代码使用，或完全没有使用方；其中包含异常后返回空值、布尔值或 `-1` 的逻辑。

## 修改

配置模块只保留当前数据库的快照读取、失效及原有 TTL 抖动实现。删除 3 个无使用方的统计包装、7 个无使用方的 Redis 操作包装及其多余导入和常量。

机器人使用的 Redis 连接、连接池、关闭及健康检查仍由原模块提供。未引入替代缓存或假 Redis，没有改变正在使用的连接逻辑，也没有删除知识库统计接口。生产代码净减少 105 行。

## 定向验证

5 项不同用例通过：

- 隔离子进程明确禁止导入 Redis，正常配置读取、缓存命中、失效后重读仍成功。
- 返回的顶层快照可独立修改；数据库实例切换与显式失效不复用其他来源的缓存。
- 过期后数据库故障保留原异常，不返回旧快照、不自动重试；恢复后重新加载当前值。
- 错误数据库返回类型明确失败，不伪装空配置；修复来源后可重新读取。
- 既有生成入口的配置读取故障仍阻止模型和消息保存。

语法树比较确认：保留的 3 个配置函数与 7 个 Redis 连接/生命周期函数逻辑均与基线一致；被删除符号在项目 Python 调用方中已无引用。新测试 Ruff、生产文件语法和增量静态、补丁空白检查通过。

仅执行新增及必要关联检查，没有全量回归或付费请求。Redis 连接函数本阶段只核对代码等价，未连接真实服务；服务器同步待连接恢复。
