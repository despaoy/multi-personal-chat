# LoRA 请求保持所选提供商，读取故障不再回退（2026-10-14）

## 实际问题与修改

普通非 vLLM 请求发现本地 LoRA 路径时，旧代码直接配置 PEFT 并调用全局 ModelManager.set_provider，可能把用户已选择的 DeepSeek 等提供商永久改为本地推理，影响后续请求的模型、审核客户端和上下文预算。路径查找又捕获所有异常返回 None，可能把读取故障当成没有适配器继续使用基础模型。ModelManager.set_lora_adapter 也会在当前提供商不支持适配器时设置未选中的 PEFT 实例。

删除请求中的自动提供商切换，LoRA 选择先验证当前提供商的实际接口能力：现有 vLLM/transformers_peft 路径支持该请求字段，其他提供商返回明确 422，提示选择基础模型或显式选择支持 LoRA 的提供商。该检查先于角色准备及模型调用。远端兼容 API 已配置的 model 参数不变；本次只约束额外 LoRA 叠加请求，不改变远端模型本身。

显式本地提供商继续使用已注册适配器的路径，缺少可用目录返回 409，目录读取 OSError 保留原因并返回 503，均停止生成。目录查找保留容器注入列表、按名称与历史存储 ID 查找的实际约定，移除异常吞掉、陈旧注释及全仓无调用方的空 LORA_PATH_MAP 别名。

ModelManager 只向当前提供商的 setter 分发；当前提供商无此能力时，明确的适配器设置报错，基础模型的 None 清除操作正常返回，不触碰其他提供商。三份生产代码净减少 27 行，无新增意图规则、分类器、配置或降级框架。

## 定向验证

服务器共 17 项不同的直接相关测试通过。初跑 14 通过、3 失败、21 项其他测试未运行（1.39 秒）；三个失败来自新控制用例用 null 表示未指定适配器，而实际 MessageRequest.loraName 是默认空字符串。改用真实接口的空字符串后，只重跑三项，全部通过（1.01 秒）；生产协议和有效断言未修改，没有重跑已通过项或全量回归。

控制覆盖三个不支持额外 LoRA 的提供商各自的显式/激活选择，要求 422、目录查询/模型/回复保存均未调用、提供商未变、未配置隐藏的 PEFT。显式本地提供商分别覆盖有效路径、目录缺失与读取故障，验证正确 setter 只调用一次或完全不调用，原始 OSError 保留，错误时不生成、不保存。

管理器直接控制验证设置仅到当前提供商；目录扫描和数据库读取故障控制要求原始异常传播。关联既有四项原生提供商控制继续验证编译消息和明确输出额度传入所选提供商、不可用 vLLM 不改走本地模型；容器注入 LoRA 列表的路径查找继续通过。

部署前只读确认当前服务器为 openai_compat，激活 LoRA 数量为 0；当前 DeepSeek 基础模型请求不进入新增拒绝分支。未修改实际模型配置、激活记录、适配器目录、权重、凭据或用户数据。测试只使用隔离小文件和受控推理入口，不加载模型，不调用付费服务。

语法、增量静态与差异检查通过，无新增静态问题。此阶段完成所选提供商与适配器分发的边界清理；本地 PEFT 内部加载/量化/热切换及 vLLM 的能力探测仍按既有实现，未计为本阶段新验证。整体精简优化目标继续。
