# 回答缓存的共享锁范围收敛

基线：4ce86025b81644d83e281cf0f13880cdaa8839a6。

## 问题

沿知识问答入口、请求连接快照、检索、证据包、来源复核和回答缓存审查后，确认 AnswerCache 在共享锁内深复制完整回答。复制一条缓存记录时，其他键的读取也必须等待；写入前的复制同样持有锁。共享锁因此承担了与缓存索引维护无关的工作。

服务器复现使用三个真实索引分区、正式运行时、原文读取器、证据包、提示词、引用校验和默认缓存。虚构资料完整包含日期、时段、否定、条件及例外；嵌入、排序和模型输出是明确的测试控制。

先生成一次完整结果并确认缓存命中，再有意暂停其中一次快照复制。修改前，读和写两种情况下，无关键的读取均无法在释放复制操作前完成。这是受控并发证据，不是实际延迟或吞吐基准。

## 修改

读取在锁内取得缓存拥有的记录并维护过期、LRU 和命中计数，退出锁后复制快照。写入先完成复制，再进入锁提交记录并维护容量。缓存内部保存的对象继续独立于调用方，且不会原地修改。

没有增加锁、包装、配置、重试或防御分支；生产代码净行数不变。命中计数在取得有效条目时记录；后续复制异常仍直接抛出，不返回成功或旧数据。写入复制失败时不提交新值。

## 验证

- 133 项关联测试首次全部通过，覆盖回答、缓存、来源生命周期及知识问答请求上下文；原有断言全部保留，新增两个直接针对本次读写并发的案例。
- 相同真实 RAG 结果的原生前后对照：修改后，无关键读取能在暂停的读或写复制操作释放前完成，完整原文、引用及来源回执保持一致。
- 调用方修改返回结果或写入参数中的嵌套引用、原文回执，不会改变缓存持有的记录。
- 读写复制失败保留原异常对象，后续正常读取恢复；来源变更、来源 I/O 故障、过期、容量和 LRU 的既有用例继续通过。
- 缓存复用仍标记 cache_hit=true、model_invoked=false；每个原生场景只发生一次受控模型生成，没有真实模型费用，也没有将缓存响应标为新验证。
- 代码复核确认复制已完全移出锁，其他缓存方法、回答编排、来源校验、模型连接、检索及 API 代码未修改。Python 检查、仓库完整性和差异检查通过。
- 后端部署后就绪、前端登录为 200，受保护消息接口为 401；前端、其他服务和配置保持不变。

没有运行全量回归或前端构建。本阶段证明共享锁不再串行等待快照复制，未衡量生产环境的延迟收益，也不涉及真实模型理解质量。
