# 云端主答退出本地适配器锁（2026-10-15）

## 复现与根因

主答非 vLLM 分支先取得 LLM 并发容量，再用 local_model 锁包住适配器选择、检索和生成；OpenAI 兼容云端也走同一把锁。服务器隔离复现通过实际主答入口运行三个完整合成问题，容量为 2，但实际模型适配回调同时最多只有 1 个。模型回调使用明确测试控制，没有真实网络模型或业务数据读写。

## 修改与边界

只有当前 OpenAI 兼容云端分支使用标准库 nullcontext，跳过本地模型锁和无意义的清空本地适配器动作；保留既有并发 semaphore、排队超时、推理超时、取消及 finally 释放。不增加新锁、策略层、配置或重试，不改模型与数据库选择。

本地适配器选择和生成继续完整互斥，目录错误与缺失仍明确失败，避免不同角色的本地适配器在解码中被另一请求修改。进入本轮非 vLLM 分支时固定提供商类型，模型分派前若类型已变更则报错，不改用新提供商；模型调用完成后的类型标签使用本轮来源，避免管理员在生成期间切换类型导致回复被标成其他提供商。未增加关键词分流或未训练分类器。

## 定向验证

45 项首轮通过（1.73 秒），覆盖容量为 1 与 2 时的并发上限、无关本地锁不阻塞云端、两个本地适配器串行且解码期间选项不变、失败或取消释放容量且不重试、分派前提供商变更明确失败。关联检查覆盖原编译云端协议、缓存来源、LoRA 选择、推理超时及跨事件循环锁重建。

随后把两个容量用例改为事件屏障，避免依赖机器调度速度；新增生成期间切换提供商仍标记原类型的用例。只运行这 3 项，全部通过（0.92 秒）；其余已通过用例未重跑，最终相关用例 46 项有通过证据。没有放宽断言、重复全量回归或付费探针。

这些验证证明实际 API 调用链在控制条件下的容量、锁、释放和类型来源行为；原云端协议用例另使用隔离 HTTP transport。没有执行真实 DeepSeek 压测、吞吐收益测量或新的语义/RAG 质量验收，付费模型调用为零。没有验证运行中同提供商内部模型配置变更的精确版本归属，不把本轮类型固定描述为完整配置快照。

语法、增量静态和差异检查通过。服务器先修改和验证；部署只重启后端，要求就绪 200、配置及其他服务进程不变，再按哈希同步本地、服务器提交和 GitHub。整体后端精简及长期记忆/RAG/动态上下文优化目标仍在进行。
