# 长期记忆输出协议与失败回执

本阶段修复模型额外字段被忽略的问题。原先 `{memories: [], error: ...}` 会成为
正常无变化，带有有效候选及 `error` 的结果仍可能写入。服务器隔离复现确认了
这三种情况：空集合、有效集合附加字段、候选附加字段。

## 修改

- 顶层只接受 `memories` 和可选 `erase_source_ids`，候选只接受声明字段及仍在
  使用的时间别名。集合整体通过协议检查后，才进行业务筛选和持久化。
- JSON、集合、置信度、操作及文本类型检查使用具体的 `MemoryResponseError`。
  失败回执包含 `invalid_model_response` 和固定字段路径，不输出模型原文或
  模型提供的额外字段名；协议错误不可重试，也不切换模型或修改要求。
- 保留真实记录使用的数组和完整 JSON 围栏，合法空结果、低置信度不写入、
  来源删除授权、证据归属和生命周期语义保持不变。
- 两处旧测试补齐已经必需的 `attributed_to=user`，保留原有业务断言。

没有增加意图关键词规则、分类器、重试或响应修复器。后端产品代码净增 21 行，
用于一处协议字段定义、两处集合边界检查及可定位的错误回执。

## 验证

- 服务器直接相关测试共 **145 项通过**，未运行全量回归，未重复整组测试。
- 使用服务器实际记忆客户端及已有配置的 **DeepSeek Flash** 新调用 **2 次**：
  完整个人专业事实保存且关联原始来源；无个人事实的临时算术题合法无变化。
- 对上述一次真实响应进行额外字段故障注入：整体失败、零部分写入、回执
  不含输出原文。这是一次受控记录复用，不计为新的模型验证。
- 语法和定向静态检查通过。AST 对比确认业务证据、权限、持久化及生命周期
  函数保持原样；原有真实模型记录未改动。
- 已部署服务器，后端就绪与前端登录页均返回 200；配置及其他服务未改动。
  验证后按文件摘要同步本地。

两次合成抽查不能保证模型对所有自然语言输入的理解质量。本阶段只收紧已确认
存在的输出协议漏洞，没有改动历史数据，也没有回填旧记录。

模型原始交换、隔离数据库和故障注入原文仅留在服务器运行目录；本提交仅包含
源码、测试和本报告，不包含密钥、真实用户内容或运行数据。
