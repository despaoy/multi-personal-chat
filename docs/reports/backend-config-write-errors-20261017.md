# 设置保存失败状态与输出长度显示

基线：`e01963eabede766650069fc96b00a631248bc10f`。

## 问题与修改

普通设置保存原先只明确处理模型运行时刷新失败。隔离复现确认：写入已成功、最后读取保存结果失败时，仍直接抛出未分类异常，没有说明配置已经保存。

`backend/api/config.py` 现在对保存、缓存失效、必要的运行时刷新和结果读取统一报告安全的 503，以及对应 `stage` 和 `configPersisted`。确认写入成功时该字段为 `true`，写入开始但未取得确认时为 `null`，不会把可能已经写入的操作声称为“未保存”。原异常原因保留，没有自动重试、切换提供商或回退到旧配置。

两个设置入口共享实际重复的 JSON 解码边界，错误 JSON 返回 400；非对象配置及服务端接入令牌限制继续返回原有 422。配置字段校验、脱敏占位值过滤及成功响应保持原有行为。提供商失败提示改为说明用户应核对哪些状态，不在自然语言提示中展示 JSON 类型用语。

新增成功路径检查还发现了原有真实缺陷：脱敏关键词 `token` 把输出长度 `maxTokens` 当作凭据，返回 `****`，前端因而无法得到保存数值。修复只豁免这个现有公开数值字段，其他密钥、密码、令牌脱敏和服务端接入令牌隐藏保持不变；没有为通过测试修改原成功断言。

业务源码增加 28 行、删除 19 行，净增 9 行，无新依赖、通用策略框架或意图分类规则。
