# 记忆持久化契约：第十四阶段（2026-10-09）

## 问题与修改

调度器 `_persist_proposal` 与仓储 `append_claim/erase_memory` 各保留旧接口分支。旧 upsert/delete 无法完整表达版本链、待确认状态、生效时间和保留条目约束，部分缺失接口被报告为 skipped；没有有效持久化回执也可能被调度器统计为 saved。

检查实际调用链后确认：正式仓储只有 DatabaseCharacterMemoryRepository，SQLite 与 PostgreSQL 适配器均提供 append_character_memory_claim 和 erase_character_memories。旧分支主要服务于过期测试替身，不再需要生产兼容。

- 调度器直接调用 append_claim 和 erase_memory，删除旧 add_or_update_memory/delete_memory 分支及相关 skipped 特判。
- 仓储直接调用两个数据库的正式版本化写入与完整删除接口，删除第二层 legacy upsert/delete 降级。
- 写入结果要求显式 persisted 布尔值；False 是正常无变化，True 才增加已保存数量，缺失或非法值报告失败。
- 现有词面/模型写入测试替身改为正式仓储接口；原来验证未来变更不执行旧接口的测试继续保留权限断言，缺少正式接口现在明确抛错。

两个业务文件净减少 79 行，无新依赖或配置。保留独立使用的旧 CRUD 公共接口，未删除其调用方或历史数据；本阶段删除的是语义持久化链自动退回这些接口的行为。
