# 来源目录读取故障明确传播（2026-10-13）

## 问题与修改

实际链路是角色检索 → collect_curated_sources → 证据审核/回答。来源目录原先捕获 ValueError、OSError、UnicodeError，将实际读取失败改写为 unavailable 条目后继续。文件缺失、解码错误、完整提取超限及读取期间文件变化，因此可能被当作正常缺少证据。

删除这层异常吞掉分支，实际读取故障保留原因向上传播。正常没有对应可见证据、受知识边界限制或没有启用可选提取器时仍返回明确的 no_visible_source，不将缺少证据编造成事实。生产代码净减少 3 行，没有新增配置或处理层。

## 验证与限制

服务器 7 项直接相关测试通过（0.70 秒），37 项未受影响测试未运行。覆盖新鲜完整来源、不可见来源、文件缺失明确失败，以及解码、容量不足、读取期间修改在回答模型调用前失败；正常完整生成输入仍保留来源和限定条件。旧文件缺失测试改为要求原始异常，未删除错误输入或通过宽松断言让测试通过。

语法、差异检查通过，无新增静态问题。未运行全量回归，付费模型调用 0。不修改生产源文件或历史数据。该变化意味着普通检索附带来源目录审核时，实际源文件故障也会使请求失败，需修复源文件、索引声明或明确容量。

本阶段不改变已有有效证据在后续版本变化时的正常失效规则，也不宣称全部来源授权与并发路径已经完成审计。整体优化目标继续。
