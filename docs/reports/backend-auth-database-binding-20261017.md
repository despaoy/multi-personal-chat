# 认证数据库与应用容器一致

服务器隔离复现确认：生成接口已使用当前应用容器的数据库，注册、登录和
用户信息仍使用全局数据库。隔离库中真实存在的用户因此登录返回 401，
注册检查、写入和资料读取也可能访问错误的库。

## 修改

- 三个认证接口通过同一个请求依赖取得当前应用数据库，不再导入全局库。
- 生产首次注册的用户计数、重名检查及事务写入使用同一数据库。
- 缺少应用容器直接失败；计数查询缺少结果不能按零用户放行。
- 删除登录函数中只重新抛出原异常的冗余捕获。
- 密码散列和校验、JWT、Cookie、注销、注册锁、阻塞任务容量限制及数据库
  内的首次管理员事务保持原实现。现有用户信息响应语义没有在本阶段扩展。

产品代码净增 7 行，用一个请求依赖替代三处全局数据库访问，并明确失败。
没有增加配置项、模型调用、意图规则或兼容回退。

## 验证和部署

- 30 项直接相关检查全部通过，没有重复全量回归。
- 两个独立数据库用相同用户名及不同真实密码完成注册、错误密码拒绝、
  Cookie 登录、本人资料读取及退出；全局数据库访问被测试主动禁止。
- 生产首次注册使用当前库计数，后续注册仍被拒绝；无容器、数据库异常、
  缺失计数均明确失败。原有密码工作线程、数据库背压及并发事务检查通过。
- 静态检查、语法及差异检查通过，相关密码与令牌辅助函数逐一比较未改变。
- 已重启服务器后端；就绪检查及前端登录页均为 200，未登录访问用户资料
  和生成接口均为 401。运行配置和其他服务没有改变，再按摘要同步本地。
- 此阶段新增付费模型 HTTP 请求为 0，没有重测模型生成。隔离 Cookie 流程
  通过 ASGI 路由验证，未使用生产账号执行登录或向生产库创建测试用户。

隔离库、测试凭据和运行日志保留在服务器，不进入源码提交。
