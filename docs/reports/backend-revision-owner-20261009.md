# 知识版本管理旧入口清理（2026-10-09）

## 修改

删除已无生产调用方的 API `_mark_rebuild_dirty`。它曾在事务提交后再次维护持久化版本、重置本地标记并吞掉数据库异常；文档和容器业务已通过数据库原子事务维护版本，仅需本地缓存失效。

保留现行 `_invalidate_local_knowledge_index`、数据库版本事务及完成版本 CAS。更新锁说明，明确进程锁只保护本地状态，跨进程持久化一致性由数据库负责。

旧测试改为调用现行数据库版本接口与本地失效接口。原子发布测试继续禁止提交后单独的版本通知；替换为禁止数据库公开 mark_knowledge_index_dirty，以保留反重复提交约束。一个过期的进程锁阻塞测试改为真实双线程文档提交：重建暂停在完成提交前，另一线程独立提交文档，然后旧重建必须被数据库拒绝，最终保持 dirty。

## 验证

32 项相关测试最终通过。首轮 31 passed、1 failed：旧向量替身缺少当前重建接口的锁和 flush。补齐后仅重跑该项，1 passed（1.14 秒）；原断言保留，并增加必须实际重建的断言。没有放宽失败条件。

测试使用临时真实 SQLite，包括真实线程及文档事务；索引使用明确替身。没有调用模型或运行全部回归。精简旧线程同步过程不等于降低业务要求：保留的是旧索引完成操作不能覆盖新版本这一现行一致性契约，不再要求数据库提交被无关的进程缓存锁阻塞。

数据库其他写入接口和跨进程性能不属于本阶段新验证范围。部署、增量规范及版本同步记录保存在服务器本阶段备份目录，不提交运行数据和私有原文。
