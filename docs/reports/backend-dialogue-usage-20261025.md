# 训练对话生成的批次职责与实际用量

基线为 `186693b334e0285e54c3e6c420848dedb325dfd6`。本阶段审视平台入口与独立生成调用，确认AstrBot正常消息已有调用记录；训练对话生成仍在所选提供商返回后直接发布批次，没有收集或保存实际用量。旧NoneBot工具入口另有显式关闭记录的实现，留待其实际交付及模型选择边界一起审查，没有将研究调用一律开启计量。

## 职责与行为

轮次分布、场景轮转、批次规格、完整提示构建与输出解析集中在training/dialogue_generation.py。API负责请求和数据库归属、任务生命周期、取消、进度及HTTP回执；原有提供商快照继续贯穿研究和全部批次，不读取中途切换后的默认模型。

批次规格只保存轮次与场景，数量和输出上限从它们派生；计划只保留有限轮次目标，按需生成批次，不提前展开所有将来任务。总批数与实际迭代使用同一计划，删除最初按20组估算、随后按6组重新计算的两套来源，以及嵌套循环中的重复取消检查。80组任务在资料搜索期间就显示准确的16批。

每批复用已有account_usage收集并确认提供商计数，purpose为dialogue_generation。确认后才把该批加入结果和进度；模型、格式或记录失败均终止，不以空批次、较少数量或另一模型补齐。先前已验证并确认的批次通过原有partial_result保留。取消保留已确认数据，进行中的未知计数为NULL；缓存、模拟输出或字符长度不会冒充实测。记录归属当前应用数据库，每批有独立traceId，同一任务共享会话标识。

训练API的生成编排从248行减至125行；业务源码整体净增加28行，包含计量和职责映射。没有新增模型调用、配置开关、语义关键词或分类器，也未修改批次分布或模型提示语义。
