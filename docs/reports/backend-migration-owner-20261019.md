# 迁移事务故障立即终止，计数反映实际结果

基线：`2d3e3148b9ae76ffea680b96ae7b9255752768d2`。范围为独立 SQLite → PostgreSQL 迁移命令及其行为测试，没有执行业务数据库迁移。

## 问题与修改

原逐行迁移捕获所有异常，事务失效时回滚整批后继续处理，但没有撤销此前累计的插入数量。真实连接中断后可能报告插入两行，数据库实际只剩一行。错误日志还会直接格式化数据库异常，将 SQL 参数带入日志。

现在只对明确的 IntegrityError/DataError 保留逐行 SAVEPOINT 隔离和失败计数；行数据被拒绝时仍可处理其余行，整个命令保留失败的非零退出语义。连接、事务、SQL 或其他意外故障直接传播，不回滚重建后继续，不返回错误的完成数量。日志只记录行号与异常类型，省去数据库参数。

迁移主入口用标准资源作用域关闭只读 SQLite 连接，并通过 finally 关闭 PostgreSQL；读取、逐行迁移或序列同步失败也释放资源。字段映射的复制语义、正常冲突处理、序列同步及其他辅助函数保持不变。生产代码净减少 35 行，没有增加包装层、重试或配置。

## 验证与测试精简

- 19 项迁移行为测试首次全部通过，包含新增的 6 项约束类型、致命错误停止和资源释放检查；所有原有行为断言经 AST 核对保留。旧夹具用 RuntimeError 模拟数据库重名，已改为真实的约束异常类型，原有插入/失败计数断言不变。
- 删除 36 行依赖导入失败后自动替换模拟数据库模块的测试设置，并删除两个未使用导入。测试依赖缺失将明确失败；需要的故障通过具体边界显式注入。新增有效行为检查后测试文件净增加 27 行。
- 新建隔离 PostgreSQL，执行正常来源、单行约束失败和真实连接失效三组观察，以及恢复后的完整重跑。正常与逐行约束结果保持一致。连接失效时，改前返回 `(2, 1)`、实际只有第三行；改后抛出原 OperationalError、只尝试前两行、没有提交记录，恢复后完整写入三行。
- 实际带来源参数的行约束异常改前会将合成标记写入日志，改后不再出现。静态检查首次发现两个未使用测试导入，清理后静态、差异和服务器仓库完整性检查通过，没有重复已通过的行为测试。
- 服务器前后端就绪/登录为 200，受保护接口为 401/nosniff，配置及所有现有服务进程不变。此文件只由离线命令使用，因此没有重启无关后端。
