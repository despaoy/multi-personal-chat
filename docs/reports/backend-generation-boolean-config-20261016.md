## 实际问题

生成入口、缓存准入和缓存标识分别用普通真假判断解释 `useKnowledgeBase`，字符串 `"false"` 会被当作开启。引用开关用字符串集合解释，任何未识别拼写都会悄悄变成关闭；独立任务开关另有一套仅识别 `true` 的判断。

通过真实共享生成入口、显式模型替身和完整请求上下文复现：引用开关填入非法值时没有报错，模型仍继续生成。

## 修改

三处知识库判断、引用开关和独立任务开关统一调用已有 `read_bool`，采用相同的明确布尔表示。缓存标识依据实际布尔含义计算；非法值指出配置名并报错，不显示原始值。

独立任务配置在检索之前解释，避免错误配置先执行审核或检索。默认值保持原设定，显式的全局禁用检索仍优先。生产代码净减少 3 行，没有新增配置解析层、重试、模型或数据库调用。
