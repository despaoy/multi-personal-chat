# 知识库路由只使用当前数据库身份（2026-10-13）

## 实际问题与修改

聊天链路的分类器返回知识库名称后，_resolve_kb_id 曾在全局路径优先读取训练时保存的名称→ID 映射；注入数据库及全局数据库读取异常都被吞掉并返回 None。调用方因此可能撤去知识库过滤继续检索，或使用已过期的 ID。

路由现在只使用本次请求的数据库，未注入时使用当前全局数据库。SQLite 和 PostgreSQL 增加同一语义的按唯一名称查询，直接读取当前身份，不再为路由加载全部知识库的文档/文件夹统计。删除训练映射读取器、两个重复查询分支、异常吞掉及取消过滤的 None 分支。

分类器已经选中的名称在当前数据库缺失时抛出 LookupError，说明应刷新分类器或恢复知识库；实际数据库错误原样传播。现有聊天统一处理返回 HTTP 503，停止检索与回答。正常存在的空库或查询无匹配仍可以明确说明没有资料，分类器没有选择具体库时仍允许既有通用查询。

训练保存的名称→ID 已没有运行时使用方，同时删掉生成该状态的数据库列表查询、函数参数和新模型配置字段。分类器继续预测名称，旧训练文件与模型权重不修改，已有旧字段不再参与检索身份决策。生产代码净减少 43 行，没有新增配置、依赖或处理层。

## 验证与限制

服务器 14 项定向测试全部通过（1.97 秒）；22 项无关测试未运行。包含真实 SQLite 的改名后精确名称查询、含引号名称的参数绑定、旧名称失效、真实旧训练映射文件不得覆盖当前 ID，以及全局/注入路径的有效空库、选中库删除、数据库读取失败、无选中库四组 API 用例。错误用例要求 HTTP 503、原始原因保留、检索/回答调用均为零；其他库的完整虚构文档保持不变。

PostgreSQL 查询及 SyncPgAdapter 的命中、无匹配和故障三项通过，验证绑定参数、同步传播以及会话/适配器资源释放；使用明确的隔离会话控制，未连接真实 PostgreSQL 服务。原有数据库方法和管理端列表统计保持不变，没有数据库迁移或生产数据修改。
