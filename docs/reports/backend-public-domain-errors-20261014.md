# 独立公共检索分支不再吞掉故障（2026-10-14）

## 实际问题与修改

聊天的 _retrieve_rag_bundle 在混合角色原作与业务知识库，或已知业务对象伴随未解任务时调用 retrieve_domains。原先它捕获每个分支的任意异常，返回 status=unavailable 和空 bundle，再继续另一分支；上层可能生成看似正常的部分回答，将模型/索引/读取故障当成普通无证据。

删除分支 try/except，必要分支失败立即传播，后续分支、证据审核和回答不再继续。无效分支返回值在已有边界直接抛出 TypeError，指出具体来源类别和字典协议要求。生产代码净减少 3 行，没有新增规则、错误框架、配置、重试或降级。

正常检索成功但没有可靠候选仍是合法业务结果；角色分支正常弃答不抹掉独立业务资料。来源身份、完整问题、否定、例外、来源碰撞与最终证据可见性检查保持。历史 unavailable 记录的只读解释保留；当前检索不再通过故障制造这类记录。

## 定向验证

服务器 25 项不同的直接相关测试通过。初次运行 23 通过、2 失败（3.21 秒）；只重跑校正后的两项超时测试，通过（2.67 秒），未重跑已通过项或全量回归。静态、语法、差异检查通过，无新增静态问题；付费模型请求 0。

六组分支控制分别覆盖两个来源类别的提供商异常、超时和非字典返回，要求停止后续分支且不返回部分成功。四组真实聊天入口验证实际语义计划解析、问题对象绑定、线程检索、统一 HTTP 503 处理：两个来源分别提供商故障/超时，确认审核和回答均未调用，计划与完整问题绑定各执行一次。

超时测试最初额外要求异常对象身份不变；服务器 Python 3.12 的 asyncio 标准库会把线程 Future 的 TimeoutError 转换为同类型的新实例。只读核对标准库后，测试改为严格验证原始类型与完整 args，同时保留 HTTP 503、完整问题、分支调用顺序和禁止后续调用断言；普通异常仍验证同一实例。没有修改生产逻辑来规避标准库行为，也没有接受模糊异常结果。

成功控制继续核对混合检索原生来源编号、原作非血缘限定、业务否定与末尾例外、正常角色无结果时的业务原文、索引版本、来源碰撞拒绝和不可伪造的最终证据归属。公共领域测试复用一份完整服务配置，避免为新失败用例重复搭建同样的检索环境；隔离测试显式禁止意外调用真实审核提供商。

未修改生产资料、索引、用户数据、运行配置或凭据。没有进行新的真实模型质量评测；本阶段验证检索故障不伪装为成功。整体后端精简目标继续，当前意图仍由已配置 DeepSeek 语义模型处理，分类器待用户训练后另行接入。
