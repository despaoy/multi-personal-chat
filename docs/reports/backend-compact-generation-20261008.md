# 生成链路精简：第二阶段（2026-10-08）

基线 e2dac89792dd82d3d92d459c8c977f21bfb5807e。服务器先修改和验证，再同步本地、GitHub。

## 已核实的调用链

API/ChatGenerationService 完成身份、请求与历史处理后进入 `_generate_reply_impl`；生成主体读取配置与角色映射、准备上下文，再按提供商调用 vLLM 或模型管理器。两者共用 `_generate_with_retrieval` → `generate_character_response` 的上下文构建与证据约束。生成完成后保存消息，按保存及投递状态决定记忆回写，随后构造响应与写缓存。

原先两个入口分别复制消息保存、投递快照、记忆回写、警告持久化、响应构造和缓存写入，存在维护不一致风险。上阶段删除固定回复兜底后，`generationError` 分支已没有生产者。配置读取异常还会吞错并换用默认值。

## 修改

合并两个入口的公共收尾流程，保留各自模型显示名称与持久化标签；删除失效的 `generationError` 状态判断、`fallback_*` 中间状态及重复错误出口。`generate.py` 净减少 176 行，不新增抽象层、依赖或配置项。

生成配置读取失败返回 HTTP 503，保留原因；模型管理器的调用即使没有熔断器也受现有超时限制，取消后释放并发许可。确定性业务结果不记录为模型调用。

## 验证

共 57 个不同的定向测试节点通过。覆盖两种生成入口、内部调用不持久化、确定性回复来源、注入数据库、消息保存回执、记忆回写容量、SQLite 与隔离 PostgreSQL，以及配置读取失败、超时取消和资源释放。仅重测失败或修改直接影响节点，没有运行全量回归。

初次运行中 6 个 PostgreSQL 节点缺少专用库配置；补齐现有隔离库后通过。旧 vLLM 不可用后回退的预期按已明确的新错误契约更新。旧保存夹具补齐已有的 `saved_receipt` 参数，不更改原数据库贯穿断言。

按同一 Ruff 配置比较基线与修改文件，无新增问题。未进行付费模型调用；这些定向模拟测试不构成真实模型质量证明。
