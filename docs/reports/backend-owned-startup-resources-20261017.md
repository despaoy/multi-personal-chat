# 必要资源启动与退出清理

本阶段修复必要资源初始化失败仍继续启动、启动后段失败跳过清理，以及缺少 SQLite 路径时猜测另一数据库的问题。服务器先修改、隔离验证，再部署和同步本地。

- 资源池、备份、访问控制、加密及熔断组件直接作为必要依赖导入，删除五个自动停用标记。初始化错误保留原始原因并阻止服务启动。
- 生命周期保护覆盖启动过程，后续失败仍释放已分配的池和备份调度器。PostgreSQL 保持自身适配器的关闭流程，不创建 SQLite 资源。
- SQLite 池和备份共享容器数据库的实际路径；相对备份目录仍相对数据库目录解析。缺少数据库路径直接报错。
- 关闭时只释放已创建的模型管理器，避免为关闭操作新建实例。删除未使用的 GPU 总显存查询，保留可用显存判断。
- 管理接口的正常能力字段保持原格式。删除两个已无用途的测试开关，补齐旧启动测试的应用状态和容器前提；既有业务断言保持不变。

70 项定向测试一次通过，包括必要导入失败、不同启动阶段失败后的资源清理、SQLite/ PostgreSQL 正常生命周期、配置隔离、凭据加载及管理接口。未重复全量回归，真实模型调用为 0。修改文件静态检查无新增问题，同时清除此前记录的 7 项问题。生产代码净减少 80 行。

服务器已重启并验证：后端就绪和前端登录页均为 200，匿名访问受保护接口为 401，安全响应头正常；运行配置与其他服务进程未变。

范围限制：本阶段未修改模型、长期记忆或检索策略；Redis 可选行为以及关闭失败的统一报告仍需独立梳理。SQLite 数据库对象的线程局部连接生命周期保持原有设计，不能将池清理等同于所有数据库连接已关闭。总体优化目标继续进行。
