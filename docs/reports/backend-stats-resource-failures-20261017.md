# 资源采集与告警配置的明确失败

日期：2026-10-17。基线：`4b8ddbcfc36687aa539f39e52d8b0ad87ac466bd`。

## 问题与修改

隔离复现确认：GPU 两条采集路径都失败时仍返回零值，磁盘读取失败也填零；负资源缓存时间被强制改成零；NaN 告警阈值静默抑制告警，负计数阈值则会产生无真实失败的告警。

服务器检查发现没有安装 NVML Python 包，已有的 `nvidia-smi` 能正常读取一张 GPU。统计采集直接采用该工具作为唯一来源，删除 NVML、命令行和填零之间的切换，不新增依赖。保留首张 GPU 的原有统计范围；成功查询得到空列表才表示没有设备。命令失败、超时、无效结构及不可能的数值均报错。

磁盘使用绝对系统根路径并直接传播读取失败。资源边界统一返回带环节和异常类型的安全 HTTP 503，保留原始异常原因，不输出原始错误内容；请求取消保持取消语义。缓存仅在完整采集成功后更新，过期后失败不能使用旧值。数据统计、活动、告警和服务状态接口仍可独立使用。

新增共享的非负整数、有限非负浮点数读取器及具名配置错误，缓存和告警设置在使用前验证。队列比例限制在 0 到 1，其他阈值拒绝负数、非有限值及错误类型。缺失配置保留正常默认值；零缓存时间仍表示不缓存，零阈值仍立即触发。错误明确指出配置项和约束，不记录其原始值。公开示例补全已有告警设置说明。

生产代码增加 91 行、删除 69 行，净增加 22 行；新增部分用于共享校验与安全错误信息，没有增加通用监测框架。
