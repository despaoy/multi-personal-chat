# 对话生成失败时保留已完成批次

基线：`855aff2f99dcd126d2ae439fc5b85de5cea86aae`。用户确认服务器稍后恢复连接，并明确授权先在本地修改。

## 问题与修改

生成请求可能在第一次进度轮询前完成首批、再因下一批格式错误或模型异常失败。原接口只返回错误及数量，页面结束轮询后无法取得完整对话。

- 错误响应保持原来的非成功状态码、原因和异常链；有已完成批次时，附上当前任务局部已验证列表、数量及已知耗时。未通过校验的批次不发布，不读取可能属于后续任务的全局进度，不自动重试。
- API 客户端保留结构化错误状态及详情；错误有 `message` 时只用它构造提示，避免整批对话进入错误文案。既有字符串、校验数组及非 JSON 错误继续明确失败。
- 生成页面在失败时接收已完成结果，再显示错误并结束当前请求；不把失败标记成功。日志只记录错误文案。已有取消、任务归属和自动保存流程沿用。
