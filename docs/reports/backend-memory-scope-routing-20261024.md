# 移除记忆范围的词面筛选

从正式应用入口执行隔离真实链路时发现：用户完整说明两项事实，并明确允许在以后与指定角色的所有会话中使用，后台保存了事实，却只保存为 conversation 范围。另一个没有旧历史的会话因此读不到这些记忆。

根因是模型调用前的词面候选筛选。两个正则只识别有限的跨会话、跨角色措辞；未命中时，语义授权审核直接跳过，提议模型也只能选择 conversation。这次输入没有缺少事实或授权，问题发生在后端收窄了模型可见的操作范围。

## 修改

删除两个范围正则和候选筛选函数。先让提议模型依据完整原话选择记忆范围，再在执行跨会话或跨角色操作前，对实际请求的范围进行语义授权核验。正常会话范围提议不增加审核调用。未获授权、审核不确定或模型结构错误时明确失败，不把扩大范围的提议改存为 conversation。

当前原文绑定、连续引文、事实归属、否定、旧目标、事务及来源有效性校验保留。候选集合的结构校验移至已有 JSON 解码边界，供请求范围审核和事实解析共用；同一响应仍只解码一次。离线实验已有的预审入口继续使用完整原话，默认审核两个跨范围选项，不再依赖措辞筛选。业务代码净减少 7 行，没有新增语义关键词规则或分类器。

## 验证

- 58 个直接相关测试文件共 990 项通过；另补查未包含在首组中的 19 个解析关联文件，348 项通过。合计 1,338 个不同案例通过，无跳过，未重跑全部后端回归。
- 两项新增真实 SQLite 用例覆盖原先不命中词面模板的角色与全局范围表达，检查提议、授权、保存及另一个会话读取。原有未授权整批拒绝、引用不能授权、错误原文、结构错误、范围限制和暂时故障重试断言保留。
- 原始真实复现使用当前 DeepSeek Flash，5 次请求均成功，共 7,133 tokens；两项事实实际保存在 conversation，跨会话检查失败。
- 修改后在新隔离库发送相同完整资料，执行全新请求与响应。普通用户经实际注册、登录及鉴权进入正式生成队列，模型实际提取并将两项事实保存为 user_character，完整原话保留，没有预置记忆。
- 第二轮使用同一用户的独立群聊会话范围，服务端历史为零，实际选中了两项记忆，保留专业、研究方向及否定，结合作品原文回答人物关系。检索返回三项资料、两个引用；回答区分个人记录与原作人物，核对的完整引语及说话人与原文一致。返回 partial_source_context 提示，不能据此推断整个作品资料均已覆盖。
- 两轮请求及回复均实际归档；客户端伪造的身份被正式入口替换为登录用户；队列 submitted/completed 均为 2，failed 为 0；注销后身份接口返回 401。修改后共 14 次真实 DeepSeek 请求、67,154 tokens。全阶段 19 次、74,287 tokens，未推断人民币费用。
- 静态、语法、仓库完整性、源码哈希和差异检查通过。服务器部署后就绪及登录页返回 200，未登录受保护接口返回 401；生产配置及前端进程保持一致，随后按哈希同步本地。

## 仍需处理

模型在首轮回复中仍错误声称自己没有长期记忆权限，而后台实际完成了受授权写入。这是本轮人工复核发现的能力表述问题，不因机制检查通过而视为解决；后续应让回答依据真实的平台能力和写入阶段表述，不能用固定成功答复掩盖未完成的保存。

当前私聊长期记忆与历史按稳定用户身份归属，新建前端会话仍可能读到该用户私聊历史。因此本次使用独立群聊范围验证无旧历史时的跨范围读取，没有更改私聊语义。测试通过实际 ASGI 请求及应用生命周期执行，没有验证真实浏览器、网络代理或界面显示。所有数据与写入均在隔离数据库，应用配置取自在线 PostgreSQL 的只读快照；请求、响应和原文证据留在服务器运行目录，没有提交源码仓库。
