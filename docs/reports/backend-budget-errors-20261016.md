# 区分输入完整性错误与预算不足

日期：2026-10-16。基线：`52c681b44ef4cc5ee9b82527e78ab4ea7b653d5d`。

审计主聊天的语义依赖规划 → 问题绑定 → 检索证据 → 统一生成请求链。问题绑定的入参构造会检查完整原问题、依赖及逐字义务分区，也会检查历史整轮预算；旧实现把这一段全部 ValueError 改标为容量不足。服务器隔离预检使用真实 parser 先验证完整输入，再分别损坏 query 绑定和义务原文，两者均被误报 QuestionBindingCapacityError，原因为普通 ValueError，且没有模型调用。

现在复用已有 InputBudgetError，仅将真实历史预算不足包装为既有 QuestionBindingCapacityError；原问题、任务分区、历史形状等完整性错误保留具体错误。模型交换后的响应解析错误仍按原有审核错误处理，不改变该边界。

统一生成请求的普通、分支和纠正重试固定输入溢出也使用同一个预算类型，保留原错误文案及 ValueError 继承兼容。整包证据筛选仅捕获该类型，删除两条错误文案的匹配集合，其他错误直接传播。分支资料追加后统一计算一次固定输入成本，删除重复计算；不新增异常类、配置、策略或补救模型调用。已有输入预算类型的说明调整为所有必须完整保留的数据输入。

服务器 11 项定向检查通过（1.60 秒）：新增 5 项覆盖两类完整性错误、真实历史整轮容量及其类型化原因、普通和分支完整输入溢出；既有整包证据/引用筛选及背景依赖 3 项、问题绑定正常历史来源 1 项、实际 wire 容量不足 1 项、纠正重试溢出 1 项。最后一项使用项目已有 DeepSeek 离线 BPE 数据，保留不得发起第二次请求的有效断言，并加强预算异常类型要求。没有重复全量回归或放宽输入/证据要求。

语法、增量静态及差异检查通过后仅重启后端，检查就绪、原配置与其他服务，再按 SHA 同步本地、服务器 Git 和 GitHub。预检及测试均未调用真实模型，不提交密钥、运行数据或私有对话；不将构造与错误边界测试当作真实模型语义质量证明。
