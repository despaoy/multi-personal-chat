# 无效向量在缓存和检索边界明确失败（2026-10-16）

## 实际问题

服务器原代码通过实际角色索引、完整关系问题和隔离编码输出复现：NaN 查询的向量通道返回空，但 hybrid 仍返回 3 项；全零和 768 元素的错误维度查询在 vector/hybrid 都返回 3 项。错误维度被矩阵实现重塑成两条查询，而上层只读取第一条。NaN 模型输出还会被写入查询缓存，编码器恢复后仍复用坏结果。

这属于编码或检索失败，不能当成正常无匹配。真实在线链为生成入口、角色运行时、HybridRetriever、DomainIndex；已有生成边界会把传播上来的检索异常报告为 503，不需要新增包装层或意图规则。

## 修改

从既有 normalized_vector 提取共享 vector_norm：校验有限值及正且有限的范数。原归一化接口保留 float32 转换、展平、异常和结果契约。索引查询核对实际索引维度并调用这一校验，保留输入幅度、原始内积和阈值行为，不在索引层重新归一化。

本地角色编码器保留原有 Torch 池化与归一化，对完整返回矩阵核对行数和列数，再逐行调用共享校验。坏输出在 embed_texts 返回前失败，因此不会进入查询缓存，也不会作为正常批量结果用于构建索引。继续保留显式 sparse、空索引、非正 top_k 和真实阈值无匹配语义。

没有新增模型、分类器、关键词判断、自动重试或降级路径。生产代码只改动三个相关文件，共用一处数值校验。

## 验证

服务器执行 54 项定向测试，全部通过，238.62 秒；没有重复运行已通过用例。覆盖 NaN、正负无穷、零范数、范数溢出、错误查询维度经 vector/hybrid/runtime 传播；真实池化路径的错误行列数、失败不缓存及下一次恢复；健康批次、空输入、缓存副本/淘汰/并发、原始内积分数与阈值，以及共用归一化函数的记忆读写和缓存行为。没有运行全量回归。

旧 RAG 测试替身使用 test-384 模型标识，与现有真实索引清单不符；改为保留编码器身份，仅隔离查询编码函数并显式提供测试模型路径。新增模型输出用例只替换 tokenizer/model 输出，实际执行池化、归一化、校验和缓存代码，没有绕过 embed_texts。测试明确为隔离控制，不代表新的真实模型语义验证。

语法、增量静态及差异检查通过，独立只读审查未发现明确问题。测试有 4 项来自 jieba/其依赖的既有警告。初次测试观察连接在 120 秒到期，原进程继续运行；读取原日志确认全部通过，没有重新启动测试。没有付费模型或外部 HTTP 模型请求，未执行新的 DeepSeek 语义质量和真实吞吐验收。
