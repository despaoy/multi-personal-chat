# 通用知识分块保留原文并遵守大小限制

基线：`e3b5006b6b04a776b9100845bb928ada879ba848`。复核文档创建、修改、ZIP、目录及子目录导入到 SQLite 分块、FAISS/BM25 索引的完整调用链后，只修改共享分块器。

## 问题与修改

原实现把段落或句子 strip 后以空格重新拼接，检索分块不再是原文片段；合并长度没有计入插入的空格。超过预算的长句没有可靠切断，叠加重叠部分后仍可能超过 chunk_size。按末尾两句重建重叠的两段代码重复，而且不能保证配置的重叠长度。引号计数也没有覆盖同字符引号的实际边界。

新实现用原文切片输出结果，在窗口后半部优先选择段落、其次句末边界，没有合适边界时按明确大小切片。边界位置一次扫描、二分定位；不 trim、不拼接额外字符、不推断语义。每块不超过字符预算，相邻块精确重叠，末块覆盖文档结尾；空白文档仍不产生索引块。非法预算明确失败，不夹到其他值。默认 600 字符、100 字符重叠保持不变。

实现由 94 行减少为 37 行，净减少 57 行。已有 API 和评测仍通过 simple_text_split 别名共享同一实现，没有增加服务层、重试或分类规则。

## 验证

- 62 项相关测试首次全部通过：新增 30 项分块契约和五入口发布/索引检查，其余为直接关联的原子发布和文档契约。既有测试、预期和断言没有修改。
- 五个发布入口、三种完整合成来源共 15 组真实 SQLite/FAISS 隔离观察。修改前只有 5 组满足块大小限制，没有一组能按配置重叠还原完整原文；修改后 15 组全部满足大小限制、连续原文切片、精确重叠与完整覆盖。
- 文档正文和知识库、文档归属保持一致；实际索引保留既有的路径及标题前缀，前缀后的内容准确来自已保存分块。向量编码使用明确的受控实现，没有模型下载或付费模型调用。
- Python 基础静态检查、差异检查及服务器仓库完整性检查通过；部署后后端就绪、前端登录均为 200，受保护接口为 401 并保留 nosniff。配置及其他服务进程未改变。

## 影响与限制

改变的是以后创建、修改或导入文档的分块内容，已有文档及其持久化分块没有迁移。原始字符保真和预算优先于超长引文的完整性；预算按字符计算，不能等同模型 token 限制。此阶段没有验证真实模型回答质量、PostgreSQL 或旧命令行导入器的整体行为，也没有重复全量回归或前端构建。

初始观察脚本因临时目录中的旧测试模块遮蔽当前模块、以及未计入既有索引标题前缀而中止；修正观察环境与契约后取得上述完整改前记录。这两次脚本问题未计为产品故障或有效对照结果。
