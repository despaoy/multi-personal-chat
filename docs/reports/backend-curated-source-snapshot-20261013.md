# 来源摘录与哈希使用同一快照（2026-10-13）

## 问题与修改

角色检索来源目录和生成前来源复核原先各读文件三次：读取哈希快照、由提取器另读摘录、再读取检查文件变化。中间读取的内容可能不同于首尾内容，导致来源哈希与摘录不一致，也增加了重复读取。

OriginalTextExtractor.extract 接受调用方已经读取的字节，来源目录与最终复核从该快照提取完整声明范围；独立调用仍读取实际文件。保留首尾一致性检查，每个阶段由三次读取减为两次。移除不再使用的读取包装。生产代码净减少 4 行，没有新增配置、依赖或降级分支。

定向测试还发现，来源被缩短后，完整提取的行号错误会早于来源版本检查出现，阻止旧证据按已有规则失效。最终复核现在先比较文件哈希，已变化的来源直接返回明确的来源变更错误，由现有逻辑移除失效证据及依赖它的场景摘要；其他独立证据保留。删掉最终条件中重复的正文哈希计算，入口已经验证该哈希，最终还要求摘录完全相等。真实读取故障和不合法收据继续向上传播。

## 验证与限制

首轮服务器定向测试 34 项通过、1 项失败（0.98 秒），失败暴露上述来源缩短时的校验顺序问题。修复后只运行来源复核直接相关的 8 项，全部通过（0.68 秒）；没有重复运行完整回归。

验证包括：完整提取的类型及容量约束、目录读取故障、提取期间原文暂时改变后恢复时摘录仍对应原哈希、复核后来源变化、共享场景去除失效来源、部分证据不得复用整组范围，以及独立来源的否定和例外保留。新增快照测试使用完整虚构输入，不涉及真实用户对话。语法、差异检查通过，无新增静态问题。付费模型调用 0。

本阶段不修改索引、原始资料或历史数据。首尾读取检查不能阻止检查结束之后的并发写入，也不保证底层文件读取具备事务快照；本次保证的是摘录与记录的哈希来自同一份已读取字节。整体优化目标继续。
