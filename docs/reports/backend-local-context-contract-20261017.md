# 本地上下文窗口不再静默扩容

基线：`11c85fdc29aacfc15582751329dfbb71d33534b1`。

## 问题与修改

`generation_request.py` 和 `provider_context.py` 分别解析 `VLLM_MAX_MODEL_LEN`，并用 `max(1024, value)` 改写配置。隔离复现确认：明确配置为 `0` 时，两个入口都会声称窗口为 1024，而不是报错。

在已有 `inference/context_budget.py` 中统一本地窗口读取，生成请求默认值和提供商预算共同使用。保留原有 1024 最低预算要求：现有审核预算对象同样具有该下限；现在小于该值或无法解析为整数的设置明确报错，不将其抬高。合法值精确保留，缺省值仍是 8192。错误指出配置名和要求，不回显错误原值。

删除重复解析函数、只供其使用的默认常量和无用导入；内部审核对象保留独立验证，最低值使用同一常量。业务源码增加 19 行、删除 11 行，净增 8 行，没有增加框架或依赖。

云端工作窗口及其范围、历史上限推导、审核和来源预算逻辑保持原样，不让未使用的本地错误配置阻断云端路径。独立记忆写入器的显式零窗口字符预算模式未改动。

## 验证与范围

37 项定向检查首轮全部通过：28 项新增检查覆盖两个入口的非法值、最低边界、合法精确值、缺省值、上下文构建提前失败及云端忽略无关本地配置；9 项现有检查覆盖云端独立性、有效范围、审核预算传递和本地缺省。原测试与断言未修改，没有重复全量回归。

通过 Python 3.10 语法解析、差异空白及 Ruff E9/F 增量检查。AST 核对确认除了共享读取、最低常量及移除重复实现外，生成提示、检索、审核及云端预算实现保持一致；记忆写入器和其原配置测试源码未变。

只读核对服务器当前选中预算有效，本地窗口配置同样有效；没有查询密钥、改动配置或调用模型。服务更新后就绪与前端登录页面返回 200；匿名受保护接口返回 401，安全响应头正常；运行配置和其他服务进程不变。

本阶段处理应用配置被静默改写的问题，不扩大模型实际服务窗口，也不保证任意内容都能装入合法窗口；完整输入的容量校验仍由原链路负责。未进行真实本地推理或新的 DeepSeek 回答质量验证，没有新增意图规则或启用分类器。整体目标继续进行。
