# 统一模型适配器的输出上限解析

基线：`f99428c94306070d713b2a615af2d1ad1e598153`。先在服务器修改、验证和部署，再同步本地。

## 问题和修改

OpenAI 兼容、Ollama、llama.cpp、本地 Transformers 和 vLLM 的提示词入口各自处理输出上限，使用真假判断选择覆盖值。显式传入 `0` 或 `False` 会被替换成已保存的额度；配置中的小数还会被 `int()` 截断。这些入口仍供生成、训练评测和直接调用使用。

五个适配器现在共用 `read_provider_max_tokens`，复用已有 `GenerationOptions` 的数值契约。仅在覆盖值为 `None` 时读取配置；非正值、布尔值和不能表示整数的值明确失败。缺省时原有的 512 上限保留，主生成参数的现有默认值和配置优先级不变，没有增加数值校验框架。

本地 Transformers 在导入执行依赖和进入模型加载前完成上限解析；其他适配器在借用客户端或发送请求前完成校验。修正参数后可继续正常调用，不保留错误状态。

同时合并 vLLM 的异步实现与仅转发的 `async_generate` 入口。全仓库文本审查确认 `generate_async` 只有定义和类内调用；同步入口改为调用统一的 `async_generate`。其他模型选择、请求构建、历史处理、采样和资源所有权逻辑保持原实现。

生产代码净增 2 行。未增加服务层、配置、重试、模型切换或语义规则。
