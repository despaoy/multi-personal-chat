# 检索评测故障不再变成正常零分

基线：`ffc7cfbbf839a3631108752eecc794fe8ddde7f1`。完整检查检索评测指标、数据接口、调用方和相关测试后，服务器先修改和验证，再同步本地。

## 问题与修改

评测器原先捕获检索异常并改成空结果，继续输出正常零分；接口把损坏的答案标签改成空标签，可能使题目失去可评判依据却仍返回成功。缺少必需 `questions` 字段的数据文件也会被当成空数据集。

删除这些回退：检索故障保留原异常并终止本次评测，接口明确返回未完成；文件缺字段直接报错。列表和评测共用一次标签解析，拒绝非法 JSON、非列表和非字符串标签，解析失败发生在加载检索器之前。数据库中允许的 NULL 标签仍表示合法未标注，真正的空数据集和检索未命中继续正常返回。

移除没有调用方的固定分数模拟方法及其无用导入，取消这项手工模拟调用。保留原有召回率、MRR、nDCG 计算和已有离线分析方法。日志只记录失败环节与异常类型，原异常保留在内部因果链，不输出额外的私有错误详情。

生产代码净减少 27 行，没有新增错误类型或重试策略。SQL 和正常响应的结构模板 AST 保持一致。

## 验证

- 原生 SQLite、真实 JWT 和管理员复核下，对照十个 HTTP 场景：正常列表、正常评测、空数据集及两个 NULL 标签场景的完整响应逐项相同；五个故障场景从错误的 200 成功变为明确的 500 失败。
- 损坏标签的四个场景均在检索器创建前失败；检索故障不再变成未命中。核心 OSError 和 TimeoutError 保留同一原异常对象，缺必需字段的文件不再生成空评测结果。
- 另用保存的基线实现重新执行“有效题目但无检索命中”的 HTTP 对照，确认完整响应相同，仍为 200、可评判题数为 1、召回率为零。这是新执行的机制对照，没有把旧响应当作新模型结果。
- 先运行三个相关模块的 48 项测试，全部通过；补充正常未命中后只执行新增 1 项，也通过，共 49 项。新增 8 个用例覆盖上述核心行为，原有有效断言保留，没有执行全量回归。
- 修改文件的 Python 语法、未定义/重复/未用名称检查及服务器仓库完整性检查通过。
- 服务器启用后，后端就绪和前端登录页均为 200，匿名受保护接口为 401 并保留 `nosniff`，配置哈希和前端进程不变。

本阶段检索器返回值是显式测试控制，用于验证评测协议，不作为真实检索理解质量证据。模型调用为 0；SQL 未修改，没有重复执行 PostgreSQL 或真实模型链路。
