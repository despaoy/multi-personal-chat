## 实际问题与架构调整

检查了原始检索片段、引用标记、最终预算、模型请求、向量编码和审核器提供商选择的调用链。

复现了一处处理顺序问题：引用绑定先为片段添加来源标记，空白正文因此会变成非空字符串。后续预算校验只能看到加工后的文本，原始空正文可能被掩盖。

将原有预算校验提取到 `knowledge.evidence_packets.validate_evidence_packet`，引用绑定在添加标记前调用，预算处理复用同一入口。校验条件及错误与原预算实现 AST 一致，删除引用层较弱的重复校验。来源 ID、完整正文和非法数据失败语义保持统一。

三个生产文件净增加 **5 行**，用于公共函数、类型和说明；校验实现从两份收敛为一份，没有新增语义规则或回退分支。

## 测试前提与结果

- 证据预算用例补齐引用对应的原始文档，继续验证非法片段在模型调用前失败、原始数据不变。
- 向量用例补齐完整分词协议，包括特殊 token 数、原始 token、溢出窗口所属来源及掩码。非有限/零/溢出向量、维度和行数异常、失败不写缓存及成功后缓存隔离的断言保持有效。
- 分词现有协议每批包含原始 token 读取和窗口编码两次调用，相关次数检查随协议更新；实际模型调用和缓存复用次数仍严格检查。
- 引用层两个非法片段用例改为检查共享校验入口的准确错误归属，保留异常类型、模型不被调用及原输入状态检查。
- 审核器路由测试使用阻止真实 HTTP 传输的隔离策略，实际工厂仍接受测试提供的完整假客户端。旧运行方式直接拦截被测工厂，造成九项误报；生产审核器与模型选择代码未因此修改。

**11 个相关模块、157 个不同用例全部通过。** 首轮仅两个错误归属断言未适配；随后只补测其所在函数的七个参数用例，没有重复运行全项目测试。静态与差异检查通过。
