# 聊天检索直接使用大模型语义规划（2026-10-14）

## 用户最新要求与实际修改

按“不要用规则了，之后再训练分类器”的要求，当前聊天检索意图使用已配置的 DeepSeek 语义规划，暂不接入分类器。实际链路由“规则/分类器判意图 → 可选规划 → 检索”变为“完整语义任务规划 → 按来源依赖决定检索”。规划结果复用于后续对象绑定及证据审核，没有再增加一次意图模型调用。

移除聊天入口的关键词/未训练分类器调用、重复的私人任务预判及渲染试探，以及本轮不再使用的分类器知识库名称→ID 转换。规划始终接收完整当前原文、实际采用的完整历史和提供商审核预算。已验证的 public_knowledge 或 unresolved_source 依赖触发公共检索；私人来源、题设材料和纯控制请求不以公共知识补事实。来源依赖不授予读写权限。

plan_retrieval_views 成为聊天检索的必要步骤，删除可选开关、原文标题和 Corrective RAG 的跳过规划分支。原 RAG_TASK_PLANNER_ENABLED 不再控制此步骤，DYNAMIC_CONTEXT_SEMANTIC_REVIEW_ENABLED 仍单独控制动态上下文审核。useKnowledgeBase=false 继续明确停用检索及其规划，不启用替代路径。

超时、错误结构、依赖覆盖不全及完整输入超预算，仍通过统一 HTTP 503 明确失败，在检索/回答前停止。权限检查、证据完整性、记忆操作授权及最终响应校验保留。生产代码净减少 80 行。模型规划会成为启用知识库时每轮的必要成本，正常私人轮也先规划，不再依赖关键词节省该次调用。
