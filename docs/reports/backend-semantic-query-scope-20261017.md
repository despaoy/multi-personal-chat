# 逐任务语义检索范围与旧分类器归档

日期：2026-10-17。基线：`448620f134d4b374bd9c52f30e8eb5d8f45202b4`。

## 问题与修改

原先的身份、双人关系分类器根据整段问题中的词语决定检索范围。在同时询问两人关系和导师任命的完整问题中，双人过滤会在排序前删掉另一项任务需要的导师关系原文；即使对象绑定正确，也无法恢复已经丢失的证据。

现有问题对象审核现在同时声明每项任务的 `retrieval_scope`，没有增加模型审核环节。主聊天和独立知识问答共同使用这份语义结果。选择知识域也需要审核任务范围，不能绕过这份契约。

- `identity`、`independent_identity`、`direct_relation` 约束已绑定人物的结构化归属；`open` 由模型明确返回。
- 检索按各任务范围的并集保留候选，避免一个任务删去另一个任务的依据。未解决来源分支保持未知，不能取得已绑定业务对象的授权。
- 必需范围缺失、非法枚举、人数不符或跨请求、跨知识域的范围直接报错，不能自动改为开放检索。通用业务来源仍有明确声明的名称绑定契约；名称契约不能代替角色检索要求的范围契约。
- 身份、关系关键词分类器移至 `experiments/query_scope.py`，只供历史离线对照；正式检索不再导入它们。结构化人物归属及关系端点检查的函数体保持不变，访问控制和新鲜来源核验继续独立执行。
- 缓存提示契约升至 `grounded-answer-v6`，防止复用旧检索决策的答案。流式知识问答与普通入口都先检查已选知识域。
- 记忆来源读取器缺失时报告明确的接口错误并保留异常链；读取器执行时的数据库或解析错误直接传播，不会被包装成接口缺失或空结果。

生产模块合计增加 191 行、删除 112 行，净增 79 行，包含新的统一范围模块。本次以消除整句规则与逐任务语义之间的冲突为目标，不以减少行数替代正确性。

## 定向验证

604 个不同测试身份的最终结果通过。统计按每个身份的最新结果汇总，不把失败复测算作新增用例；已通过部分未重复运行。只选择本阶段受契约变化影响的测试、新增范围用例、失败项及记忆读取器关联路径，没有运行全部回归。

验证包括完整多任务导师原文、两个闭合关系任务的并集、无关第三组关系排除、人物归属、历史指代、缺失或非法范围、跨请求或域、未解决对象不获得业务授权，以及来源读取成功、接口缺失和执行异常。测试进程禁止接触真实审核客户端。

旧测试控制补齐了现有规划参数、真实嵌入适配接口、事实方面审核、实际来源位置引用和发送前的完整来源读取。来源读取器逐项核对原始授权快照，没有绕过来源撤销检查。原有私人事实保留、错误对象不能获得支持、别名登记不能代替业务事实等业务断言保留。

静态检查、语法检查和差异空白检查通过。历史分类器函数体与归档版本逐项一致；结构化归属函数体与基线逐项一致。新进程导入实际聊天及知识问答模块时未加载离线实验模块。既有实验 API 中显式的离线消融入口保持原样。

## 真实模型抽查与限制

使用服务器当前配置的 `deepseek-flash`、真实本地嵌入、真实向量召回及排序，在完整合成原文上完成 6 次实际付费调用：3 次主聊天审核、1 次回答，以及 2 次独立知识问答规划和绑定。

主聊天审核得到一项双人直接关系范围和一项开放的导师任命范围。导师原文在排序前保留、完整进入回答请求，回答包含任命人和另一人物没有提名权的否定事实，并绑定有效引用。独立问答得到明确双人范围，在排序前排除另外两组关系，保留所问人物对。

第一次回答探针使用了适配器不支持的 `top_p=0.9`，请求在发送前明确失败，未产生该次生成费用。修正测试为显式支持的参数后，逐字核对并重用此前 3 次实际审核，只新增回答和独立查询所需调用；复用结果没有标记为新的模型验证。失败记录和原始交换留在服务器，未上传 GitHub。

这些抽查说明当前完整案例可用，不保证任意语义判断都准确。语义范围不证明事实、权限或全部证据充分性。此次没有更换模型、增加分类关键词、训练分类器或扩大公网访问。
