# Redis 消息去重失败行为与连接发布

本地基线：`c1af36e12d7c13ce9b972acc0fe3cc52ddce05be`。按当前指示先在本地修改，服务器同步待连接恢复。

## 问题与修改

- 异步客户端在连接检查前写入全局变量，并发请求可能提前使用未验证的客户端。现在检查成功后才发布，初始化失败及取消保留原异常，不返回 `None`。
- Redis 去重故障原来改用进程内字典，不同进程无法共享结果。删除这条回退路径；消息处理入口明确报告去重状态无法确认并停止生成。未选中回复的消息不访问去重服务，正常重复消息仍直接跳过。
- 原异步连接池允许超时重试。`SET NX` 可能已经成功而确认丢失，再执行一次会被误判为重复消息。现在显式配置零次命令重试，连接异常及超时均直接报告；后续独立请求仍可重新初始化失败的连接。
- 删除空的机器人 HTTP 关闭函数及应用关闭时对它的调用。连接日志不再输出包含凭据的 Redis URI，路由日志不再截取用户原文，去重错误日志只记录异常类别。

保持原消息键和一小时过期时间。生产代码净减少 22 行，没有新增依赖、模型判断规则或替代存储。

## 定向验证

基线上的连接失败传播及去重失败传播两项控制均失败，证明原逻辑吞掉了异常。修改后分批验证 17 项不同 Redis/机器人用例通过，另有 1 项既有应用关闭关联检查通过：

- 初始化失败、负向检查、取消、并发等待、后续恢复及已验证客户端复用。
- 原子写入的正常结果、连接故障、写入故障及无效返回状态。
- 真正注册的消息处理函数在去重失败时停止生成并明确报错；未选中消息和正常重复消息不生成回复。
- 使用项目声明的 Redis 5.2 客户端连接池与实际重试实现，分别确认超时及连接失败只执行一次操作。
- 连接及去重错误日志不包含测试凭据或合成私有错误内容。

测试使用完整合成 OneBot 事件、真实 SDK 类型和机器人模块，外部服务边界由明确的控制对象替代，没有连接真实 Redis、启动机器人监听或发送消息。新增测试 Ruff、三个生产文件语法及增量静态检查、补丁空白检查通过；语法树核对确认应用关闭逻辑只删除了旧空函数调用。没有运行全量回归或付费模型请求。

本阶段没有实现完整投递事务：生成前保留消息标记的既有语义仍在，结果不明时报告失败并要求重新发送消息。真实 Redis 故障、平台投递和服务器部署尚未验证，不将这些控制测试计为真实服务验证。
