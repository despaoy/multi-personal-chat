# 聊天知识检索归回知识模块

聊天生成入口此前直接承担作品与通用资料的来源选择、混合域检索、索引准备、完整原文回填及修订号核验。知识业务依赖 API 私有函数，独立检索评测也必须导入整套聊天入口，职责方向与后端目录约定不一致。

将实际异步检索实现迁入 `knowledge/chat_retrieval.py`，以 `retrieve_chat_knowledge` 供聊天编排调用，移除 API 中的旧定义和索引生命周期依赖。没有保留转发函数或兼容别名。迁移前后函数的语法树完全相同，仅函数名变化；来源选择、数据库归属、线程边界、请求上下文、原文预算和前后修订号检查保持原语义。

更新 24 个相关评测模块和 49 个测试文件：直接检索改用知识模块，生成链路的观察及替换指向实际调用名。仅检索的四个维护评测模块不再导入聊天 API。没有新增测试用例、语义规则、回退、容错分支或配置。业务源码合计净增加 9 行，来自独立模块的说明及导入；主要收益是职责和依赖方向收敛，并非减少总行数。

## 验证

- 服务器首轮执行 855 个直接相关案例，850 个通过、5 个失败、无跳过。失败对应四处合成原文数据库夹具仍替换旧 API 的依赖，新模块因此正确报告原文不存在；没有转用其他来源或放宽原文断言。
- 修正这四处依赖位置并移除未使用导入后，只复测四个相关文件，共 58 个案例全部通过。按案例身份合并最新结果，855 个不同案例全部通过、无跳过，保留首次失败记录。
- 原有测试断言不变，覆盖作品与通用来源、混合域、完整原文、元数据更新、索引失败、来源变更、任务绑定、上下文预算、引用及生成错误传播。
- 独立进程禁止导入任何 API 模块后，仍能成功导入知识检索入口，确认知识模块没有反向依赖 HTTP 层。
- 静态、语法、仓库完整性、源码哈希及差异检查通过。服务器部署后就绪及登录页返回 200，未登录受保护接口返回 401，安全响应头存在；配置及前端进程保持一致，随后按哈希同步本地。

本阶段未调用真实模型、未重复全部后端回归，也未重复构建前端。24 个评测模块只验证语法及调用引用，没有重新执行全部付费评测。本次迁移不构成模型理解质量或整体性能提升的证据。生成入口仍承担其他业务编排，整体优化继续进行。
