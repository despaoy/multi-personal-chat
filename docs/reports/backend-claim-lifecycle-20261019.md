# 收敛记忆生命周期字段与评测来源身份

基线：`393ba95b5fb1737e1e4573e4f7628803aabeeb4a`。先在服务器修改、验证和部署，再同步本地。

## 问题和修改

数据库仓储已经严格校验声明的状态及关系类型，召回层仍在当前过滤、历史过滤、事件证据、排序和返回记录中反复解析旧字段，并把缺失状态默认为有效。当前与历史过滤还各有三组重叠的状态排除判断。

核心召回改为直接使用 `status`、`relation_type`。当前记录仅判断有效或显式允许的待确认状态；历史记录一次判断有效、已替代、归档及显式允许的待确认状态。移除重复排除分支、两个冗余状态集合及旧状态读取函数。时间窗口、关系排除、证据、主体和排序策略继续沿用原契约。

旧字段仍有两个真实评测适配器使用，因此格式转换集中到明确的 `decode_legacy_memory_lifecycle` 入口。历史格式原有缺省定义只在其入口处理；旧值 `current` 归一为 `active`，显式空值及未知状态或关系报错。数据库仓储保持原有严格枚举校验，召回核心缺少标准字段直接失败。

评测计数还存在两个已复现的问题：整数 ID `0` 在旧身份读取中被当成空值，导致旧版本泄漏漏计；返回结果找不到来源时，空字典和默认有效状态会掩盖对应关系错误。现在计数直接使用实际适配器输出的同一份记录，完整保留 `0` 的身份；找不到来源明确失败，不伪造有效状态。两个重复的评测字段读取函数随之移除。

生产代码净减少 9 行，其中召回模块减少 16 行。未增加服务层、重试、锁、配置或自然语言语义规则。
