## 十二项失败的处理

- 七项别名相关失败缺少当前解析契约要求的语义范围授权。直接解析测试现在显式提供绑定完整原文及授权证据的合成审核结果；调度器测试补齐范围审核响应，再提供原有记忆提议。原有别名、否定归属、生命周期、目标键、跨会话可见性和独立规范姓名断言保留。范围授权失败及引用不能授权的关联测试通过，没有修改生产授权判断。
- 三项主体归属测试在选择 OpenAI 提供商之前，尝试替换 vLLM 对象上的 async_complete，尚未进入业务断言就失败。现在先选择实际测试提供商，再替换其完成接口，原有主体及最终输入断言保留。
- 一项实际流式损坏测试缺少提供商 name，且替换了旧的聊天 API 依赖位置。现在提供完整的 vLLM 身份并在 app.providers 替换实际依赖，损坏字节必须失败、关闭上游及事件顺序断言保留。
- 一项旧测试要求全局提供商切换后中断当前请求，与已采用的请求连接快照契约相反。替换为同等范围的当前契约检查：本请求继续使用固定的原连接；下一请求选择不支持的提供商时明确失败且不能命中旧模型缓存；切回原连接后可合法复用原缓存。实际请求参数、调用次数及上下文清理均有断言。汇总时明确将旧案例映射为这一替代案例，不将两者重复计数。
