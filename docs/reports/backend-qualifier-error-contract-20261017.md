# 记忆限定错误的明确失败

此前模型给出的限定字段违反结构或证据覆盖约定时，`_sanitize_qualifiers`
返回空标记，调用方再把整条候选当作普通不保存，无法从回执分辨协议失败。
本阶段移除这些静默分支，沿用已有 `MemoryResponseError`，产品代码净减
**4 行**，不增加策略层、分类器、重试或模型调用。

## 修改

- 进入限定校验后，结构、字段声明与唯一性、数量、标量类型、非空及长度、
  证据覆盖违反约定，均报告具体错误，不改写、不丢弃部分限定来换取保存。
- 删除调用方的 `qualifiers is None` 分支。整批候选通过解析后才持久化，
  无效的第二条候选不能导致第一条先写入。
- 具体模型协议错误的回执增加安全 `message`，同时保留错误阶段、原因、
  字段和不可重试标记。消息均为固定文案或已知字段模板，不含模型原文。
- 唯一生产入口已经过 JSON 解码，限定键必为字符串，删除不可达的重复
  键类型防御；数字形式的 JSON 键仍作为未声明字段报错。
- 合法无限定、已有单项上下文列表、实际引文中的限定、待确认 `false`
  标记等既有语义保留。权限、证据条件、持久化与生命周期未放宽。

## 验证及限制

- 直接相关测试最终 **110 项通过**。首轮 108 项中 10 项仍要求旧的静默
  不保存；将协议错误改为明确失败断言，保留其余正常拒绝及成功断言，
  仅复测三个修改函数的 18 项。
- 另新增数量上限及 JSON 边界两项，错误说明加入回执后只复测相关四项；
  未重跑完整组或全量回归。一个旧正例补齐必需的用户归属字段。
- **零新增模型调用**。原样复用此前服务器保存的四条真实 DeepSeek 响应，
  走实际调度器与隔离数据库：两条正常历史消歧仍保存，两条长计划现在
  明确以 `invalid_model_response / qualifiers` 失败，零部分写入。
  原始来源完整保留，长计划仍能检索到完整原话。
- 这些是记录回放，不是新的模型质量验证。长计划的结构化提取仍未解决，
  本次只修复错误被当成正常无变化的问题，不声称模型已成功提取。
- 定向静态、语法和差异检查通过；结构核对确认其余准入条件及数据处理
  未变。原有真实模型记录未修改。
- 已部署服务器，后端就绪和前端登录页均为 200；配置及其他服务未改动，
  随后按摘要同步本地。
