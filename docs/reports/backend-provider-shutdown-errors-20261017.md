# 模型 provider 关闭错误明确传播

隔离构造六种真实 provider 后确认：`ModelManager.shutdown()` 虽然尝试逐个关闭，却吞掉所有普通关闭异常并返回成功，外层生命周期因而无法识别内部释放失败。

本阶段保留注册顺序及逐个尝试行为，用 `ProviderShutdownError` 明确保存每个失败 provider 的名称和原始异常。错误说明只包含 provider 名称及异常类型，不包含密钥、地址或原始错误文本。取消及其他控制异常保持原类型传播，聚合原因仍保留同轮的全部关闭错误。成功关闭仍返回 `None`。

首次采用退出栈时，测试发现跨线程传回错误会覆盖部分隐式异常上下文。因此改用明确的失败集合，原始异常对象不再依赖隐式链拼接保存；同时保留调用方启动失败的上下文。没有新增依赖或备用关闭路径。

14 个有效场景通过。初次 13 项中 12 项通过并定位上述跨线程问题；最终只验证直接受聚合错误修改影响的 12 项，包含一个新增的“取消同时伴随其他关闭失败”场景，两个未受影响的关联检查沿用已通过结果。未重复全量回归，真实模型调用为 0。静态检查无新增问题，语法兼容 Python 3.10。

六种 provider 的构造、生成、HTTP 客户端借用及 GPU 释放实现均经 AST 比对保持原样，既有测试文件未修改。仅修改管理器关闭契约、新增错误类型及修正过期模块说明，生产代码净增加 13 行，用于可靠报告多项释放失败。

服务器先修改、测试和部署，再验证实际应用子进程完成正常退出并恢复。后端就绪及前端登录页为 200，匿名保护接口为 401，安全响应头正常；运行配置、其他服务和当前模型配置未变。随后同步本地及 GitHub。

本阶段处理管理器内部的释放错误，不代表模型、RAG、记忆或所有后台模块已完成整体审计。总体优化目标继续进行。
