# 安全装配明确失败并固定配置来源

服务器隔离复现确认：已启用安全中间件时，开发与测试环境的导入失败
会被捕获并跳过；开关拼错或写成带空格的 true 也会被直接解释为关闭。
构建出的应用因此只留下 CORS，未报告配置或依赖错误。

## 修改

- 安全装配只读取调用方已经提供的应用启动快照，删除重复的全局开关
  及当前环境回退。唯一生产调用方原本就在传入这个快照。
- 复用既有严格布尔解析器。非法值明确报错；标准 true、带空格的 true、
  数值字符串 1 及缺省启用都正确装配安全组件。
- 删除导入失败后跳过组件的分支，任何环境的原始导入错误直接传播。
- 明确关闭时不导入相应依赖。生产环境禁止关闭的既有生命周期门禁保留，
  没有新增开关、错误包装或另一套布尔规则。

产品代码净减少 15 行。启用时的中间件顺序、具体鉴权逻辑及 CORS 配置
保持原实现，其他可选依赖标记未在本阶段修改。

## 验证

- 16 项定向检查一次通过，没有全量回归或新增模型请求。
- 开发、测试、生产设置下的已启用依赖失败均停止构建，保留原始错误。
  非法和空开关不能关闭安全组件，明确关闭不会访问对应依赖。
- 通过实际应用工厂发出 ASGI 请求：匿名管理员接口返回 401，允许来源
  的 CORS 头及 nosniff 安全头保留；不同应用的配置隔离检查通过。
- 静态比较确认仅装配函数、重复开关及解析器导入改变，原启用注册顺序
  完全一致，生命周期、启动校验、路由和安全中间件实现未变。
- 已重启服务器后端：就绪与前端登录页为 200，未登录资料、生成及管理
  接口均为 401，实际管理接口包含 nosniff 安全头。配置及其他服务未改动，
  随后按摘要同步本地。

没有在生产环境模拟依赖缺失或修改安全开关。失败注入只发生于服务器
隔离测试进程；测试日志、隔离数据库及凭据不进入提交。
