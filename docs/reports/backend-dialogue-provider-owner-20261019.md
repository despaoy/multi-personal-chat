# 批量对话任务的模型资源归属（2026-10-19）

本阶段审查生成入口、批量对话生成、模型管理器和研究评测调用方。聊天请求已固定选中资源，但批量对话生成仍只在开始时检查默认模型，搜索资料及每批之间会重新读取管理器，存在同一任务混用模型的问题。

## 处理

批量任务在开始时复用现有 `resolve_request_context`，持有选中资源；云模型使用已有连接与配置快照，本地模型使用原实例。搜索和后续批次都不重新选择提供商。没有新增另一套解析或快照逻辑，也没有加入切换检测、重试或替代模型。

选中资源真实失败时，继续使用现有明确错误和部分结果机制。原有取消、并发任务互斥、完整批次解析、数量检查、外部资料可信度说明及 mock 禁用逻辑保留。

全仓库调用和动态访问检查确认 `ModelManager.generate` 与 `ModelManager.set_lora_adapter` 已无实际调用方，删除这两个旧转发方法。历史报告中的名称保留；基础提供商及支持 LoRA 的实现不变。`ModelManager.async_generate` 仍有研究评测脚本使用，保留，不将“主聊天不再调用”误判为全局无调用方。

两个生产文件合计净减少 7 行，没有新增防御分支、语义关键词规则、分类器或依赖。AST 核对确认训练 API 的其他函数、模型管理器其余实现全部不变。

## 验证

修改前四个完整隔离用例分别复现：搜索后云转本地、第一批后云转本地、搜索后本地转云，以及切换后避开原模型真实失败却返回 200。修改后四项全部通过，校验同一任务各批使用同一资源，并保留原云模型、地址、凭据及采样配置。失败路径保留第一批结果并返回真实上游错误，不切换到可用替代模型。

另外 63 项直接关联检查首次全部通过，覆盖角色搜索成功与失败、批次格式与数量、取消和重置、并发任务所有权、提供商配置与关闭、现有评测错误接口。合计 67 个不同测试，无跳过，没有重复整套回归。补全三个旧夹具的提供商实例，将旧管理器适配器测试改为直接操作选中提供商，原有 170 条有效断言保持不变。

测试使用真实 ASGI 路由、真实批次解析、真实管理器与云协议，HTTP 和本地资源均明确隔离。每次合成输入有完整角色描述、条件、时间限制、输出数量与轮次；不把缺前提当作产品缺陷。真实模型和外部 HTTP 调用为零，不声称完成内容质量或真实本地权重评测。

静态检查、仓库完整性及差异检查通过。服务器先修改并验证，后同步本地和 GitHub；不改变当前 DeepSeek 设置，不提交凭据或运行资料，不开放公网。

本阶段固定任务的资源归属，不冻结本地权重热加载，也不承诺资源永远可用。后端整体精简和长期记忆、RAG、动态上下文优化继续进行。
