# 知识索引单一维护路径（2026-10-09）

## 调用链与问题

文档更新通过 save_knowledge_document 原子提交文档、完整分块、索引版本和 dirty 状态；删除同样原子更新版本。检索前的 _ensure_vector_index 按当前版本重建并核对完整快照，失败不能标记 complete。

但更新/删除 API 在数据库提交后仍执行另一套增量索引操作：重复分块、查目录、加工向量文档、删除旧向量并添加新向量，异常仅记录警告。下一检索仍须重建，因此这条路径重复消耗资源，并可能产生部分中间索引。

## 修改

删除 API 的重复增量索引代码、重复分块/路径查询以及删除前不再使用的分块查询。统一遵循既有创建文档的契约：文档事务成功后清除本地加速状态，检索需要当前索引时统一重建。

移除因此不再有调用方的 VectorDatabase.delete_documents、_rebuild_index_excluding 和 _rebuild_bm25。它们原本包含异常返回 0、按能力猜测重建等旧分支。文档删除功能和权限依赖保留，不删除历史业务数据或当前索引文件。

## 验证

7 项相关测试通过：首轮三个已有原子发布/内容更新测试通过；四个新增测试因未注入模型加载替身而在准备阶段失败，补齐完整替身后仅重跑失败四项，4 passed（2.43 秒）。没有放宽断言或重跑成功测试。

新增测试使用真实 SQLite、FAISS 和磁盘快照、固定合成向量，覆盖更新/删除只提交一次版本且不直接调用索引入口；随后统一重建得到正确新内容或空索引，磁盘重载一致；重建失败返回失败、不标记完成。出现四条现有 jieba/pkg_resources 依赖警告。

无全量回归、无付费模型调用。文档接口成功表示数据库文档事务已提交，不承诺向量已完成；下一检索仍需通过既有版本/重建检查。本阶段未证明全部跨进程并发或真实模型质量。

部署、代码规范和同版本同步记录保存在服务器本阶段备份目录，不提交私有原文和运行数据。
