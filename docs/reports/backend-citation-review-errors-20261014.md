# 回答引用补全故障不再伪装成功（2026-10-14）

## 实际问题与修改

generate_character_response 在回答完成、来源最终校验之后执行 recover_missing_citations。原先注释模型超时或任意故障、无效 JSON/引用结构、完整输入容量不足，都会返回原回答和失败状态字符串；来源身份或正文不一致也会被改成空来源列表。上层可能把未完成引用补全的结果当成整体成功。

删除模型异常吞掉与失败状态结果，保留原始异常向上传播；完整输入预算不足在发送前报错，不裁剪来源或回答。标注解析器对无效结构、未知来源、伪造/歧义引用直接抛出具体错误，整批不返回部分引用。重复 JSON 字段在同一解析边界拒绝，不通过覆盖旧字段猜测有效输出。来源标识、标题、完整正文及重复来源的不一致明确报错。

正常合法空引用列表保持 no_exact_span，已经绑定引用、非模型回复、来源直读及没有可标注来源的正常情况保持既有业务语义。保留逐字来源和完整答案，只补充可信检索元数据，不重写事实。完整输入的预检查继续保护后续候选匹配开销，补充候选后的最终预算也继续独立验证；直接复用已构造的数据，去掉一次 JSON 反向解析。生产代码净减少 10 行，无新增意图规则、分类器、错误框架、模型重试或降级。

## 定向验证

服务器实际修改后，41 项直接相关测试全部通过（1.50 秒），7 项不相关旧入口测试未运行。涵盖精确引用成功和元数据归属、合法无逐字依据、错误 JSON/字段/键/来源、同句多来源歧义、非答案原句、外部字面来源标记、无效重复片段整批拒绝、相同来源重复有效片段仅绑定一次，以及超时、取消、预算不足和来源未实际进入上下文。

三组实际聊天检索生成入口使用完整的柳港续租原文及费用、日期、原件、末尾例外任务。语义计划使用明确注入的完整响应；候选已通过真实对象、来源和事实审核，数据库原文再校验也使用同一完整快照。主回答执行一次、标注执行一次，分别注入提供商故障、超时或无效 JSON，确认原始异常传播而不返回已有回答，不额外重生成事实或重试模型。

关联回答引用测试原先让标注调用再次返回普通答案，恰被 invalid_annotation 降级吞掉。现在按实际调用协议为没有选用引用的控制显式返回合法空 JSON，保留原有引用顺序、完整来源、预算剔除和不能恢复被剔除来源的断言，新增主调用/标注调用数量核对。没有放宽有效断言换取通过。

本阶段完成引用补全自身的故障传播。引用准备入口和其他上下文模块仍需按实际调用链继续审查，整体后端精简目标继续。当前意图和任务计划使用已配置 DeepSeek 语义模型；后续分类器由用户训练后另行接入。
