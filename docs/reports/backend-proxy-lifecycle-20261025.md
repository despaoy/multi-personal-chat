# 统一代理转发与请求生命周期

基线为 `4f5c56ff1261f4c448287d713394a7bda94618c3`。本阶段沿页面请求、Next.js 路由、代理、后端响应和读取取消审查实际链路，在服务器先复现和修改，通过后按文件哈希同步本地。

## 问题与修改

原代理没有接收客户端取消；收到上游响应头便清除超时，正文卡住不再受该期限约束。catch-all 重复解析、序列化请求，并依据 Content-Length 判断是否存在正文；没有该提示的合法输入可能丢失。专用路由另有无效删除输入替换空对象、登录响应解析失败仍沿用成功状态、训练故障改造为空进度等重复处理。

现在统一转发实际方法和原始正文，由后端负责业务结构验证；不在代理中猜测或补造输入。GET、POST、PUT、PATCH、DELETE 共用一个路由实现。删除七个重复专用路由及其方法包装，原有接口由 catch-all 继续提供；保留健康检查路径映射和登出清除本地 Cookie。身份转换、同源限制、后端路径白名单和后端独立鉴权继续有效。

客户端取消与既有期限共同控制实际上游请求。JSON 响应在该期限内完整读取，超时报504；其他响应保留流式读取，通过 Web Streams 管理完成、失败、取消与计时器释放。已经开始发送的流不能改写 HTTP 状态，故障通过读取失败终止，不返回完成结果。连接故障报502，意外错误继续抛出，不使用固定业务回复或服务切换。fetch 解压后的正文移除失效的编码与长度头，状态、错误正文和 Cookie 按实际结果转发。

业务源码位于 `src/` 的净变化为 **减少348行**。没有增加依赖、业务配置、模型调用、语义关键词或分类器。
