# 共用嵌入模型开关的配置解析

基线：`692c5d5b8a0dabb9222bd6d402174ced6cfe1b2a`。沿长期记忆、通用知识库及作品知识检索的模型路径解析入口检查，服务器先修改和验证，再同步本地。

## 问题与修改

共用模型路径解析器为 `ALLOW_REMOTE_EMBEDDING_MODEL` 独立维护真值集合，将拼错的开关当作关闭；显式路径、缓存或本地目录存在时还会提前返回，完全跳过该配置。这会隐藏配置错误，且与其他必要功能开关的错误行为不一致。

删除这套独立解析，入口直接复用已有 `infra.environment.read_bool`，再按原顺序解析模型位置。合法配置的默认值、真值和假值别名、模型名称、路径优先级均保留；无效配置明确指出设置名称，不输出设置内容。生产代码净增 3 行，没有新增条件分支、异常捕获、重试或降级策略。其他生产代码的 AST 完全一致。

## 验证

- 服务器隔离目录分别覆盖显式路径、HF 缓存、默认目录、实验目录及无本地模型五种情况，共 25 个配置场景。修改前保存实际结果；修改后 20 个有效场景逐项与原结果一致，5 个无效场景明确报告开关错误。没有下载或加载假模型。
- 只执行路径、失败传播、完整编码窗口、梯度隔离、记忆配置顺序、资源所有权六个相关测试模块，65 项全部通过。扩展原有路径测试，增加的 3 个用例覆盖空白/大小写别名以及有无本地模型时的配置错误，不修改有效断言。
- 修改文件的 Python 语法及未定义、重复、未用名称检查通过；服务器仓库完整性检查通过。
- 使用生产环境读取入口确认真实本地模型目录可以解析，重启后端后 `/ready` 为 200，前端登录页为 200，匿名受保护接口为 401 并保留 `nosniff`；配置哈希和前端进程保持不变。

本阶段模型调用为 0，没有重跑全量测试。上述隔离路径探测不是模型理解质量评测；此前的真实 DeepSeek 和原生检索验收记录继续作为各自提交的证据。
