# 避免原话预算检查重复序列化整包

`compile_sources` 原先每加入一条记录，重新序列化、转义此前全部记录来判断预算。完整读取包含较多记录时，同一正文被重复处理。

改为创建一次固定包结构，累计各完整记录的 JSON 转义长度和逗号开销，最后序列化完整结果。预算计算仍包含包头、括号及 HTML 转义后的长度；超预算、条数限制、遗漏诊断及空结果行为不变。没有新缓存、截断、替代证据或备用分支，生产代码净减少 1 行。

服务器验证：

- 175 组新旧函数结果对照完全一致，覆盖空记录、不同条数、精确预算边界、中文、引号、反斜线、换行、HTML 特殊字符及 emoji。
- 200 条完整合成记录、每版重复 20 次：旧实现约 0.736 秒，新实现约 0.022 秒。这是单函数的本次测量，不代表端到端性能或模型质量。
- 原话召回、预算延后、选择容量、覆盖状态与云端 RAG 交付五个相关文件的 55 项测试全部通过，无跳过。
- 静态、仓库完整性及差异检查通过。
- 后端重启后就绪与前端登录返回 200，未登录受保护接口返回 401；配置及前端进程未变。按内容哈希同步本地。

对照与测量使用隔离合成资料，没有调用真实模型，没有重复运行全部回归测试。
