## 问题与修改

complete_turn 的统计和关系更新异常只写日志，回执没有失败标记。称呼更新还在消息来源 ID 或专用方法缺失时改走普通关系 upsert，绕过原始消息权限/时间保护。

- 移除普通关系写入降级分支；称呼只通过声明在仓储合同中的 set_address_from_turn 写入。数据库负责来源 ID、时间与权限校验，来源拒绝保留原含义，非 written 成功回执明确失败。
- 回执以 failed_writes 记录交互统计和称呼更新失败阶段；不撤销或隐藏已完成的记忆写入，也不声称未确认的操作已经回滚。
- Web 提示同时包含回写失败和已有记忆保存提示；只给阶段名称，不包含异常原文。
- 投递端保留实际语义写入回执和部分完成结果，将回写失败标记 blocked、原因 completion_write_failed，避免错误标为 completed 或重试整轮重复计数。需要检查相关依赖和已完成操作后处理，不自动重放已完成步骤。
- 两处旧异常日志不再携带堆栈和私有异常内容，只记录角色与异常类型。

业务代码净减少 10 行，无新依赖、配置、数据库迁移或用户数据删除。已生成的回复继续保留，回写故障单独反馈。
