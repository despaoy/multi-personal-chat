## 问题与修改

- `services/character_context.py` 的历史和关系备忘录读取异常被转换为空列表，模型可以在缺少必要上下文时继续。现在直接传播读取错误，沿已有 API 边界返回脱敏 503，内部保留原始原因。删除重复的备忘录加载包装。
- `character/natural_relationship.py` 的 `load_notes` 只负责转发并容忍缺失接口；删除该函数，调用方直接使用仓库接口，并在仓库协议补充明确声明。
- `repositories/messages.py`、`repositories/character_memory.py` 的历史、备忘录、来源关联和来源搜索，在数据库缺少接口时伪装成空结果。SQLite 和 PostgreSQL 正式实现已具备这些接口，删除缺失接口的空列表兼容分支。
- `character/source_memory.py` 对来源搜索、关联、窗口和最新权限读取的异常返回空召回包，使上层继续。现在失败直接传播，协议字段缺失也明确报错。检索、排序、预算、原文完整性和权限范围规则保持原有行为。

5 个核心业务文件合计净减少 29 行，没有增加依赖、通用异常框架或配置项。

合法空记录、没有匹配、已删除来源、显式携带现场历史，以及明确关闭来源召回的路径继续有效。假想分支的独立来源策略保留。缺少必要接口的自定义适配器需要补齐接口，否则明确失败。
