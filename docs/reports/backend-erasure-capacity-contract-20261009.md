# 记忆删除候选容量错误契约（2026-10-09）

## 问题与修改

`backend/character/memory_llm.py::_search_existing_memories` 在来源选择器已匹配完整删除和保留目标、但目标数量超过 10 时返回空集合，隐藏容量不足。

改为抛出已有的 `InputBudgetError`。调度器在 `memory_search` 阶段返回失败及 `input_budget` 原因，在模型调用和记忆写入前停止。不会截断必要证据。未匹配、授权不明确、正常空集合的规则不变。

生产代码净增加 2 行；没有增加配置或抽象层。

## 验证

- 新增三个定向测试：10 条完整目标成功选择、11 条完整目标预算报错、调度器失败回执且没有模型调用或记忆写入。
- 首次运行三个新测试失败：合成输入使用“删除”而没有明确长期记忆删除语义，未进入有效授权分支。修正为“从长期记忆中删除”，没有放宽业务规则或断言；仅重跑这三个失败测试，3 passed（0.40 秒）。
- 首轮另一个既有正常空集合测试通过，没有重复运行。
- 修改文件语法检查通过，无新增 Ruff 问题，差异空白检查通过。
- 本阶段付费模型调用 0 次；容量判断先于模型，无需通过真实模型验证此分支。没有全量回归。

## 范围与限制

使用完整合成来源、证据片段、归属及保留指令，未导出私有原文。调度器测试使用真实 SQLite 仓储和明确的候选读取替身；不声称覆盖真实模型生成、历史数据迁移或全部删除语义。

部署检查与同步记录保存在服务器本阶段备份目录。服务器验证后再同步本地并提交同一版本；运行数据、密钥与私有原文不提交。
