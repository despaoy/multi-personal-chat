# 风格目录读取与无用写入精简（2026-10-19）

基线：`91ef17ecc58bb7e173c6188bdb46646542fd8fae`。服务器先修改、定向验证和部署，再同步本地。

## 调用链及问题

管理员风格目录、数据集创建及数据集相关操作经 `get_dataset_preprocessor` 创建并缓存 `DatasetPreprocessor`。旧构造流程调用私有加载方法，捕获所有错误后返回空或部分风格目录；工厂随后缓存这个不完整对象。损坏配置即使修好，也继续命中错误目录。

全仓源码、文档与动态访问形式检索确认，`add_user_style` 没有调用方，`_save_user_styles` 只有它一个调用方；`_load_user_styles` 只由构造函数调用。项目没有通过这两个写入方法提供风格编辑入口。

## 修改及影响

- 风格读取直接放在构造函数内，一次解析并完整构造配置映射。读取、JSON 和配置字段错误自然传播，不新增包装或校验；工厂只在构造成功后发布实例。
- 删除无调用方的两个风格写入方法及单次调用的加载方法。手工配置文件、风格目录查询、列表副本、默认字段值及数据集其他功能保留，未删除历史文件。
- 没有配置文件和合法空映射仍是正常空目录；故障不能伪装成这两种状态。

生产代码净减少 **35 行**，未增加依赖、模块、规则、重试或防御分支。其余方法、数据集导入及全部 API 的 AST 保持一致。
