# 来源身份存储损坏明确报错

日期：2026-10-16。基线：`324ba87bb09838c00c12695dbc34f626371d4b15`。

## 问题与修复

`db.memory_claim_source_revisions.linked_revision_plan` 在核对已授权记忆的实际来源时，将 `origin_scope` JSON 解码错误、结构错误或字段错误全部捕获后跳过。真实记忆读取仍记录 revision 状态为 available，最终生成校验再移除该记忆，看起来像合法无匹配，掩盖了存储损坏。

服务器隔离 SQLite 预检先以正常原文、真实关联 claim、关系和来源版本完成准备，确认有一项记忆；只破坏来源身份 JSON 后，准备仍成功且 revision 状态 available，最终变成零项、no_match。没有调用真实模型。

现移除该宽泛吞错分支。存储身份必须是六字段列表，并通过既有 `source_scope` 身份校验；格式错误沿真实记忆准备及发送前复核传播，API 准备边界返回 503。保留正常授权排除：合法的不同会话、不同 owner、不同角色来源仍不可见；同一旧 claim/source 配对关联多个合法原始范围时，仍维持既有歧义空结果。没有扩大权限或自动修复数据。

产品变更仅 7 行增加、8 行删除，没有新异常层、模型调用、重试、降级或规则分类。
