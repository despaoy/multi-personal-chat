# DeepSeek 真实生成与用量保存抽查

在 adb54e3014e97e0dd65adfb184688a05d31603ee 上，针对刚完成的实际用量记录执行两次新的 DeepSeek Flash 请求。不是历史响应重放。

两个并发任务分别提供完整的虚构历史与当前更正：日期和金额发生变化，人数保留历史值，明确尚未获批，并分别包含下雨、停电时改为线上的条件。通过正式 generate_reply_core 进入当前生成编排，检查发往模型的消息包含完整历史与当前原文，保存后逐项核对回答、原始消息和对应调用用量。

## 结果

- 两个模型请求均返回 200，正常结束。回答正确保留各自日期、金额、人数、否定与条件，未混用另一个任务的事实。
- 第一次返回输入 473、输出 31、合计 504 tokens；第二次输入 475、输出 32、合计 507 tokens。数据库中的三项计数逐项一致，usageSource 均为 provider，总量为 1,011 tokens。
- 原始当前消息和最终回答正确保存在隔离 SQLite 中。没有业务数据写入，在线进程与配置保持一致；服务就绪、登录及未登录受保护接口状态为 200、200、401。
- 仓库完整性检查通过。没有重复执行整套回归，没有修改生产代码。

## 范围与前提

模型连接使用在线 PostgreSQL 配置的只读快照，测试写入使用独立 SQLite；为了隔离，关闭本次测试的响应缓存与知识检索，设定固定生成参数。没有替换模型响应。此次证明普通生成的输入传递、简单多事实理解、任务隔离及实测计量保存；未覆盖 HTTP 登录、队列调度、RAG、角色长期记忆、复杂权限或全系统账单。

首轮准备脚本错误读取了兼容 SQLite 的旧配置，在模型调用前中止；核对在线数据库来源后修正为 PostgreSQL 只读快照。前期准备没有发出模型请求。本阶段真实模型调用总数为两次。模型返回的缓存命中 token 也是实际报告的一部分，但此次没有进行价格与费用折扣换算。
