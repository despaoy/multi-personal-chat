# R1V4 E1 checkpoint 生成质量选择结果

## 结论

本轮 E1 训练成功结束，但四个 checkpoint 均未通过真实生成门禁，不能选择正式 adapter，也不能开始 E2。`checkpoint-150` 只是 validation loss 最低，不是可用模型。

这是一项有效的负结果：它证明仅凭训练完成、loss 下降或 perplexity 改善，无法判断人物模型是否真正变好。

## 评测设计

- 使用 Gold v2.1 派生的 30 条开发题，不使用 Gold v3 调参。
- 题目包含人物表现 8 条、事实与人物认知 7 条、多轮 7 条、安全 8 条。
- 安全题覆盖 `allow`、`refuse`、`clarify` 等全部 8 种预期动作。
- 题目按四个大类交错执行；五组使用同一题序和生成参数。
- 多轮题逐轮真实生成，因此每个模型共检查 44 个回复，而不只检查最后一句。
- 使用 Qwen3-8B-Instruct BF16 和真实 vLLM 0.10.2，`mock=false`。
- 固定 `temperature=0`、`top_p=0.9`、`max_tokens=256`，关闭 thinking。

## 逐题观察

- 部分直接事实题仍能给出正确短答案，例如“四条琉璃是妃的什么人”。
- 人物题和人物认知题经常被压缩成“不会。”“好。”，信息不足。
- 个别回答出现语义矛盾，例如“即使后悔，我也不会后悔”。
- 多轮题丢失前文约定，或只回复“记得”“不知道”。
- step 200/232 在多轮场景出现严重单词循环，单条重复率达到 99.6%。
- 所有请求都成功返回，没有服务错误，所以失败来自模型生成行为，不是 vLLM 或网络异常。

## 原因判断

当前证据更支持“优化强度对本任务仍过高”：`r=32/alpha=64`、7 个 target modules 在 step 100 前已经明显改变生成分布，继续训练后发展为循环。数据已经通过标签审计，926 条记录也足以进行本阶段实验，因此不应在没有新证据时再次大规模重写数据。

validation loss 反映模型对固定验证答案的下一个 token 预测，却没有检查开放生成是否过短、矛盾、丢失上下文或循环。今后必须同时保留 loss 选择和生成门禁。
