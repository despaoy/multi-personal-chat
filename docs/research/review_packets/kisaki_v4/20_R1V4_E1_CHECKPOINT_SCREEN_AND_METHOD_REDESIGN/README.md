# R1V4 E1 全 checkpoint 筛查与方法重设计

## 结论

本轮已有 checkpoint-20/40/60/80/100/116 均不适合作为正式 R1-E1。checkpoint-20 最接近 Prompt-only，但已经出现新的事实编造；随着训练步数增加，人物口吻变强的同时，跨场景串扰、关系误判和虚构经历持续增加。

因此不再从本轮训练中强行选择“相对最好”的 checkpoint，也不启动 E2。下一步应先重构训练数据暴露比例和情境条件，再做一次低强度 E1 recovery pilot。

### 代表性问题

- checkpoint-20 在 `kisaki_v21_safety_012` 中把现实文件大小解释为“魔法浓度”，说明很早就出现为了展示角色而编造世界规则的问题。
- checkpoint-40 在 `kisaki_v21_multiturn_015` 的“归还推理小说”中虚构用户要带笔记本，训练语料中大量无关笔记本场景发生了跨场景串扰。
- checkpoint-60/80 在 `kisaki_v21_persona_024` 中虚构“琉璃的病”和每天去房间探望，在 `kisaki_v21_factual_009` 中生成不存在的父母离别记忆。
- checkpoint-60/80 在 `kisaki_v21_multiturn_020` 中虚构“上次烤焦”，并把妃对亲近者的戏谑泛化成持续怀疑。
- checkpoint-116 能在个别题目中给出更具体的茶和甜度选择，但同时产生更多无依据人物经历，净收益仍为负。

## 数据暴露审计

当前 926 条训练记录包含 2,068 个 assistant 监督目标。按数据来源统计：

| 来源 | 记录 | assistant 目标 | assistant 字符 | 字符占比 |
|---|---:|---:|---:|---:|
| 原作提取 | 522 | 629 | 20,309 | 16.75% |
| Codex 用户模拟 | 251 | 1,255 | 96,530 | 79.63% |
| DeepSeek 用户模拟 | 3 | 15 | 1,499 | 1.24% |
| 其他人工审核构造 | 150 | 169 | 2,883 | 2.38% |

不能把 79.63% 直接等同为梯度权重：当前 batch size 为 1，语言模型损失通常会在单个序列的有效 token 上取平均。但它仍说明模型接触到的 assistant 文本、轮次模式和长回答结构主要来自通用用户模拟；这 254 条五轮模拟也占全部训练记录约 27.4%，远高于其应承担的角色风格权重。

用户模拟本身不少回答质量良好，但大量内容属于实验建议、情绪安慰、生活规划等通用助手任务。它们容易让模型学会长篇建议、固定安慰句和跨场景概念关联，而不是原作中简短、关系敏感、事实有边界的月社妃表达。

## 论文核验与启示

### 角色训练与情境

- [RoleLLM](https://arxiv.org/abs/2310.00746) 将角色画像、Context-Instruct、风格模仿和角色条件指令微调拆开，说明人物训练不应只有一个统一画像加对话答案。
- [Character-LLM](https://arxiv.org/abs/2310.10158) 同时建模 profile、experience 和 emotional state，支持把“人物是谁”“经历过什么”“当前情绪是什么”分开表示。
- [CoSER](https://arxiv.org/abs/2502.09082) 使用原著真实对话、场景设定、人物经历和内心活动，并提出 given-circumstance acting。它直接对应本项目的关系混淆问题：模型必须先知道对话者、场景、当前目标和已发生事实，再生成台词。
- [BEYOND DIALOGUE](https://arxiv.org/abs/2408.10903) 指出画像与对话可能冲突，并强调场景级、句子级的 profile-dialogue alignment。它支持“每句话都应有情境和人物依据”，而不是“每句话都要堆砌口癖”。
- [OpenCharacter](https://arxiv.org/abs/2501.15427) 比较角色化回复生成与改写，支持继续使用受控生成扩充，但前提是逐条验证画像和情境对齐。

### 人物边界、事实与决策

- [ERABAL](https://arxiv.org/abs/2409.14710) 通过 boundary-aware learning 处理与人物属性相近但超出人物认知边界的问题，并报告较少对话也能带来改进。
- [RoleRAG](https://arxiv.org/abs/2505.18541) 使用实体消歧、结构化知识图和认知边界检索减少人物知识幻觉，支持把原作事实交给 RAG，而不是要求 LoRA 记住全部剧情。
- [Character is Destiny / LIFECHOICE](https://arxiv.org/abs/2404.12138) 专门评测人物驱动决策，并通过 persona-based memory retrieval 的 CHARMAP 提升决策准确率。它与项目的“情景决策”维度高度一致。
- [ChatHaruhi](https://arxiv.org/abs/2308.09597) 结合改进提示词和从剧本提取的人物记忆，进一步支持“风格训练 + 事实检索”分层。

### 评测

- [CharacterEval](https://arxiv.org/abs/2401.01275) 是正确论文地址，不是此前材料中误写的 `2402.14000`。它使用 13 项指标、4 个维度和人工质量控制评测中文角色对话。
- [InCharacter](https://arxiv.org/abs/2310.17976) 通过心理访谈和心理量表评测 personality fidelity，可补足只看措辞风格的问题。
- LIFECHOICE 补足情景决策；项目现有事实、多轮和安全集继续补足工程使用场景。五个角度可以保留，但应分别有独立证据，不能压成一个总分。

### PEFT 与数据质量

- [LoRA Learns Less and Forgets Less](https://arxiv.org/abs/2405.09673) 表明低秩 LoRA 通常比全量微调学习得少，但更能保留域外能力。当前结果说明“保留更多”仍不等于不会被错配数据带偏。
- [LIMA](https://arxiv.org/abs/2305.11206) 展示少量精心筛选的监督数据也能有效对齐，支持优先减少低价值模拟，而不是继续扩充数量。
- [NEFTune](https://arxiv.org/abs/2310.05914) 能改善通用指令微调，但不能修复画像、事实和场景标签错误，因此暂不启动 E2。
- [DoRA](https://arxiv.org/abs/2402.09353) 和 [rsLoRA](https://arxiv.org/abs/2312.03732) 主要提升学习能力或高 rank 稳定性；当前瓶颈是“学错内容”，增加学习能力可能放大问题，不能作为第一修复手段。

## 推荐的新 E1 方法

### 1. 建立 source-balanced V5 候选数据，不覆盖 V4

- 保留 522 条原作提取记录作为风格和关系事实的核心。
- 保留 150 条短构造记录，但重新检查其场景与画像是否逐句一致。
- 从 254 条五轮用户模拟中只保留约 15-25 条最有价值的长程场景，优先覆盖关系边界、承诺记忆、冲突修复和现实安全。
- 普通技术问答、通用学习建议和重复情绪安慰不再大量进入角色 LoRA；它们由基座能力和系统业务层负责。
- 以 assistant 目标数、字符或 token 暴露比例共同审计，而不是只看 JSON 记录数。建议用户模拟不超过训练记录的 10%，assistant 监督 token 不超过 25%。

### 2. 引入 given-circumstance 训练契约

每条训练记录明确提供：

- 当前对话者及关系距离。
- 当前场景和已经发生的事实。
- 妃在这一轮想保护、争取或隐藏的内容。
- 允许引用的原作事实与未知边界。
- 当前适合表现的画像维度，而不是要求所有特征同时出现。

训练和生产必须使用同一种上下文结构。对话者身份应来自系统解析后的可信角色状态，不能直接相信用户输入的姓名。

### 3. 把知识与人格分层

- LoRA：学习稳定语言节奏、关系差异、边界感和情景选择倾向。
- 结构化人物记忆/RAG：提供人物关系、剧情事件、物品、地点和时间证据。
- 会话状态：记录本轮已经出现的承诺、物品和安排，解决“推理小说、十分钟、下午喝茶”等多轮遗忘。
- 证据不足时允许自然表达不确定，禁止为了显得像角色而补全剧情。

### 4. 低强度 recovery pilot

第一轮只训练一个修复基线：

- LoRA `r=4, alpha=4`，仅 `q/k/v/o`。
- 学习率从 `5e-6` 开始，最多 0.5 epoch。
- 每 5 step 保存一次，并在 5/10/15/20 step 做同一开发集诊断。
- checkpoint 选择不再依赖 eval loss；必须同时满足人物增益、事实不退化、多轮不退化和安全无严重新增错误。
- 先不启用 NEFTune、DoRA、RSLoRA 或 Packing，避免再次混入额外变量。

若 source-balanced 数据仍造成基础能力下降，再考虑一个“KL retention”受控变体：在少量中性、安全和技术提示上约束 adapter 输出不要偏离 Prompt-only。它目前只是待验证假设，需要单独实现和消融，不能与数据修复同时宣称效果。

### 5. 新门禁

- 开发集 pairwise：候选胜数不得低于负数。
- 人物一致性允许提升，但事实、安全任一维度不得下降。
- 不允许新增人物经历、地点、物品或关系事实的严重错误。
- 多轮题必须逐项保留物品、时间、地点和用户明确约定。
- 通过开发集后，再使用未参与选择的新题目确认；当前 30 条不能继续充当最终证据。

## 当前决策

- 现有 checkpoint 全部保留为负结果。
- E1 尚未冻结。
- E2-E5 继续暂停。
- 下一项工程工作是构建 source-balanced V5 候选数据与对应审计，不是继续调大 rank 或直接跑 NEFTune。
