# 情境证据决策：后续 AI 接手提示词

以下内容可直接交给下一位编码 AI。它是一份后续工作指令，不表示其中待办已经完成。

## 任务

请在现有多角色聊天系统上，继续提升长期记忆、动态上下文、RAG 和 LoRA 的最终回答质量。优先研究“什么情境下应使用什么证据、采取什么角色行为”，而不是继续堆积关键词规则。先读 `docs/CURRENT_STATE.md`、`docs/research/CONTEXTUAL_EVIDENCE_RESULTS_20260919.md`、`docs/research/CONTEXTUAL_EVIDENCE_USAGE.md` 和研究映射。以最新实测汇总为准，历史实现记录中仍保留已结束的“正在运行”文字。

## 已知事实，不要重新包装成新结果

- 记忆直接选择的推理配方优于非推理开发结果，但种子间有错误与超时；三次事后多数全对不等于独立测试全对，也没有上线多数投票。
- LongMemEval 固定 70 题中，RRF 的整体检索效果优于所测两个分层候选。公开英文位置召回不是中文人物回答准确率。
- BGE 精排的开发 Hit@1 没超过现有规则；排序能力与证据充分性应分开评价，不能直接把原始 logit 或 sigmoid 当作可靠概率。
- 全量语义状态复核改善部分漏检，也新增误读。v2 开放感谢标签、保留完整输入、明确超预算回退；这些契约修复不是学习式路由训练。
- 公开 CharacterEval 首轮关系实际是 stranger，原报告 familiar 文字有误，已明确更正。32 条原报告仍含两次错误，不能替换成后来单题诊断的交付结果。
- `6761` 两组错误来自可直接复现的守卫兜底契约问题；修复后交付的仍是通用兜底，不是角色质量提升。
- 人工评审未完成；没有新的获批 LoRA。现有失败适配器仍不得自动批准。

## 修改边界

工作区包含大量原有未提交修改。先看状态与局部差异，不重置、不覆盖、不批量整理无关代码。不要修改真实用户数据库、生产环境配置或默认启用实验开关；不要训练、部署、购买额度或下载大型新模型来绕过尚未解决的评测问题。需要这些动作时先说明依据、成本和授权要求。

保持用户/角色/会话/剧情隔离、记忆撤回和删除保护。候选召回不等于可注入事实，选择成功不等于实际装入上下文；策略和守卫只能依据真正注入的证据。不要截断后半句纠正、偷偷缩短训练 prompt、将模型猜测回写成用户事实。

## 推荐实施顺序

1. **整理独立终测集。** 将已经观察过的中文合成题全部标为开发集。新题按完整会话/原作场景分组，隔离来源、反事实配对和改写。先冻结问题、证据与评分规约，再生成答案；不要依照新结果修金标。AI 草拟题必须明确标注，人工确认前不得叫人工金标。
2. **先评最终回答。** 固定底座、关系阶段、提示与预算，至少比较规则基线、情境记忆、状态/策略、组合；保留失败与兜底。分别评价事实支持、时效和主体、边界遵守、角色自然度。匿名随机排序，人工评分为空就保持为空，不能由同一生成模型自评冒充人工。
3. **把收益变成决策监督。** 只有拿到上述独立回答比较，才构造“无检索/检索/澄清/拒答”等候选动作的效用标签；明确动作失败成本。训练/验证/测试按来源组隔离，先与提示式选择器和原规则比较。不要仅优化闭集动作标签，就声称体验更好。
4. **审查再训练。** 使用已经实现的完整证据条件化 SFT/DPO 导出。chosen 必须有正确来源支持；语气自然但事实错误的答案不能作正例。检查 SFT 和 preference 各自指纹、来源泄漏、完整 token 长度、量化与部署兼容性。先做数据审计和训练 dry-run，获准后才实际训练。
5. **按证据晋升。** 单模块和组合都需回归、安全/隔离验证、独立质量比较。优势不稳定则保留默认关闭；失败报告不删，结果中同时给分母与局限。不要预设所有新模块必须上线。

## 交付要求

每次修改说明具体文件、行为变化、测试、实测结果及尚未验证部分。报告数据/模型/源码版本、采样种子、实际关系阶段、重试和兜底；开发诊断与独立终测分开。保留可重放报告，不保存推理草稿。使用公开论文时链接原文和实现，区分借鉴、适配与真正复现，不宣称未经证明的科研首创。
