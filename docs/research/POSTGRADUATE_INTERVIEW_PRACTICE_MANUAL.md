# MultiPersonal Chat System 保研面试复习手册

> 用途：按真实面试顺序整理项目介绍、常见追问和回答要点。后续练习中确认无误的内容逐步追加到本手册。

## 1. 项目整体介绍

### 1.1 两分钟版本

我的第二个项目是 MultiPersonal Chat System，这是一个以虚拟人物模拟为研究对象的本地大模型实验系统。我的目标不是让模型简单模仿几句口癖，而是研究如何让通用大模型在不同情境和多轮对话中，更稳定地表现出目标人物的语言和行为特征。

在研究过程中，我主要从五个方面分析人物模拟效果，包括语言风格和表达习惯、不同情境下的行为选择、原作事实和人物关系、长对话中的人物一致性，以及与用户交流时的长期记忆。安全性作为独立的系统质量和评测要求进行考虑。

在实现上，我首先整理原作中的人物对话和剧情资料，并构建人物画像、训练数据和验证数据。Prompt 用于规定人物身份、行为边界和当前对话要求；LoRA 用于参数高效微调，在冻结基础模型的情况下训练低秩适配器，让模型学习人物的语言风格和部分行为倾向；RAG 用于检索原作事实和人物关系。系统还设计了置信度与拒答机制，在检索证据不足时降低回答的确定性，减少模型编造。对于用户长期记忆，系统结合规则和 LLM 判断，异步提取用户明确表达的重要信息，写入记忆存储，并在后续对话中按需检索。

在工程实现上，系统以 Qwen3-8B 为基础模型，使用 vLLM 提供推理服务，FastAPI 负责消息处理、会话管理、角色与 LoRA 选择、RAG 调用、幂等去重和历史记录保存，再通过 AstrBot 接入 QQ、微信等外部平台。

项目过程中，我发现早期训练数据和评测流程存在人物偏移、模板化和污染风险，因此重新整理数据，建立独立验证集和最终盲测集，并设计单变量实验比较不同方法。这个项目让我完整实践了大模型的数据处理、微调、检索、评测和部署流程。

### 1.2 讲述结构

```text
项目定位 -> 研究维度 -> 技术方法 -> 工程架构 -> 问题发现与个人收获
```

### 1.3 表述边界

- LoRA 的作用应表述为“用于学习更稳定的语言风格和部分行为倾向”，不能仅凭训练完成就声称效果已经提高。
- RAG 已设计检索、置信度和拒答机制；具体效果需要通过独立检索与回答评测证明。
- 独立验证集用于训练过程中的模型选择，最终盲测集用于训练和调参结束后的评价，二者不能混用。
- 项目名称统一使用 `MultiPersonal Chat System`。

## 2. 面试追问

### 2.1 为什么不能只使用 Prompt，还需要 LoRA？

**推荐回答：**

Prompt 是对人物身份、性格和回答方式的显式约束，主要作用于当前上下文。它比较灵活、容易修改，但依赖上下文长度；在长对话中可能出现约束弱化和人物漂移，而且一些复杂的语言习惯和行为倾向难以完整地用规则描述。

LoRA 则是在冻结基础模型大部分参数的情况下，利用人物数据训练低秩适配器，使模型从数据中学习更稳定的语言风格和部分行为倾向。因此，Prompt 更像是当前对话中的显式约束，LoRA 更像是通过训练形成的参数适配。两者结合可以同时获得灵活控制和相对稳定的角色表现，但 LoRA 的效果依赖训练数据质量，不能仅凭训练完成就证明人物模拟效果一定提高。

**记忆关键词：** 显式约束、上下文长度、参数适配、数据质量。

### 2.2 LoRA到底改变了模型中的什么？

**推荐回答：**

LoRA并不是重新训练整个模型，而是在冻结基础模型原始参数的情况下，学习一个低秩的参数增量。假设原权重矩阵是 `W`，LoRA通过两个低秩矩阵 `B` 和 `A` 表示更新量，得到新的权重：

```text
W' = W + B × A
```

虽然 `B × A` 的形状与 `W` 相同，但由于中间的 rank 较小，所以实际需要训练的参数量远少于全量微调。这可以降低训练显存和适配器存储成本，同时保留基础模型原有的通用语言能力。对于我的项目来说，基础模型已经具备中文理解和普通对话能力，我主要希望它学习目标人物的语言风格和部分行为倾向，因此采用 LoRA 进行参数高效微调。

**记忆关键词：** 冻结原始参数、低秩增量、`W' = W + B × A`、减少训练参数。

### 2.3 LoRA中的 rank 是什么？为什么越大不一定越好？

**推荐回答：**

LoRA中的 `rank` 是低秩适配器的中间维度，可以理解为适配器的表达容量。假设原权重矩阵为 `n × m`，LoRA将更新量拆成两个矩阵：`B` 为 `n × r`，`A` 为 `r × m`，两者相乘后得到可以加到原矩阵上的更新量。`r` 越大，适配器能够表示的参数变化越复杂，但训练参数量、显存占用和训练时间也会增加。

`rank` 越大不一定越好。如果数据量不足、数据质量不高或训练控制不当，过大的适配器容量可能使模型过度记忆训练样本，出现过拟合，降低泛化能力。因此不能只通过增大 `rank` 来追求更好的效果。

**记忆关键词：** 适配器容量、两个低秩矩阵、参数量、显存、过拟合、泛化能力。

### 2.4 训练集、验证集和独立测试集分别有什么作用？

**推荐回答：**

训练集用于更新模型参数，模型直接根据这部分数据计算损失并进行训练。验证集不参与参数更新，主要用于观察模型在未参与训练的数据上的表现，并选择合适的 checkpoint、训练轮数或其他超参数。独立测试集在训练和调参完成后使用，用于估计模型面对未知数据时的最终表现。

不能反复使用测试集选择模型，因为每次查看测试结果都会提供额外信息。如果根据测试集结果反复调整模型、Prompt或训练参数，模型选择过程就会间接适应测试集，产生测试集信息泄漏，最终分数可能被高估，不能可靠反映模型在真实未知场景中的泛化能力。

**记忆关键词：** 训练集更新参数、验证集选择模型、测试集最终评价、信息泄漏、泛化能力。

### 2.5 Transformer中的注意力机制主要在做什么？

**推荐回答：**

Transformer中的自注意力机制会让每个Token根据当前语境计算它与其他Token之间的相关程度，然后对相关Token的信息进行加权聚合。这样，模型可以建立相距较远的词语、句子和对话内容之间的联系。

这适合处理角色对话，因为人物的回答不仅取决于当前问题，也取决于前面的身份设定、人物关系和历史对话。注意力机制可以帮助模型在生成当前回答时利用这些上下文信息。不过它不等于无限记忆，过长的对话会带来更高的计算开销，也可能使较早的信息被弱化。

**记忆关键词：** 相关程度、加权聚合、长距离依赖、上下文利用、不是无限记忆。

### 2.6 为什么事实知识和人物关系使用 RAG，而不是全部通过 LoRA 训练？

**推荐回答：**

LoRA和RAG解决的问题不同。LoRA可以通过训练参数，使模型学习更稳定的语言风格、表达习惯和部分行为倾向，适合处理相对稳定、难以用规则完整描述的模式。RAG则是在推理时从外部知识库检索相关资料，再将证据提供给模型，适合处理人物经历、人物关系等需要准确、可更新和可追溯的事实。

LoRA并不是完全不能学习事实，但把事实全部写入参数可能出现记忆不准确、知识更新困难、无法提供证据和模型编造等问题。因此项目中让LoRA主要负责人物表现，让RAG负责外部事实；同时通过检索评测、证据相关性检查和证据不足时的拒答机制降低错误风险。

**记忆关键词：** LoRA负责表现、RAG负责事实、可更新、可追溯、LoRA不是事实数据库。

### 2.7 怎样判断模型更像目标人物？

**推荐回答：**

我会建立独立的 Gold 评测集，从语言风格、人物事实和关系、情境行为、长对话一致性以及跨会话长期记忆五个方面设计问题。对于基座模型和不同 LoRA 变体，我固定相同的 Prompt、生成参数、测试问题和请求顺序，对生成结果进行匿名成对盲评，判断哪一个回答更符合目标人物。

训练损失下降只能说明模型更好地拟合了训练目标或训练数据，不能证明人物模拟效果提高。如果训练数据存在偏差或错误，模型可能只是更好地记住了错误内容。因此最终结论要结合独立测试集、自动指标和人工盲评，不能只看 loss。

**记忆关键词：** 独立评测集、五个维度、固定条件、人工盲评、loss 不等于人物效果。
