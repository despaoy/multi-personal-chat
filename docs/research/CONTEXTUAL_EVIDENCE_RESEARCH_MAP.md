# 从规则拼装到可评测的情境证据决策

核对日期：2026-09-19。本文区分论文原方法、项目适配和未完成工作，不把模块组合自动称为科研创新。

## 核心研究问题

在同一个角色、同一段近期对话下，改变证据的主体、时间、认知边界或可靠性，系统能否相应改变“取用哪些证据、采取什么行为”，同时保持人物稳定特征？

值得研究的是这种条件依赖和可验证行为，不是增加一批“遇到某词就切换语气”的规则。一个可检验的假设是：**授权过滤 → 情境召回 → 证据判断 → 人设条件行为 → 证据条件生成**，能减少相关但无用的记忆注入与叙事层混淆。假设尚未被本项目的最终独立实验确认。

## 新版基准的适用范围

[LongMemEval-V2](https://arxiv.org/abs/2605.12493) / [官方实现](https://github.com/xiaowu0162/LongMemEval-V2) 已在官方原版仓库链接。V2 侧重网页/企业代理轨迹中的状态、流程、易错点和前提意识，不是原版对话事实记忆的直接替代。

其后端接口明确隔离问题 ID、题型、答案等评测元数据，这一点适合借鉴。项目新增适配同样做到：只让检索看到查询、带说话者和日期的原文；官方 `answer_...` 会话 ID 会映射为中性 ID，`has_answer` 不进入嵌入或提示。不能把网页代理成绩等同于本项目的中文角色聊天成绩。

## 实测后调整的路线

1. **不直接推广更大的精排器。** 真实 BGE 三种输入视图均未超过原规则 Hit@1；结构化输入改善 Hit@5，不足以宣布整体胜出。保留默认关闭和逐题分歧审查。
2. **先验证用途判断。** 中文挑战中 MiniLM 增加召回也增加误注入，所以后续比较“旧召回”“扩大候选”“情境选择”，同时看精确率、召回率、负例注入和服务失败。
3. **让比较覆盖反事实变化。** 同一查询改变人物、同一人物改变用户边界、同一事实改为过期/第三方/角色猜测。人物变化不应强迫每题行为都不同；任务和边界优先。
4. **不要用已有错误生成自我强化的数据。** 新训练样本必须经过来源审核；反事实、原始样本及同来源证据整组划分，不随机拆到训练和测试。语气好的错误答案可以作 rejected，但不能作 chosen。
5. **最后才学习联合路由。** 收集各策略在独立开发场景中的真实回答收益，训练小型决策模型；验证集固定后不反复挑分数。若只优化策略标签而不评估最终回答，会把“动作看起来合理”误当成用户体验改善。

## 推荐正式实验

- 检索：候选覆盖、证据精确率、时间/主体/叙事层错误、无答案错误注入。
- 行为：明确任务保留、拒绝建议边界遵守、无依据关系升级、人物价值观一致性。
- 生成：最终事实正确、引用可追溯、未知时恰当拒答、人物自然度；匿名随机顺序双人评审，分歧留存。
- 因果消融：同模型、同索引、同固定测试，分别打开记忆选择、策略条件、精排、LoRA，再测组合；别把同时更换模型和数据后的差异全部归给某个模块。
- 统计：按完整用户轨迹/原作场景分组，而不把同一事实的改写当成独立样本；报告分母和不确定性，不以十几题的百分数代替稳定提升。

当前已有代码合同测试、真实本地生成模型的证据选择/策略诊断，以及开发和公开子集检索结果；新 LoRA、独立中文终测、最终回答人工盲审均未完成。

## 公开中文人物评测的补充依据

进一步核对 [CharacterEval](https://arxiv.org/abs/2401.01275) 的标题/摘要、[官方 README](https://github.com/morecry/CharacterEval)、生成/格式转换/计分脚本和 MIT 许可。论文概述为 77 个人物、1785 段多轮对话、23020 个样例与四类十三维评价；**本轮实际获取的公开 test 文件**则是 4564 条、77 个出场角色，画像文件含 78 项，4531 个 ID 有维度映射，共出现 12 个维度标签。不能将论文全数据规模写成本次已运行规模。

固定仓库修订 `c3d44a6fc1790cc8c4b2fd7c01f0c72930655e0c`，数据保存在项目外缓存，未导入训练/人物注册表。测试文件 SHA-256 为 `6d9723a1484f1d2739bcf388c7960abe1933b7a5a1fddae0170cc9ea7c66dcd8`，画像文件为 `d9b4c9f7ab63b89b3c348ae88b43c87872f0f6a5cb06d7f31cbe64a630e6434e`。公开仓库许可不自动解决底层小说/剧本的全部再分发权利，故不将原文批量复制到本项目。

对项目最有用的是把“言语一致、行为一致、对话一致、知识准确、知识幻觉、知识曝光、自然度”等拆开评估，不用一个相似度概括人设质量。官方转换脚本会跳过 ERROR/空输出并只取第一行；本项目的完整回复审阅应保留失败分母、完整输出及守卫回退。如果另做官方兼容分数，必须单列这种转换，不能冒称与完整回复评审相同。尚未下载/运行 CharacterRM，也没有新的人工分数。

另核对了 [RoleLLM](https://arxiv.org/abs/2310.00746) 的摘要及[官方实现说明](https://github.com/InteractiveNLP-Team/RoleLLM-public)。其角色资料、Context-Instruct 知识提取、RoleGPT 风格示范和 RoCIT 训练说明了知识/风格/角色条件应分别设计。本文不把现有选择器叫做 RoleLLM 复现，也不直接将其公开角色样例混入月社妃 LoRA；那会改变目标人物与数据分布。

## 进一步实测取舍

另核对 [Self-Consistency Improves Chain of Thought Reasoning in Language Models](https://arxiv.org/abs/2203.11171) 标题和摘要：原方法采样多条推理路径，按最终答案的一致性聚合，主要报告算术/常识推理任务。这里仅借鉴多次采样与一致性比较，不将记忆 ID 集合投票叫作原文完整复现。逐 ID 多数可能拼出没有任何一次完整提出的组合；因此又补充“完整集合严格多数”回放，未达成集合共识算决策失败，不能当作正确拒答。失败使用 consensus 命名，避免把模型均正常返回时的分歧误记为接口故障。没有存储或展示推理草稿。

直接选择、四维审核、先理解再选择，在原 24 题分别正确 19、19、20 题，在 16 条迁移探针分别正确 11、12、10 题。按“一对两题都对”计分分别为 **3/8、4/8、2/8**。增加步骤不是稳定提升；探针基于已知错误由 AI 编写，不能称为独立终测。

Qwen 模型卡建议非推理采样温度 0.7/top-p 0.8，推理模式 0.6/top-p 0.95，并明确不建议推理模式使用贪心。离线对照现支持这些参数、固定种子及推理结束边界；不改变线上默认，也不把一次种子结果认作稳定提升。
