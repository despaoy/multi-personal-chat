# 长期记忆 M2：事项生命周期

## 行为

只对明确、短句式事项执行确定性规则，不新增模型、定时任务、数据库表或迁移。默认规则路径接入；手动开启后台 LLM 记忆的部署仍走原后台路径，本轮不替换其写入逻辑。

| 用户说 | 系统记录 |
| --- | --- |
| 我明天要面试。 | 计划中；把“明天”固定为记录当天 +08:00 的下一天 |
| 我正在准备毕业答辩。 | 进行中；日期未确定 |
| 面试已经结束了。 | 唯一匹配的未结束面试改为已完成 |
| 面试取消了。 | 唯一匹配的未结束面试改为已取消 |
| 面试推迟到后天了。 | 已延期；更新计划日期 |
| 面试延期了。 | 已延期；清除旧计划日期，不继续当作确定日期 |
| 原计划日期过去，用户没说结果 | 检索时显示“日期已过，结果未知”，不自动推断完成或失败 |

计划、进行中、已完成、已取消、已延期作为 `metadata.event.state` 保存。数据库的 active 表示“当前有效版本”，不是“仍未完成”；完成后的经历仍可以被回忆，文本明确标注已完成，不再伪装成未来待办。更改沿用版本化替代，原句、消息来源和旧版本保留。

## 实现路径

`memory_extractor` 的现有门禁 → `event_memory.parse_event` → `write_rule_memory` 分流 → 唯一事项匹配 → 版本化追加 → `memory_service` 读取时呈现日期与状态。

普通聊天不新增事件查询。只有提取出事项时，读取当前用户、角色、会话范围内的有效记录进行匹配；不会跨用户或群聊修改。此读取目前无数量上限，是为避免被旧候选上限截断而误判唯一性；大规模事项库可后续改为专门的索引查询，不需要增加模型。

检索仅补充事项主题字段的词面评分，避免新增状态、日期标签稀释短问题的相关度。未改全局候选数量和检索架构，不代表 M3 已完成。

## 明确边界

- 覆盖面试、考试、答辩、会议、体检、旅行、项目、论文、申请、保研及带具体名称的这些事项；其他复杂表达仍沿用原提取行为。
- 日期仅支持今天、明天、后天和完整 `YYYY-MM-DD`，按 +08:00 日历日处理，不识别小时、下周三、农历或用户自定义时区。原词保留在证据里。
- 事项按完整名称匹配。同名、不同日期可以并存；多个未结束候选时，不执行模糊结束/延期。无对应事项时，不把孤立的结束句擅自接到其他记录。
- 不解析“那个结束了”，不进行跨句代词推断，不处理同义名称自动归并。
- 已结束事项不会被同一日期的普通计划句自动重开。延期后再次提原日期，如果复用了原记录键，则保守跳过，不猜测是改回日期还是另一次事项。明确改期请使用“面试推迟到 YYYY-MM-DD”。
- 同类未定日期事项也可能与新定日期计划并存，复杂情况需明确名称或通过已有记忆管理修改。未添加新的强制确认或审核界面。
- 只对旧 `goal_事项名称` / `promise_事项名称` 的唯一精确匹配做生命周期升级；不批量重写旧数据，也不自动更改关系备忘录。
- 当前句仍在生成后回写；这轮未改变先生成、后保存的会话时序。模型当轮还需依据当前用户消息理解取消/完成。

## 验证

固定时间测试覆盖跨日时区、原句来源、完成/取消/延期、重复、歧义、隔离、旧记录兼容、同消息顺序、实际检索的过期标记以及聊天完成入口。测试使用临时 SQLite；未修改真实数据，未做真实模型对话效果实验或 PostgreSQL 实库验证。

本轮主流程回归 218 项通过；后台记忆兼容、证据编译与事件的补充测试 85 项通过（两组有重叠，不相加）。改动模块静态检查通过。

研究取向延续 M1：借鉴 LongMemEval 的时间与更新评测维度、Zep 的时间/来源区分；不复现完整图系统，也不使用论文结果作为本项目效果结论。
