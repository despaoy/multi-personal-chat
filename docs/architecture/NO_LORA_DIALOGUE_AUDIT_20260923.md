# 无 LoRA 人物对话链路审计（2026-09-23）

## 结论边界

本轮重点是长期记忆、动态上下文、作品 RAG 的实际协作，不是 LoRA 训练。
不能把单元测试通过、接口返回成功或命中某条记忆等同于人物模拟达标。
目前已确认存在软件链路缺陷，也存在证据已经给到模型、模型仍不正确使用的问题。
尚不能据此断言“换更大模型就能解决”；那需要相同输入、相同证据的模型对照实验。

## 测试设计

- 使用服务器现有 Qwen3-8B-AWQ，基础模型，未加载 LoRA。
- 现有 300 个三轮场景草稿冻结为输入，另增加 8 个现有作品索引场景，总清单 308 个。
- 按场景 ID 在修改前固定开发/保留划分；保留集未用于本轮修改。不是声称完全盲测。
- 最终提交模型的对话为开发集 75 个、保留集 41 个。预先排除 192 个需要夹具或超出本轮范围的场景；提交过也不等于完整场景验收通过，见下方追加覆盖审计。
- 每个场景独立用户，实际模型连续回答三轮；真实写入隔离 SQLite，不向生产聊天或记忆库写测试数据。
- 额外对记忆相关场景做无历史探针：保留同用户持久记忆，移除对话历史，重新生成最后一个问题；不写回探针输出。
- 逐轮记录准备后的上下文、注入记忆 ID、所有模型请求/回复、检索证据/引用、守卫重试/回退、写入结果及持久记录。
- 后续审阅以这些证据区分提取、持久化、召回、提示组装、生成与守卫问题，不按答案关键词计算“人物相似度”。

运行参数：`MEMORY_LLM_ENABLED=false`，动态语义选择/决策开关关闭，长期记忆语义检索默认开启，模型上下文窗口 8192。未增加线上评审模型调用。

实际提交的场景类别：日常身份 14、多轮承接 11、意图任务 14、边界安全 13、基础记忆 14、条件否定 12、版本更正 4、事项状态 9、时间歧义 7、关系 4、节奏预算 1、原作 RAG 8、输入边界 5。共 116 个三轮场景；排除项为外部夹具/范围外 105、操作指令夹具 52、状态夹具 35。类别名称代表探索范围，不代表其中所有机制已验收。

### 已知评测限制

1. 第一版基线执行 78 个场景，其中 3 个后来发现前置夹具未落实，已从最终开发集排除。基线不能直接用 78 作同口径通过率分母。
2. 早期脚本把额外只读观测放入生产写入超时范围，可能触发观测超时。最终脚本已移至生成之后；早期延迟不用于性能结论。
3. 早期隔离源码副本只有索引，没有原文目录。最终副本补齐原文；原文效果对比存在这一夹具差异，不能全归功于代码修改。
4. 模型对话测试通过服务编排入口，不代表浏览器渲染、鉴权、平台回执或真实 PostgreSQL 已完成端到端验收。
5. 采样回复有波动；没有用一次输出的好坏推导统计显著性或人物相似度百分比。
6. 冻结清单复核又发现覆盖缺口：`afc2c5cd4290`（UTC 换日）未实际注入指定时钟；`6386f84be725` 未预置“两条助手问句”；`6ebad286dc0f`、`a2231553d203` 仅执行服务输入，未执行浏览器检查。这些可保留为探索性对话记录，但不能宣称对应夹具/界面检查通过。安全场景也仍需人工安全评审。
7. 真实模型运行集中于当前已注册人物月社妃；跨人物隔离以仓储/服务回归测试覆盖，不等于多个人物都已完成真人相似度评审。
8. 取消按新近程度截断后，候选读取与排序成本随授权记忆量增长；最终提示数量仍受限，但不能据此声称大规模延迟已验证。501 条干扰记录回归不是生产容量压测。

## 通用修复

| 缺陷 | 修复 | 独立验证 |
|---|---|---|
| 历史未区分人物，基础模型人物共用历史 | 新增 `messages.characterId`；贯通保存、仓储、SQLite、PG、编排读取 | 两个人物、同账号、不同账号、超过查询上限的干扰历史 |
| 群与频道同号混入、同时间顺序不稳定 | 按会话类型过滤，使用时间与 ID 双排序 | 同号不同类型、同时间两轮 |
| 旧记忆先被最近 30/100 条窗口丢弃 | 默认在授权范围内排序后选择；显式候选上限仅留给旧消融实验 | 31/101/501 条干扰记录；真实持久库无历史召回 |
| 历史便签被误标成长期记忆命中 | `memory_status` 依据实际注入的记忆 ID，不依据参考文本是否非空 | 有便签但无持久记忆 |
| 外部检索失败把个人回忆一起否定 | 收紧弃答约束作用域，仅限制需要外部资料的事实 | 提示契约及真实开发集；模型服从仍不稳定 |
| 无实体的作品追问没有检索上下文 | 从最近连续的用户话题恢复已注册知识域，不引用助手猜测，不越过转题 | 两个替换人物、无关转题、助手虚构不进入查询 |
| 已有检索证据中的人物名被误判为无端搬用原作 | 只放行本轮检索证据中实际出现的名字，其他守卫不变 | 有证据名字不触发额外改写 |
| 假设/选择问句被守卫误当偏好断言 | 区分条件与问句，仍保留独立事实断言检查 | 非饮品替换场景；并非完整语义蕴含校验 |
| 多条证据重复同一父场景 | 按场景 ID 去重，保留各事实引用 | 两个事实共享同一场景 |
| 已抽取的原文未传到最终模型证据 | 原文摘录带出处放在证据前部，避免被重复背景挤掉 | 原文文本实际出现在最终检索上下文 |
| 事实问句被“喜欢/完成/录取”等词误判成喜悦分享 | 先区分问句与陈述，再计算积极分享与自我披露；建议、问候、求助仍走各自已有分类 | 绘画、运动、申请、录取四类问句，以及庆祝后提问、难过后求建议的回归 |

另补充了运行时能力边界与现实急症求助提示。它们与冻结的训练提示契约分离，**提示存在不代表模型可靠服从**，真实回答仍需审阅。

以上不是把测例答案写入代码：没有按场景 ID、人物专属答案或测试数据建立回复分支，也未修改冻结人物训练数据、保留金标或作品知识卡。

## 尚未解决的问题

- **提取覆盖不足**：省略主语、并列偏好、复合基本信息会漏存；最近历史可暂时掩盖漏存。
- **召回意图不足**：泛化提问可能有记录却未注入，需按证据任务而非不断添加问句词表改进。
- **证据服从不足**：已有否定/条件证据时仍可能解读成情绪；无记忆时也可能直接猜一个短答案，现有句式守卫抓不到所有情况。
- **事件歧义**：存储层保守保留多场事项，但回复可能擅自断言全部取消。数据库没有误改不等于回答没有误导。
- **自然度不足**：重复“嗯”、连环追问、分享被解释成隐藏动机、助手式服务话术，以及随意补造角色自身偏好。
- **现实能力与安全**：曾承诺实际提醒、面对现实急症回应不足。不能仅靠增加一句提示就宣布解决；这是部署前的重要门槛。
- **输入边界误伤**：正常代码/HTML 展示请求被输入验证器拒绝，和记忆/RAG 核心问题分别记录。
- **长证据完整性**：默认轻量参考区仍有截断边界；本轮未将其伪装成已经完整通过长文夹具。

### 人物模拟的审查维度

不能用“提到了人物名”或“采用某个口癖”判断相像。以下结合当前人物画像与逐轮事实审阅：

| 维度 | 检查内容 | 已观察到的缺口 |
|---|---|---|
| 身份与主体 | 角色、用户、原作同名人物能否区分 | 用户网名仍可能被当成原作身份 |
| 价值与关系 | 独立判断、尊重边界、关心具体事情是否一致 | 有时把简单庆祝解读为隐藏问题，缺乏语境依据 |
| 记忆连续性 | 已确认事实、更新、否定、限制是否保留 | 复合表达漏存、泛化问句漏召回、缺证据时猜测 |
| 原作可靠性 | 回答、引文与实际检索证据是否对应 | 检索改善不保证生成时不添油加醋 |
| 对话自然度 | 分享、陪伴、沉默、转题、结束是否得到合适承接 | 重复追问、“嗯”密集、助手式服务话术 |
| 现实边界 | 不虚构现实行动与工具能力 | 虚构上午活动、承诺提醒等仍有出现 |
| 风险应对 | 人物语气不能压过现实求助 | 急症回应仍不足，不能部署验收通过 |

这些是定性审查结果，不是经多人盲评校准的相似度评分。后续宜在相同输入证据下做基础模型对照，并按上述维度独立评审，而不是继续叠加口癖或针对错误回答写模板。

## 部署与数据兼容

本轮只修改本地代码和 `/home/boot/lhm/` 内隔离评测副本。没有发布 GitHub、覆盖线上源码、迁移线上数据库或重启生产服务。

新增迁移：`backend/alembic/versions/010_message_character_scope.py`。
已有未标注人物的消息仍保留可查看，但不猜测归属、不注入具名人物的历史；这会使部分旧历史不再自动承接，需要部署时明确告知或另行进行可核实的迁移。
PG 消息保存同时补齐原先遗漏的分支身份字段，避免分支消息失去作用域。

## 复现入口

```text
python -m evaluation.dialogue_audit --suite <冻结suite.txt> --output <新的隔离目录> --split dev --memory-only-probe
python -m evaluation.dialogue_audit --suite <同一suite.txt> --output <另一个新目录> --split holdout --memory-only-probe
python -m evaluation.dialogue_audit_report --trace <traces.jsonl> --trace <probes.jsonl> --output <新的报告目录>
```

必须先配置同一模型服务和索引；评测模块自行使用隔离 SQLite。不要在导入应用数据库之后才切换数据库变量。
输出 `generated_not_yet_reviewed` 只表示拿到了回复，绝不表示检查项通过。
