# 记忆有效时间契约：审计结论与待实现边界

## 已确认的问题

同一用户原话“我这周在柳州出差，下周就回去。”，真实模型两次给出的区间分别为调用时刻起七天和零秒。两者都通过ISO格式校验；零秒记录在保存后一分钟已被当前召回过滤。七天区间也不能算正确：用户没有说从发送时刻起恰好七天。证据为 `.tmp/mechanism-r100-validity-audit.json`，基于r97/r99真实输出与实际召回函数，非新模型调用。

另一个独立缺陷是时间基准漂移：模型payload曾使用后台处理时刻，规则提取曾使用回答结束时刻。r100已将其统一到服务端prepare记录的received_at，规则与事件写入也传递同一observed_at；直接内部调用无显式时间时取入口时刻。payload同时给UTC和项目现有事件时区+08:00的同一时刻，不推断用户的个性化时区。跨月、跨年、闰日及UTC跨日本地测试已覆盖。它不认证模型输出的valid_from/to。

## 下一阶段必须满足的语义约束（尚未全部实现）

1. **来源、观测、有效时间分离。** 原话与source ID不可被模型日期替代；observed_at来自服务端，created_at属于事务；有效时间必须携带来自原文或可信解析的依据。只有ISO格式合法不构成依据。
2. **时间点不伪装成零长度区间。** 现有召回使用半开区间。一天内发生的事件应有点/日期精度，不应通过相同起止值表达“当时发生”；持续状态的零长度区间不代表有效信息应马上消失。
3. **粗粒度不伪造精度。** “下周回来”最多给出日历范围，不能伪装成明确的某日某时某微秒。消息锚点和时区要固定；结束不确定应保留未知或范围，而非补齐模型猜测。
4. **证据保留与当前断言分离。** 未能确定有效期不应删除整条用户陈述，也不应简单清空所有日期后将其永久当作当前事实。应保留带消息时间的原始陈述，并明确区分“曾经提到”与“当前已确认”；这需要与现有source/episode读取及当前记忆投影协调。
5. **投影策略可观测。** 必须能区分明确过期、未开始、时间未解决、区间无效、解析失败。不得用一个“无记录”掩盖这些状态，也不应让临时计划阻止不相关稳定字段的直接读出。

## 验证要求

使用独立用例覆盖绝对日期、相对日/月/周、跨年、闰日、来源时区、延迟写入、点事件、持续状态、只知开始、只知结束、改期和取消。要同时观察源陈述是否保留、当前投影是否正确、历史查询是否可达、生成是否误断言；不能只断言数据库里有一行。

现有“>=起点且<终点”的执行契约、模型日期进入持久化的路径均仍在。r100没有将新时间策略上线，没有把所有日期清空或将异常候选全部拒绝。下一步需先实现明确的时间精度/来源表示，再选择可验证范围内的执行行为；未经验证的日期不得被包装成确定事实。

## r101–r102 已落地与仍未实现的边界

- r101提供精确保留的日历表达解析并接入既有事件规则。日期范围不代表事实持续区间。
- r102新增语义写入metadata.temporal_provenance：版本、生产路径、可信观测时刻、模型原始端点文字及精度、端点是否逐字出现在证据中、区间形态。所有模型端点的role_verified仍为false，文字出现不证明起止角色。无端点表示unspecified，不表示永久有效。模型自行输出的同名metadata不会透传。
- 已验证的qualifiers.time如逐字出现在证据中，可作为source_span保留解析结果；角色保持unspecified。没提供该字段时不会假装已抽取所有源时间表达；r97/r99的两份出差输出都没有可用time qualifier，因此此字段仍空。
- 原始日期精度在parse_llm_proposals进入旧ISO归一化前保留。旧归一化会将date-only及naive datetime补成UTC；新元数据将date-only标为日历日，将无时区时刻标为unresolved，不沿用该假精度。但旧顶层valid_from/to和召回执行尚未切换，所以本轮不解决提前过期。

下一步必须联动当前投影、历史/source读取、字段存在三态、证据包与快捷回答，不能只改过滤条件。独立规则能支持的稳定自述应保留可靠读出；未知时效的原始陈述应可作为带来源时刻的引用而不是当前断言。r99真实住址输出也自动附带模型起始时刻，所以“凡有模型日期就全降级”会破坏正常住址回答，不能作为最终方案。还需要处理未来更新不应立即替代当前版本、粗粒度结束范围与明确事件时间的角色验证。上述都是未完成事项。

## r103 本地读取策略

已对r102产生的version=1、producer=semantic_memory、validity_authority=unverified记录接通读取视图，不更改存储行或迁移旧记录。仅接受具备观测时刻、原话和source IDs的记录：

1. active/current稳定自述如可被既有规则独立完整支持、content/key一致、无qualifiers、显式第一人称开头、无可检测时间限定，则按观测时刻起、直到后续版本修改的日常状态约定读取。不是证明该事实永久为真。
2. 其他记录变为observation原话引用，携带可信观测时间和时效未知标志；模型提议不再使引用提前过期。当前字段快捷读取不能把引用当成值，未知也不转成“没有记录”。已有明确typed字段不被无关legacy引用抹除。
3. 被替代/归档记录不重新开放为无限有效的状态；历史原话按观测点落在查询窗口内匹配，而不是把观测时刻当无限区间。撤回/删除及pending默认排除规则保持。
4. 证据编译和选择器数据携带temporal_mode/observed_at，源引用包不把观测时间标成事实有效期。明确原话查询入口支持这些已验证生产路径的来源记录，仍显示时效未核实及来源日期。

还发现规则提取可把“到年底/三个月”等吞入实体值，故相同content并不能单独证明稳定。source_temporal_spans只作通用日历/时长/边界词的词面信号，不给语义角色，不推断日期；发现信号时保留引用而非直接断言。此词面信号并不覆盖所有自然语言，而且可能命中名字中的时间词，需要实际对话评估，不能宣传为完整时间理解。

尚未解决：没有模型端点的未定时效记录、历史旧schema迁移、未来提议提前SUPERSEDE旧事实、一般时间角色与精确有效区间验证。r103仅本地，真实历史输出组件重放成功不等于新模型端到端使用体验认证。

## r117：缺失模型端点不再绕过相同的读取判断

version=1、producer=semantic_memory 的 unspecified 与 unverified 现在使用同一来源投影。只改变模型端点的有无或值，不再改变命题是否可作为当前状态；未知schema、其他生产者及生命周期规则不变。仍不修改存储记录，不增加模型调用，不认为无日期等于永久有效。

独立规则支持的完整当前自述仍可直接读出；规则不覆盖的真实陈述保留原话，但可能不能成为结构化字段。这仍有明显不足：自由生成的content与规范模板不同、复合证据、年级表达等会产生不必要的未知状态。修复日期一致性不等于这套窄规则已经有充分覆盖；也没有解决未来更新提前替代、完整时间角色和旧schema迁移。
