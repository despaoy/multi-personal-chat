## 研究依据与采用范围

2026-09-26重新读取官方README相关段落（没有复现论文全量结果）：

- [LongMemEval](https://github.com/xiaowu0162/LongMemEval)：独立评估提取、多会话、更新、时间、拒答；检索以turn/session为原始值，扩展索引键；以证据轮/会话定位计算召回。采用“证据可检索”和“派生事实正确”分层评测，不采用其大上下文预算或假定英文成绩能迁移到中文人物。

## 待实现的最小实验

1. 数据库已保存消息作为原始来源，不复制一份永久“事实”；查询必须同时约束用户、角色、平台、adapter和群聊/分支范围，沿用delivery过滤。管理后台全局搜索接口不可用于人物私有记忆检索。
2. 候选返回原始user消息、对应assistant、消息ID、发言时间、会话ID。助手可用于理解对话，但不是用户事实证据；不截断user内容。不保存指令性摘要，不把凭据/拒绝记忆内容重新暴露给长期记忆路径。
3. 离线先比较turn和完整会话窗口；普通关键词召回可能只命中旧计划，必须评估后续更正覆盖。不能按“最后一句”推断更新目标，也不能把邻近更正直接应用于多个事件。上下游证据必须在同一预算下比较。
4. 输出独立证据包（历史陈述，不保证当前有效），与active事实分开。来源时间不等于事项日期；“周六”歧义不得任意归一化。原话中的指令仍不执行。
5. 先用日志离线回放确认召回，再接入隔离SQLite全链路；生产PG与浏览器E2E另列未验证，不能以模拟PG替代实际事务验收。

## 验收矩阵

- 多个不同事件、相同主题不同日期、跨轮省略替换、取消后新计划、完成后重开、无日期纠正；新旧证据是否同时完整出现。
- 用户/角色/群聊/私聊/分支/交付失败隔离；显式不保存、已删除来源、敏感信息不经另一通道回流。
- 虚构在前/在后、回到本人、整段撤回、助手编造；测证据归属和最终回答，不能只测“没有保存错误”。
- 长历史超过24轮、超过16000字符；完整轮边界、末尾限定、事件时间与当前时间；不把超预算删光信息算最终成功。
- 与结构化事实已有正确召回对照，记录新增检索耗时、输入长度、真实模型调用数，普通对话不新增LLM抽取/审查调用。

## r70离线结果

新增evaluation/episodic_recall_audit.py，仅离线合成资料，无数据库/模型调用或运行时接入。相同scope先过滤，再比较字符bigram命中的单轮和完整会话，完整JSON包预算（包含元数据/转义），只按用户原文打分，助手不能产生命中。拒绝记忆/敏感资料使该会话整体不候选，避免丢掉纠正而保留旧计划。scope和私聊归一化只是试验调用契约，不等于生产授权验证。

3类×2预算×2模式共12个对照：同会话无词面重合纠正，session补回而turn漏掉；跨会话纠正两者都漏；两个事件加含糊撤回，session在1500字符完整，在350字符整包放不下，turn两种预算均漏撤回。完整证据也不代表撤回目标可确定，回答应保留歧义。未调用模型、不评最终回答，不把这种小合成集当泛化分数。

因此不能直接接入“命中原始消息就当现在事实”。下一步应测试跨会话后续更新窗口、任务/事件归属和无词面纠正的召回；同时量化预算挤出与无关后文干扰。若无法保证更新覆盖，候选只能是有时间来源的历史证据，不可填充active字段或绕过当前事实验证。

## r77来源角色与事实主体分开表示

2026-09-26重新读取[LongMemEval论文摘要](https://arxiv.org/abs/2410.10813)、[项目README](https://github.com/xiaowu0162/LongMemEval)与[Graphiti抽取结构源码](https://github.com/getzep/graphiti/blob/main/graphiti_core/prompts/extract_edges.py)。此处未声称完整复现论文。LongMemEval将indexing/retrieval/reading分开，其README保留user/assistant角色，且推荐普通历史不要默认user_only；本项目仅在个人原始证据读取中试验user_only，普通助手历史仍完整保留，不能把局部消融推广成全局删助手。Graphiti结构明确source_entity_name、target_entity_name、episode_indices、valid_at/invalid_at，实体消解依赖抽取和历史，而非简单时间排序。尝试读取resolve_edges.py返回404，未将不存在文件当依据。

r74–76证明：完整检索不等于正确读取；来源发言者不能自动等于句中事实主体；未知取消对象不能凭最新时间替代事件标识。现有SQLite scope保存了speaker ID，但原包没有机器可读的speaker_role。r77仅新增实验provenance视图：标明historical_user_utterances、speaker_role=user、speaker_id和conversation_character_id；described_subject/current_validity仍not_resolved。此为数据库来源元数据，不是LLM生成结论；不能因为说话者是user，就把引用、朋友或小说句子登记为用户事实。

先在冻结完整链路输入上比较compact与compact+provenance，人物system、问题、24轮历史、原话/时间/ID不变。语义有效性未知，不能据元数据直接跳过外部检索、自动回写active事实或宣称主体问题已解决。更新边/事件有效状态只有在独立可靠的语义识别与歧义验收后才能成为默认机制；本轮不添加图数据库或每轮LLM审查。
