# 后端优化与验证策略

核对日期：2026-10-19。本文件规定后续开发与验收方式；已完成的验证以阶段报告和当前运行结果为准。

## 架构与职责

- 保持模块化单体。API 处理协议、身份与响应转换；业务服务编排任务；仓储负责持久化边界；模型适配器处理外部调用与结果转换。
- 明确依赖归属：应用容器绑定数据库和调度资源；请求持有已解析的模型连接、预算、历史与证据；后台任务持有独立完成回执。读取、写入和回执不得跨应用数据库。
- 同一持久化依赖的仓储包装共享缓冲身份；角色和既有用户范围继续隔离。即时任务先提交同范围的旧缓冲，再按顺序处理。
- 业务规则和数据转换保留单一权威实现。移除已确认无调用方的兼容入口、重复状态、重复清洗和无效抽象；保留必要事务、权限与资源释放边界。

## 配置和失败行为

- 为每类设置定义来源、优先级与生效时机，区分未配置和显式无效值。已解析的请求配置不得在处理中被其他请求改写。
- 按显式配置选择模型、数据库和检索模式。必需依赖不可用、响应结构错误或无法满足约定时报告具体失败；禁止静默换模型、换数据库、返回模拟数据或旧缓存。
- 重排启用后，模型加载或打分失败直接上报。确定性排序属于显式选择的模式，不能作为模型故障后的替代路径。
- 超时、取消和有界重试对应明确的任务状态。观察等待超时不代表任务已取消，也不能另建重复任务；只对可安全重试的暂时性故障重试。
- 已生成回复与后续存储分别反馈结果。保存失败不能显示为已保存，也不能触发重复推理；部分写入保留已发生操作及失败阶段。
- 合法无匹配、证据不足、安全拒绝与系统故障分别表达。群聊和私聊都不得把上游故障静默当作成功。

## 记忆、RAG 与上下文

- 用户原文保留完整的否定、条件、时间与人物归属。意图、摘要、检索问题和模型推断可追溯到来源，不能提升外部资料的权限或可信度。
- 在请求、数据读取等信任边界校验文本，内部使用已验证数据；合法缩进和换行原样传递，不反复清洗。历史保持角色结构，助手推断不得转为用户事实。
- 角色作品索引、用户知识库和私人记忆保持各自来源与授权范围。使用实际可见证据回答，缺少必要证据时明确说明。
- 回答缓存绑定实际输入、历史、来源版本、模型连接与生成参数；复用如实标记，不能当作新的模型调用或真实验证。来源变更或读取故障不能由旧结果掩盖。
- 不新增语义关键词规则或未训练分类器。需要语义理解时使用显式配置的模型环节；启用后的审核失败不以规则状态替代。

## 安全与运行边界

- 鉴权、签名、防重放、来源校验及凭据保护遵循[安全策略](../../SECURITY.md)；日志不记录密钥或不必要的用户原文。
- 后端保持 BACKEND_WORKERS=1；进程内并发任务遵守容量、限速和会话顺序，服务交由受监管进程管理。
- Claw 代码执行默认关闭；处理不可信代码时采用受限容器，并保留 CPU、内存、时间及文件访问约束。
- 模型训练、LoRA、部署和外部服务的实际验收范围记录在[发布检查表](../RELEASE_CHECKLIST.md)，与单元测试结果分别说明。

## 修改与验证

1. 先审视真实调用链、依赖和现有测试，用完整、隔离的资料复现实际问题。
2. 按独立问题修正根因，验证成功路径、失败路径及相关授权边界；常规实现保持直接，避免逐层增加保障分支。
3. 只运行受修改影响的测试和必要关联检查。接口改变时迁移调用方与测试替身，保留有效业务断言；不靠放宽结果或删除有效检查获得通过。
4. 完整阶段需要检查跨模块组合时执行一次整体验证；发现问题后只复测失败或新增修改影响的部分。
5. 区分受控模型输出、缓存复用、真实模型调用和人工质量评价，记录完整前提及各自局限。功能达到约定的可用标准后结束该项优化。
6. 服务器先修改和验证，有效后同步本地，再按阶段同步 GitHub。代码、模型权重、持久化数据和运行记录分开保存，不提交密钥或私有对话。

当前开发范围包含本地与内网服务器验证，公网开放另行决定。
