# 对话链路修复与复测（2026-09-23）

## 范围

从真实模型失败样例出发，按入口、记忆提取/更新、动态策略、请求组装、RAG、输出检查逐段定位。业务修改在本地；远程只在 `/home/boot/lhm/multipersonal-runtime/evaluations/chain-fix-source` 运行独立源码和独立 SQLite 测试库，调用现有 vLLM。未覆盖生产源码、未重启线上服务、未修改正常用户数据，未提交或推送 Git。

## 修复内容

1. **人物与 LoRA 解耦**：普通生成请求支持 `characterId`；选择人物不再自动选用其他激活中的 LoRA，基础模型可以使用人物上下文。未知人物、人物/LoRA/分支不匹配明确拒绝。显式人物上下文失败返回错误，不悄悄退成普通聊天。
2. **网页接入**：测试对话新增独立人物选择；明确选择 default 真正表示基础模型。新人物入口的 sender 从登录身份取得，不能使用提交的其他用户 ID。人物切换清空显示；清空按钮明确不删除长期记忆。
3. **上下文预算**：生成请求读取 `VLLM_MAX_MODEL_LEN`，缺省 8192，部署模板向后端传递与 vLLM 相同的值。固定提示/当前问题/证据/输出已超过预算时明确拒绝，历史按剩余预算截断。当前仍是保守字符估算，不冒充 tokenizer 精确计数。
4. **回忆问题误判**：不再把“你记得我喜欢什么吗？”或历史假设句当作偏好事实。明确表达不知道、询问未知偏好不再误报为编造；不同子句独立检查，不能用前半句“不知道”掩护后半句猜测。
5. **记忆状态**：实际查询后无相关参考时，传入 no_match 提示；强调没找到不等于用户没说过。有记忆时要求保留条件、否定、事实归属，不把一条记忆推广成所有细节已知。
6. **提取覆盖**：支持“咖啡我挺爱喝的，不过过了下午三点就不碰了”这类明确饮料倒装句，保留完整条件。完整自我陈述后另起的小说引文不再连带丢弃前面的事实；“我喜欢咖啡，你喜欢什么？”能保留前半句。敏感信息、拒绝记忆、假设、引用内部仍不直接写入。
7. **条件合并**：对明确的饮料限制，“晚上不喝”“不加糖”“不加奶”可以作为独立维度合并，保留原证据与版本。未知条件、同维度冲突仍待确认；不是通用自然语言条件推理。
8. **动态策略**：“你记得我喜欢什么饮料吗”不再因“记得我”触发表达亲近策略；“你还记得我吗”仍保留关系含义。
9. **RAG 路由**：“主人公”不再命中“主人/主仆”关系分区，“哪本”进入事实意图；真实“她的主人是谁”仍保留关系检索。
10. **轻量化**：一般主动建议只做软诊断，不再单独触发第二次生成；明确不建议/不追问及安全边界仍保留硬检查。无相关记忆且唯一硬失败为编造偏好时，直接自然说明记不清，不用第二次模型调用重复猜测。兜底不再提及用户没有见过的“刚才的推断”。

## 同一 8B 模型的效果证据

完整评估先后运行两轮，每轮 12 场景各 2 次，再对后续修正进行小范围复测。只使用合成用户数据。

- **RAG**：实际生成编排入口两轮均回答“月社妃是《缟玛瑙的不在证明》的主人公”，引用正确 fact 卡；此前错误答案为《蓝宝石的存在证明》。支持“路由缺陷是本例重要原因”，不代表所有 RAG 问题解决。
- **基础模型人物记忆**：在独立库调用真实生成编排，先说“我喜欢咖啡，但晚上不喝”，下一轮正确回答“我记得你说晚上不喝咖啡”。没有加载角色 LoRA。
- **自然表达**：此前零候选的下午三点限制现在被保存、召回；模型会说下午四点已超过限制。但仍可能接着主动提出“如果很想喝，也可以陪你点一杯”，因此仅判定存储/召回改善，不判定完整建议效果通过。
- **无依据回忆**：最终回答不再直接交付虚构的柠檬茶偏好；部分样例需要事实守卫兜底，不能据此说模型本身已不再产生幻觉。
- **已知正常行为**：条件保留、偏好改口、籍贯/现居区分、事件完成/延期/取消继续正确。

## 未宣称解决的部分

- 模型仍会机械追加邀约/建议，有时擅自推测限制原因或提出例外；有时把“没查到”说成“你还没告诉我”。已添加约束，但不能仅凭提示词保证消除。
- 新增的自然表达和条件合并是有边界的规则覆盖，不能理解任意省略、指代、多事件或复杂条件。
- 普通记忆检索候选仍有上限。大量记忆时较旧的相关条目可能无法进入候选池；需要带用户范围约束的索引检索和规模测试，不宜简单改为每轮全库嵌入。
- 输出检查不是逐事实语义蕴含验证；“已有一条相关记忆”下的其他细节仍不能全部由规则证明正确。
- 线上尚未替换为修复版。应先审查变更，再同步部署并执行真实网页验收。
