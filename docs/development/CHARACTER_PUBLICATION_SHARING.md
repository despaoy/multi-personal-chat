# 角色库：选入资料的独立分享（2026-11-18）

本轮是独立副本的实现交付，不是上线或角色库最终验收。基线为 `80d6b398ad259d488c1b631cea02046a63c3dfa2`。不代表 Windows 工作区的未提交修改；未推送、部署、切换或启动服务。

## 用户流程

1. 保存角色后，进入“发布角色分享”。独立资料默认不选。可加载当前设定版本的资料版本，选择一份资料集，再逐篇勾选。一次分享最多100篇，沿用原资料集5MB限制；不混合不同资料版本。
2. 发布预览展示完整已保存设定与所选原文。确认发布冻结这些内容；不自动公开未选原文、未来资料、私人聊天、记忆、演进关系或账号配置。设定中的 `relationships` 与 `reference_text` 仍是作者主动编写的角色设定。
3. 接收者登录后先预览，再确认复制该发布编号。产生接收者自己的角色、不可变设定版本及独立资料版本；生成新 corpus ID，索引回执不继承，状态从 pending/attempt=1开始。
4. 作者只改资料也能发布更新。接收者检查更新时看到设定差异、资料新增/替换/移除及双方资料全文。导入前明确确认替换本地修改；确认后生成本地新版本，已有会话继续绑定旧设定和旧资料。
5. 修改角色设定（如开场白）会把该版最新有效资料原子复制到新的设定版本，避免资料悄悄丢失。旧会话保留原版；新资料需要重新索引。
6. 关闭分享后，新预览、复制、作者更新读取被禁止。撤销发布内容引用的作者资料后，整个相关发布的预览/新复制/更新导入被禁止，需作者重新发布不含撤销资料的内容；不静默删掉部分原文继续复制。已经复制的独立副本不删除、不撤销。
7. 原作资料管理继续展示等待、处理中、失败及完成状态，并复用既有失败重试接口。后台 Temporal 配置和服务是运行依赖；本轮没有启动这些服务。

## 数据及事务

新增迁移 `028_character_publications`，在角色表增加 `publication_id`、`source_publication_id`；新增不可变 `character_publications` 和按接收者/request_id唯一的 `character_publication_copies`。

发布编号是角色身份、设定修订、来源资料版本及选入内容的 SHA256。相同确认内容重试复用编号；只改资料也产生不同编号。发布事务核对设定修订和预览时的原发布编号，锁定所选资料未撤销，再插入快照。相同内容并发发布保留同一有效令牌。

复制事务重验精确令牌、发布编号、发布设定版本和资料有效性；角色、版本、资料及请求回执一并成功或回滚。相同 owner/request_id/publication_id 的重试返回已有副本；同一请求改用另一发布被拒绝。已完成复制的重试即使作者后来撤销，也只返回接收者自己的既有副本，不再读取作者内容。

导入作者更新校验接收者设定修订、其预览时的最新有效资料ID，以及作者发布编号。事务内再次检查；并发编辑/新增资料/撤销不能静默覆盖。相同已完成导入的响应重试不再新增版本。原修复的分享关闭/令牌轮换竞争保护保留，实现在 `CharacterPublicationRepository._guards`，原回归测试继续通过。

API新增 `POST /{character_id}/sharing-preview`。启用分享要求 preview_id及选入清单；复制要求 publication_id/request_id；作者更新要求 publication_id/local_corpus_id（允许显式null）。旧客户端直接复制或无预览发布会返回422，需要同步更新前后端。角色包 `multipersonal-character-v1` 的导入导出含义不变，不新增文件格式。

迁移保留既有有效分享链接，将旧已发布设定（不是私人草稿）转成不含资料的legacy快照。SQLite运行时亦支持补齐；不会自动选入旧资料。迁移支持重复升级；降级保留角色/版本/资料，但丢弃新增分享快照及重试映射，不能把降级视为完整数据回滚方案。
