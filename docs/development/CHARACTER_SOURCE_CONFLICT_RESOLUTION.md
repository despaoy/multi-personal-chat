## 选择语义

`choices` 是资料 ID 到 `local` 或 `author` 的映射，没有默认选项。必须恰好包含当前所有可解决冲突，不接受缺漏、未知 ID、非冲突 ID 或其他值。按整篇标题和正文选择，不接收客户端拼接的正文。

- `both_modified`：保留所选一方的整篇版本。
- `local_delete_author_modify`：选 local 表示删除，选 author 表示保留作者版。
- `local_modify_author_delete`：选 author 表示删除，选 local 表示保留本地版。
- `addition_id_collision`：双方独立新增相同 ID 无共同来源证据，即使提交选择也继续拒绝。不得靠选边静默建立来源身份。
- 缺失、撤销、错配、损坏或不再有权读取的共同基线仍拒绝，不返回基线正文或它的逐篇差异。

无冲突资料仍按第一阶段规则保留本地单方增改删、采用作者单方变化。保留本地顺序，追加作者新增；选择删除的篇目不生成空壳。选择完成后重新检查最多100篇、每篇模型约束和总 UTF-8 JSON 不超过5MB。全部删除时不建立空资料集。

## 三步接口

1. `GET /api/character-library/{character_id}/source-update` 保持第一阶段协议，提供本地、作者、冲突 ID 和类型。
2. `POST /api/character-library/{character_id}/source-update/preview` 请求：

```json
{
  "revision": 1,
  "source_revision": 1,
  "publication_id": "作者当前发布编号",
  "local_corpus_id": "接收者当前资料版本编号，或 null",
  "choices": {"a": "local", "b": "author"}
}
```

后端重新授权并加载 B/L/R，计算最终 `settings`、`sources`、`source_merge`、`resolved_conflicts` 及 `preview_id`，返回准确版本标识和选择。预览不写数据库。无冲突也可以使用此接口，必须明确提交 `choices: {}`。

3. `POST /api/character-library/{character_id}/source-update` 提交第2步原请求字段，加上返回的 `preview_id`。不能提交 `settings`、`sources` 或拼接结果；请求模型禁止未知字段。`choices` 和 `preview_id` 必须同时存在，否则422。确认时重新计算，并要求预览摘要准确匹配。

缺漏或无效选择返回422；未知基线、ID碰撞、超限、过期版本/预览返回409；其他账号的角色不可见，返回404。预览没有固定时长失效：状态前提改变即失效。过期后须重新获取计划、逐篇选择及最终预览，旧确认不能写入。

## 预览绑定及事务

摘要以规范 JSON 和 SHA256 绑定账号、目标角色、本地角色修订、作者设定修订/发布、本地资料编号、共同基线编号及内容、本地和作者资料、当前及将写入设定、准确选择、合并计划，以及作者分享令牌。令牌和基线正文仅内部参与计算，不返回给客户端。摘要是内容/版本前提，不代替授权，也不是证明人已浏览页面的凭据。

确认继续使用既有事务守卫：作者仍分享准确发布及令牌，作者资料和共同基线资料未撤销，本地角色修订和最新有效资料编号未变。旧会话不迁移。成功时建立新角色版本和接收者独立资料集，索引状态 pending/attempt=1，不继承作者/旧索引回执。新增资料索引的真正执行仍由既有索引处理链完成。

关闭后重开相同发布会更换令牌，旧最终预览也失效。另一账号或同一账号另一角色副本不能复用预览编号。常规 API 生成的资料/设定版本不可变，本轮没有添加绕过这些版本约束的写入口。

## 幂等与迁移029

新增 `character_source_update_receipts`，主键为 `(owner_user_id, character_id, preview_id)`，保存规范化确认请求和结果修订号，不保存私人聊天/记忆/关系或正文。回执与新角色版本、独立资料在同一事务写入，任一失败全部回滚。

精确已完成请求在结果角色修订仍为当前版本时返回已完成结果，不重复建版本或资料。即使作者随后关闭分享，回执仅确认接收者已有成果，不再读取作者私有内容。选择或请求不同不能借用旧回执；后续角色修订已前进时返回409。本地只更换独立资料而角色修订未变时，重复确认也不重写资料。处理相同确认在准备阶段或提交阶段交错完成的情况；确定性双线程 SQLite 回归验证仅生成一份成果。

SQLite 运行时和 ORM 同步建表；Alembic `029_source_update_receipts` 依赖 `028_character_publications`。PostgreSQL 等使用迁移的环境在启用新协议前必须执行029；本轮未操作真实环境。迁移降级只删回执表，不回退已产生的角色/资料版本，但会失去新协议的完成回执，因此不能把降级当作业务数据回滚。

无冲突旧请求不携带 `choices` 和 `preview_id` 时保持原有导入及幂等协议。存在冲突的旧请求仍409，不通过兼容路径自动覆盖。旧客户端没有逐篇选择网页，因此本轮后端功能尚不能视为网页已交付。
