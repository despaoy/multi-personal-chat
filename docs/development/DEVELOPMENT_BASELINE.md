本文件记录已确认目标与验收边界，不代表当前代码已经完成。现有实现及逐阶段验证见 `CHARACTER_CHAT_FOUNDATION.md`；旧文档的技术待选项以本基线为准。

## 目标与停止条件

补全可运行、可验证的网页角色聊天系统，首版面向个人/少量用户，但账号隔离从开始就实施。角色自然表达、独立立场、长对话连续、可管理记忆和独立剧情分支是核心；不以完美模型效果作为基础开发结束条件。

用户于 2026-11-15 将停止线从 80% 调整为 70%；本周 Codex 额度已用达到 70% 时暂时停止。使用 Codex `get_usage_limits` 的周窗口（10080 分钟）和 `usedPercent`；不能用目标 token 数代替周用量。开始每次目标续行、每阶段结束及较大操作前复查，达到/超过 70% 即保存交接并将目标设为 paused。不能保证计量延迟或其他任务共享用量下精确停在 70.00%。不得自动使用重置额度。2026-11-14 首次核对已用 12%；之后必须重新读取，不沿用此数值。

## 产品范围

- 网页优先；名字、人设、开场白可试聊，支持示范对话、人物关系、场景和资料导入。
- 默认初识，不读取旧关系/记忆。延续关系由用户选已有会话及继承范围；新设定继承旧状态时展示差异并确认。
- 角色设定不可变版本；旧会话保留原版，新会话最新版。分享为独立副本；作者已发布更新由用户选择导入，不携带私人经历。
- 普通聊天保持独立立场；明确假想分支允许覆盖设定，分支保存/继续，历史状态按起点带入后独立演进。
- 最近对话、分段摘要、相关原话检索和场景状态共同维持连续性。
- 回复保存后可靠后台提取记忆、关系和摘要。明确无冲突长期偏好可自动保存；含糊/冲突待确认。用户可查看依据、纠正、删除，并逐条授权把记忆分享给其他角色；手动关系设定不得自动覆盖，涉及其变化需接受建议。
- 编辑替换当前走向；撤回选定消息及后续；派生状态按保留历史恢复。彻底删除先展示关联分支/副本，由用户选范围后立即撤销读取权，再清理原文/快照/索引。
- 原作问答先支持一个预设角色；混合检索、重排、必要上下文展开、实际回答出处快照。资料更新：旧会话选择迁移，新会话最新。
- 主动话题覆盖未完话题、用户事件、符合人设的虚构日常、久未出现问候；离线主动联系按会话授权，频率/免打扰/去重检查；虚构日常留下剧情记录，不冒充外部活动。
- 应用内消息是正式记录；Web Push 需授权，通知失败不能重复创建聊天消息。

## 原始问卷选择与详细产品验收（2026-11-15 核对补充）

已从本线程原始消息核对原题与紧随其后的回答。用户的字母回答有对应题目，不能视为信息缺失；此前答复中“缺少对应题目”的判断撤回。此处恢复已有要求，不是新增加的用户选择。后续更具体的确认优先于早期选择。以下场景是验收示例，不代表模型效果已经验收。

| 原题与回答 | 确认含义 | 产品行为及验收场景 |
|---|---|---|
| 首轮1：ABCD，项目用途 | 角色聊天、原作问答、共同推进故事、创建自己的角色 | 四种用途都保留；不能把共同推进故事简化为普通问答或仅保存一份分支 |
| 首轮2：AC / A / C | 用户为自己或熟人及自建角色用户；网页入口；允许自建角色 | 用户填入或导入人设后能立即试聊，不强制使用唯一预设角色 |
| 首轮3：ABCDE，首次体验 | 人物感、原作出处、选择改变剧情、自建即聊、QQ正确会话回应 | 当前网页验收包含前四项；QQ作为后续平台目标保留，依后续范围决定不在本轮交付 |
| 首轮4：A / B / BC | 尽量贴近原作；关系随对话发展；聊天内及授权后的聊天外主动发言 | 人物以自己的方式回应；熟悉后与初识时的反应不同；未授权不得离线主动联系 |
| 首轮5：C / C | 自动保存部分稳定偏好；用户选择把某条记忆分享给其他角色 | 分享是逐条、指定范围的授权，不是所有角色默认共用用户记忆；后续确认明确无冲突可自动保存、含糊或冲突待确认 |
| 首轮6：B / B / BC | 简短正文、展开出处；先确认角色/场景/时间线；保存并继续、多分支/旧节点/重选剧情 | 问题指代不清时先澄清；同一旧节点选择不同决定，可继续不同走向并切回原会话 |
| 首轮7：ABC，条件为接入群聊 | 仅被@、被@或回复角色消息、允许主动参与三种模式 | 保留后续平台设计；不将三个互异模式理解为必须同时启用，不在当前网页范围中擅自交付群聊 |
| 首轮8：列出的五项 | 自然稳定、连续性、记忆管理、剧情保存继续、自建分享 | 五项均在当前目标，不能因为问卷原先要求选三项而删掉其中两项；按用户列出顺序作为开发优先级 |
| 第二轮1.B | 分享后复制并可修改 | 复制包含角色设定和创作者选入的资料；接收方改开场白不改变作者原版；双方聊天、关系和记忆各自独立 |
| 第二轮2.C，后续默认初识及仅延续才使用旧记忆 | 新会话选择延续或重新认识，默认初识 | 旧会话仍可续聊；新初识不因同账号而自动带入旧私人经历 |
| 第二轮3.A | 从已有消息分出剧情支线 | 从“准备离开”处尝试挽留，保存后能继续支线，也能返回原会话原有进度 |

后续展开题已明确的细节：

- **人物表达**：用词、语气、说话节奏；符合人设的立场及分歧表达；随关系变化的不同反应；主动追问、接梗、提起旧事。普通聊天允许拒绝、争论、提出条件；假想分支允许明确剧情指令改变设定。不得把随口命令默认为全局改人设。
- **创建层次**：名字、人设、开场白即可试聊；可补示范对话、人物关系、初始场景；可导入角色设定文件与查阅资料。具体文件格式兼容清单不能从“支持导入”自动推定。
- **记忆**：能查看、纠正、删除及查看依据；“今天不想喝咖啡”不能未经确认就固化为“平时从不喝咖啡”。纠正后按新状态回应；旧摘要、检索及迟到任务不得恢复已失效的内容。
- **编辑与撤回**：编辑替换当前走向，后续消息移出当前会话；撤回从指定消息开始撤回后续；两者按保留历史重新确定关系和记忆。另开分支与替换当前走向是不同操作，不能强制将编辑变为新分支。彻底删除另按用户选择的关联范围执行。
- **历史分支**：带入截至该消息的对话和当时关系，之后独立演进；不能让一个月前创建的历史分支自动知道用户今天刚说的事。共享记忆须遵循单独授权和历史准入规则，不得无条件使用当前全量记忆。
- **继承来源**：用户选择已有会话作为起点，不默认从最近会话或全局关系池继承。新设定可继承所选旧关系和记忆；发生设定冲突需用户确认，不能静默合并。
- **版本更新**：已有会话沿用原设定、新会话使用新设定；分享副本遇到作者更新时提示，由接收者选择是否导入。
- **原作问答**：先完成一个预设角色，正文保留角色口吻、出处展开；角色、场景、时间线不清先澄清，明确后仍缺证据时不捏造。早期题目的“月社妃”属于未选中的2.A，不能据此认定用户指定了首个预设角色。
- **主动话题**：未完话题、用户事件（考试/面试后关心）、符合人设的日常分享、久未出现的问候；用户开启并设置频率和免打扰。虚构日常保存为剧情，不伪装成真实外部行动。
- **送达**：应用内留消息与授权浏览器通知均支持，由用户选择；下次打开网页能看到正式会话消息，通知重试不能产生重复消息。

未在这些原题中确定的参数包括：多维关系具体指标、主动消息默认频率与上限、首个预设角色及原作资料完整范围、角色文件兼容格式、冲突处理具体界面及效果量化门槛。需要时应先继续查后续原始技术问答，再判断是否仍待确定；不得把本段当成这些内容在完整历史中一定不存在的证明。

## 技术决策

Next.js/React/TypeScript；FastAPI/Python 模块化后端；PostgreSQL 主数据；pgvector 私人记忆；OpenSearch 原作/角色资料混合检索；Temporal/Python Worker；HTTP+SSE；本地文件存储保留 S3 接口；Service Worker/Web Push。组件版本实施时锁定兼容组合，既有 PostgreSQL 14 不是最终版本承诺。

DeepSeek Flash 为暂定开发模型；适配器保留本地/云端/混合配置，辅助任务独立选型；Pro 只作候选。两轮独立脚本评测不是应用验收，不将 A/B/C 测试提示直接当生产定稿。主聊天故障默认提示重试；辅助任务仅切到预授权提供商。云端仅发送必要上下文，可选会话仅本地。

消息持久化目标为不可变节点、分支路径、状态快照。原始记录与推导结果分开，来源/范围/修订/确认状态可追溯。数据库是权限和有效性依据，旧索引和旧任务不能重新授权失效内容。任务与模型建议提交必须幂等、检查当前修订；用户直接修改优先。

## 最终验收

核心流程通过实际网页操作、刷新/重启后状态正确；初识/继承/共享遵循明确范围；账号/角色/分支无非授权混用；编辑/撤回/删除后旧任务不写回；手动设定不被自动覆盖；回复/记忆/主动消息幂等；原作引用可核对；PostgreSQL真实集成验证；部署/恢复/配置和限制文档完整；真实模型失败案例保留。只有每项具备证据才可完成目标，不能缩小到已实现的子集。
