## 2026-11-18 独立副本核查：角色分享事务

本轮基线为 GitHub main `80d6b398ad259d488c1b631cea02046a63c3dfa2`，使用新克隆的独立工作副本。环境旧副本为 `8511e95` 且存在未提交修改，未改动；本轮不代表用户 Windows 工作区的未提交内容。未推送、发布、部署或切换服务。

### 真实实现与缺口

- `CharacterSettings` 的 `reference_text` 会随设定分享、复制及作者更新；导入导出仅支持 `multipersonal-character-v1` 的设定字段。
- 独立原作存储 `character_source_corpora` 尚未接入分享：发布参数只有 revision/enabled；分享查询、复制和作者更新均只读取 settings_json。没有创作者选入独立资料的参数或 UI，不能宣称资料随角色完整携带。
- 复制只新建角色和版本记录，不读取私人会话、记忆和关系状态。`relationships` 是创作者设定字段，不是聊天演进关系。初识会话使用空历史及初始状态，既有会话通过 character_revision 读取不可变角色版本。
- 作者更新需显式导入并校验本地/来源修订；旧会话仍保持原设定。独立资料的复制、更新差异、撤销语义及旧会话资料绑定保持，仍需完整实现及验证。

### 本轮修复

复制此前在读取分享后直接创建角色，关闭分享、发布新版或令牌轮换发生在这两步之间时仍会成功。本轮在创建角色的同一事务中锁定来源记录，重验精确 share_token/shared_revision；冲突返回既有 RevisionConflictError（API 映射409），不留下角色或版本。仅修改作者私人草稿不影响已发布版本复制。不新增迁移，不修改 Next.js。

### 验证与限制

- 新增三种确定性交错测试，修改前均失败，修改后通过；另验证作者私人草稿变化仍可复制旧发布版。
- `pytest backend/tests/test_character_library.py backend/tests/test_character_sources.py backend/tests/test_character_chat.py -q -p no:cacheprovider`：48 passed；使用已有 Python 3.12 虚拟环境、合成 SQLite 数据、无模型调用。出现已有 Starlette/httpx 弃用警告。
- 改动 Python 文件 Ruff 和 git diff --check 通过。
- 未运行 PostgreSQL 真实并发、浏览器、前端构建或真实模型验证；本轮未修改前端，独立副本没有 node_modules。未发现仓库跟踪的 AGENTS.md 或 .agents/skills。
- 当前工具没有 get_usage_limits，无法核实开发基线规定的周额度；没有沿用历史百分比或声称未达阈值。

下一轮应先核对用户实际工作区差异，再设计不可变的资料分享清单及发布身份：作者明确选入资料，复制在同一事务生成接收方自己的资料版本且重新索引，作者更新需预览并确认资料差异，旧会话绑定不变。不要直接把最新资料自动公开，也不要复用作者权限或索引回执。本模块仍未最终验收完成。
