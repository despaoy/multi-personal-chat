## 原作资料重排、引用与会话迁移

## 浏览器提醒

迁移 034 为每个会话分别保存浏览器订阅和发送结果。用户开启应用内主动联系后，可选当前浏览器，并通过点击按钮授予浏览器权限。每个会话最多登记五台浏览器。关闭单台浏览器的提醒只删除对应会话的设备登记。关闭会话的主动联系、删除会话或恢复 SQLite 备份会清除相关浏览器登记。重新开启主动联系后，需要逐台重新授权。

正式消息先保存到应用内收件箱，随后后台检查授权与免打扰时段，并对五分钟内的新消息尝试发送通用提醒。推送只传递去重标识，点击打开当前站点的收件箱。短时故障最多尝试三次，失效订阅会清理。已经交给浏览器推送服务的提醒无法由应用撤回。无提醒配置、浏览器拒绝授权或发送失败时，用户仍可从收件箱查看消息。

启用前，需要在 API 和聊天 worker 配置相同的 VAPID 私钥及联系地址，并在 worker 打开 `CHARACTER_CHAT_PROACTIVE_ENABLED`。私钥通过 `CHARACTER_WEB_PUSH_PRIVATE_KEY` 提供，格式为 32 字节 P-256 私有标量的无填充 base64url。联系地址通过 `CHARACTER_WEB_PUSH_SUBJECT` 提供，接受 `mailto:` 或 HTTPS URI。浏览器端需要安全上下文。服务端目前接受 FCM、Mozilla 和 Apple 的推送服务地址。

## 关系阶段如何影响人物表达

网页角色会话现直接复用原有四档熟悉程度的表达规则。初识保持礼貌，避免假定默契或打听私事。熟悉时可在相关场合提起有依据的共同经历，同时尊重用户当下的边界。生成提示只采用已生效的关系，待确认的建议不影响角色表达。

## 记忆纠正与共享列表一致性

## 继承历史的不可变节点与路径

PostgreSQL 的 037 迁移和 SQLite 的启动迁移会把已有继承历史拆为账号内共享的不可变内容节点、有序路径和会话自己的状态检查点。节点保存正文、出处与原消息标识。分支的记忆纠正和关系调整只更新该路径的状态。原会话的新消息仍由原有消息表提交，以保留生成幂等、编辑和撤回的事务。客户端继续读取原来的历史结构。

共享节点的外键要求路径、节点和会话属于同一账号。删除会话只移除选中的路径，其他分支仍可访问其节点。删除与分支创建按同一顺序锁定共用节点，只有无路径引用的节点才可回收。SQLite 恢复旧备份时重放删除回执，保留未选中的路径及其出处，清理无引用节点。旧记录没有逐轮状态时，迁移保留原文和出处，按原有规则限制从缺失状态的消息继续分支。

迁移 040 和 SQLite 启动升级将撤销状态写入只含资料版本 ID 的回执。以后撤销时，版本状态与回执同一事务提交。离线恢复合并较新数据库、待恢复快照及可读到的旧版撤销状态。即使恢复的快照早于该版本发布，回执也会保留，下一次恢复时仍可阻止该版本重新进入资料目录、索引和检索。未撤销版本和已保存的历史出处按备份恢复。没有较新的撤销记录时，恢复工具无法从旧快照推断后来发生的操作。

107 项 SQLite 定向回归通过，覆盖旧版状态兼容、先恢复到版本尚未发布的快照、再恢复到撤销前的快照、从较新数据库重建，以及已保存出处保留。LHM 隔离 PostgreSQL 通过真实 `pg_dump`、`pg_restore` 和迁移 040，连续准备两次均保留撤销回执，含备份中不存在的版本和旧程序仅标记撤销的版本。临时实例已停止。

## 浏览器提醒重试与失效订阅

推送平台返回 404 或 410 时，清理订阅以当前发送尝试和订阅版本为准。新尝试已取得租约或完成发送时，旧响应不能删除订阅。当前尝试确认订阅失效时，用户同时聊天或修改关系也能正常完成清理。两种情况都保留已经正式保存的应用内消息。

85 项本地后端回归通过，包含 Web Push 加密和真实 Temporal 工作流。LHM 隔离 PostgreSQL 27 项回归通过，覆盖先重试成功、后收到旧 410 的顺序。推送平台响应由替身控制，公网平台实际送达仍待验收。临时实例已停止。

## 浏览器提醒的 Retry-After

可重试的推送失败会读取平台返回的 `Retry-After`。支持从收到响应算起的秒数或绝对 HTTP 日期，同时保留本地最短 60 秒等待。若平台要求等到提醒的五分钟有效期之后，就结束这条浏览器提醒的重试，应用内正式消息仍可查看。[HTTP 等待时间规范](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3) [Web Push 限流](https://www.rfc-editor.org/rfc/rfc8030.html#section-5)

90 项本地后端回归通过，包含真实 Temporal 工作流及受控 429 HTTP 响应，覆盖秒数、日期、无效响应头、响应耗时和提醒过期。LHM 隔离 PostgreSQL 的 27 项回归通过，验证等待时间持久化以及后续迟到响应的处理。公网推送平台实际送达仍待验收。

## 主动互动的明确日期候选

从用户单条原话中识别“本周日”“下周三”“下下礼拜一”及“12 月 3 日”一类有明确指向的时间。按会话设置的时区换算原消息发送时间，周一作为每周起点，未写年份的月日限发送当年。明确事件默认建议在次日上午九点联系。单写星期、多个备选日期、日期范围、无效日期和已经过去的日期仍由用户填写。自动识别只预填候选，用户确认后才创建安排。

包含真实 Temporal 的 102 项本地回归通过。最终日期规则另通过 32 项主动互动回归，覆盖跨周、跨年、备选及紧凑日期范围、撤回后来源失效和明确确认。真实 Chrome 使用本地模型替身验证“下周三面试”在上海时区预填周四九点，点击确认才创建任务。

## 明确日期的主动提醒去重

同一会话里，从对话选取的同类型、同日期事件视为同一场。已有待发送或已送达安排时，换一种说法或选择不同发送时间也不会新增。其他日期的同类事件仍可安排。用户可用手动安排区分同一天的多场同类事件。日期不明确时沿用原话来源及请求号去重。

迁移 041 为新安排保存事件类型与日期。旧安排可从仍保留的原消息时间和话题恢复识别。105 项 SQLite 后端回归、28 项 LHM 隔离 PostgreSQL 回归及真实 Chrome 验收通过，覆盖待发、已送达、旧安排、不同日期和直接重复提交。
