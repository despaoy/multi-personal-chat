# 角色原作资料三方比较：后端第一阶段（2026-11-19）

## 本轮边界

仅修改后端作者资料更新及测试。没有改Next.js、前端类型或页面、文件格式、长行分块/索引、数据库结构或依赖。角色名字、人设等设定字段沿用既有完整设定确认逻辑；本轮三方比较只针对独立原作资料，不宣称实现整个人物设定的自动合并。

## 三份资料的来源

- B：接收者 `source_publication_id` 指向的上次导入作者发布的选入原文。它不是接收者上次合并后的资料，也不是作者当前最新版。
- L：接收者当前设定版本中最新有效的独立资料集。没有有效资料版本时为已删除全部资料的状态。
- R：作者目前仍公开、资料未撤销的新版发布中选入的原文。

基线必须归属于记录的来源角色及作者设定修订，来源角色仍开启分享；基线资料必须归属于相同作者/角色/设定版本，且未撤销，发布快照中的原文必须能在该版权威资料中核对。仅含设定的已知发布可以构成明确的空资料基线。旧记录缺少发布指针、记录缺失、错配角色、资料撤销或无法核对内容时阻止导入，不从本地文本、当前作者版或文字相似度猜测基线。

不向预览返回基线正文；不可用时不返回基线编号或它的逐条比较信息。接收者自己已有的独立资料副本仍属于接收者，作者撤销不会删除它。

## 稳定来源ID与合并规则

按同一作者来源链中的原文ID识别同一份资料，标题和正文作为整份文档比较。不按标题/内容相似度匹配，不拆分段落自动揉合。

| 条件 | 结果 |
|---|---|
| 仅L修改 | 保留本地修改 |
| 仅L删除，R与B相同 | 保留本地删除 |
| 仅R修改或删除，L与B相同 | 采用作者变化 |
| L、R都删除 | 保持删除 |
| 双方作出完全相同的修改 | 采用一致结果 |
| 双方修改且结果不同 | `both_modified`冲突 |
| L删除、R修改 | `local_delete_author_modify`冲突 |
| L修改、R删除 | `local_modify_author_delete`冲突 |
| B没有该ID、仅L有 | 保留本地新增 |
| B没有该ID、仅R有 | 采用作者新增 |
| B没有该ID、L与R都有 | `addition_id_collision`冲突，即使文字相同也不推定共同来源 |

不同ID的相同文字仍是独立资料；复用基线中已有ID视为对那份资料的本地修改。系统没有证据判断用户是否意图另建同名身份，因此不自动重命名、合并或丢弃。文档中不同字段分别被双方修改仍可能形成整份文档冲突，这是本阶段的保守行为。

保留本地资料顺序，在末尾追加真正新增的作者资料。合并后再次检查最多100篇、每篇模型字段限制和序列化UTF-8不超过5MB；两个各自合法的资料集并不保证合并后合法。

## 可核对预览与拒绝行为

既有GET `/{character_id}/source-update`新增：

- `baseline_publication_id`：可用基线的发布编号，不可用为null。
- `incoming_sources`：作者原始新版选入资料。
- `source_merge`：`status`为ready/conflict/blocked；包含`reason`、逐ID的`actions`、`conflicts`及`merged_sources`。
- 既有`sources`在ready时表示将实际写入的合并结果，使现有前端差异预览与将写入的资料一致；conflict/blocked时没有可提交结果，其`sources`仅展示当前可见的作者内容，不能视为合并成功。

例如B有a、b；L修改a、删除b、新增local；R保留a、b并新增remote。ready计划保留修改后的a、local及remote，不恢复b。连续导入后B前进到作者R，不能前进到含local的合并结果；否则下一次会误把作者未携带local认作作者删除。本轮有连续导入回归。

POST保持原请求字段和鉴权方式。conflict/blocked会返回409及明确的“不能自动覆盖，需要明确处理”提示，不写设定版本、资料或任何部分合并结果。当前前端没有冲突选择控件，本轮不增加绕过确认、强制覆盖或自动重建基线的参数。缺失基线不是刷新即可修复的问题，后续需要明确的基线处理流程；本轮安全拒绝。

## 事务、索引和旧会话

确认时重新计算计划并核对原基线编号。除既有本地角色修订、最新有效本地资料ID、作者发布/令牌/资料复验外，同一事务锁定基线快照及原资料未撤销。预览后更改本地资料、作者换版、关闭分享或基线撤销都不能沿用过期确认写入。提交过程中撤销导致整笔回滚。

成功导入仍产生新角色版本和独立资料版本，更新来源发布指针，资料索引从pending/attempt=1开始，不继承旧索引回执。没有资料的合并结果不建立空资料集。重复已完成请求沿用既有幂等行为，不再增建版本。旧会话不迁移，原角色/资料版本继续保留。
