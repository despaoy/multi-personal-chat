# 角色聊天基础重构

本次重构依据需求确认对话推进。目标是补全可运行、可验证的产品基础，真实模型质量另行评测。

2026-11-14 用户已确认新版 [开发基线 v1](DEVELOPMENT_BASELINE.md)，技术方向与完成边界以该文件为准。下文验证记录为历史增量，不等于当前全部验收完成。

## 已确认的产品行为

- 网页优先，后续平台接入顺序待定。
- 自定义角色至少包含名字、人设和开场白，可添加示范对话、关系、场景和参考资料。
- 角色修改后，已有会话保留原版本，新会话使用新版本。
- 新会话默认初识，不带入旧记忆。用户可明确选择带入已共享的信息。
- 延续关系时由用户选择已有会话，继承其关系和有效记忆。新设定与经历冲突时需要确认。
- 长期偏好允许自动记忆，含糊或冲突的信息待确认。支持查看、纠正、删除和选择性跨角色共享。
- 编辑用户消息后替换当前走向，后续消息退出有效历史，相关记忆、摘要和关系同步失效或重算。
- 撤回指定消息及后续对话，按剩余有效对话重新确定记忆和关系。
- 从消息创建分支，保留截至该处的经历和关系。修改原会话不改变既有分支；彻底删除按明确选定的范围执行。
- 普通聊天遵循人设，分支可接受明确的设定修改。
- 分享通过复制形成独立角色；原作者更新时提示，由接收者选择导入。
- 预设角色支持原作问答和可展开出处，澄清后仍缺证据时明确表达不确定。
- 主动消息按会话启用，支持频率、免打扰、应用内消息和授权后的浏览器通知。

## 技术边界

沿用 Next.js/React/TypeScript 与 Python/FastAPI，PostgreSQL 为正式部署方向，维护当前 SQLite 路径的数据兼容。模型通过既有提供商协议调用。

用户后续已确定 PostgreSQL+pgvector、OpenSearch、Temporal，以及暂定 DeepSeek Flash 的开发配置；本地/云端适配均保留。现有同步提取与复制快照须按新基线迁移，不继续视为最终架构。账号角色库与现有静态作品画像分别管理，由会话绑定明确的角色来源和版本。

## 当前新增入口

- 页面 `/character-library`，面向已登录用户。
- API `/api/character-library`，服务用户自己的角色和历史设定版本。
- 分享按显式发布的版本提供快照，编辑私有设定不会自动发布。
- 角色包格式 `multipersonal-character-v1`，导入只接受设定内容，不接受账号、权限、会话或记忆字段。
- Alembic `017_character_library` 增加角色与版本表。
- 页面 `/chat` 与 API `/api/character-chats` 提供用户会话、聊天、编辑撤回和消息分支。
- Alembic `018_character_chat` 增加版本绑定会话和可追溯轮次。编辑/撤回通过有效状态排除原走向，不等同于物理删除。
- 新旧聊天入口共享 `inference/local_model_access.py` 的本地模型互斥锁。用户角色调用复用 `GenerationRequest`、提供商快照及调用计量。
- 新聊天入口通过 `services/character_chat_memory.py` 复用既有语义记忆提示词、客户端和原文证据校验；使用既有 `MEMORY_LLM_ENABLED`、`MEMORY_LLM_BASE_URL`、`MEMORY_LLM_MODEL` 等配置。共享回复编译器的旧记忆写入仍关闭，避免双重写入。新适配器只写当前会话状态，不使用旧全局记忆表。
- 自动提取目前在回复生成后、轮次事务提交前同步执行，有独立超时与计量。明确无冲突的长期偏好可直接确认；含限定、其他类型及同一事项冲突进入待确认，未确认内容不进入后续提示词。未知语义键的手动记忆存在时，新候选保守地待确认。失败时记录状态并保存回复，用户可手动补充；持久后台提取和失败重试仍待优化。
- 自动关系更新由 `RELATIONSHIP_LLM_ENABLED=true` 独立开启，默认关闭，复用 `MEMORY_LLM_*` 的连接、模型、超时和预算配置。读取旧关系及本轮双方原话，要求双方逐字证据、高置信度和受限阶段；不按轮数递增亲密度。与记忆提取串行执行，因此两者启用时会增加保存回复的延迟。失败保留旧关系及成功提取的记忆，页面显示状态；成功记录证据并与本轮原子提交。原文匹配只能保证引用存在，不能保证语义判断正确，真实模型效果仍待评估。
- 会话记忆接口支持新增、纠正和删除，携带会话修订号。手动记忆绑定当前最后一轮，无消息时绑定初始状态。纠正/删除同步更新本会话所有状态快照，避免回退恢复旧值；已有独立分支不受影响。删除结构化记忆不会删除原始对话文字，不等同于彻底遗忘。生成上下文只接纳已确认记忆。
