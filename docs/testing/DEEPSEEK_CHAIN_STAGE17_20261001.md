## 完整场景与实际缺陷

三份完整合成知识资料分别为北岸榆影工坊纸雕课程、北岸工具维修及南岸另一工坊绘画课程。纸雕预约编号 YY-573-R，维修编号 WX-204，绘画编号 ZY-882；维修资料明确维修预约不能自动完成课程预约。原生 API 实际导入三份资料并建立向量/关键词索引。两道新问题分别仅询问纸雕编号及出处、询问纸雕和维修编号及能否互相替代；没有要求记忆或插入长历史。

基线两次真实 DeepSeek 回答内容正确，但都返回全部三份检索资料作为引用。单来源回答附带维修、绘画资料；双来源回答附带无关绘画资料。根因是生产生成链路直接复制检索候选引用，没有根据实际回答使用来源进行绑定。

第二道问题中，必需的纸雕资料分数为 0.0，而无关绘画资料为 0.4458。这证明不能用零分排除、任意阈值或固定 top-1 代替回答来源选择。

## 修复

新增 `inference/answer_citations.py`，在实际生成前从权威检索文档与匹配引用建立应用来源键 `[S#]`，拒绝冲突或未知来源 ID，保留全部可准入的完整来源，不按分数剔除资料。通用资料以完整来源包进入已有预算处理；角色资料保留原有来源包、文档归属和背景依赖，仅附加对应来源标记。

生成提示要求在使用某份外部资料支持事实时附上来源键，并区分私人记忆及当前用户陈述。生成完成后只绑定实际输出且属于最终准入来源的键，按首次引用顺序去重；元数据来自服务器提供的来源，不解析模型自报的文件名、标题或 ID。已被预算排除的来源不能靠输出标记恢复。未知或缺失标记不会触发“回填全部检索引用”；保守保护回复不携带来源。内部标记从最终正文移除，正常纯对话中的字面标记和明确原文摘录保持原有行为。

`generation_request.py` 统一执行上述契约，`api/generate.py` 返回实际绑定结果；组合任务也不再以全部检索引用补齐空结果。没有增加第二次大模型审核或改变实际 DeepSeek 模型配置。
