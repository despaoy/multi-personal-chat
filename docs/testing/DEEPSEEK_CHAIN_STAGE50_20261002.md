## 实际问题

独立管理员进程通过真实接口改名知识库后，数据库名称已改变，索引修订却未改变。已预热读进程因旧修订仍相等而沿用缓存，实际 DeepSeek 主请求和 API 引用摘要都继续包含旧知识库路径。

删除文件夹的界面明确说明“文档将移至未分类”。原数据库实现只清空 `folder_id`，仍保留旧 `category`；即使索引重建，实际模型证据和引用摘要仍显示已删除的目录。数据库删除与索引失效通知还分属不同事务。SQLite 知识库更新另有部分字段覆盖问题：描述更新可能清空名称，只改名会清空描述。

两题课程正文完整、模型事实回答正确；实际错误是后端来源路径，不能归因于模型理解不足。

## 修复

SQLite 与 PostgreSQL 的知识库改名在同一事务中更新名称、增加索引修订并写入 dirty，未提供字段保持原值。同名、仅描述变更不推进修订。知识库级联删除将文档、分块、文件夹、知识库和索引失效一并提交。删除文件夹保留全部文档原文与分块，原子清空文件夹关联、把分类移到“未分类”并推进修订。数据库通知失败时全部回滚。

公共接口在成功提交后只清除本进程的加速状态，不再依赖第二次数据库通知；对象并发消失时返回不存在。文件夹接口说明与现有界面一致，没有新增删除文档行为。
