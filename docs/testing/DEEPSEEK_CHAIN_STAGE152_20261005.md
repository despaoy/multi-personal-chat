# 阶段152：普通规则记忆的来源版本核验

日期：2026-10-05。整体优化目标 active，公网开放不在范围内。

## 根因与修复

正常来源捕获、规则提取、规则写入和作用域内召回生成的普通规则记忆此前没有绑定原始来源版本。新增基线中未改变来源的控制通过；准备后明确对隔离虚构来源做正文改写或撤销的行政故障注入，保持记忆存储记录未变，旧证据仍进入最终模型输入，两个反向控制失败。没有人工制造记忆包或授权回执。

初稿把所有来源接入原话读取回执，虽然通过三个新增控制，却使正常删除另一条记忆后、仍有效的独立规则记忆在守卫重试中丢失。这次失败保留，初稿未部署。原话层的所有者删除时间限制用于防止已删除信息经其他原话复现，不能为此放宽。

最终实现单独的内部来源版本读取：只读取当前作用域中实际记忆编号与来源编号之间的关联，来源必须仍为 recorded，返回编号、接收时间与正文 SHA256 指纹，不向上层返回正文。数据库事务内部计算实际正文指纹，不依赖正常捕获后可能为空的 body_digest。原话召回及原话回执继续执行原有所有者限制；独立有效的规范记忆可以保持，而来源已经变化、撤销、关联缺失或读取失败的包不能进入最终发送或守卫重试。正文变化不允许替换为未审核的新事实。内部关联及指纹不进入选择消息、模型输入或冻结完成快照，无新增模型调用、数据库结构或迁移。

## 针对性验证

11 个唯一节点通过：7 新增、4 直接相关。覆盖普通规则来源未变、准备后正文变化、来源撤销；元数据只读且不返回正文、正常删除另一记忆后原话限制保持而独立规范记忆保留；他人或其他角色及错误记忆/来源关联不能借用权限；内部指纹不进入模型或完成快照；单包来源读取失败只移除该包；合法语义投影、原有语义来源变化、正常删除后的守卫重试、原有内部版本隔离。初稿回归失败及实际反向基线均保留。新文件静态零问题，七个现有文件原诊断基线保持，未全文件格式化。

实际 PostgreSQL 用正常规则写入和召回准备两条完整虚构记忆；在等待公共审核期间，另正常写入并删除一条独立记忆以触发所有者原话限制，确认原话读取为空而仍有效记忆的元数据指纹不变。再对原已捕获目标来源进行明确的作用域内行政撤销故障注入，确认目标记忆自身存储指纹未改变。共享 API 生成前旧证据消失，独立记忆的完整表述和证据保留，内部指纹不发送给模型。一条新的真实 deepseek-flash 主答 8/8 内容检查及严格 JSON 通过；缺少公共规则保持未知，partial_answer 状态保留。公共规划、分类和审核故障明确为组件控制，本阶段不宣称原生登录、历史或向量检索验收。原始完整问题、输入及模型输出仅保存服务器。

初次真实数据库用例在调用模型前没有选中预期记忆，费用零。零模型对照确认仅“核验……”及补充所属人的变体选中零条，明确“读取我保存的偏好并核验来源”选中两条；后者用于来源版本的单一职责验收，并非把前者标成通过。这一召回边界留作下一阶段实际问题。初次失败进程和最终进程均已确认终止，没有超时重启或重复付费主答。

新增发送 1、HTTP200 1、主答 1、辅助 0、原生请求 0；usage 估算费用 0.00104848 元，并非账户账单。未重跑旧全量或旧已通过付费主答。
