# 阶段150：未解任务隔离与多来源否定别名

## 问题与修改

完整新用例在正常服务器登录、导入和检索中首先失败：两个业务对象已识别，但一条边界说明没有对象，整段请求仍落入角色检索，独立业务完整规则丢失。现在已识别业务与未解任务分别检索；未解任务继续保留原角色路径，不获得业务对象授权。一个分支不可用也不抹掉另一分支完整原文，全未解问题保持原严格路径。

恢复检索后发现身份解析器将不同来源对同组名称的“不确定”和“不同业务”都判成冲突。现在允许不同来源各自报告这两种不建立同一性的判断；同来源重复、肯定与其他关系冲突、伪造引用继续拒绝，不创建别名授权。真实失败输出离线重放后零身份绑定，独立规则来源角色保留。

后一次审核将整数任务身份写为字符串，并引用不存在的名称绑定。进一步明确事实与来源审核的JSON身份类型、无对象方面为空、空bindings不准填写授权编号。解析器未放宽，未自动转换身份或补造授权。

## 完整输入、实际结果与限制

隔离PostgreSQL复用已验证的8条正常虚构记忆、47轮正常历史及向量种子，没有重播旧历史或旧成功主答。四份新虚构资料完整经正常接口存储：已作废的肯定名称登记、当前否定登记、另一业务完整规则和独立业务完整五项规则；当前权威快照的FAISS、元数据和BM25一致性校验通过，四份正文均完整在索引。

已作废登记、当前否定登记和独立业务规则完整进入实际辅助审核；另一业务规则已存储、索引，但没有被本轮检索选入辅助审核或主答，不把四份已导入写成四份均已审核。两份关系登记不提供业务规则，也没有被强制作为业务事实入主答。实际主答完整包含独立业务规则和指定私人原话；其他无关原话不要求全部入包。

17个唯一相关检查通过：10个新增、7个直接受影响的既有节点，无旧全量测试。实际原生主答内容含义20/20，逐字值19/20：一项将“两项原件”展开为两份原件名称，暴雨暂停、预约不能豁免两份原件均正确。当前否定别名业务五项保持未知，独立业务五项正确，私人八项限定逐字一致，两项偏好不能证明现实审核与跨业务边界为false。partial_answer正确，八条记忆不变，未新增写入或守卫重试。

原回答包含代码围栏，严格裸JSON失败，完整原回答保留；只在独立内容评估去围栏，不改写产品返回，不为格式重测成功主答。旧metadata.pkl并非现行权威快照，且正常索引附加标题，因此早期观察的字节全等false不代表正文丢失；原观察保留，随后使用现行快照完整正文包含及一致性校验核实四份正文。
