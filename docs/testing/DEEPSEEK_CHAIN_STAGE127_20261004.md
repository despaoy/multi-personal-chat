# 阶段127：原文分区的独立公共任务

阶段126的新333字任务内容正确，但同一句中的两个独立公共业务共用一个来源依赖编号。来源对句中部分条款相关，不代表整个句中其他业务也有依据；仅按句段关联不能表达这个边界。

在既有规划调用中增加public_partitions，不增加另一轮规划调用。模型只为每个公共句段提供各独立业务开始处的短原文字面标记，程序验证标记唯一、存在、顺序合法，并由原文计算字符偏移。每个公共段恰好一项，程序完整分区，没有删去任何字符或末尾限定；不让模型数偏移、不改写任务，不输出答案。共享字段、例外、范围和指代仍由完整原始query提供，不能为了分解而丢失上下文。

分区任务使用独立public:段:分区身份，区别于私人编号和原句段编号。公共来源审核分别读取各任务与完整原问题，保存全量取得的索引片段及核验后的完整原始正文；只能返回允许的任务身份和实际来源，不返回私人、父句段整数或布尔身份。最后生成器再次验证精确query片段、连续完整覆盖、身份、顺序与整轮query绑定。实际可见来源为每项任务分别报告相关候选已进入、没有相关证据或未进入，语义充分性仍为unverified，不能宣称每个事实真实或现实许可已通过。

旧依赖协议仍可读；新分区无效时保留已合法的来源依赖与原文搜索视图，不发明切割，也不能授予私人绕过。该情况回到明确标为segment_unverified的粗粒度审核；它不能证明业务级分解成功。原作专用、明确标题、纠正检索和无有效依赖等路径的既有范围保持，尚未统一。

只测试本阶段新增/直接影响节点。十八个完整虚构新节点覆盖同句两业务不同依据、私人原话保留、完整末尾、空/私人/布尔/重复父段、改写/重复/零位置/反序切割、容量、篡改后的缺口/丢后缀/外来query及非法任务身份。每个负例先运行完整正例。另三个直接既有依赖、query绑定和接口状态节点通过，共21个唯一通过节点，未跑旧全量回归。初次静态脚本把导入排序和格式化合并作AST比较，导入顺序变化触发断言；分别核验后，格式化本身AST保持，五个改动文件零新增静态诊断、零基线差异。原检查记录保留。

新的488字请求同时要求完整私人八限定、两公共业务各四字段，并问另一业务未知能否使已知公开费用变未知、公共规程能否证明本人现实登记复核已完成。两个公共业务在同一句，共享四字段契约；这是新完整测试维度，不重发既有333字、1126字或其他已通过主回答。真实八条种子和47轮推进递归核验，正常历史保留；原生认证导入完整公共文档，必需私人原话和公共全文在主请求发出前门控。没有人为记忆、历史、回执数或资料注入。

原生HTTP200、无兜底，五次实际官方Flash HTTP200非思考调用：一主四辅助。真实规划给出合法原文分区，公共审核与付费主请求保留同一组独立身份；已知业务相关候选实际进入，另业务没有相关证据，两个身份不同且没有合并业务任务。链路30/30、内容18/18，八个私人限定、四个已知值、四个缺失null及两个跨来源布尔值正确。部分回答保留公共abstained提示，未宣称任务所有条件充分。私人来源仍在正常近期历史之外，八条存储和旧原文精确保持，实际取得的所有源回执返回；零写入、删除或调度保存。

初次免费记账误沿用上一案例六次调用断言，实际只有五次，30/30与18/18已通过；保留原检查并仅修正实际调用统计，没有为凑调用数重发。按保存usage/cache既有口径估算0.06292228元，非平台账单或当前价格。主输出2048、新公共审核768及既有组件输出预算保持；完整问题和来源不裁剪。

服务器先实现并验证，后端新进程就绪200，环境与其他服务保持，随后同步安全实现、独立虚构单测和统计。真实输入、回答、正文及身份哈希留在服务器。

设计参考[Decomposed Prompting](https://arxiv.org/abs/2210.02406)的模块化任务分解，以及[Self-RAG](https://arxiv.org/abs/2310.11511)对检索材料必要性、相关性反思的方向。这是对现有DeepSeek链路的协议设计，未训练或复现论文模型；本阶段实测只证明该复合场景的关联和内容结果，不能借论文结果认证全系统正确。

后续仍需验证共享代词、跨段依赖、切割没有识别多个业务的情况，以及每项任务内部多事实/例外的实际充分性。完整字面分区证明没有丢字，不证明模型的业务边界语义一定正确；合法无切割和粗粒度回退也不能声称任务已经全部细化。整体目标继续。
