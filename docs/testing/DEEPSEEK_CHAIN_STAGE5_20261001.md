# DeepSeek 后端链路优化：第五阶段

基于 `1cec2738`，先在服务器复现并修复原生云端上下文预算、长计划写入及完整记忆编排，再同步验证有效的源码。本阶段不替换模型，不把输入缺失或模型容量当作链路失败原因。

## 完整长输入在模型调用前失败

五回合基线先保存真实用户昵称和饮品偏好，依次提供三份约 7400 字的完整虚构档案，最后读取档案及用户资料。接口允许这些输入；档案编号、口令、责任人、地点、日期和状态具有明确前序依赖，后续回合未重置前提。所有用例按同一个鉴权用户范围顺序执行。

原生回答编排仍使用本地 `VLLM_MAX_MODEL_LEN=8192`，忽略显式云端工作预算。三个长输入在调用模型前因预算不足返回 500，三个复核器同时因旧输入限制回退。最终问答缺少资料，是链路未交付完整材料的后果。

新增 `inference/provider_context.py`，按实际选中的提供方解析工作预算。`openai_compat` 使用独立的 `OPENAI_COMPAT_CONTEXT_WINDOW_TOKENS`；本次测试明确配置 65536，未配置时保守使用 8192，不假定厂商理论最大窗口。云端预算同时传到回答编译、历史读取、来源读取、三个复核器及完整记忆参考区。本地窗口和已有默认限制保持原契约。所有序列化仍受完整输入与溢出保护；放不下的记忆包整条省略，不裁掉末尾限定。

修复后的相同五回合全部成功。三份材料完整进入三个复核器和回答输入，最终八项资料回答正确；虚构档案没有作为用户个人事实写入。

## 长计划提取正确，但后端拒收或预算丢弃

扩展用例另外提供一份约 7400 字的本人计划：每周日上午九点半去城东青苔工坊练习木刻；末尾明确只有不下雨才去、下雨取消、尚未开始实施。最后一个回合受控关闭历史读取，原始来源召回也关闭，仅验证持久记忆能否独立回答。模型在回答和提取中均理解了这些信息。

首轮提取把分散的原文拼接成一段连续 `evidence`，还返回了不支持的 `status` 限定。后端正确拒收这些不合约字段，但原接口没有向模型明示数值及限定键边界，也无法用短引文表达长消息中的全部计划条件。

现在提取输入明示短值、连续引文及限定键的边界。带条件、尚未实施的完整计划可以使用已有 `shared_event` 原话观察契约：短引文只承担来源准入，后台保存完整当前发言；原话观察只证明用户说过这些话，不确认行动已发生。普通不确定事实仍使用原有 PENDING 契约，不因此成为事实。

第二次实测中，模型已正确返回原话观察及逐字复制的“只有当天不下雨才去；下雨就取消”，后端却仍只在开头短引文中校验限定，导致再次拒收。修复后，保存完整当前发言的原话观察在完整当前来源中逐字核验限定；普通语义事实继续按短引文校验。未知限定键、编造限定、拼接或编造引文仍拒收，不使用模糊匹配恢复它们。

另一个独立瓶颈是记忆参考区固定 6000 字符预算：完整长原话及其证据包会被整条省略。现将云端工作预算传入原子记忆包编排，并保留原话观察的主体未解析、用户发言、描述未验证等标识。计划原话始终在不可信用户参考区，不进入系统指令。

## 最终证据与回归

最终七回合、27 次实际 DeepSeek API 调用全部 HTTP 200、返回 `deepseek-v4-pro` 且正常 `stop`。原生注册、登录 Cookie、鉴权、请求队列、独立 PostgreSQL、原生提供方、记忆写入及三个原生复核器均参与。19 项原生链路检查全部通过；对同一批原始调用另做 8 项持久化和模型输入审计，全部通过，审计函数也纳入后续测试工具。

独立读取的模型请求仅有系统消息和当前用户消息，完整计划通过一条带来源标识的记忆包交付。实际回答是：“你计划每周日上午九点半到城东青苔工坊练习木刻。取消条件是当天不下雨才去，下雨就取消。你还没有开始实施。”来源审计确认完整原文持久化、完整原文到达最终模型输入、历史未参与、末尾取消及未实施限定保留，且未被当成系统指令。

本阶段五次真实诊断运行共 31 次生成尝试，28 次生成成功，105 次 API 调用均正常结束。基线和两次扩展复测保留了长输入失败或记忆拒收记录；一次中间复测仍有个人计划的语义复核无效输出回退，最终复测该环节采用成功。不能用 HTTP 200 或单次修复宣称所有链路通过。

- 新增提供方预算和原话计划回归共 21 项；相关来源、时效、记忆和编排回归 230 项通过。
- 最终全量回归 4493 项：4479 通过、11 跳过、3 失败。仍为已记录的 DPO/ORPO 训练环境依赖问题，没有新增业务回归失败。
- 检索与新增模块 lint/格式、全仓库未定义和重复名称、772 个 Python 文件语法、依赖、迁移 head、仓库完整性及发布卫生检查通过。测试工具导入不改变环境。
- 原部署 `.env` 校验值保持不变，沙箱仍只读保护它；生产服务未重启、模型配置未切换。

合成完整用例保存在 `tests/fixtures/deepseek_native_long_cases.json`。可复用测试工具为 `evaluation/native_long_context_probe.py`，`--require-success` 会在任何检查失败时返回失败。原始失败及成功调用、编译快照和日志保存在服务器私有 `evaluations/r148pg.s3/stage5-*`；来源拒收审计、最终模型输入审计和校验清单保存在 `backups/backend-chain-20261001/stage5_*`。API 凭据不进入仓库或调用记录。

本阶段 HTTP 使用 ASGI 应用内传输，RAG 关闭；它证明完整长历史和长计划记忆链路，不证明网络反向代理、全部 RAG 路径或生产进程已加载更新。持续目标仍有效，后续继续验证原生 RAG、取消与恢复、部署加载。
