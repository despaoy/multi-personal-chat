# Stage 46：跨进程 RAG 索引与引用刷新

本阶段修复了已预热读进程忽略其他进程资料更新的问题。服务器先修改并验证，确认有效后部署、同步本地及 GitHub。长期记忆、RAG、动态上下文的持续优化目标仍在进行。

## 复现条件及真实结果

复用 Stage 45 已通过 25 项检查的完整合成课程资料：三份完整文档、三个分块、两个知识库。克隆实际 PostgreSQL 测试库及持久化索引，验证文档、分块与父证据一致；仅重置克隆测试账号的密码，再通过真实登录接口认证。父库知识文档、分块和配置的前后摘要相同。没有重放原有资料写入、导入或旧模型问答。

读进程先通过实际搜索建立索引，再用本轮新问题预热 RAG 缓存，预热不调用模型。独立写进程通过管理员接口修改第一份文档的标题、分类及知识库归属，正文及分块不变。写进程随后通过真实搜索重建自己的索引，将共享数据库的状态写为新修订号的 complete。两个进程共享实际测试数据库，但索引目录独立；这不证明多个进程并发写同一索引目录的安全性。

写进程结束后，读进程直接进行普通生成，期间不手动清缓存或修复索引，也不先进行读进程的更新后搜索。回答随后与实际数据库、两侧知识库范围、引用及落盘索引核对。两个正式测试均使用当前 `deepseek-v4-pro`，各一轮新回答、三次 HTTP 200 模型调用，共两轮回答、六次调用。不是重复完整历史回归。

## 根因与修复

`_ensure_vector_index` 以进程内 `_vector_index_built` 为依据直接返回。另一个进程的更新只会重置它自己的布尔标记，无法重置读进程；读进程既不查询持久化修订号，也不更新向量或上层缓存。

仅增加修订号检查仍不够：另一个进程已经写出新 complete 状态时，旧本地索引与新数据库的分块数量仍相等。旧跳过重建逻辑只核对全局状态、数据库指纹和数量，可能再次误认可本地旧资料。

修复增加本进程实际验证过的修订号。每次就绪检查先读取共享数据库的当前修订号，只有与本进程已验证的修订号相同才走快捷路径；未改变时不扫描全部分块、不重新嵌入。读取失败、格式非法或负修订号均返回未就绪，不能继续授权旧缓存。

首次加载或修订号改变时，即使全局标记 complete，也必须逐条核对本地实际加载的资料身份、分块位置、标题、正文及知识库名称形成的路径、分类和知识库归属。构建与核对共用原文到向量资料的转换函数。真正一致的索引可复用；旧本地资料必须从当前数据库重建、落盘，并通过原有 cache generation 机制使检索缓存失效。重建完成前仍检查修订号，重建期间再次发生更新时不授权旧结果。

## 定向验证及审计

新增 17 项单元测试全部通过，覆盖其他进程将状态保留 dirty 或重建为 complete 时的标题、分类、归属和正文变更；未改变修订号的查询成本；新进程加载同数量旧索引；合法索引复用；数据库不可读、非法或负修订号；重建期间再次更新；最后文档删除；损坏的本地资料身份。首次 17 项都因测试驱动导入遮蔽而在准备阶段报错，修正后仅重试这 17 个失败项，执行实际行为均通过。没有重测已通过项目或旧回归，也没有运行全套测试。

首次真实驱动 `stage46-workers-base`（读进程 2168032、写进程 2168538）在写进程目录边界检查处停止，未更新资料、未调用模型；修正路径层级后以新的隔离标签运行。正式基线及修复进程、写进程、推理队列、记忆任务、完成任务与数据库待处理写入均已终止。

32 项实际证据检查外，16 个保存证据反例均被审计拒绝，包括同进程伪装、不同数据库、错误标题、假完成状态、无修订号增长、写进程仍运行、丢失原文、父库被修改、重放旧问题、旧引用、错误范围、未失效缓存、活跃队列、非当前模型及模型输入缺少新标题。这些是人工修改的审计输入反例，不是实际模型或生产运行记录，未产生模型调用。

原标题合法保留在未改变的正文和继承历史中，不能要求模型输入全文都不出现它。审计分别核对更新前预热检索和生成时检索的真实记录、新检索标题与模型输入、最终引用；保留真实继承历史，不把它伪造为空。审计纠正及格式整理均使用已保存真实结果，不重跑问答。新 Python 文件静态检查通过，已有文件没有新增静态诊断；保留格式整理前原件并验证导入符号及非导入语法树等价。
