## 修复与边界

新增 `knowledge.source_expansion`：持索引锁检查 snapshot_validated、检索开始时的缓存 generation、每个原有分块的稳定 ID/正文/标题/文档 ID/知识库/类别/位置。拒绝身份歧义或过期分块。只补同一文档、知识库、标题与类别中符合原过滤范围的分块，并按来源顺序、距离和位置确定顺序。原有高相关分块保持在前，补充部分 score 与 normalized_score 为 0，不增加置信度投票。

补充量上限由配置的工作窗口估算，超限的分块整块略过，仍保留原有高相关分块。小资料可以补齐关联章节；大资料不被替换成无法入预算的整篇文档。实际系统提示、当前问题、长期记忆、历史、输出和引用开销仍由统一最终预算裁决。这是索引分块补充，不声称已重建完整原始文档或证明任意资料完全覆盖。

补充分块转换成带 supporting_document_ids 的 background 包；最终预算必须已接纳同来源的原有分块，才能接纳补充包。每块保留自己的来源 ID，引用开启时仍绑定各自原文。通用和纠正性 RAG 均走该补充边界，人物专用 RAG 保持自己的检索契约。补充后再核对数据库修订号，拒绝检索期间的资料变更。每次通用检索增加一次修订读取，无新增模型调用。

修复后的零云调用检查使用相同完整资料，选块为 0、2、4、1、3、5，六组必要条款均进入实际请求，原置信度保持 0.7958，来源摘要不变。估算 5638 tokens（该边界用 1024 输出预留；提高到 2048 后也在窗口内）。
