## 完整输入与预期

原始发言：请记住我的饮料偏好：工作日晚上我只喝不含咖啡因的麦茶；周末上午我喜欢淡拿铁，但只在已经吃过早餐且当天没有胃痛时喝；我不喜欢浓缩咖啡。这些是我本人现在的习惯，不是朋友的喜好，也不是假设。

原始问题：根据我之前明确告诉你的本人饮料偏好，分别列出工作日晚上喝什么、周末上午喝什么及全部条件、明确不喜欢什么。保留时间、咖啡因、早餐和胃痛限制，不要把条件性喜欢推广成无条件喜欢或把一种咖啡的厌恶推广到全部咖啡。

预期同时保留7项信息：工作日晚上、不含咖啡因的麦茶、周末上午、淡拿铁、已经吃过早餐、当天没有胃痛、不喜欢浓缩咖啡。后两项是同时满足的条件，不得推广为无条件喜欢拿铁；浓缩咖啡厌恶不得推广到全部咖啡。

原始提案及完整回复保存在同阶段 JSON fixture 的 observed.audit 中，既未裁剪也未替换模型内容。模型回复为：

```json
"按你之前说的，你的饮料偏好是：\n\n- 工作日晚上：只喝不含咖啡因的麦茶。\n- 周末上午：喝淡拿铁，但必须同时满足两个条件——已经吃过早餐，且当天没有胃痛。\n- 明确不喜欢：浓缩咖啡。\n\n没有把淡拿铁说成无条件喜欢，也没有把对浓缩咖啡的厌恶扩大到所有咖啡。"
```

## 证据与范围

后台记忆客户端使用当前768输出限制；本次真实写入调用消耗496输出token、2176总token，完整JSON以stop结束，未触发截断。三个提案的 evidence 均为当前发言连续原文，时间和条件 qualifiers 均与证据一致。后端忽略模型自报的 observed_at，以本轮服务器 received_at 为观察时间；周频限定没有被伪造成日历有效期。

这次问题明确要求“之前告诉你的偏好”。召回实际读取了3条事实记录，但它们在该历史任务中全部作为 observation 过滤，used_memory_ids为空。最终请求同时包含两条历史消息和不可信 dialogue_evidence 中的完整原话，模型完整回答7项内容。因此证明的是实际提案→验证→提交/来源关联，以及历史原话→上下文→真实回复；不能据此宣称已证明事实条目单独召回、远距离无近期历史召回、复杂记忆修正或跨会话召回。RAG 本次未请求。

结果保存瞬间 db._pending 为1，后台语义任务为0；没有将待写计数改写成0。真实进程退出后独立读取数据库，3条记忆、3条关联和两条来源均已落库，没有观察到这些验证对象丢失。该终态读取不证明所有无关辅助写入都完成。
