# DeepSeek 后端阶段94：没有可靠语义候选时读取指定标题

基线 7403a3acec0a9b64ac5ef49d89818e4812fb1f09，模型仍为官方 deepseek-flash，65k窗口、原历史和完整来源保持原状。

## 问题与修复

离线复现发现：索引已经核验且明确存在指定标题，但 expand_source_context 在语义候选为空或弃答时直接返回，独立的指定标题根本没有查找。此证明没有调用模型，不声称在自然运行中观察到了模型回答失败。

服务器先修改一个生产文件 source_expansion.py：完整、正向、明确的标题读取可以在语义候选被拒绝后继续精确查找。拒绝的候选和旧引用清空，绝不转成可信来源；只使用同一已核验索引代际和原过滤范围内的精确标题根，并经过原有新鲜数据库正文读取及修订核对。语义置信度保持原值，不伪造高分。只有实际纳入可用来源时才退出弃答；查无、预算无可见正文时保留弃答及真实查找范围，已定位不等于完整正文可见。同标题的不同版本均保留独立身份。

非明确读取、引用背景、否定读取仍保留原来的低置信度拒绝。没有修改角色专属域门控、预算、检索阈值、记忆解析或辅助审核，也没有启用实验独立子任务模式。

## 定向与真实验证

15个新边界节点及2个直接相关的既有节点一次全部通过，共17项。覆盖空候选、低置信候选隔离、普通/引用/否定读取、未核验或变化索引、重复身份、非法分块身份、原过滤范围、同标题版本、预算零可见、新鲜原文读取及原始修订变化。静态问题0。没有重复已通过的节点或全套测试。

新用例122字符：

> 分别读取《绿泽角色本人偏好》《绿泽加速受理》，说明角色在这个合成场景当前最喜欢什么，以及加速的公定费用、时限、完整办理条件和例外。另按我过去的本人原话列出当时最喜欢的方案与加速使用前提。请区分公定规定与我的偏好，不能把条件满足当作已经实际办理。

公共合成资料、问题与预期、来源哈希及结果核对见 [用例与结果](../../backend/tests/fixtures/deepseek_flash_title_without_anchors_result.json)。完整本人原话、私人预期值及完整模型回答保留在服务器受限评测目录，公开材料不包含它们。旧4条记忆来自原核验快照，不再导入、重写、推进历史或重放旧已通过的问题。

真实验证明确标为评测专用的“语义候选丢失模拟”：先保存实际自然检索回执，再仅替换候选列表与候选引用为空、置信度0及弃答标记；不修改真实索引、数据库正文、历史、来源或记忆。模拟脚本仅在隔离评测中运行，未部署，不能据此声称自然检索原本失败。实际原生鉴权、队列、上下文、精确标题扩展、新鲜正文读取、审核与官方模型调用均走真实链路。

实际发送请求完整包含 doc506 加速说明、doc508 角色当前正文及两条本人原话。最近16条历史不含原话，仍通过原来源回忆进入；没有减少或注入历史。精确匹配只产生请求的两个来源根，原自然候选不被提升。模型准确区分角色当前偏好与用户历史偏好，正确理解公定18元/5小时、完整表格 AND 核验通过、核验失败退回普通流程/预约不豁免核验，也保留私人来源中使用前提的完整限定。明确条件满足和喜好均不证明已办理。原4条记忆及限定完全不变，问题写入 no_change/接受0，25项实际核对通过；评审者为assistant，没有真人复核。

5次官方Flash调用均HTTP200/stop，原生回执及主回答各1次。按实际usage、缓存命中及周六闲时价格估算 0.14580780 元，包含辅助选择、策略与写入审核；不是平台账单。调用上限10次、最坏费用预留3元，并没有为压低费用减少输入或省掉必要验证。
