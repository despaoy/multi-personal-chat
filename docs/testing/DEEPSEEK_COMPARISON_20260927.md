# r126：DeepSeek 首轮同输入对照

## 范围

用户授权使用其 DeepSeek API 测试，确认公开资料可直接测试。密钥用 getpass 输入进程内存，没有写入文件、请求产物或报告。测试仅发送已有合成人物对话与公开原作资料，没有部署、覆盖或重启生产。

官方 /models 实际返回 deepseek-flash、deepseek-v4-pro；本轮选择 **deepseek-v4-pro**。参考官方接入与thinking文档，使用 `thinking.type=disabled`。11次回答调用，0writer，0新检索，0在线重试。

这不是一次新鲜HTTP全链路：复用r125六个问题、r124两个RAG问题、r122三个人物归属问题的完整 model_calls[0].request.messages，保持system、证据、原问题逐字不变。temperature/top_p/max_tokens/frequency_penalty保持原值；移除本地LoRA、repetition_penalty及chat_template参数，转换thinking接口。用真实云端回答调用现有guard与retryable/fallback函数诊断，不声称执行过整个服务、writer或重试。

因此该实验主要回答：**相同已准备好的输入，换模型是否改善阅读/生成，以及现有guard会不会误杀新模型回答？** 不验证DeepSeek记忆写入质量、长会话、人物长期一致性或生产并发。

## 结果

| 场景 | 原8B表现 | DeepSeek原始回答及限制 |
| --- | --- | --- |
| 姓名＋未知饮品 | 编造温热红茶 | 正确回答姓名，饮品未知 |
| 拼模型＋未知音乐类型 | 原始回答虚构“听别人提起”，最终整段回退 | 正确回忆拼模型，音乐未知；当前guard仍会整段误回退 |
| 喜欢水果但没有排名 | 正确 | 正确保留两种喜欢与无排名 |
| 喜欢羽毛球但康复前不能打 | 漏答、无据陪打，随后回退 | 明确喜欢、当前不能安排；当前guard仍会误回退 |
| 本人与室友不同喜好 | 原始归属正确，随后整段回退 | 正确区分两人，用户滑雪喜好未知；当前guard仍会误回退 |
| 用户喜欢科幻小说 | 冒领为角色的喜好，并扩写原因 | 正确用“你”归属，不编原因；但解释偏防御、冗长，自然性仍有改进空间 |
| 用户哥哥与原作哥哥 | 正确区分 | 正确区分明川和琉璃 |
| 原作关系＋用户插画 | 归属可读但角色外解释冗长 | 朋友关系与插画属用户均正确；额外“我只会泡红茶，不会画画”无输入支持，不能判整段完美 |
| 妹妹陶艺／本人修钟表 | r122正确 | 正确区分 |
| 本人在姐姐公司工作 | 冒领为角色经历 | 明确是用户，公司在淄博 |
| 妹妹送杯／本人喜欢 | 正确 | 正确同时回答喜欢者与送礼者 |

首组六题主要语义明显优于原8B，但仅一次采样。追加五题的核心问题均正确，RAG题有无据能力扩写。不能宣布总体准确率100%，也不能用这11题代表所有人物体验。当前检查会将3条有据回答立即替换为“这点我暂时记不清，不能凭空猜。”；其余8条没有blocking。未用强制全局偏好检测作为真值。

## 耗时与用量

11次全部finish_reason=stop。实测端到端API耗时0.563–1.843秒，均值1.214秒；短回答、非流式、禁用thinking，部分输入缓存命中，不是长对话p95或并发承诺。不与不同时刻、本地不同缓存的8B作严格速度因果比较。

提供方报告输入19114、输出264、合计19378 tokens，包含缓存输入；这里只报告接口usage，不估算人民币费用，不同模型分词不可直接横比。
