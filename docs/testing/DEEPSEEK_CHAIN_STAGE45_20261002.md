# DeepSeek 后端链路第 45 阶段：元数据迁移后的 RAG 索引与引用一致性

## 完整新案例与实际根因

本轮使用新的隔离 PostgreSQL 库和真实嵌入、Faiss/BM25 索引，导入三份完整合成资料：澜岚工坊玻璃镶嵌课现行规则、明确已作废草案，以及另一工坊的玻璃绘画课。正文明确给出日期星期、开课/结束时间、教室、联系人、编号、工具、雨天与停课例外、提交截止及书面确认条件；没有留缺省事实让模型猜。完整资料、185 字新问题和迁移条件见 [用例](../../backend/tests/fixtures/deepseek_knowledge_metadata_scope_cases.json)。

资料 1 起初放在草案库，标题为“澜岚工坊玻璃镶嵌课草案副本”、分类“待整理”。先通过实际搜索建立索引与缓存，再通过实际管理接口仅将其标题改为“澜岚工坊玻璃镶嵌课现行确认规则”、分类改为“现行课程”、迁到现行库，正文和分块不变。资料 2/3 保持在现行库，明确不能替代资料 1 的现行规则。随后直接做普通角色 RAG 问答，更新与问答之间不调用搜索接口、不手工修索引；生成结束后再检查旧库和新库的实际搜索结果。

真实基线 `stage45-scope-base`（PID 2161109）完成 1 次回答、4 次当前 deepseek-v4-pro HTTP200 调用。数据库迁移、标题更新与原文保存正确，课程字段全部正确理解，但模型仍把旧标题称为“当前标题”，API 引用也仍为旧标题；旧库继续召回迁出的资料，新库缺少它。保存证据统一检查为 17/25。

两个后端缺陷叠加：文档更新接口仅在正文变更分支标记索引 dirty，标题、分类、知识库变更没有失效已建索引；普通生成的通用 RAG 路径直接读索引和缓存，不经过搜索接口的索引就绪检查。因此已保存的新元数据无法到达真实模型上下文与引用。不是模型规模或事实输入缺失问题。

## 修复

标题、分类、所属知识库这些已经用于索引和过滤的字段实际变化后，文档更新接口标记 dirty 并递增修订号。正文变更和元数据同时变更只失效一次；相同字段值、空更新和非索引文件元数据不强制重建。元数据更新不重写原正文或分块。

普通生成进入通用 RAG 或纠正检索之前确认索引就绪，按现有机制完成 dirty 重建、修订号校验及落盘；索引缓存 generation 随真实重建更新，旧缓存不能继续作为新结果。若重建不能完成，抛出检索不可用，由现有生成降级路径处理，不能使用旧来源。人物多尺度证据继续使用自身索引，不依赖通用索引。

增加 `--knowledge-metadata-scope` 新诊断模式，复用当前原生驱动、真实认证、生成和存储观察，只运行本轮新资料与一次迁移问答。基线未重放任何旧阶段问题或来源写入。
