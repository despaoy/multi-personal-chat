# r111：网页来源身份与实际完成后写入链路

## 已修复的根因

网页 TestChatDialog 发送角色请求时不提供 `sourceMessageId`；API字段默认为空，`_save_message` 和 `_complete_character_turn` 原样传递。后台 `_process_job` 将其标为 `missing_identity`，无法保存独立原话，即使回复正常生成。

新增HTTP回归先在旧实现失败：两次请求都返回200，但来源ID为 `['', '']`。证据 `.tmp/mechanism-r111-before.xml`。

修复仅在认证后的网页角色入口：未提供非空来源ID时生成 `web:` + UUID，先于排队分配，让同一请求的消息存储与完成后写入共享身份。已有来源ID保留，集成平台和分支路径不改变。不是内容指纹，不去重重复句子，也不声称解决网络重试幂等性。

没有改提示词、增加复核模型、修改关系规则或放宽记忆写入门。

## 真实链路验证

新增 `backend/evaluation/web_memory_live_replay.py`，路径：ASGI HTTP `/api/generate` → 实际 ChatGenerationService → prepare_turn → 实际vLLM客户端/服务器模型 → 共享generation/guard → 消息入库 → complete_turn → 实际后台记忆模型与仓储。

明确边界：登录使用固定测试身份，排队使用inline适配器；没有启动公网HTTP监听，没有测试真实登录/限流/浏览器。SQLite及配置均隔离，RAG关闭、无LoRA，可选语义复核关闭；来源召回显式启用、窗口扩展关闭。逐轮等待writer队列排空，尚未验证不等待时的异步体验。不是生产部署验收。

服务器现有Qwen3-8B-Instruct-AWQ，7场景，10条原始输入+9个问题，19次真实生成、17次真实记忆模型调用。19个HTTP响应全部200；实际对话会加载已保存的用户与助手历史，没有用人工历史替代。

下载隔离数据库进行只读核对：19条消息、19个不同web来源ID，17份原话逐字对应输入；身份均来自认证测试用户，而非请求里的伪造senderId。2条被上游跳过的输入没有被偷偷保存为原话。校验脚本 `.tmp/mechanism-r111-verify.py`。

## 新发现的真实问题

| 观察 | 具体证据 | 原因/下一步 |
| --- | --- | --- |
| 条件计划没有进入长期来源 | “如果我下个月拿到录取通知，才会去德州报到。现在还没拿到。”返回 skipped_fiction_or_note，0原话 | `_FICTION_CONTEXT` 将句首“如果/要是”等与虚构放在一起，complete_turn在scheduler之前拦截。不能靠调召回解决 |
| 回忆问题仍调用writer | 9个问题全部buffered_idle且各调用1次记忆模型 | `classify_memory_write_mode` 对任何允许写入的非命令都返回idle。不是所有问题都应永久排除，但纯读取缺少轻量跳过路径 |
| 新陈述被当成无依据回忆 | “我以前爱吃香菜。”及“现在口味变了，我不吃香菜了。”均被guard换成“这点我暂时记不清，不能凭空猜。” | 原生成触发unsupported_user_fact，随后确定性兜底。需要检查当前输入支持与历史支持的区分，不应全局关闭guard |
| 冗余询问和助手式承诺 | 明确说培训取消后仍问安排有无变动；会议回答主动提议确认天气交通 | 事实读取正确不代表人物自然度合格；不能按9个最后问题得分掩盖中间轮体验 |
| 虚构讨论仍混淆 | 初次回复追问搬到潍坊是临时还是长期；后问用户是否搬家时继续混淆“我” | 写入门正确拒绝虚构事实，不代表对话理解正确 |

纯问题writer输出以空列表为主；还出现从旧history复制evidence的NOOP/SUPERSEDE候选。这些没有带来新增有效事实，不能把模型返回JSON视为有效更新。原话记忆目前也保存了这些问题，后续需要评估索引噪声与语义归属。

有近期真实历史时，用户与朋友住址、明确取消、省略取消、练习者归属和最终偏好问题答对或基本答对；条件问题能从短期历史回答“不确定”，但长期来源仍为空。不能据此声称长期记忆问题已解决。
