# DeepSeek 后端链路阶段 59：关闭引用显示时仍保留完整通用知识证据

日期：2026-10-02。基线：`d5c224947d15123f3a8615b861d7f7bb1853f027`。服务器先修改、验证有效后同步。所有测试资料、账号与克隆数据库均为合成夹具。

## 问题与复现

通用知识库使用 `RAGHelper.format_context_results` 的 2000 字符限额。开启引用时，`prepare_answer_citations` 会从完整检索结果重建正文，所以中间裁剪不一定影响最终模型请求；关闭 `RAG_CITATIONS_ENABLED` 后，API 丢弃引用元数据，后续无法补回正文，最终请求只保留开头。

服务器使用完整的 3404 字符锦岚规程，规程编号 XL-936-N；旧草案与库存记录在前，最终设备、资源、数据划分及禁止事项在末尾。统一分块器实际将完整引文保存成一个完整片段。零云调用复现使用受控的已选检索结果，执行真实格式化器、共享 API 与模型请求构建器，在模型边界停止：引用开启时原文完整，估算总量 3580；关闭时末尾有效条件缺失，估算 3153。相同完整输入低于当前 65536 工作窗口。没有将中间格式化裁剪误判成引用开启路径的最终丢失。

## 修复

新增 `document_evidence_packets`，把已检索的通用知识片段按完整正文与稳定片段 ID 组装为独立证据包，不根据引用显示决定正文。共享 API 将完整包交给最终请求预算，整包接收或排除。没有合法绑定来源时，引用准备步骤保留完整证据、去除无效引用候选，并不创建引用命名空间、输出策略或修复调用。开启引用时仍对已经接收的完整包绑定真实来源标记。

检索、权限、信任区隔与最终令牌预算沿用已有契约。`RAGHelper` 的旧格式化接口仍保留，其他调用路径不在本阶段的修复证明范围。没有增加正常请求的数据库查询、云调用或表结构；生产引用显示配置保持原值。
