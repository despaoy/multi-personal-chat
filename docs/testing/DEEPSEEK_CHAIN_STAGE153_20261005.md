# 阶段153：本人、朋友与否定别名的完整依据

日期：2026-10-05。整体优化目标 active，公网开放不在范围内。本阶段没有后端代码修改、生产重启或旧全量回归。

## 先排除用例误判

阶段152首个真实数据库用例用“核验本轮仍可用的……”表达，没有明确偏好所属人；后来补充“我保存的、在本轮……”又用逗号拆开所属人与偏好话题。非上下文召回在这两种问法中没有选中候选，不能把它直接判为完整信息的生产缺陷。

本阶段重新做五个完整问题版本、分别比较非上下文和上下文候选读取，共十项新的零模型调用对照。连续明确本人所属人的“核验我保存的……偏好”及明确“读取我保存的……并核验来源”，两种读取模式都选中两条正常捕获与规则写入的完整偏好，实际存储和来源版本绑定完整。前述模糊或逗号分割版本在非上下文模式不选中，在生产配置使用的上下文候选模式保留两条给后续审核。明确只问其他人的任务也由上下文审核决定是否使用；有候选不等于主体授权。实际生产进程配置启用了上下文筛选，但此次对照不宣称实际原生认证或筛选模型验收。首次探测进程因模块加载路径失败未进入模型，记录保留，修正环境后完成这些对照。

因此阶段152报告中的“核验个人偏好漏召回”是待核对边界；现在未证明信息完整的本人问句或生产候选路径存在这项缺陷。无需为不充分的测试问法放宽主体判定或候选使用权限。

## 新增真实模型链路

用正常来源捕获、规则提取和规则写入准备三条完整虚构来源：本人对两种饮品的正、负偏好；朋友的相反偏好、朋友名称及别名，以及明确“朋友别名不是本人别名”的末尾否定。SQLite 免费基线和实际隔离 PostgreSQL 均实际运行这些操作；朋友来源没有提取为本人的规则事实，本人原有两条记录保持。

实际 PostgreSQL 的生产上下文候选路径取得两条本人记忆，正常 ContextualEvidenceSelector 用真实 deepseek-flash 分别审核混合本人/朋友任务和只问朋友的任务。全部实际候选编号每次各分类一次，混合任务使用两条本人证据，只问朋友任务不使用本人偏好；审核输入含完整内容及证据，不以预设选择回执替代实际模型判断。

正常 SourceMemoryService 单独召回完整朋友来源，随后共享生成路径使用可信准备作用域的原话与结构化记忆核验回调。实际主请求包含三条完整来源、两条本人完整表述及证据，未带内部版本或指纹。一次新的真实 Flash 主答通过十二项内容检查：本人两个偏好、朋友两个相反偏好、朋友名称、朋友别名、别名属于朋友、本人的别名未知、私人描述不证明现实审核，以及本人两条完整证据句和朋友整条完整来源逐字复述。严格 JSON 通过。最终规范记录哈希未变。

这是实际数据库、实际筛选模型、实际来源召回和实际共享主答的组件联动；未验收原生登录、交付历史、向量检索、公共 RAG 或真实模型记忆提取写入。朋友的原话仍是用户历史自述，不能升级为现实验证。完整原始问题、來源和模型输入输出仅保存服务器，不导出到 GitHub。

新增模型发送三、HTTP200 三、主答一、辅助筛选二、原生请求零。usage 估算 0.00424848 元，并非账户账单。首次成功进程已按原 PID 与启动时间确认终止，没有重启或重复付费主答。只执行新增对照，没有旧全量回归。
