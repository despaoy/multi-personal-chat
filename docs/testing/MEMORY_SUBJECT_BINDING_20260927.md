# r121：个人字段的显式主体绑定与事件通道反例

## 落地范围

memory_subject.py 合并既有读取/写入两套不一致的人称关系词表。
对姓名、偏好、专业、学习阶段、地点、工作字段，从模型 evidence 在原始 source 的
匹配位置回到完整分句，检查直接主体。只在包含该 value 的所有匹配分句都明确属于
非本人时拒绝个人字段候选；多义/未知不被当成确定他人。截掉主体的引用不自动获得本人归属。
memory_query 共用 owner grammar，避免写入/查询对同一关系短语有不同理解。

没有增加模型调用或提示词，没有改写用户原话或迁移既有记录。
这是有限的显式语法识别，不是通用中文依存分析；未知称谓、转述、隐含指代仍不充分。
旧的第三方保护仍保留，既有保守误拒绝没有由此全部解决。
shared_event/goal 等非个人字段暂未纳入这项直接主体拒绝，因为第三人作主语的事件
仍可能涉及用户，例如“姐姐喜欢我送她的陶杯”；不能简单将其全部删掉。

## 下一步

保留本轮个人字段保护，但主体契约必须扩展到事件/关系，并明确“来源发言者”不等于
“事件参与者”。不能简单放行模型自报 user，也不能因第三人作主语就抹掉涉及用户的事件。
需要对 actor/recipient/owner/subject 的角色与原文跨度建立独立约束，验证多主体与共享事件。
模型阅读阶段冒领经历也需独立定位；本轮不是全项目验收。生产未改，所有远端运行结束。
