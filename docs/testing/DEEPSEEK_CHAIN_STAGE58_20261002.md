# DeepSeek 后端链路阶段 58：公共证据与私人来源的最终预算衔接

日期：2026-10-02。基线：`7a1af3369e3c72bce8008149f1870020ea06ad4d`。服务器先修改、验证有效后同步。所有来源、问题和账号范围均为完整合成资料；没有读取生产聊天内容。

## 问题与证据

角色知识的生产单例固定使用 6000 字符上限；共享生成 API 又使用 `GenerationRequest.evidence_max_chars=6000`。当前云模型工作窗口为 65536。完整的文溪私人来源为 21051 字符，公开规程为 8461 字符，均有最终限制，公开规程有独立来源编号 WX-804-Q。

服务器使用真实缓存 MiniLM 向量、BM25、角色多粒度索引与实际上下文服务复现。检索选中了公开卡片，却因整包大于 6000 字符而排除正文；即使显式扩大检索预算，最终请求仍会再次排除公开证据。同一完整私人来源与完整公开资料组合的估算总量（含输出与安全余量）为 11525，确实低于 65536。私人存储只有一个完整原始来源，没有结构化事实。该复现零云调用，不能归因于资料不足或模型容量。

## 修复

云提供商预算令公共角色检索延迟字符预算裁决：`rag_max_chars=None`，最终请求 `evidence_max_chars=0`。多粒度检索仍执行领域、可见性、来源与背景依赖筛选，将完整已选包交给现有 canonical 请求构建器。它依据实际固定输入、输出、安全余量和上下文窗口整包接收或排除，并同步筛选引用和背景依赖。私人来源的预算决定仍先确定，公共包尝试不会反复改变该决定。

本地提供商仍保留 6000 字符；显式实例的默认值仍为 6000。角色检索单例在提供商预算变化时刷新，避免使用另一提供商的旧预算。共享生成 API 显式传递提供商的最终证据预算。没有新增数据库查询、云调用、表结构或生产配置变更。生成 API 的无关格式变化已还原。

## 准备过程与计数

初始离线脚本遗漏缓存 embedding 路径，零云调用终止；补全路径后测试构造误用了检索状态名，零云调用终止；复用同一合成数据库/索引修正状态后获得有效预算证据。

第一次真实用例没有用正式书名号指明规程标题，置信度 0.1833，按现有阈值弃答；出站资料完整性检查阻止主调用，只有一次动态策略调用。补全正式标题后检索通过，但隔离 SQLite 默认 `deepseek-chat` 覆盖环境变量，实际返回 `deepseek-flash`；它的一次策略与一次主回答仅作为准备记录，不算大模型验证成功。更新隔离数据库时旧配置缓存仍存在，出站型号断言阻止所有错误调用；按正式配置更新流程清除隔离缓存后，才获得上述两次 pro 调用。

本阶段累计 5 次云 HTTP200 完成调用，其中准备调用 3 次 flash、有效验证 2 次 pro；累计两个真实主回答，其中只有一个符合本阶段大模型要求。所有作业均结束。原有生产配置的三个校验值保持一致。修复验证只涉及新用例及其失败准备，不重复旧业务或全套测试。
