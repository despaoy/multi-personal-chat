# DeepSeek 后端链路阶段 56：原始来源接入可用用户话题历史

日期：2026-10-02。父提交：8d03490c766376c69b0ce81bcfa0f278759613ee。持续优化目标保持进行中。

## 实际根因

角色记忆候选已经使用可用的用户历史，但独立原始来源召回仍仅查询当前消息。当当前请求是“按刚才那个继续，给我七天的执行安排。”时，已保存的历史明确谈青岚，完整原始条件也已保存，但来源检索无法利用该话题；没有可用的类型化声明时，原始条件完全进不了模型请求。这是已记录信息未接通检索的链路问题。

服务器隔离 SQLite 的零模型基线有 41 条完整来源、零条声明；当前查询返回无匹配，同一请求补上已有话题就能读到完整原始记录。实际隔离 PostgreSQL 的新用户同样复现了当前查询无匹配，并验证新增历史检索可找到完整条件。

## 修复

在来源服务中保留当前请求的独立检索，另加入已加载用户文本历史的独立检索。历史文本由已有角色上下文函数编译，助手/系统消息和非文本值不参与。每个检索仍最多读取 32 个候选，合并排序保留声明关联、当前请求与历史检索各自的首选，最终来源锚点仍最多四个。没有增加模型调用；有非空用户历史时增加一次同范围来源查询，没有历史时不增加查询。

两条检索均通过相同数据库范围与删除围栏；选中后继续按来源身份重新读取当前授权正文，避免从候选缓存恢复已删除文字。原始话语继续标记为主体及当前有效性未解析，并不写成当前事实。

原始来源查询原先限制为 8000 字符，与可用历史总长度不一致。现在接受完整文本，通过单个 JSON 数组绑定全部索引词，保持查询参数数量恒定，不裁掉头尾话题。该路径的输入来自已有历史加载器；并未将最终模型上下文变成无限预算。来源注入仍遵守整条正文预算，过长来源不会以缺少条件的片段冒充完整证据。

## 输入完整的新合成场景

青岚项目与资源均为虚构测试条件。原始记录明确：RTX 3060 / 12GB，全程离线，不允许云端调用或下载，禁止训练及微调，只验证已缓存且可离线启动的 Mini 0.6B 分类模型；完整权重、分词器及全部依赖齐备；1500 条本地四类标注文本，1200/300 固定划分，验证集不得调参，目标为推理复现、显存峰值及验证准确率。另有 40 条完整无关库存来源。没有类型化声明或缓存事实。

服务器历史只有“接下来只谈青岚；请依据我保存的该项目原始条件作答。”，由实际来源接口和消息接口保存。当前请求不重复项目名、硬件或网络条件。新用户通过真实登录认证；此场景不重放此前任何模型业务。

## 仍有的边界

稀疏索引和合并排序不是语义正确性的证明。多项目历史、更多候选及四条锚点或整条来源预算仍可能遗漏有用条件；本阶段没有通过截取正文来隐藏这个限制。历史检索增加一次 SQL 和索引词计算，尚未做吞吐量基准。历史加载器与最终上下文预算有界。并发删除在授权重查之后、生成之前发生的情况及跨批次一致性尚未全面验证。保存结果条件审核不能替代通用逻辑蕴含。合成硬件和本地模型资源没有进行实际硬件或模型性能评测。

最终核对发现旧 test_source_memory_recall 中一条“8001 字符必须报错”的参数化场景与新历史查询要求冲突，移除该场景及其专属拒绝分支。其余函数 AST 不变，空查询/标点两个场景的断言与原 else 分支 AST 相同；只收集确认这两个保留场景，零测试执行。已有新长历史测试已验证超过 8000 字符的完整头尾及恒定参数，因此不重复运行。此清理在服务器先完成，追加同步提交，不需要再次部署后端或调用模型。
