# 阶段143：对象、别名及来源审核失败诊断

日期：2026-10-05。整体优化目标仍为 active，公网开放不在范围内。

## 问题与修改

完整独立虚构资料包含当前有效别名登记、别名业务规则、另一业务费用、明确不收费、雨天暂停及预约不豁免原件。私人原话通过正常 SQLite 捕获及授权读取；混合人物资料通过真实原文提取器读取完整临时文件。这些是组件与协议测试，不冒充原生登录、历史、向量召回或真实模型故障。

两个完整正向节点先通过。15 个新失败节点复现了对象、名称身份和来源位置审核失败时内部缺少收到的原文及完整输入。其中包括无效 JSON、任务编号类型错误、伪造登记引用、跨来源位置、非文本响应、传输错误及超时。

现在在等待响应前登记审核阶段和实际完整消息，收到文本后原样保留；只有失败时将此次交换存入内部 failure_diagnostic。非文本响应和没有响应都保留 raw=None，不转换或编造文本。成功解析后清除临时诊断，来源位置原响应只在整批验证通过后成为 object_span_review。严格解析、授权和证据接纳规则保持。

失败诊断不进入后续审核或最终模型消息，也不能使 unavailable 变为有效证据。无效整批公共审核仍拒绝该批业务来源；独立人物原文与正常授权私人原话继续进入生成请求。不能因收到诊断而授予部分证据权限。

## 验证与边界

最终 18 个唯一节点通过：17 个新节点和 1 个直接受影响节点。修复后首次检查 16 通过、2 失败：新混合用例错误要求人物任务也显示 review_unavailable。程序正确显示 handled_by_independent_curated_domain；仅改测试断言，并只重测这两项。最初新文件导入排序检查在单元测试之前失败，修正排序后语义保持，所有原始结果留存在服务器。

成功路径保留登记、两项业务及五项事实；两项明确否定仍有接纳的原文依据。失败路径保留私人原话和独立人物正文，业务失败原文与输入均不进入最终消息，诊断中放入有效 JSON 也不会升级状态。旧源码仅窄改，未格式化，静态诊断基线保持；新测试格式化前后 AST 相同，导入排序单独确认导入集合及其他 AST 不变。

另外在隔离数据库重新读取既有完整来源，四份既有真实 DeepSeek 成功响应按完全相同消息离线复用，修改后完整审核回执及选中来源与原记录一致。没有重放已通过付费主答，没有新增模型 HTTP，也没有原生会话请求。本阶段新增估算费用 0 元；这是新增调用统计，不是账户账单。累计计数保持原生成功请求 571、模型发送 2275、HTTP 200 为 2268，保留 7 次已有非 200。
