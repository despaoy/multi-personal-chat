# r125：偏好检查的全局放行与整段回退

## 已验证的根因

`build_reply_guard` 用 `not has_relevant_memory and not asserted_preference` 决定是否检查整段回答。服务传入的 has_relevant_memory 只是 `bool(injected_memory_ids)`。因此姓名记忆也能关闭所有偏好检查；用户说过某项偏好也会放行其他偏好。相反，只有原话、没有结构化 claim 时，明确的原话偏好可能被当成无依据。检查器仅扫描部分第二人称表达，角色冒领成“我喜欢”又可能漏检。

这是证据范围与断言范围不对应，不能通过增大上下文窗口、把整个检查调严/调松解决。当前仍未修复在线机制；本轮落地的是可复现审计工具和新鲜真实链路基线，不将诊断宣称为修复。

## 历史审计

新增 `backend/evaluation/preference_gate_audit.py`，只重放第一条原始模型回答；强制开启现有检测器仅用于发现审查候选，不等于认定幻觉。不把后续写入数据库的 claims 作为此前生成的证据。分别保存 prepared 用户历史和实际请求的用户消息，避免把被预算排除的历史算作已入模；不兼容/缺失 guard schema 明确跳过。

- 近期 r111–r124：219 audited、13 not_replayable；80 次关闭检查，7 个审查候选。7 个候选的偏好本身都有来源支持（6 条为同一赠礼场景跨版本重复），不代表整个回答质量都通过。
- 全部现存 traces：2499 audited、173 not_replayable；628 次关闭检查、89 次检测器命中、69 个关闭状态下命中。它们包含跨版本/跨轮重复，不是 2499 个独立任务或 69 次确定幻觉。
- 人工检查发现正确回忆、澄清、第三方归属与有问题的扩写混杂。具体旧反例包括“喜欢红茶”变“最喜欢红茶”、由素描推断色调偏好、由摄影与饭局推测对摆盘感兴趣。未逐条完成全部69条语义裁决，不报告误判率。

## 论文依据与下一轮实现约束

本轮读取了两篇论文官方摘要，未声称复现其基准或中文表现：

- [FActScore](https://arxiv.org/abs/2305.14251)：一段生成可以混合有依据和无依据的信息，整段二元判断不够。借鉴**逐项对证据**，不是引入其昂贵在线检索/裁判。
- [MiniCheck](https://arxiv.org/abs/2404.10774)：逐项模型验证可能很昂贵，专门的小型grounding模型可降低成本。论文报告的性能/400倍成本差是其自身设置，不外推到本项目中文人物聊天；未下载或部署模型。

下一步必须满足：

1. 有姓名证据不能许可饮品、习惯或人格推断；一个有据子句不能许可整段。
2. 原话中的明确喜好与结构化偏好都属于潜在证据；source-only 不等于无依据，但来源非空也不等于每句都受支持。
3. 分开主体、肯否、条件、程度与时效；“喜欢”不自动支持“最喜欢”，“不能做”不自动等于“不喜欢”。
4. 支持、冲突、未找到支持、规则不能判断要区分；字符串不完全匹配不是足够的反证，不能误杀自然转述。
5. 未验证逐项支持前，不启用全局强检查、不全局撤掉防护、不增加通用重试；重试r119已有失败与额外耗时证据。
6. 修复要同时通过上述负例和正确转述/第三方/条件反例；不能只修“红茶”词表，不能把原回答中正确部分和错误部分一起视作全部正确或全部错误。
