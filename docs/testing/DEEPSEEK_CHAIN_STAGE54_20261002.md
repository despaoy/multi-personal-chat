# DeepSeek 后端链路第 54 阶段：完整记忆出处被关联数量挤掉

日期：2026-10-02。基线 f64a01c52b8737b8dcad7b98e4717e61fb966671。持续目标仍在进行。

## 问题及复现

旧字段和语义记忆的当前事实投影需要读取完整、可授权的原始出处。原代码将最多 100 个记忆 ID 一起传给出处读取器，读取器却只返回最新 100 条“记忆—来源”关联。这两个数量不是一回事。一个关联多份原文的合并/导入记忆可能占满结果，挤掉同批次另一条记忆的实际出处，随后该记忆降级为“原话时效/字段未核实”。

完整合成夹具包含两条记忆、101 条有效来源关联：较早的原话“我的专业是信息管理与信息系统。”对应一条旧字段 fact_信息管理与信息系统；另一条无关库存合并事件对应 100 条完整库存登记。所有来源有完整正文、可信时区回执、同一用户/角色/会话范围和实际关联。库存正文包含材质、数量、存放架、盘点日期、核对状态，不能替代本人专业。关联图作为合法的合并/导入历史夹具在隔离库中预置，不声称普通当前消息写入器会一次建立 100 条关联。

SQLite 和实际 PostgreSQL 均复现：默认读取返回 100 条，漏掉专业的真实出处；较大旧读取能看到全部 101 条，证明资料确实存在；旧投影把专业存在状态设为未知。数据库原话、关联、记忆均未因读操作改变。问题发生在模型调用之前，不归因于信息缺失或模型规模。

## 修复

事实出处核验新增精确“记忆 ID + 来源 ID”配对路径。仓储从已有记忆记录声明的完整来源身份列表生成请求，每批最多 200 对；SQL VALUES 使用绑定参数，连接实际 memory_source_links 和 memory_sources，验证相同范围、已记录状态、删除水位。每个请求配对最多返回一个实际来源，不再让无关关联占据全局 top-k 名额，不按模型给出的来源身份重新建立关联。

来源正文和回执来自当前数据库；原检索排序、原话召回预算、字段投影的完整性/条件/时效规则保持原行为。投影仍不能从未关联、已撤销、跨范围或缺失正文的来源建立当前事实。旧外部仓储仅保留原有兼容路径，不声称这些外部适配器已获得相同完整性。

## 范围

精确配对读取是一批 SQL 的当前授权视图；多批来源与前面的记忆记录读取仍不是一个跨表、跨批的事务快照。删除或并发更新发生在各批之间的情况需另测。大量原文的总读取成本、模型选择预算、较晚的条件与语义改写、一般记忆提取正确性不由此阶段证明。此阶段只证明完整已有来源不应因无关关联数量被静默挤掉，以及对应资料可被实际大模型理解。持续目标未完成。
