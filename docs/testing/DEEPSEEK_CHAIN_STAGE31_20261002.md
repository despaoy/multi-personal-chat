## 服务器优先修复与精确写回

业务改变仅四个文件：API 生成、SQLite 适配器、PG/同步适配器，以及共享 `db/message_feedback.py`。不新增数据库列、迁移或权限入口。

`_save_message` 保留 bool 契约，额外向调用方提供真实 add_message 返回的存档 receipt。消息确实归档成功后才执行原有 complete_turn；只有完成产生保存提示时才补写最终公开回复。正常 capture、无提示和内部未持久化路径不追加保存提示，也不自动重复模型或原话写入。

共享参数化 UPDATE 必须同时匹配真实存档编号、NULL 分支、平台、适配器、发送者、会话种类和 ID、角色、客户端会话、来源 ID、追踪 ID、完整用户正文、原始回复。只更新 reply；其他列与原话 body 不变。原回复可为初始版本或同一最终版本，因此重复同一补写不叠加提示。若记录被删除、范围/正文不符、回复已被别的修改改变则返回 false；不按客户端 sourceMessageId/文本查找、批量更新、改写另一条或重建已删除记录。假想分支和缺失权威明确拒绝。

API 和数据库共享最终提示渲染，两个生成消费者在同一注入数据库上补写自己拿到的真实 row receipt。若提示存档失败或状态未知，仍保留当前失败提示并补充“刷新后可能看不到本次保存状态”，不把未确认的历史存储说成成功，不泄露异常细节。回写超时只是不确定，可能存在晚提交；本阶段没有把等待取消视为事务回滚。

存档此后保存的是与实际 API 一致的最终公开回复，包括系统独立保存提示。原实际模型部分仍在最终回复前缀，评测云调用原始输出和 token/model 计量不改；**不能称生产 model_invocations 保存了完整原始输出，它只存计量和错误信息。** 没有复制用户正文到新表，没有把助手提示作为用户原话或用户本人事实。原 source 身份、时钟、撤销、owner fence、source-only、语义容量和 RAG 权限不改变。
