# r128：无 LoRA 的 DeepSeek 实际链路测试

## 结论

换用更强模型改善了主体区分、条件理解和未知信息处理，但不能证明长期记忆、RAG、动态上下文已经可靠。当前有模型理解正确、系统拒绝写入或删掉正确答案的问题。无需先扩大上下文或重写人物提示词。

## 方法与边界

- 服务器隔离快照运行实际聊天服务、上下文构建、记忆调度/准入、SQLite，以及第二批真实角色 RAG；未发布或修改生产服务。
- 实际调用 deepseek-v4-pro，非思考模式，无 LoRA；回答和记忆提取均使用该 API。HTTP 响应的 model 字段仍是被注入适配器前的本地旧标签，应以 provider_calls 和 manifest 为准。
- 17 场景、41 轮 HTTP 200；42 次新回答调用（包含一次重试）、40 次新记忆提取调用，非录制模型响应。
- 第一批 12 场景/28 轮，12 个冷读问题：去除近期聊天历史，但开启原始来源召回。第二批 5 场景/13 轮，6 个问题：保留历史并开启 RAG。可选模型复核关闭。
- 固定测试身份、内联测试队列、隔离数据库；不涵盖生产鉴权、真实后台排队、负载与长期大量历史。
- 下面是人工按核心语义检查的单次探索样本，不是统计可靠的准确率、人物相似度或与 8B 的同条件全链路对照。

## 逐链路定位

### 1. 模型理解不等于成功保存

离线用原 writer 输出及当时历史/目标白名单重新执行准入，以 Python return tracing 确认失败位置，无新模型调用、无数据库写入：

- multi_field 故乡候选在 memory_llm.py:880 第三方主体规则被拒；现居候选在 :1037 限定字段检查被拒。不可统一归因于模型没提取。
- changed_residence：模型提出 SUPERSEDE，目标为原现居地记录；在 :1067 本地位置键推断与目标键不一致而拒绝。旧绍兴记录仍 active。入模既有完整搬家原话，也有系统生成的“现居地 unverified”，存在机制层矛盾，不是原话被上下文截掉。
- additive_pets：两次自然改写在 :1007 grounded_value 检查被拒。
- qualified_residence：在 :1080 value/content 字面包含检查被拒；不是两个正确位置候选分别成功保存。
- natural_reason：preference_detail 限定字段在 :1037 被拒。

原始来源召回能兜底很多问答，所以只测最终回答会掩盖结构化写入缺陷。下一步应处理字段契约兼容、主体/位置谓词判定与自然改写接受，不新增昂贵模型复核，也不按测试城市和宠物名特判。

### 2. 删除操作没有落地，回答却声称完成

用户说“从记忆里删除”，writer 正确生成 ERASE 并指向原记录，但在 :968 删除意图正则检查被拒。现有模式包含“从记忆中删除”，未覆盖该自然表述。原记录与来源仍存在；最后回答“现在没有保存它”与数据库不符。

修复方向：删除/更新作为有结果回执的操作，回答依据实际执行结果；删除范围覆盖事实及相关来源召回，避免只让模型口头答应。应以多样表达回归验证，不能仅增加一个例子的同义词后宣布解决。

### 3. 检索与后处理仍有问题

哥哥混合问题首次模型回答：“你的哥哥叫明川。我原作里的哥哥叫琉璃。”但 guard 判 unprompted_canonical_identity，触发一次重试及 character_guard_sanitized，最后只剩“你的哥哥叫明川。”角色资料本身明确写有琉璃，但本轮检索为 character_abstention。须协调问题意图、人物资料和检索状态，避免将明确被问及的角色信息当成主动跑题。

手机品牌题检索返回无关告白/小说资料，却标记 ok；模型自行保留不确定，并不意味着 RAG 检索正确。下雨安排题回答正确，但外层仍标 abstained/abstention；边界表达轮也触发了无证据检索。需要分开外部知识子任务和个人对话子任务，减少无关检索与错误状态。

### 4. 动态上下文的效果尚不能单独归因

不建议、不追问、结束话题和条件指代的实际回答正确。但近期历史、对话便签和来源召回同时存在，未做关闭动态上下文的消融。因此只能说当前组合在这些场景有效，不能声称动态模块独立通过全面测试。
