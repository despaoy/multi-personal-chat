## 修复

不可变记忆结构增加来源完整性和原始片段位置，读取服务与直接仓储读取均传递这些字段。只解释应用已有的 v1 原文片段标记；未验证的旧记录显示 unverified，缺少标记或文字自称“完整记录”不能证明完整原话，更不会生成 complete=true。

坐标必须属于已有来源，区间使用整数、保持原顺序且不重叠，长度与实际保留证据逐段一致。无法验证的坐标不修补、不重新计算；已识别的部分来源标记仍保留，位置则为空。字段来自保存的应用元数据，不能授予删除、主体解析或当前有效性。

完整 JSON 记忆包、普通参考格式与动态选择候选均带来源完整性信息。完整路径说明位置是原始 Unicode 字符索引、起点包含终点不含，并提供从真实相邻坐标得到的已知空缺；没有推测空缺文字，也没有假定缺失的首尾范围。选择器的 content_complete 仅表示本次传输没有截断候选，不表示原话完整；选择结果保留原始不可变记忆对象。

部分来源的时间读取视图不重新补入完整旧来源，也不能把片段解析成新的当前事实。即便组件调用方提供旧完整正文，也只使用已保留的证据和原始观察时间。来源合并不会把单个部分片段当作完整来源而丢掉删减说明。原话中的命令与完整性自述仍处于不可信参考区。

增加 `--memory-source-completeness` 诊断模式，复用既有原生驱动与签名交付流程。该模式要求实际父状态和唯一记录完全一致，将新问题作为读取请求，不额外执行删除或第二个冷读取。
