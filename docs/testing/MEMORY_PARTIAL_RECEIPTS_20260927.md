# r135：LLM记忆执行的部分完成、冲突和取消回执

## 复现与修复

旧调度器将一项成功、一项因来源撤销跳过的批次报告为saved；版本冲突则和任意存储异常混成failed。取消中途也可能丢失本任务之前已经提交的计数。

现在按任务保留operation_outcomes与conflicts数量。成功与failed/conflict/skipped并存为partial；纯版本冲突为conflict，不计为数据库故障。不自动将旧模型提案重放到新目标：MERGE内容可能依赖旧版本，未经重新推导不能照搬。每项完成后刷新回执计数，随后取消仍保留已确认提交项，整体状态为cancelled。取消中的那一项是否在底层线程提交仍未知，不把cancelled解释成“全部未执行”。

## 测试

新增状态组合测试在修改前5项失败（其中包含缺少诊断字段的失败，不全是状态错误）；修改后通过。取消测试固定第一项完成、第二项等待，再关闭工作器，确认保留persisted=1。

真实SQLite交错测试：在模拟模型completion期间写入新版本，随后旧SUPERSEDE被数据库拒绝；当前只保留新值，旧来源仍保存，回执conflict/persisted=0；completion仅一次，没有静默再推理或重放。该测试注入已验证提案以隔离执行层，不代表自然语言解析或真实模型效果通过。
