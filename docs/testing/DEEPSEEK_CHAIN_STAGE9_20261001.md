## 实际生产入口

两名专用普通测试用户通过真实 HTTPS 登录、网关和 /api/generate 完成 12 轮聊天。账号由测试准备步骤单独创建，未开放公开注册，未使用现有用户身份。输入完整保存在 `backend/tests/fixtures/deepseek_production_memory_cases.json`。实际发送内容不包含预期答案。

场景覆盖四项个人资料、夜间饮品条件、居住地更正、朋友资料不能变成本人资料、情绪与未完成任务、另一用户无资料时明确未知，以及第二用户独立保存资料。每轮使用新的 UI session；私聊的历史仍按认证用户归属，不能将这称为没有近期历史的冷记忆测试。

修复前 12 个请求均成功，答案和来源／隔离的独立审计 16 项通过。但两名用户的姓名被写成 `fact_姓名`，标准 `user_name` 字段不存在。原始生产结果另有一个模型标签断言误用了 ask 接口的格式；generate 实际格式为 `deepseek-v4-pro (openai_compat)`。原始结果保持不变，独立审计记录了这项检查器修正。

## 复现、根因和修复

实际解析、SQLite 存储和字段召回的三项用例复现失败：明确姓名被普通事实类型遮蔽，以及“我目前住在”没有被既有规则语法识别。不能只凭最近历史支持的正确回答，推断标准长期记忆字段可读。

- 对没有现有目标、没有限定字段、操作为 ADD 的 `other_user_fact`，只有独立规则提取器从引用和完整消息中都证明同一个唯一字段和值，才归入标准字段。沿用置信度、主体、来源、作用域和既有提案校验；不根据模型的自由总结推断字段。
- 居住语法补齐明确的“我目前住在”，与既有“我现在住在”一致。来源地和现居地同值时仍保留歧义；未来计划和条件不被提升为当前住址。完整原文是假设时，即使引用只截取内部肯定句，也不能成为当前个人字段。
- 有现有普通事实目标的操作保持原键，不自动迁移旧记录。旧库所有普通事实的全面回读／迁移仍须继续验证。

新增 8 项行为回归。相关提案回归和 88 项主体／引用边界检查通过。完整回归 4508 项：4505 通过、0 跳过、3 个既有训练依赖失败、0 错误。两项 DPO 显式 SFT 参考适配器和一项 ORPO 依赖失败保留。

## 原生 DeepSeek 冷记忆和动态上下文

另用隔离 PostgreSQL、原生 app、实际认证和推理队列调用 deepseek-v4-pro。输入沿用现有完整四项资料、更新／并发读取及按顺序执行的三轮“不建议、不追问”边界场景。第三轮个人资料读取受控移除近期历史，同时关闭原文召回；实际使用四条保存记忆。此实验单独证明所列冷记忆条件，生产新 UI session 不作为该证明。

5 秒语义复核配置下，三轮复杂边界复核超时回退；31 次已观察到的云端调用完成，实际编译的禁止建议／追问边界仍在。超时而未完成的调用不加入成功计数。保持原模型和输入，使用 30 秒配置重测后三轮复核均 applied；34 次实际云端调用均 HTTP 200、deepseek-v4-pro、finish_reason=stop。不能据此声称每次请求永远需要 30 秒。

原有评测把一个特定信号名或两种文字模板等同于完整行为边界，漏掉实际编译的安静陪伴和负面自述约束。检查现在独立验证“不提供方案／不自动建议”和“不追问”的完整约束，仍要求三轮实际复核成功、排除建议／追问策略、最终答案不追问，并新增完整动态上下文进入实际模型请求的检查。没有把超时回退改成复核成功，也不靠导入编译器常量判定通过。

原始结果保留，独立核查的 21 项链路检查通过；另保存不依赖编译器常量的边界审计。存在一次启动参数不支持的准备失败，进程已退出、未调用模型；未将其算作实测成功。
