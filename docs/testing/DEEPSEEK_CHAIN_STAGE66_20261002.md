# Stage66：复合个人查询的字段与时间范围

已修复完整复合个人查询只使用一个全局时间窗的问题。每个已解析请求按自己的字段与时间过滤，并取合法证据的并集；真实原文、来源和版本状态保持不变。新增结构化请求时间信息让选择器区分过去和当前任务。真实 DeepSeek 同时回答历史住址和现居地，且限定到已记录日期。

## 完整用例与实际发现

基线 `571a0a7fe91ee1748b3c7567db87e194eda04c5c`，三处提交与运行状态一致。纯合成来源：2026-09-30T01:00Z“我现在住在德阳。”，2026-10-01T01:00Z“更正，我现在住在晋中。”；SQLite 参考时间 2026-10-02T02:00Z。真实捕获、提取器和规则写入建立两份完整来源及 user_residence 版本；旧德阳 superseded、有效至10月1日01:00Z，当前晋中 active、从该时间生效。

完整问题：“2026年9月我的居住地是什么？请告诉我，我的现居地是什么？”；另测相反请求顺序、先9月后10月、先10月后9月，以及当前/9月/10月单独查询，共7个完整查询。原始有效期足以回答已记录的9月30日住所与当前更正，不证明整个9月每一天都住德阳；回答应保留这个边界，不伪造未记录的时间。

原全局 `_historical_query_window` 为两问一起建立第一个历史月份范围。两种过去+当前顺序、先9月后10月均只保留德阳，丢失已经完整保存的晋中和更正来源。三个确证失败发生在模型之前；单独当前与历史查询能正常拿到对应资料。

基线脚本保存了全部7个实际结果后，因“10月只应有一个版本”的错误断言终止。只读有效期核对证明：旧德阳在10月1日凌晨仍有效，10月有两个重叠版本合法；反向10月/9月也正常保留两条历史候选。这两项不作为缺陷，没有改成午夜、更换来源或重跑查询让断言通过。仅纠正保存审核的预期。

## 修复与数据契约

`memory_query_time.personal_time_tasks` 复用既有完整 self lookup/profile grammar，对每个独立请求解析原始子句和字段，时间前缀仍由现有窗口解析器处理。整轮有未知陈述、独立日期框架、外部主体、引用或未解决指代时，整个复合计划保守回退，不删除不方便的子任务。

`memory_service` 对同一条记录仅应用请求该字段的时窗，采用合法并集，而不是给所有字段共享所有日期。显式 include_historical False/True 继续采用原控制契约。请求当前版本的 active 条目标为 nonhistorical；仅通过历史请求的 superseded 条目保留 historical、有效期、旧状态和准确来源。真实 query 仍用于排名、来源、语义选择和生成，没有制造事实或改写版本链。

排名填充前优先覆盖每个字段/时间请求；候选上限不增加，诊断记录各请求时窗和字段覆盖。该覆盖只表示存在相应证据候选，不证明整个月份都有记录，最终候选预算及后续选择仍可能不足，不能当作无限容量保证。

复用原 SQLite 库读取：三个失败均恢复两条准确关联的来源；过去+当前的旧德阳 historical=true、当前晋中 historical=false。先9月后10月两条均作为历史证据。四个合法单独/反向控制的条目保持原样，所有表摘要与版本记录不变，原文和时间均未重写。

## 原生验证发现的后续选择问题

首个隔离原生实验的真实召回已选出两条，准备诊断记录两个时窗和覆盖，但选择器实际 pro 输出旧 ID40=stale、当前 ID41=use。完整旧值因此未进入实际主请求；传输检查拦截主回答，原生HTTP500，只有选择器/策略2次辅助 pro 调用200/stop，0次实际主回答。没有把该状态误称为整体成功，也没有强制覆盖模型分类。

原选择器只接收整轮 raw query、二元历史标签与有效期，缺少后端已经解析出的独立任务与字段信息。补充完整 query_tasks（原始子句、字段、原始时间表达、当前/历史模式）和候选 memory_key；协议要求逐任务判断，某条历史证据对其中一问有效时不能因另一问询问当前或发生替代就一律视为过期。时间重叠只允许说明已记录部分，不代表整个期间持续有效。这些是任务语义和已保存元数据，非新增用户事实；全部原始候选与来源仍不变。

全输入预算继续计入新增信息，超限保持原拒绝机制；未知/外部主体消息不被部分注释。没有强制 use、修改分类输出或把旧值设为当前。一个明确测试验证模型仍可返回 stale、应用仍保持原决定与原 MemoryItem 对象。动态上下文和最终主回答也保留各版本的角色与时间。

## 定向测试与真实 DeepSeek 结果

24个新增用例最终通过：闭合复合任务/字段解析、未知和其他主体整体回退、真实来源与规则版本联合召回、原显式控制、用户隔离、读不改存储、不同字段不能共享彼此时窗，以及选择器任务元数据、原文/来源不变和不强制标签。11个直接受影响的既有历史保守路径、版本链、系统指令隔离及输入预算用例通过。

实际执行36次：35次成功、1次新增模拟测试返回 Python mapping 而非真实 JSON 文本导致预期失败；修正测试返回协议后只重跑该失败节点。没有重跑其余已通过测试、全套回归或旧模型用例。格式与导入整理前后可执行 AST 和导入集合不变，静态检查无新增诊断。

只重试尚未产生主回答的完整新用例。独立 PostgreSQL 从已审核纯合成模板克隆；新普通认证用户按实际用户 ID 稳定私聊归属。来源时间采用原声明时间，要求不晚于服务器当前时间，并在发问前独立只读核对旧 valid_from、旧 valid_to=新 valid_from 和来源正文。固定 SQLite 时钟与原生真实接收时间分别记录；未用前一天/前一小时替换成不同月份，也不声称种子由模型语义写入。

成功实验4次实际请求与响应均 deepseek-v4-pro、HTTP200/stop，含选择器与1次实际主回答；原始两问完整出现在最终请求中。旧ID40与当前ID41均 selected/use，旧superseded+historical、当前active+nonhistorical、两份准确来源保留，动态策略 applied、普通历史为空。DeepSeek 回答：“按我这边能查到的记录，你在 2026 年 9 月 30 日说过自己住在德阳；第二天，也就是 10 月 1 日，你更正为住在晋中。所以 9 月当时的说法是德阳，现居地按你最新的更正来看是晋中。”时间指代和数据边界准确。

阶段合计6次真实 pro 200/stop调用（首个失败2次辅助+成功4次）、1次实际主回答/完整答案，没有遗漏失败调用。保存链路检查39/39，回答6/6，23个反例拒绝丢历史包/原文/来源/时间覆盖/持久化、错误归属/模型、个人信息进系统指令及仅答当前等错误。独立只读核验真实实验库、data_directory、精确用户owner/scope：来源全文和有效期未变、新旧住所各1、问题来源恰好一次、写队列清空、住所版本链前后相同。

结构化任务及协议修改后同一失败用例一次成功，不证明模型在所有场景都会稳定选择。没有通过无条件随机重试或绕过选择器来取得成功，也没有把首个错误分类归因于已验证的召回层。
