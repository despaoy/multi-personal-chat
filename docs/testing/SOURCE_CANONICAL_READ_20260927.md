# r131：来源规范读取与搬家主体边界

上一轮实质进展为分句更新修复和真实版本验证。本轮再次读取现有实现及r130证据后发现：temporal_projection以writer摘要逐字匹配规则模板判断有效性，导致准确自然摘要被降级；memory_subject的直接谓词没有搬家表达。

## 实现

- 对已有semantic_memory来源记录，在原有主体、完整证据、时态、条件和状态检查通过时，以来源解析出的唯一同字段内容构造规范读取视图。不再要求显示摘要等于模板。不改数据库、模型时间边界不作为有效性证据；不同来源值冲突仍为observation。
- 名称、地址、专业等自然改写能进入既有类型读取路径。若摘要写错但来源清楚，读取源事实，不照抄错误摘要；原存储仍保留便于溯源。
- 共享主体检查补充搬到/搬家到及刚/刚刚体标记。覆盖多种亲属、室友和代词；不针对包头或妹妹写特例。原文来源保留，不允许他人搬家提升为本人位置字段。

123聚焦测试通过；1487记忆/来源/时态/上下文/语义相关广回归通过，2627未选，4既有警告。证据.tmp/mechanism-r131-regression.xml。Ruff与定向diff通过，不是全项目验收。

## 真实链路复测

复用r130四场景12轮，服务器隔离API/SQLite，DeepSeek无LoRA，冷读且原文召回开启，可选判断接云端，无RAG。12回答、12writer、12策略、8筛选，共44次新调用；语义复核未触发，0本地生成，全部HTTP200。

- 搬家+专业：数据库SUPERSEDE保持，新地址和专业入模为asserted_state，回答“你住在遵义，专业是地质学”，不再因摘要自然表达而说无法确认。
- 他人搬家+未来计划：妹妹包头不再进入user_location；本人茂名保持active。模型通过来源正确区分本人现居、妹妹已搬、本人明年计划。
- 新旧住处在同一quote：仍因整个quote包含“之前”降为observation。回答核心地点正确，但读取契约未通过；不可把局部模板解耦当成时间语义全修复。
- 姓名+地址：地址已asserted_state，writer却把“我叫闻溪”标为other_user_fact，落到fact_闻溪，姓名仍observation。最终把局部未知泛化为全部信息不确定。说明强模型仍会分类不当，且上下文中混合已知/未确认信息的机制仍有问题。没有宣布该场景通过。
