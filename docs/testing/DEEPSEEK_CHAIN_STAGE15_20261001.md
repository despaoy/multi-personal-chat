## 完整条件

合成用户先明确声明：每周日下午两点计划参加北岸榆影工坊纸雕课；只有当天不下雨、护目镜完好、预约收到书面确认三项都满足，才允许个人出门。任意一项不满足即取消出行。用户尚未提交预约，也未参加过；满足必要条件仍不能证明已经出发。完整原话通过真实鉴权生成接口和 DeepSeek 记忆写入器保存，没有用测试插入来代替模型提取。

原生知识 API 导入三份独立完整合成资料：榆影工坊课程、工具维修、另一家工坊绘画课。课程规则明确普通雨天仍开课，只有红色暴雨预警才停课；周日下午两点四十分开课，联系人许苒，编号 YY-573-R。维修与别家课程不能替代该课程信息。通过真实离线向量化、混合索引和搜索读取，没有注入知识检索返回值。

在隔离数据库通过实际消息保存接口插入 12 个完整问答轮，用作既有长历史。它们是明确标识为虚构、非私人事实、非工坊规则的档案；不是生成请求，不计为 DeepSeek 回合。原来的计划及回复也保留在历史里。最终读取 26 条消息、25463 字；其中 12 个背景原话共 24987 字。

最后完整问题给出普通雨、无红色预警、护目镜完好、未收到书面确认的场景，要求分别说明个人是否符合出门条件、哪些不满足、是否已预约/参加，以及工坊是否停课、开课时间、联系人和编号。全部必要信息都已提供，不将私人条件与公开规则混为同一事实。

## 实际结果与证据

两轮鉴权生成 HTTP 200，共观察到 9 次真实 DeepSeek API 调用，均为 `deepseek-v4-pro` 且正常 `stop`。运行预算 65536，语义复核超时 30 秒；记忆写入、记忆选择、语义状态复核、策略复核均使用实际提供方。没有切换小模型或伪造模型返回值。

第一轮正确理解全部三项条件。最终回答区分：个人因雨天和未收到书面确认不满足必要条件，应取消出行；护目镜条件满足。用户未提交预约或参加过课程。工坊普通雨天仍照常开课，下午两点四十分开始，联系人许苒，编号 YY-573-R。实际返回原生课程来源引用，没有引用维修编号或别家课程来作答。

32/32 独立检查通过，依据保存的实际通信与隔离 PostgreSQL，而不只依据答案文字：

- 完整原计划作为用户原话观察持久化及被选入最终记忆包，主体未解析、描述未验证，不把计划提升为已发生行动。
- 26 条消息及 12 段完整长背景实际进入最终模型请求。完整计划、所有背景原话同时进入三个实际审核器；选择/语义/策略状态分别为 `selected/applied/applied`。
- 完整课程规则进入最终知识证据区；私人来源和知识来源各在自己的证据区，不把原话当作系统指令。
- 三个真实文档成功导入及搜索；持久向量、索引、BM25、数据库有效块数均为 3。每个资料只有一个完整块，没有遗漏末尾天气条件。
- 最终必要条件判断、当前未预约/未参加状态、课程仍开课、独立时间及来源编号正确。

这证明本次 2.5 万字场景的实际链路，不证明所有长度、历史、召回或失败恢复都正确。实际候选资料仍有辅助文档和零分候选；没有据本次正确答案宣称所有引用的相关性已经最优。

## 评测工具修复与失败记录

新探针最初在退出应用生命周期后调用同步 PostgreSQL 适配器做最终块数核查，触发 `SyncPgAdapter is closed`。该次探针终止失败，原始 `partial.json`、9 次通信及日志保持不变，没有修改成成功结果。只读连接原隔离集群恢复实际记忆/文档事实，保存独立恢复文件；未重跑已成功生成。后台调度统计未在终止前持久化，无法恢复，所以不声称调度失败指标为 0。

现在在资源仍打开时抓取存储快照并保存 `checkpoint.json`，关闭后只用快照完成检查；同时修正策略状态检查器误期待 `selected`，策略的实际成功状态为 `applied`。移除本用例不使用的旧冷读取标志，避免把完整历史场景描述成清空历史。

单独的零模型调用真实应用启动/关闭验证证明：快照在适配器打开时保存，应用关闭后仍可读取，同样的关闭后适配器调用确实会失败。初版生命周期验证遗漏必需的提供方地址，在生产配置校验前停止；补全后只重测该项，不重测模型用例。

一次只读恢复 SQL 使用了错误大小写列名，改为真实 `chunkCount` 后继续读同一数据库。独立通信分类一度把同有 `recent_history` 的记忆写入请求误作语义复核，按 `current_message` 区分后核对真实复核输入；这不是业务截断，也没有触发模型重跑。

新增 5 个专门审计测试全部通过：完整历史模板清单、末尾内容变化、历史不能冒充已选记忆、历史不能冒充最终知识证据、私人和知识来源不能交换。只执行这 5 项，没有运行全套、上一阶段用例或已有长输入/RAG 场景。静态及差异检查通过。
