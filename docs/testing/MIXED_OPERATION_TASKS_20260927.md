# r138：混合操作确认与独立问题组合

## 实现

对有实际执行回执、且以明确删除指令开头的混合请求，按显式标点/连接词分离独立剩余任务；保留剩余文本全部内容，不把后续问题丢掉。引述、依赖操作结果的追问与不支持的表达不拆分。此语法不授权删除，只处理既有回执。

确认由回执直接输出，剩余任务走原生成路径；递归子请求移除操作指令和固定回执段，不重复提交writer，不增加回答调用。RAG查询也使用剩余任务，避免操作词污染检索；结果组合为task_composite并记录两个任务模式。全确定性组合新增tasks/composite模型标签，避免误标rag/abstained。

不改人物prompt，不增加复核模型。安全、引文、时态和权限校验未放宽。该拆分仍是有限语法，不是通用任务解析器。

## 本地测试

34项聚焦响应测试通过，包含完整剩余任务、pending/failed/partial仍回答独立问题、引用和依赖问句不拆分。初版测试使用“删掉地址”但没有记忆限定、现有删除意图不识别，5项失败；调整测试为与真实执行契约一致的“删掉你记住的地址”，未扩宽删除授权。

广回归2205通过、1跳过、1990未选、4既有警告，148.33秒（.tmp/r138-wide.xml）。随后追加全确定性组合标签测试，5项标签回归通过。重叠不累计。Ruff/diff通过。最后标签调整未上传服务器，不影响此次实际模型组合路径。

## 真实模型与数据库证据

两个独立场景各3轮HTTP200，均暖历史、无LoRA、全可选判断接入DeepSeek，各9次新调用（3answer3writer3policy），selector/semantic未触发，0本地生成。

1. 原失败场景：删除住址并解释四季。claim/source实际清空；确认正确，回答解释地轴倾斜与公转；后续说不再保存。中间模型实际user_query只有四季问题，task_results保留删除和内容两个任务；一轮仅一次回答模型调用。
2. 跨RAG迁移：删除专业并询问月社妃/琉璃关系。claim/source清空；返回正确删除确认和兄妹关系，琉璃是哥哥。实际RAG状态ok、3条引用、人物任务保留。追问专业正确否认保存。

第二场景的首轮“请记住我的专业”与最后保存状态问题仍触发外部RAG并被标记character_abstention，虽然回复核心正确。这是**个人任务路由/响应元信息缺陷**，不能把整个RAG场景称为全面通过。

证据：.tmp/r138-mixed-{manifest.json,traces.jsonl}、.tmp/r138-rag-{manifest.json,traces.jsonl}。服务器仅隔离r138快照；生产未改。远端运行结束、SSH退出。
