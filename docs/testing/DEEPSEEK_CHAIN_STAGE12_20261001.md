# DeepSeek 后端链路：第十二阶段（2026-10-01）

修复明确新旧地点更正的完整证据提取，使既有语义记忆在只读时间视图、现值读取和保存状态中得到一致判断。先在服务器修复并部署，验证后同步本地与 GitHub；仍使用实际 `deepseek-v4-pro`、65536 上下文。

## 根因与修复

完整原话“我目前住在舟山，已经不住丽水了”已有真实来源和版本边，但提取器只保留第一分句。时间视图要求完整证据独立支持断言，因此将此条目留作观察；模型能读出舟山，保存状态却无法确认现居地。相同值的自我否定甚至会让原规则路径错误保留第一分句。

扩展既有同字段更正语法：完整肯定句与完整旧地点否定必须属于同一居住地或工作单位字段，旧值和新值明确不同，才提取肯定新值并保留整句证据。支持“已经不住…”“不再住在…”“已经不在…工作/上班”等完成否定；沿用已有字段语法和所有上游许可、主体、条件及时间检查。这类第一人称地点否定不能解析时，不会截掉它以制造当前事实。同值矛盾、代词、不同主体/谓词、未来、假设、额外期限及问句保留为未核实观察。没有放宽时间视图的完整证据要求，也没有迁移、改写原数据库记录或版本端点。

## 完整输入和实际模型对照

`tests/fixtures/deepseek_place_correction_cases.json` 完整保存姓名、籍贯、旧丽水地址、新舟山更正、引文、真实 `SUPERSEDE` 边、语义时间来源元数据及独立预期。当前更正故意保存模型提出的零宽有效期，以验证读取由原话语义和可信观测时间决定，而不是模型时间猜测。预期值不会作为额外答案送入模型。

复用原生认证 PostgreSQL 探针，只选择 `residence-correction`。实际历史加载后控制性清空，独立原话池、知识库和记忆写入关闭；使用真实注册登录 cookie、`/api/generate` 与原生推理队列。基线仅在独立评测进程加载已备份的原提取器，未替换线上文件或模型结果。

前后各一次实际云调用均 HTTP 200、`deepseek-v4-pro`、`stop`。两边都正确回答姓名岚舟、籍贯宣城、当前住舟山；基线现居地为未核实、保存状态无法确认，修复后现居地已确认且保存状态正确。完整新旧地址更正实际进入模型通信，读取没有历史或原话池补偿，包没有预算遗漏。原持久化整句、零宽端点及真实替代边保持不变。独立核查 16/16 通过；最终探针内置检查全部通过。基线字段状态检查失败的原始结果和通信记录保留，未改写为成功。

新增 17 项完整条件用例；原实现 8 失败、9 通过。相关五个文件共 184 项：初次修复验证 183 通过，1 项仅因测试预期把产品已有显示名“现居地”写成“居住地”而失败。修正这一测试准备错误后只重测该失败项，1/1 通过；没有重跑其余已通过用例。提取器、同字段更正、规则存储、时间投影及旧字段读取是直接受影响范围；格式、静态错误和差异检查通过。没有运行全套测试。

同步前补查到句末“了”被误作地点值，会放过同值否定；只针对两个完整句补测，修改前 2/2 失败。现在只在该完整居住地更正语法中将句末助词与地点值分开，保留原话不变。最终只运行本文件 19 项，全部通过；先前其他四个文件没有重跑。两个来源参数最初因中文参数名的转义没有被选择，零选中报告保留，随后按完整来源参数精确选择两项取得有效失败证据。最终提取器已重新加载。此项语法修正不改变既有不含助词的实际模型输入，既有通信和线上状态结果保持原样，没有重复调用模型或线上已通过的状态请求。

同一生产合成测试账号的只读快照对照，原提取器现居地状态为未核实，修复后为已确认；原始完整引文不变。切换时仅重启后端，原配置、已有数据和其他服务保留。部署后只重复此前失败的一次 HTTPS 认证保存状态请求，HTTP 200，返回“当前可用的长期记忆里，有你的姓名、现居地记录。”四项核查通过，没有重复此前已通过的两人个人资料生成。生产内部复核调用未单独抓取通信，不据此虚报云调用数。
