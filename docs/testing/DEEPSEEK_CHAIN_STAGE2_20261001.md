# DeepSeek 后端链路优化：第二阶段

本阶段基于第一阶段提交 `c5e9b181`，继续使用真实 `deepseek-v4-pro`，先在服务器修复，实测有效后将相同文件同步回本地。完整输入和预期保存在 `backend/tests/fixtures/deepseek_chain_stage2_cases.json`；预期不会进入模型请求。

## 确认的链路问题与修复

### 通用事实的改写与累计新增

真实模型正确输出“两只猫：麦芽和芝麻”，但后端按字面相邻字符检查与原话的相似度，拒绝了 `MERGE` 候选。第二轮进一步发现，首次写入的“养了一只名叫荔枝的猫”也可能因语序变化被拒绝，导致后来完整补充仍无可检索记忆。

对于通过主体、证据、置信度及限定词检查的 `other_user_fact`，若新建或累计合并的自由摘要无法独立校验，后端现在保存**完整用户原话的观察记录**，而不认证该摘要为事实。新记录的键由原话本身的 SHA-256 生成；累计合并改为 `COEXIST`，保留原记录。元数据明确标记 `quoted_source`、用户说话角色及未解析的描述主体，供后续检索与上下文编译区分语义。捏造的猫名、数量或颜色不能进入展示内容或键。

这个回退不扩大姓名、专业、喜好等规范字段的接纳范围，不降低置信度，不放过伪造证据、未知限定词、越权主体或不存在的目标。原话较长时完整文本留在证据中，不裁剪成更强的事实。能够逐字校验的普通合并仍走原路径。

### 删除最新版本后旧版本残留

实测删除新增猫信息后，当前回答已无猫名，但旧的 `superseded` 记录还在数据库中。原因是调度器同时传递键和最新 ID，而数据库优先按 ID 删除该版本及后代，不会向前删除旧版本。

经过原有目标校验的语义 `ERASE` 现在按其逻辑键删除完整版本链及派生记录；ID-only 和旧适配器接口保持原有行为。删除仍受用户、角色和作用域约束，并沿用原有事务、来源撤销及延迟任务防恢复机制。测试同时核对旧版、关联原话、来源检索词、独立专业和另一用户的同名键。

### 合法 JSON 围栏导致语义复核失效

真实语义复核返回了完整合法状态，却用整个 `json` 代码围栏包裹，直接 JSON 解析将其判为无效并回退。现在仅移除整个响应外围的 JSON 或无语言围栏；状态字段、枚举、数值、安全边界及大小限制继续验证。前后附带说明、其他语言围栏、不合法 JSON 和未知枚举仍回退。

### 缺少某个字段不证明从未保存

存在专业记录时，整体记忆状态为 `available`，此前只为整体无匹配加的限制不足以约束猫名缺失问题。现在对已检查的正常、有空缺及检索异常状态统一说明当前可见证据范围：不可据此断言用户从未告知、系统从未保存，也不可编造删除或过期原因。执行回执仍由独立机制提供。

相关服务器回归 **2,059 passed**；最终冻结协议、通用事实和生命周期检查 **45 passed**。新增协议测试共 23 项，涵盖真实冻结输出、完整接纳、反例、实际存储/召回/编译和物理删除。首次删除复现的测试参数及会话位置修正属于测试准备问题；对齐后可稳定复现旧版残留，再验证修复通过。

完整后端回归为 **4,403 passed、11 skipped、3 failed**，不能称全后端绿灯。三项失败全部来自原有 `test_preference_real_cpu.py`：当前服务评测环境的 TRL 不提供测试所需的显式 SFT 参考适配器接口或 ORPO。此前的机制优化报告也记录了这组训练环境失败；独立偏好训练环境在 `docs/research/PERSONA_ALIGNMENT_DEVELOPMENT_20260923.md` 中另有说明。本阶段未修改这些训练代码或替换应用训练依赖。

静态检查、未定义名称、Python 语法、依赖、迁移图、仓库完整性与发布文件检查通过。CI 要求的五个文件有既有格式欠项，先在服务器整理，再逐个核对语法树完全一致后同步本地。服务器评测环境起初未安装依赖检查工具，使用解释器自带包补齐后检查通过，未改变应用依赖版本。完整后端回归首次因独立测试 JWT 少于生产要求的 32 字符而未能收集，补齐测试配置后重新运行。

提交同步核对发现，较早的隔离测试也曾因我提供的短测试 JWT 触发开发配置自动轮换，写回磁盘的 `backend/.env`。我使用服务器原有受限凭据精确重建初始配置，只有整个文件 SHA-256 与首次同步记录一致时才恢复；只改变过 JWT 一项，线上进程未重启。测试 bootstrap 现会在应用配置导入前将无效测试凭据替换为进程内临时凭据，保留有效的显式测试凭据。新增 10 项子进程用例覆盖缺失、空、短、旧占位和有效凭据在开发/生产模式下的配置隔离；相关 **37 passed**，部署文件指纹不变。服务器评测隔离层另将部署配置挂载为只读，并用无写入的探测确认保护有效。私有恢复证据保存在 runtime，不含入库凭据。

## 证据与覆盖边界

完整私有证据保存在授权 runtime 的 `evaluations/r147-backend-chain-20261001-stage2-*` 和 `backups/backend-chain-20261001/stage2_final_verification.json`。仓库只提交合成夹具、回归测试和阶段报告；密钥不在源码、夹具、日志或报告中。

本阶段实际经过 ASGI HTTP 路由、聊天服务、记忆调度、检索、上下文编译及应用完成路径，但身份固定、队列接纳为内联测试适配器，数据库为隔离 SQLite。生产鉴权、真实后台队列、PostgreSQL 和服务重载仍需下一阶段验证。源码同步不等于线上原有进程已重载或生产提供方已切换。本阶段未删除聊天存档。

下一阶段优先验证 PostgreSQL 的同等存储/删除合同、后台排队与取消、真实鉴权入口，以及部署后端到端的 DeepSeek 配置；继续定位最早失效节点，不用更换模型掩盖链路问题。
