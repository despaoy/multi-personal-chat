# DeepSeek 后端链路：第十一阶段（2026-10-01）

本阶段在服务器修复旧普通事实字段的只读兼容读取，并将有效修改部署，再同步本地和 GitHub。当前推理 provider 仍为 `openai_compat / deepseek-v4-pro`，工作上下文为 65536；生产记忆写入与动态语义复核的既有配置保持不变。

## 问题与修复

旧 `fact_岚舟`、`fact_丽水` 等记录不会参与个人字段覆盖或保存状态判断，即使其授权原始来源完整，`field_presence` 仍为 `False`。10 个完整条件的初始定向用例中，9 个复现失败；显式未来有效期用例通过。实际 DeepSeek 基线能正确读出旧资料，但后端保存状态却宣称没有记录，证实是状态链路缺陷，不是模型大小问题。

新增只读视图：通过仓储现有授权来源链接取回完整原话，要求字段/值在引用与完整来源中唯一一致、没有限定条件或冲突来源，才能以已证实的个人字段参与读取。完整来源中的其他字段不会附带升级为这条记忆。原 ID、来源 ID、版本边、有效时间和数据库记录不迁移。`SUPERSEDE` 保留旧普通字段键时，单一完整更正断言仍可读取新值。

来源缺失、跨用户同名来源、条件/假设、第三人称或冲突证据，保留为未核实原话，保存状态不能据此证明字段不存在。检索及排除字段使用相关字段提示，当前事实读取不会将它们认证为值。原话读取失败不阻断已有标准字段记忆。

实际模型对照还发现：上述原话观察缺少旧记录的观测时间，会被编译器排除。现在带入授权完整原话的可信、带时区记录时间，保留整段来源与末尾限定语；没有使用检索时刻来假定事实有效时间。

## 完整输入与真实链路

`tests/fixtures/deepseek_legacy_field_cases.json` 保存全部来源、引文、逻辑字段、版本边、问句与独立预期；预期值不会作为额外答案发送给模型。

1. 姓名岚舟、籍贯宣城、现住丽水的三个完整自述，旧键均为 `fact_…`。
2. 完整更正“我现在住在舟山”，通过真实版本边替代丽水，原普通字段键保留。
3. 完整小说假设明确说明丽水只是设想，反复区分虚构背景并在末尾否认真实住址；旧引文只有“我目前住在丽水”。姓名仍是独立完整自述。

探针使用实际隔离 PostgreSQL、真实注册登录 cookie、`/api/generate` 与原生推理队列。实际历史加载后控制性清空，独立原话池召回及知识库关闭，记忆写入关闭以隔离旧格式冷读取；没有替换模型或返回值。前后输入相同，基线使用备份的原始两个读取模块。最终三轮实际 DeepSeek 调用全部 HTTP 200、模型 `deepseek-v4-pro`、`stop` 结束。

32 项独立核查通过：保存状态、来源/版本不被改写、当前更正值、无历史及原话池补偿、完整原话进入实际模型通信、观测时间保留、假设不认证为现实，以及模型正确解释“无法确认实际居住地”。整段假设来源实际入模且没有预算遗漏；没有用“正确回答但未收到限定语”冒充链路成功。可复用探针的 10 项内置检查也对不可改写的实际通信记录验证通过。

第一轮基线完成一轮真实回答后，因为评测清除来源后复用了已撤销来源 ID 而停止。失败及原始结果保留，修正为每组独立来源 ID。第一版修复的假设包因缺少观测时间未入模，也作为未充分验证的结果保留；最终以可信时间修复后的独立结果为证据。阶段实际观察到 10 次云生成调用、10 个隔离生成轮次和 9 次无模型保存状态请求。

## 定向测试与生产核查

16 个专门用例覆盖当前字段、完整多字段来源、缺失/第三人称/假设来源、原版本链及历史窗口、跨用户同来源编号、显式未来有效期、冲突来源、旧观测证据、读取失败、完整编译及每条授权来源的一致性。早期修复的 122 项相关测试通过；最后多来源修改只运行本文件 16 项，全部通过，没有重测其他模块。格式、静态错误及差异检查通过。

多来源定向对照发现：早期来源支持姓名，后来完整来源说明那只是小说角色台词时，原投影仍确认当前姓名。每条授权来源现在都必须支持同一字段/值；对照仅运行两个边界用例，原实现 1 通过、1 失败，修复后本文件全部通过。测试先实际读取并核实两条授权完整原话；任意模型引用 ID 不能授权访问。初版两来源测试只有引用 ID 而没有实际链接，未成功提供完整测试条件，其失败与报告保留；随后修正测试准备，并未放宽生产访问权限。

最后这三行一致性判断不改变三个既有单来源真实模型用例；按定向验证要求没有重复调用它们。既有实际通信记录和原始输出保持不变。最终后端加载了该修复，保留现有配置、数据及其他服务。

用户要求后续只测修改涉及部分。本阶段在收到这一要求之前，已经完成一次完整回归快照 4511 项，其中 4508 通过、3 项原有训练环境失败、无跳过或错误；收到要求后没有再次运行全套。后续只运行对应修改的用例及必要的真实链路验证；没有相关新改动或失败证据时，不重复已通过的测试，也不默认运行全套。

切换前备份了生产数据库与配置，只重启后端，其他服务、原 `.env`、provider 覆盖文件及已有用户数据保持不变。生产现有两个合成账号的 3 次 HTTPS 认证请求全部 HTTP 200：两轮资料读取的模型、本人最新值及用户隔离共 6 项检查通过。这是包含已有历史的生产核查，不作为冷读取证明。

保存状态检查“姓名和现居地均明确已保存”没有通过：返回未核实状态。只读比较原读取器与本轮读取器的同一实际数据，字段状态完全一致，证明不是本轮新增回归。当前姓名可确认，但“我目前住在舟山，已经不住丽水了”的完整更正引文被既有严格时间视图留作观察，现居地仍是未核实；原始未通过结果保留，没有放宽检查。下一阶段将针对这种明确更正句进行修复。

`/ready` 中云模型依旧为 `not_required`，不能用作 DeepSeek 可用证明；本阶段依赖真实调用。生产回答还存在正确个人资料被标记 `abstention` 的既有标签现象，后续需检查任务/RAG 路由。
