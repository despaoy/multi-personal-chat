# DeepSeek 后端链路验证：阶段 6（2026-10-01）

## 问题与修复

本阶段验证原生通用知识库导入、离线向量索引、混合检索、带来源的问答，以及长期记忆与知识库混合任务。生成、记忆提取和动态上下文审核实际使用 `deepseek-v4-pro`，没有替换为测试模型，也没有伪造检索结果。

服务器基线为 `75beecdbcd10b623a66e121a157d6150b43e03a4`。先在服务器复现问题、备份源码、修复并验证，再同步有效修改到本地与 GitHub。

1. `/api/knowledge/search` 的索引重建计数 SQL 使用未加引号的 `c.documentId`。PostgreSQL 将它解释为 `documentid`，与真实的 `"documentId"` 列不一致，导致重建失败并降级为关键词搜索。修复为保留大小写的带引号标识符；SQLite 同样支持该写法，现有孤儿片段排除与重建一致性测试继续通过。
2. 无问号的明确请求（如“查知识库回答课程实际开课时间、联系人和预约编号”）没有被共享的信息请求识别器识别。混合任务因此只带个人记忆进入模型，缺少知识库证据。补充直接知识库、资料库、数据库查询动作，以及“同时、分别、一并”回答修饰语。继续要求直接句子边界，并屏蔽引号中的文本；资料提及、否定请求和封闭个人读取不能因此变成外部任务。

基线混合问题中，模型能回答个人计划，但明确表示无法确认课程资料。实际发送记录证实，课程证据根本没有进入本轮输入。修复后在相同完整资料条件下，模型同时回答两类事实，来源保持独立。
