# DeepSeek 后端链路优化：第三阶段

基于 `185b45bc`，先同步代码，再在服务器使用真实 `deepseek-v4-pro` 定位原生调用链问题。修复先在服务器完成，实测有效后同步本地。API 凭据只从服务器私有配置读取，不进入仓库或调用记录。

## 已确认的问题和修复

初始注册、登录、PostgreSQL 和请求队列正常，但两次生成均返回 500，尚未到达 DeepSeek。实际调用把 `max_tokens` 传给仅接受 `max_tokens_override` 的 `ModelManager.async_generate`，已有测试替身的宽泛签名掩盖了错误。现在按真实签名传递额度；新测试同时核对完整编译消息和输出额度。

生成路径此前优先尝试 vLLM，即便已选择 `openai_compat` 或 `ollama`。现在仅在实际提供方为 vLLM 时尝试该分支及 LoRA 清单检查，避免残留本地地址覆盖云端配置。vLLM 不可用时的原有后备路径仍受测试覆盖。

修复签名后，记忆提取实际返回 `length`：768 个输出 token 中 615 个用于思考，记忆 JSON 只有半段。写入器发送了本地模板参数 `chat_template_kwargs`，无法表达 DeepSeek 的关闭思考开关。原生回答也出现过思考耗尽 1024 额度、正文为空的返回。这是协议与额度使用问题，实际模型始终为 v4 Pro。

现在仅对准确匹配的官方 `api.deepseek.com` 主机发送 `thinking: {type: disabled}`，供原生回答和记忆提取使用。本地记忆服务保留模板参数，其他兼容回答服务不增加该扩展；主机后缀和 URL 用户名伪装均有测试。字段依据 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

两个原生客户端共用完整返回校验：必须正常 `stop`，且正文是非空字符串。截断、过滤、工具调用、缺失完成状态、仅有推理内容或异常响应结构不能进入后续链路。不拼接半段 JSON，不将空正文变成字符串 `None`。

## 信息完整的真实测试

`backend/evaluation/native_provider_chain_probe.py` 和 `backend/tests/fixtures/deepseek_native_chain_cases.json` 保存了可复用工具及五个用例。真实注册、登录 Cookie、鉴权、应用生命周期、原生队列、原生云端提供方和 PostgreSQL 均参与。使用应用内 ASGI HTTP 传输，尚未覆盖反向代理和网络监听器。

| 用例 | 完整信息及条件 | 最终核验 |
| --- | --- | --- |
| 四项写入 | 岚舟；老家宣城；目前丽水；专业环境工程；明确均为本人资料 | 四条活动记忆持久化 |
| 正常读取 | 明确询问姓名、老家、现住地、专业 | 四项正确，主体为用户 |
| 独立记忆读取 | 仅本轮受控返回空历史，关闭来源原文召回，保留真实提供方与存储 | 实际编译历史 0、来源区空、四个持久记忆 ID 入选，答案正确 |
| 并发更新 | 明确现在舟山、不再丽水；老家和专业不变 | 舟山活动版本，丽水旧版 `superseded` |
| 并发读取 | 更新已入队但未完成时发送同会话查询，恢复正常历史读取 | 舟山、宣城、环境工程正确；原生队列五次全部完成 |

最终可复用工具运行 5 回合、10 次真实 API 调用，均为 HTTP 200、实际模型 `deepseek-v4-pro`、完成状态 `stop`，12 个结果检查通过。额度仍是回答 1024、提取 768，没有换模型或大量增加额度掩盖问题。

本阶段所有诊断运行合计 23 次生成尝试、20 次成功；41 次实际云端调用均 HTTP 200，其中 39 次正常结束、2 次明确截断。初始两次参数错误没有到达云端，另一次回答因截断被拒绝。这些失败不计为通过。

私聊历史和记忆按稳定用户身份聚合，换前端会话名不能证明历史为空。初始测试把新会话无消息误当成编译无历史，随后核对并纠正。最终独立召回结论来自明确关闭历史的受控测试。直接查询记忆也需规范化用户作用域，不能使用前端会话名。

## 存储和回归证据

以相同 PostgreSQL 14.24 二进制创建独立集群，仅开放独立 Unix socket、不监听 TCP。每个探针在写入前核对实际 `data_directory`。线上数据库和真实用户数据未参与写入。

SQLite 与真实 PostgreSQL 的生命周期、检索、删除、历史窗口四组结果完全一致，包括作用域、来源正文、延迟提交、撤销后重试及删除竞态。另用实际记忆调度器验证逻辑键删除：旧版和新版猫名全部消失，共享来源正文撤销、检索词清除，专业和另一用户的同名键保留。

- 新增原生路由和协议测试 30 项通过；相关路由、应用生命周期及上下文回归 87 项通过。
- 完整后端回归共 4457 项：4443 通过、11 跳过、3 失败。三项仍为既有 DPO/ORPO 训练依赖不兼容，没有新增业务回归失败。
- 首轮全量测试错误地给 PostgreSQL 模块配置 SQLite URL，触发迁移测试替身，造成 17 项导入失败。修正为已核验的独立 PostgreSQL 地址、业务测试库仍使用 SQLite 后，完整重跑仅余上述训练失败。原始日志保留。
- 检索及新增文件 lint/格式、全仓库未定义和重复名称、766 个 Python 文件语法、依赖、迁移 head、仓库完整性和发布卫生检查通过。工具单纯导入不改变环境。
- 原部署 `.env` 完整校验值与初始备份一致，沙箱继续只读保护它。线上模型配置未切换，服务未重启；代码同步不等于运行中的服务已加载新代码。

原始合成证据在服务器私有目录 `evaluations/r148pg.s3`，汇总及校验记录在 `backups/backend-chain-20261001/stage3_*`。复用工具只接受本阶段独立集群，每次用新标签创建独立数据库，拒绝覆盖既有证据。
