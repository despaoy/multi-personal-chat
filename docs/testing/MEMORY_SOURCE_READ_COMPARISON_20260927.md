# r108：完整来源读取的真实回答对照

## 测试范围

固定r107四组实际Qwen3-8B-Instruct-AWQ记忆写入输出及原始接收时间，两组分别写入新SQLite，再经实际事实召回、来源检索、人物参考编译和共享generation生成回答。无LoRA；不是HTTP/浏览器/完整动态prepare或RAG联合验收。角色画像保持v3-conversation-flow。基线关闭来源读取，实验组打开；均不改人物或判断提示词。

每组5个问题，各5次新鲜生成，总10次。每组只重放4份旧写入输出，没有重新采样writer。空/不合法事实候选仍不执行，但完整来源已由r107保存。实验组有4个回答恢复关键信息，另一个恢复信息但多问了一遍当前状态；不能据此宣称整体人物模拟已通过。

## 机制与边界

- 来源从独立库读取，用户发言者不等于句中事实主体。数据只走现有`dialogue_evidence`不可信通道，不变成MemoryItem，不新增当前事实。
- 已选事实通过真实claim→source关联补全原话；不能用模型source IDs猜原会话。另由范围内中文bigram/拉丁词倒排索引检索未生成claim的来源，频率加权只用于相关性排序。
- SQL读取遵守r107删除水位；排序后再批量检查来源可读性，无历史聊天兜底或原文缓存。关联来源删除时同时移除词元索引。
- 完整包最多4条、2400个转义后字符；不能通过截断丢掉后置否定。超预算记录有明确诊断，不以旧片段补位冒充完整来源。
- 后续补充覆盖式RRF保证两条检索通道各自首条不会被另一通道占满；完整文本与接收时刻已被当前无条件事实证据覆盖时，不重复注入，从而保留原有直接字段回答路径。这些通用边界不是按测试地名/句子特化。
- 本轮5次来源召回为2.37–3.39ms，只有每库一条来源，不是大规模吞吐结论。260条后续无关来源后的旧记录检索另有实际SQL测试，但不是语义召回率认证。

## 未完成与下一步

开关`MEMORY_SOURCE_RECALL_ENABLED`仍默认false，未发布生产。索引只对新捕获/同身份重放来源建立，013迁移不回填既有来源；旧来源若只在r107保存且无新索引，可通过真实claim关联读取，但不能宣称独立词面搜索已覆盖它们。需提供受控回填及覆盖诊断。

独立词面搜索不能解决完全无词面交集的改写，指代扩展/跨轮事件组合、source-only独立删除入口、长原话预算损失、第三方/虚构/取消等真实模型负例仍需验证。该轮只有正向回忆对照，不能证明模型能普遍正确归属引用或抵抗误导。全局事实不扩大原话权限；这里的范围沿用应用UserScope，私聊在入口按用户归一化，是逻辑私聊而非独立页面sessionId，未另行宣称物理会话/分支隔离。
