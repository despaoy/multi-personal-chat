# r104：时间记忆真实链路评测与排序修复

## 范围与方法

服务器隔离快照调用实际 `qwen3-8b-instruct-awq`，未加载 LoRA。9组独立语句经过语义写入调度器、真实生成、临时SQLite、实际embedding召回、人物参考编译及共享generation入口。读取使用空历史，避免模型直接从短期历史复制答案而掩盖记忆缺失。

使用现有月社妃结构化画像v3-conversation-flow；未运行完整prepare_turn动态状态估计、HTTP接口或RAG，因此不是整软件端到端/人物还原度验收。案例中的审查要求只写入结果，不进入模型请求。没有新增提示词或复核模型。

首次运行11次新写入生成、8次新回答生成。修复后复用其中4份已记录写入输出及其原始观测时间，在新SQLite复测3组，另有3次新回答生成；合计22次实际生成调用。复测排除了重新抽取内容变化这个干扰，但样本数量不支持总体准确率结论。

## 已实现的机制修复

r103把来源引用的提示标签、长时间戳与原话拼进content，又将整段content用于embedding/Jaccard相关性。展示信息稀释语义，导致“已保存但no_relevant_candidates”。

现在来源引用读取视图单独提供retrieval_content，内容为原始evidence文本。词面排序、向量编码与向量缓存键统一使用这个检索视图；最终生成仍接收时效未核实、来源时间与原话的完整展示包。没有删掉展示限定，没有降低相关性门槛，也没有按出差/轮岗定制别名。

新增测试验证展示标签不进入向量、仅改变展示内容不重复编码、展示词面不能伪造相关性。404项相关回归通过，三个既有SWIG弃用警告，Ruff通过。

## 同数据真实复测

- 出差：原来“记不清”，现在“你之前提到这周在许昌出差，下周会回去。”
- 住址：仍直接回答池州，未增加生成调用。
- 已结束实习：仍正确回答已结束。
- 轮岗：选中ID从仅1变为1和2，回答正确保留唐山/苏州；月底仍遗漏，不能算完整通过。

新回答生成约1.11秒、0.67秒、2.01秒，仅这些短输出的温启动测量，不是全链路耗时承诺。

## 下一步与未解决项

1. 保留完整来源语句，而不把模型选出的短证据片段当作完整源上下文，尤其不能丢条件、取消、截止及返程子句。来源的说话者不能直接等同于其中每个事实的主体。
2. 统一可识别时间字段的结构归一化；observed_at始终由程序提供。错误content不得因格式修复而变成当前事实。
3. 区分“变更提议不能执行”和“用户陈述不值得保留”；错误目标、结构化value、空输出需分别定位，不能靠放松所有验证解决。
4. 对缺证据时的主体错位与编造继续做实测。当前结果再次表明不是仅靠增大上下文就能解决，也不能以几个直接字段答案正确替代人物体验验收。
