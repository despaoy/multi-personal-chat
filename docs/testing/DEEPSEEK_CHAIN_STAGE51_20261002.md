实际复现与根因

在第 50 阶段已经核实的 3 份完整合成资料上，使用两个独立进程、真实本地嵌入模型和 FAISS 文件重现并发发布。A 按一种顺序写来源，B 按另一种顺序完成索引发布；读进程在 A 替换 metadata 后、替换 BM25 前实际重新打开索引。三种记录数都是 3，完整来源也没有丢失，但 LL-842-Q 的关键词位置绑定到了晴岸玻璃绘画课 doc_3_chunk_0，而不是对应的澜岚玻璃镶嵌课。基线检查 4/6，失败项正是关键词语料对齐及实际来源绑定。基线没有调用大模型，不能据此声称模型答错。

修复

FAISS、完整 metadata 和 BM25 现在写入每次独有的临时目录，封装为一个 ZIP_STORED 快照，校验维度、记录数量、唯一来源 ID 与 FAISS ID 集合、BM25 逐位置正文和统计，以及各文件摘要。写入完成并同步后只替换一次快照文件。读进程通过同一个已打开的文件描述符读取整个快照，避免跨代组合。失败保留上一个完整快照并保持 dirty；临时目录在正常成功或异常退出路径清理。损坏新快照不能回退使用过时的旧文件。旧三文件格式可读，但 API 不允许据此跳过数据库重建；空库也必须持久化完整空快照。

范围与剩余问题

本阶段修复三份索引跨代混读和共享临时文件名造成的来源错配。没有证明多个写进程的增量变更不会互相覆盖，也没有证明断电、强制终止或所有文件系统下的持久性；突然终止可能留下自己的临时目录。Windows 对打开文件替换的限制可能使发布明确失败并保留旧快照，本次真实多进程验证在 Linux 服务器完成。旧三文件保留用于兼容读取，新文件存在时以完整快照为准。任意直接操作索引文件、非法数据库关系、跨批构建数据库快照、长上下文与更广记忆案例仍须后续验证，不能据此宣称长期记忆、RAG、动态上下文全局无误。持续目标保持 active。
