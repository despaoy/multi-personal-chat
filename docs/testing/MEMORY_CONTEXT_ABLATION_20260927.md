# r116：固定输入对照，而非凭单次回答判断根因

## 范围

本轮新增 `evaluation/memory_context_ablation.py`，使用r115两份实际最终问题请求。每份请求比较四种输入，每种三个seed，共24次新的Qwen3-8B-Instruct-AWQ生成；0 writer、0数据库/索引修改。不是HTTP/检索/guard全链路测试，而是固定真实请求的模型输入对照。

四种输入为原样、仅移除重复观测副本、仅移除assistant历史、两者都移除。当前问题、所有system消息、真实user历史、完整来源包保持不变。仅当事实通道全部是observation且每条原文确实也在模型最终收到的原话包中时，允许移除该副本。不手写正确答案、不改人物提示词、不把来源提升成当前事实。

移除观测副本同时移除了副本中的时效标签、说明和重复信息，**不是仅删除“时效未知”几个字的单因素测试**。保留系统中的既有归属规则和当前查询包装。移除assistant历史也改变了长度、对话形式及回应依赖，不能推论为全球适用的新策略。

## 结果

- 完整输入6次：仍出现推荐/劝尝试或先拒绝后建议的情况；另一些回答明确不推荐。单次旧输出不是稳定质量证明。
- 仅去观测副本6次：没有稳定改善；一条把用户“以前爱吃、现在不吃”说成角色自己的经历，多条仍先推荐具体菜再附带“如果现在不吃就不推荐”。不能据r115失败就删除此通道。
- 仅去assistant历史6次：均明确回答不会推荐。
- 两者都去6次：同样均明确不会推荐。

后两组的12次一致结果支持“该案例的assistant历史与错误延续有关”，但只有一个偏好场景的两份请求，不能证明泛化、独立复现或全部人物自然度合格。这些回答很短，尚未覆盖需要解释、延续角色语气或引用角色刚才建议的任务。

下一步应在独立查询和依赖旧回答的负例上验证基于任务依赖的历史选择，而非全局删除assistant消息。项目已有独立RAG身份读取的历史视图 `_task_history`，可参考其授权范围；当前偏好确认并不在该契约中，不能简单偷用身份读取开关。

## 独立的投影不一致

只读脚本 `.tmp/mechanism-r116-projection-audit.py` 保持r115同一source、content、active状态和可信接收时间，仅改变未认证的模型日期：

| 模型日期提案 | 当前投影视图 |
| --- | --- |
| 无日期 | fact，显示“用户不喜欢香菜” |
| 附接收日日期 | observation，显示“时效未核实、不代表当前状态” |
| 附任意未来日期 | 同上observation |

原因是 `project_temporal_record` 仅处理 `validity_authority=unverified`，对 `unspecified` 直接返回；是否出现未认证日期间接决定事实/原话分类。这是真实代码不一致，不能因24次对照没有证明标签是主要失败原因而忽略。但修复必须将日期可信度与命题当前适用性分开，不能一律提升active，或一律降级所有语义记忆来取得表面一致。

“不吃”被归为“不喜欢”也仍未修复；前者可能是行为限制而非情感偏好。本轮没有依据单样例新增运行时关键词例外。

## 证据与边界

- `.tmp/mechanism-r116-ablation-{results.jsonl,manifest.json}`：24次真实生成，原始request/response完整保留。
- 输入1847–2155 tokens、24次均以stop结束，远低于服务8192窗口；本组没有窗口溢出或输出截断证据。
- `.tmp/mechanism-r116-diagnostic.xml`：64项诊断器/时效相关测试通过。Ruff通过。
- 首次独立runner缺少鉴权环境，首请求返回401，0成功生成；按既有评测方式只读加载配置后，在新的隔离目录完成。没有重启服务或更改认证。
- 仅新增诊断工具与测试，未改变运行时历史策略或时效规则。所有远端写入在授权评测目录内，生产未改。评测已正常退出、SSH关闭。
