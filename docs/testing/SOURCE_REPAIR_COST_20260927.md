# r119：有来源时重试的成本与真实收益

## 结论

不采用“结构化记忆 no_match，但有来源/用户历史时自动增加一次纠正”的候选策略。
它修正了证据通道的概念混淆，却没有稳定解决阅读遗漏。运行时已恢复原先的快捷回退分支；
不是声称原分支已经正确，而是避免将尚未验证的额外生成作为默认成本。
没有修改人物提示词、关闭事实检查、增加复核模型或部署生产。

## 实验边界

使用 evaluation/guarded_repair_replay.py，固定 r117-invariant 的 behavior_not_affect
与 r118-rag-separated 的 lore_and_user_activity 两份实际请求及首次失败回答。
模型输入使用 model_calls[0].request.messages，而不是 placement 实验前的 plan.messages。
两个首次回答仅重放，不算新调用；每例 seeds 0–2，各调用服务器 Qwen3-8B-Instruct-AWQ
进行一次现有纠正，共 6 次新生成。调用共享 generation/guard 流程；请求构造器冻结，
没有新 HTTP 生命周期、检索、writer 或数据库写入，不是全链路验收。
候选源代码保留在授权隔离目录 mechanism-r119-source；本地已撤回候选。
当前本地 runner 测量当前代码，不会自动恢复被撤回的策略。

## 实际结果

| 问题 | 新调用 | 检查未拦截 | 实际任务表现 | 单次新增耗时 |
| --- | ---: | ---: | --- | --- |
| 喜欢味道与医生禁食的区分 | 3 | 3 | 均拒绝推荐，但均未明确保留喜欢，转为“不喜欢”的假设并多余追问 | 1.80–1.89 秒 |
| 原作关系与用户插画归属 | 3 | 3 | 2 次明确归用户，1 次仍条件化；存在多余澄清、角色外解释和关系扩写 | 4.04–5.61 秒 |

6 次均正常 stop，实际输入 1470 或 3976 tokens，未达到 8192 窗口限制。
总新增生成约 19.99 秒。不能把 6 次 guard 通过记为 6 次质量通过，也不能将两个场景
的结果推广为所有重试无效。此次仅否定将“来源非空”作为足够的默认重试依据。

原错误回答没有放入纠正请求；复用已有纠正说明，没有添加针对样例的答案。
本地先验证两份请求能准确重建、各仅一次新模型调用；候选聚焦 47 passed。
撤回后的测试改为刻画当前成本边界，而非保留一组要求未采用策略的断言。

后续优先检查 writer 的结构输出失败、行为限制与情感偏好的字段混淆，以及逐项证据支持。
已观察到 r118 取消计划来源的原始 writer JSON 含额外闭括号，整个批次解析失败；
完整来源保留但没有事实写入。不要通过猜测性字符串修补掩盖语义问题，应先检查生成协议
能否约束结构，再独立验证事实准入与冷读效果。目标保持 active。
