# r109：原话记忆边界与完整动态编排实测

## 范围

服务器现有 Qwen3-8B-Instruct-AWQ、8192 上下文、无 LoRA。使用隔离源码与 SQLite；实际调用语义写入、事实召回、原话检索、`prepare_turn`、共享 generation 和输出 guard。没有经过 HTTP、RAG 或生产 PostgreSQL，不代表人物模拟联合验收。

独立 fixture：`backend/evaluation/fixtures/source_boundaries_20260927.json`，7 场景、10 条输入、9 个问题。覆盖第三方与自述、虚构引语、明确取消、指代取消、条件计划、说话者归属、偏好更正。人工评审标准未传入模型。可选模型复核关闭。

## 原始结果与定位

| 场景 | 冷读取结果 | 证据链结论 |
| --- | --- | --- |
| 用户与朋友住址 | 朋友正确；用户住址已找到却表示不确定 | `我自己现在住在…` 未得到规则支持的当前状态投影，被包装为时效未核实；不是原话没存 |
| 虚构情节 | 没把虚构搬家肯定为用户事实，但存在人称混淆、冗长确认 | 来源已完整注入；回答质量不达标 |
| 明确取消 | 正确回答不用去培训 | 新旧两条原话均召回 |
| 指代取消 | 仍回答两项安排都进行 | 取消原话已保存，但查询没有词面重合，也没有关联事实；只注入旧安排 |
| 条件计划 | 错误说“既然已经决定去” | 原话含未满足条件且完整注入；不是预算裁切 |
| 练习者归属 | 角色复述第一人称，把用户经历当成自己的 | 原话包明确 speaker_role=user；模型仍误用 |
| 偏好更正 | 正确不推荐已不吃的食材 | 两条原话均进入上下文 |

9 次生成 prompt_tokens 为 1371–1923，finish_reason 都为 stop，均只有一次生成调用。没有接近 8192 窗口上限，因此不能将这些失败归因于本轮上下文容量不足。这里也不能证明扩大模型参数没有帮助。

## 修复与拒绝的候选

发现事实通道 `memory_status=no_match` 与原话通道 `sources.status=available` 可以同时存在。原编排仍拼接“没有找到可用于回答的相关记录”，这是把事实缺失误报为全部证据缺失。

保留的运行时修改只调整该分支的触发条件：有实际原话证据时不再发出全部缺失声明；不修改既有提示词文字、不提升来源为事实、不放宽归属/删除边界、不增加模型复核。

曾实验同时给原话启用既有 MEMORY_ATTRIBUTION_POLICY：练习者归属变正确、条件回答有所改善，但小说问题退步，并违反已有 `test_raw_speech_does_not_acquire_active_memory_subject_contract`。该策略包含“不必再要求确认或追问”，不能套给对象尚未解析的原话。此候选已撤回，未通过修改旧断言来掩盖退步。

仅修正缺失声明后，指代取消、条件与人称错误仍存在；小说回答也未改善。保留的是可验证的状态一致性修复，**不是整体回答质量提升的证据**。原话功能仍默认关闭，未发布生产。

## 后续优先级

1. 为跨轮指代/修订保留可追踪的来源依赖，召回需能包含后续修订；不要用“最近N条”冒充完整关联。
2. 分离原话发言者与被描述主体的使用机制；不能批量替换“我/你”，会破坏第三方嵌套引语。
3. 扩展明确自述的状态投影，避免窄规则把普通确定陈述全部降为未知；同时保留条件与转述边界。
4. 原话支持与 guard 的事实支持不是同一回事，不能用“有任意原话”解除所有用户事实检查。
