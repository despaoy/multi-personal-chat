# r134：乱序规则记忆写入

## 根因

r133广回归偶发失败为真实状态顺序问题：两个请求各自保留接收时间，但较早请求可能在较新请求之后读取/落库。旧代码发现当前记录便提出SUPERSEDE，数据库根据接收时间拒绝；上层仅重试两种字符串错误，未处理共享MemoryClaimConflict。

固定两个观察时间、先写新记录再写旧记录，修改前稳定触发同一异常，排除只依赖调度概率的测试。数据库拒绝旧观察覆盖新状态的行为正确，未放宽此保护。

## 修改

- 共用observation_precedes时间比较，保持未知旧时间不猜测时区。
- 规则writer读到更晚的唯一当前记录时，将原始旧陈述存为archived历史，保留原观察时间和证据，不将它与当前事实合并，也不虚构有效期或前后继关系。
- 串行重复提交同来源、内容、时间的历史不重复写入。此去重不是事务级并发幂等保证。
- 对MemoryClaimConflict重新加载后作有界重试；数据库删除围栏、目标范围和时间保护不变。

## 证据与边界

首批54项规则正确性/数据库冲突/观察时间测试通过（.tmp/r134-green.xml）。新增迁移测试覆盖偏好、姓名、住址；交错测试强制在读取与追加之间写入新事实。扩大记忆回归1329通过、2808未选、4既有警告（.tmp/r134-wide.xml，89.99秒），包含新增测试，不与54项重复累计。Ruff和定向diff检查通过。

本轮无真实模型调用、未上传或部署服务器。修复针对规则writer；LLM提案可能含合并后的旧内容，不适合无条件套用同一归档策略，尚需独立验证。不能以本轮通过声称长期记忆模块验收完成。

未解决：同时重放同一旧来源的事务级去重；无当前记录但存在更新的历史版本时的乱序判定；删除回执接入即时回复；LLM写入冲突分类与恢复。PPO权重失败仍单独待查。
