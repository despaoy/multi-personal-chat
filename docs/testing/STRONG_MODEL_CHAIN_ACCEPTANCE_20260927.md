# 强模型基准下的链路验收目标

先使用更强模型归因并修复机制，再使用相同用例切回小模型对照。2026-09-27 用户重新要求设置目标；核实旧目标记录已不存在，现新建持续优化目标。强模型减少模型能力干扰，但不等于已排除所有模型错误，仍按实际调用和存储证据归因。

## 路径

1. 盘点并记录每个实际模型调用入口；区分回复、记忆提取、语义复核、证据筛选、行为决策。检索的 embedding/cross-encoder 不等同于聊天 LLM，单独保留配置。
2. r128 已完成回复+writer 强模型、可选判断关闭的基线。增加可选判断也使用强模型的独立实验，保留原触发条件、超时和结果校验，记录 fallback；不开启便宣称执行成功。
3. 先修复删除真实执行/回执、更新入库、正确答案误删，再处理字段准入与 RAG 混合意图。优先机制，提示词最低优先级，不加入案例专用城市、人名或答案。
4. 每项修改执行负例/迁移用例本地回归，再跑隔离真实 API 全链路。只有生成正确、状态变更正确、下一轮召回正确才算功能成功。
5. 通过消融比较模块开关的收益、错误与成本，决定哪些可选判断值得保留；随后同输入同机制比较小模型，不把模型能力下降误算作链路回归。

## 验收门槛

用户补充要求：长期记忆、RAG、动态上下文所有既有环节均视为未验证，不因历史测试通过而豁免。当前修复不是可靠模块清单，必须补齐全链路审计与模块交互证据。

| 链路 | 必须重新验证的环节 | 必须观察的结果 |
|---|---|---|
| 长期记忆 | 来源捕获、主体归属、提取、准入、版本更新、删除、异步调度、检索与来源兜底 | 持久化状态、版本和来源、一致性、下一轮召回、失败回执 |
| RAG | 意图路由、查询解释、向量/词法召回、融合、重排、证据覆盖、置信与拒答、入模 | 检索原文是否回答所问、主体/时序、无关证据、混合任务完整性 |
| 动态上下文 | 状态规则与LLM复核、历史裁剪、指代、条件/关系边界、证据筛选、行为决策、预算编排 | 实际入模消息、判断是否采用、来源及优先级、跨轮状态、开关消融 |
| 跨模块后端 | 身份范围、数据流与回执、超时/取消/重试、缓存、并发、数据库事务、降级、最终后处理 | 不串用户、不复活删除记录、不误报成功、不删正确答案、不重复执行 |

- 所有被测 LLM 调用有用途/模型/结果记录；未触发、超时、解析拒绝必须可区分，不能静默混用本地小模型。
- 删除不再检索到对应事实及被删除来源；更新保留正确版本关系；实际失败不宣称执行成功。
- 主体、否定、未来/当前、条件并存、信息未知与更正场景通过独立迁移测试；来源兜底不能冒充结构化写入通过。
- RAG 区分人物资料、外部原文和个人记忆；无关检索不视作支持，明确问及的正确事实不被风格检查删除。
- 多轮边界、结束话题、指代和状态切换测试；动态模块价值需要开关对照，不能仅看总体流畅。
- 保留调用数、延迟、重试、回退记录；不为通过测试无限增加复核。
- 隔离测试仅在 /home/boot/lhm/ 内，不发布生产、不覆盖用户无关修改。
