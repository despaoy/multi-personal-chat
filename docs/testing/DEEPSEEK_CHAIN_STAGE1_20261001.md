# DeepSeek 后端链路优化：第一阶段

本阶段先将服务器源码从 `57aede2b` 快进到本地基线 `6bc831de`，保留部署配置和运行数据。所有功能修复先在服务器实施并验证，验证有效后才同步到本地。

## 实际模型与测试条件

- API 返回的可用模型为 `deepseek-flash`、`deepseek-v4-pro`；本阶段统一使用实际返回为 `deepseek-v4-pro` 的模型。
- 回答、记忆写入、记忆选择、语义状态复核和行为策略均通过 DeepSeek 评测适配器调用，使用原生触发、解析和超时策略；开启开关不等于复核结果已采用。
- 生成输出预算 1,024 tokens，应用上下文工作预算 65,536 tokens。真实调用清单没有本地模型回退、取消或不完整返回。
- 测试资料为完整的合成用户陈述，预期标准不进入模型请求。角色检索使用服务器现有索引及原文，不向检索器提供测试答案。
- 记忆问题阶段移除短期历史，保留实际长期记忆与来源召回；另做保留近期历史的动态上下文/RAG 测试。
- 身份为固定测试用户，队列接纳为隔离的内联适配器，数据写入独立 SQLite。实际聊天服务、准备、生成、保存、完成和记忆调度得到测试；线上鉴权、后台队列、PostgreSQL 与部署重启尚不在本阶段覆盖范围内。
- 密钥保存在服务器受限评测配置中，不进入源码、夹具、请求清单或报告。源码同步完成不代表旧的在线服务进程已经重载。

## 已确认根因与修复

完整身份的模型输出含四个正确候选，后端只保存姓名和专业：`qualifiers.type=hometown/current_residence` 被当作不允许的自然语言限定词；此外 `老家在宣城` 被昵称启发式误判为以“老”开头的人名。没有显式“我”的裁剪位置证据及“我目前住在”也可能落入模糊的 `user_location`，无法保证故乡和现居字段分离。

位置字段现从证据中明确的故乡/居住谓词确定；已知类型标签仅在该谓词独立证明相同字段时移除。未知标签、矛盾标签、其他未知限定词仍拒绝。共享主体识别补充故乡谓词，并核查裁剪证据所处的原始分句和句子，防止第三方或假设内容被提升为用户事实。

搬家计划候选原本因 `certainty=planned` 不逐字出现于中文证据而被拒绝。现在只在 `PENDING` 且证据确有计划词时，转换为证据中实际出现的中文限定词；没有计划依据、未知标签或非待确认操作仍不接受。计划保留 `pending`，不提升为已发生的当前住处。
