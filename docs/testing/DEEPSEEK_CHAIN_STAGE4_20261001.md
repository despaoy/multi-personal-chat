# DeepSeek 后端链路优化：第四阶段

基于 `53628447`，继续先在服务器定位并修复，再将验证有效的相同文件同步回本地。本阶段验证原生语义复核、情境记忆选择和决策策略，不使用注入式云端提供方替代它们。

## 原生复核绕过模型设置

三个复核器原先直接解析共享 vLLM 客户端。真实基线中，回答及记忆提取均使用 `deepseek-v4-pro`，复核器却向本地地址发送 Qwen 请求，随后回退。四条资料已保存、召回候选也有四条，但选择器在提供方失败后安全丢弃候选；关闭历史与来源输入的独立读取因此不能回答。这不是缺少输入信息或模型容量不足。

新增统一的低层复核客户端，按实际 `ModelManager` 选择解析提供方。vLLM 继续使用共享客户端；`openai_compat` 使用同一个原生提供方的 `async_complete`，刷新已配置的端点、模型和凭据。复核消息完整保留，采样温度及额度由各复核器明确传入，不被普通回答配置覆盖，也不重新进入人物编排、RAG、记忆写入或回答提示词组装。

其他尚未支持复核的提供方明确报错并走已有安全回退，不暗中切换 vLLM。云端复核禁止 LoRA、流式和思考模式。已有枚举、结构、超时、安全和策略冲突校验保留。记忆与回答共用端点规范化，服务根地址和已带 `/v1` 的地址均不会出现重复版本路径。

## 完整输入与实际采用结果

测试工具 `backend/evaluation/native_provider_chain_probe.py` 新增 `--reviewers`。前三回合保存及读取姓名、老家、现住地、专业；随后三个回合依次提供木刻板损坏事件、明确且继续有效的不建议不追问边界、回指同一事件；最后并发更新及读取居住地。输入、历史依赖和预期保存在两个 `deepseek_native_*_cases.json` 文件。后续指代句按已保存的前序回合执行，不作为孤立、信息不全的单轮题目。

实际注册、登录 Cookie、鉴权、PostgreSQL、请求队列、原生回答、原生记忆写入以及三个原生复核器均参与。第三回合仅受控关闭历史和来源输入；其他回合历史正常读取。HTTP 使用应用内 ASGI 传输，尚未覆盖网络监听及反向代理。

最终原生默认 5 秒语义超时运行共 8 回合、34 次真实 API 调用，全部 HTTP 200、实际返回 `deepseek-v4-pro`、完成状态 `stop`，20 项结果检查全部通过：

| 环节 | 实际结果 |
| --- | --- |
| 语义复核 | 三个复杂否定或指代回合均触发并采用复核；无需复核的回合保持 `not_needed` |
| 情境记忆选择 | 首轮无候选，其余七轮选择成功；独立读取选中四个持久记忆 ID；木刻话题不注入无关用户资料 |
| 策略决策 | 八轮均采用有效策略；边界回合排除建议及追问策略 |
| 生效约束与回答 | 当前明确边界保留，后续回指仍编译出不自动建议及不得追问约束；三次回答未追问，人工核对无建议内容 |
| 并发与存储 | 五项原有资料流程保持正确；居住地更新为舟山，旧丽水版本被替代，随后查询读到新资料 |
| 提供方一致性 | 全部复核走云端，未发送本地模型完成请求 |

本阶段四次完整诊断运行共 32 回合、118 次真实云端调用，均正常结束；基线依然存在记忆选择回退，不能仅凭 HTTP 200 宣称链路通过。最终调用组成是回答 8、提取 8、语义复核 3、记忆选择 7、策略 8。最初两次基线脚本因移动目录后的导入、用例路径错误停止，尚未调用模型；原记录保留。

一轮测试曾要求所有边界回合的“当前拒绝建议”标签都至少 0.5。第三句只回指事件，其当前标签为 0.3，但已有历史边界及最终编译约束有效，实际回答也未建议或追问。该测试混淆了当前意图标签与持续生效约束。现在分别检查前两句的明确当前边界和三句的最终约束，保存了原失败记录；没有改业务代码强制增加标签分数。
