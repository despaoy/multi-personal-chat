# r132：删除准入与逐任务执行回执

## 修改与验证

自然删除请求进入原有 ERASE 路径；否定、引述、假设请求有基本排除。该规则仍是有限意图识别，不是完整自然语言授权判断。新增 schedule_and_wait 按单个任务返回实际结果，不读取全局 last_outcome。超时返回 pending，不取消已受理任务；关闭时为未结束任务返回 cancelled，释放队列计数。

真实 SQLite 回归检查删除回执返回前 claim 与关联 source 都已移除。关闭补丁后，receipt 与生命周期两个测试文件 30 项通过（.tmp/r132-shutdown2.xml）。初次受限运行因 pytest 临时目录访问权限失败，隔离重跑通过。此前较广记忆回归 1324 项通过，不包含最后的关闭补丁，不能合并声称其也已覆盖。

## 实际强模型评测

.tmp/mechanism-r132-erase-manifest.json 与 traces.jsonl：服务器独立快照、SQLite、9 轮 HTTP200，无 LoRA/RAG，冷读，来源召回开启。31 次新 DeepSeek 调用：回答9、writer9、策略9、筛选4；语义复核未触发，本地生成0。

猫名、住址两个删除场景的 claims 与 sources 都清空，删除指令不再作为事实来源保存；下一轮无法召回被删内容。否定删除专业场景保留原值。

**仍失败：即时回复声称没有删除权限，而后台随后成功删除。** 新回执接口尚未接到生成前的编排。不能报告删除体验修复完成。远端快照未含最后关闭补丁，传输会话已关闭，生产未改。

## 后续必须检查
