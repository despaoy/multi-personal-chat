# 阶段154：并行用户来源隔离与完整费用预留

日期：2026-10-05。整体优化目标 active，公网开放不在范围内。

## 实际来源与并行输入

隔离 PostgreSQL 中两个不同用户通过正常来源捕获、规则提取和规则写入保存两条完整虚构偏好，用户之间正负偏好相反。两用户使用相同 source_message_id 与完全相同的当前问题，共用数据库、仓储和记忆服务；分别按完整本人作用域读取与准备，两组存储编号不相交，真实来源版本完整，跨用户的记忆编号/来源编号关联查询均为空。没有人工制造 MemoryItem、来源回执或模型审核授权。

双方准备完成后，只对 A 已正常捕获的第一条来源做明确的行政正文变化故障注入，保持 A 记忆存储记录未变；实际数据库更新一行，B 两条来源版本及双方记忆存储哈希保持。两条共享生成链路并行执行，并用模型入口同步点确认均已到达输入阶段。十六项新的零云输入检查通过：A 失效旧包消失，独立完整负向证据保留，不借 B 的同名来源；B 两条完整证据保留且无 A 来源；未审核的新正文和内部指纹不进入任一模型输入。故障注入不冒充正常业务操作。

首次并行真实主答在发送阶段中断，未完成模型验收。定位后不重复已通过的十六项 spy 基线；使用新的隔离正常捕获来源恢复同样的准备前后关系，仅在真实发送前保留必要的作用域和全文校验。两次新的真实 deepseek-flash 主答经并行共享生成路径完成，十二项内容检查与两份严格 JSON 均通过：A 第一字段及原句未知，第二独立负向字段与整句保留；B 正、负偏好及完整原句均正确，双方私人描述均不证明现实审核，也不能用其他用户记录补齐本人未知。没有原生登录、交付历史、向量、公共 RAG 或模型记忆写入/筛选验收声明。

## 费用预留工具的实际缺口与修复

admitted_request_budget 计算出下一调用预留金额，但返回值没有保留 input_bound/output_reserved。直接与真实调用记录器组合时，第一请求已开始、用量尚未返回，第二次准入不能核算第一请求的保守预留，抛 ValueError，导致首条请求取消。第一记录实际保留 request_started、http_status=null 与 CancelledError，没有收到用量。已有 ledger 测试手动提供完整预算，未覆盖准入输出与 ledger 的实际组合。

四项新增零云 HTTP 组件测试复现失败：第一请求未返回时准入第二请求、已收到 HTTP200 响应头但还没有响应体/用量、响应读取失败、取消。修复后准入返回合法非负整数输入/输出额度；未知响应以及 HTTP200 尚未取得有效用量时仍保留全额预留，不能因状态码先到就当已知费用。有效用量到达后才按已记录使用量结算；缺少完整预留仍拒绝，不伪造用量。

八新增与三直接相关节点共十一项通过，包括四个原失败、非法新额度不能获得预留，以及已知缓存用量、混合模型和缺预算拒绝的原控制。HTTP 传输明确为 mock，不算真实模型调用。新测试仅格式化导入和排版，AST 等价；现有预算源文件没有全文件格式化，原静态诊断基线保持，新静态问题零。只修改评测预算工具及对应测试；生产记忆语义代码、保护配置及其他服务不变，无后端重启。服务器新的评测进程实际使用已验证修改。

## 真实发送与费用

本阶段实际开始发送三次，收到 HTTP200 两次；两次成功主答，首次主答发送被取消且未收到响应。原生请求零、辅助模型零，两次进程均按原 PID/启动时间确认终止。初次失败完整保留，不能将未知响应记成免费或成功。

已收到用量的两次估算费用 0.003260 元，初次未知用量按原保存峰值预留 0.020558 元。两者混合预算口径合计 0.023818 元；全部按预算峰值结算的上限口径为 0.027078 元，均非账户账单，也不冒充取消请求的真实使用量。第二次验证预算从本阶段 0.2 元中先扣除该未知预留，再准入两个请求。完整源问题、正文、精确模型输入输出和失败 ledger 只保存服务器。
