## 完整原始测试条件

问题：请核对我的当前个人资料：姓名、籍贯、现居地、专业、工作单位、年级各是什么。只写我本人的当前资料，不做建议。

SQLite 的参考时间取自服务器真实 UTC：`2026-10-02T16:43:19.625376+00:00`。六个来源从该时刻前十分钟起逐秒写入。原生 PostgreSQL 验证保留这六个实际声明时间，并在发问前确认每项不晚于真实接收时间、持久化 `valid_from` 一致。没有改日期、减少字段或补造来源来取得通过。

种子使用真实 `capture_source`、`extract_memories` 和 `write_rule_memory` 写入，六个字段各提取一项；这是规则提取与写入证明，不能证明语义大模型写入器本身准确。原生请求使用全新普通用户（实际 ID 6），web/web-character 私聊作用域、独立 PostgreSQL 数据库及鉴权 ASGI 接口。复制已审核合成模板，仅用于环境准备，不重播模板旧案例。操作前核对 PostgreSQL `data_directory` 精确为独立集群目录。

## 根因证据

1. 同一真实 SQLite 存储有六项 active 记录，召回六项。冻结 JSON reviewer 将六项均标 use，仅用于隔离代码截断，不作为模型能力证据。默认选择器剩五项，显式候选上限 24 的对照保留六项。
2. 将相同原始六个 MemoryItem 直接交给完整证据编译器，默认只编译五项，`count_skipped=1`，并非字符压力。仅在独立实验进程暂时改变数量常量、调用同一编译器后恢复，六个原始包共 3198 字符，低于 6000 字符预算。没有拼接伪造证据。
3. 使用正式 kisaki 角色提示词及规范请求构造器，完整六包加 2048 回复预算及 512 安全余量估算 5842 token，小于 65536。此值是项目的保守估算，不是供应商精确 tokenizer 计数，也不替代原生请求验证。
4. 修复前真实 DeepSeek 请求与响应均为 `deepseek-v4-pro`，选择器对六个实际 ID 全部给 use，后端仅注入五项，丢失 `user_study_stage`。原始六项已独立确认保存。主请求观测器在发送前阻止不完整证据，所以这个隔离请求返回 500、主模型调用 0；两次已经完成的辅助模型请求 HTTP200/stop 全部计入，不能称为完整回答，也不能误报为模型能力不足。

## 服务器优先修复

`ContextualEvidenceSelector.select` 的默认 `max_items` 改为 None，在原有 24 个候选范围内保留全部验证为 use 的对象及模型排序。调用者明确传入 0、1、5 等数量时仍遵守其限制，不强迫模型选择任何条目。

`compile_reference_context` 的完整证据模式取消第二个隐式五条限制，以完整证据包实际字符预算决定准入；普通紧凑模式保留既有五条规则。实际容量不足时整包跳过，继续尝试后续完整包；不截断事实、来源或原话。有效期、状态、置信度、主体授权、用户区域边界及最终服务窗口仍有效。没有把上限改成固定六条；新例覆盖 24 条能放下的完整证据。

## 精简验证及准备错误记录

新增 `test_memory_selection_capacity.py` 11 例：完整六字段；候选上限及明确调用者数量；24 条完整模式与普通模式；erased/pending/superseded/低置信度/过期/未来六种拒绝；整包超预算后保留末项；非 use 不获得准入。直接受影响的三例验证对象顺序、 mandatory input overflow 不调用模型和系统区域隔离。

旧完整编译测试中依赖固定五条的断言更新为所有八条可放下资料，保留 erased/低置信度拒绝。另一个旧预算例预期三条却失败；独立加载基线原始编译代码，使用该测试原样五条来源，证实基线也只能容纳两条。更新该过时断言，并检查第三个等长完整包确实超过总预算。只重试该失败节点；此前通过的两个相关案例未再跑。最终 17 个不同相关案例通过，共 18 次测试执行，含一次原有过时断言失败。未运行全量套件。

基线实验在结果已成功保存后，输出摘要误读 `SelectionOutcome.selected` 而报错；实际字段为 `memories`，只读核验已保存结果，无实验重播。审计准备中先修正 JSON 列表/Python 元组形状比较，再按实际 owner_key/scope_key 读取来源表，均是收集器错误，没有改来源或调用模型。新审计器把 match 赋值分行以兼容静态解析，删除未使用 timedelta，并将数据库导入放在隔离环境初始化之后。静态检查为零新增诊断；格式化保留可执行结构。
