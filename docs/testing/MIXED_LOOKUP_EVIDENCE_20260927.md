# r114：混合查询中的陈述证据范围

## 根因与实现

r113 实际模型已经提出正确搬家 SUPERSEDE，但整条 evidence 含问句而被拒绝。继续追踪发现：去掉问句后，完成式“我搬到某地了”仍不能路由到明确居住地字段；模型使用已有兼容类型 `user_fact` 时，证据修复还必须与后续类型恢复保持一致。

本轮复用完整 `lookup_fields` 契约分离尾部查询。只有整个尾部是已识别字段读取，才暴露原始前缀给现有事实提取器；不是按问号切句，也没有把所有前半句默认认作事实。语义候选引用整条混合消息而遭问题门控时，只有独立规则提取器验证了同类、同值、无条件的事实，才能采用其原始证据片段和规范内容。限 ADD/SUPERSEDE，不替代未知语义判断。

新增完整自述完成式搬家语法，支持“我／我已经／我刚刚／我刚 + 搬到／搬家到 + 地点 + 了”，用于已发生的居住地变更；未来、条件、第三方、引语、限定情况不能因此升级为当前无条件住址。原始消息全文仍保存在来源库中，claim 使用独立证据片段。

真实负例进一步发现：旧模型会引用“我搬到宣城了”，漏掉“前面搬家那句是编的”，生成错误事实。新增明确后指撤回的来源范围检查：被后续明确否认的前文不能支撑新增事实；模型不能通过截短 evidence 绕过。未知指代不猜测，保守取消该明确否认之前的事实提取，否认之后的独立自述仍可提取。先处理原有虚构范围，避免在引语内遇到否认时误把后半段当用户自述。完整原话不删除，这不是新增遗忘功能，也不自动撤回别轮已保存 claim。

没有新增模型复核、提示词、数据库结构或生产设置。

首个候选 `r114-mixed-scoped`：搬家 writer 用 `kind=user_fact`，暴露恢复步骤在类型兼容之前运行的问题，仍未更新；后置否认没有完整来源检查，最后答信息矛盾。此组保留为失败证据，不计为修复成功。

最终候选 `r114-mixed-final`：5 个最终问题分别回答宣城、考古学、衡水、衡水、衡水。逐行核对不仅看答案：搬家/专业各有正确 active 新版本和 superseded 旧版本，否认/第三方/条件场景均没有错误当前住址；5 条第二轮原话全文均保留。仍存在无据声称用户以前说过姓名、对已说明住址重复追问、泛化城市想象等体验问题，因此不是整体人物模拟通过。

三个组均 15 个 HTTP 200、各 9 次新 writer；generation 为基线 12、首个候选 13、最终候选 12。部分确定性字段回答不调用生成模型，次数差异不是质量评分。各组新鲜写入和生成，未冻结模型输出，不声称统计显著性。

最终运行期间做了两项代码顺序防护：保留既有省略证据恢复顺序、先处理虚构再应用后指否认。随后用最终本地代码重放9份实际writer，准入数量和规则提示与实测逐项一致；5组最终claim状态和全文来源检查通过。脚本 `.tmp/mechanism-r114-verify.py`，0新模型/数据库变更。引语内否认另有新增负例测试，未把实测范围扩展宣称为这些负例也做过新鲜生成。
