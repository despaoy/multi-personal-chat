# r115：偏好名词提及与具体事实断言分离

## 已证实的根因

r111 中“现在口味变了，我不吃香菜了”得到的原始回答包含“你现在的口味，应该更符合你现在的习惯吧”。guard 使用 `你…习惯/喜好/偏好` 检测用户事实，错误地将没有具体值的名词提及当成事实断言。随后 `memory_status=no_match` 的单违规快捷回退把整段回答替换成“这点我暂时记不清，不能凭空猜”。

本轮仅修复这项已证实的误判：同一分句中，所有格“你的…习惯/喜好/偏好”后没有具体值或谓词、只有空白/语气词时，不构成具体偏好事实。后续独立分句仍检查；“你的偏好是甜食”“你的习惯是早起”“你的喜好出了名”等仍需依据。没有放开所有偏好话题，也没有修改提示词、增加复核模型或更改来源存储。

需要修正此前过宽的解释：r111 另一句“我以前爱吃香菜”的原始回答是“我记得你以前说过喜欢那种味道”。用户当前说了过去偏好，并不能证明以前告诉过角色。它包含无据历史披露断言，不能与第二句的纯名词误判混为一谈；本轮没有为了消除回退而把它放行。

## 验证

- 新增 `test_nominal_preference_guard.py`：无具体值的名词提及、多分句夹带事实、明确偏好值、既有历史披露边界，以及共享生成管线不再错误触发 no_match 回退。
- 聚焦169项通过；广回归489项通过、3项跳过、3403项未选中、4个既有警告，`.tmp/mechanism-r115-regression.xml`。聚焦与广回归重叠，不相加。3项是缺少本地asyncpg导致的PostgreSQL历史契约测试，不代表PG验证通过。
- 复用真实首轮模型输出重放，59条trace中55条可重放；其余4条没有可重放模型调用。只有上述名词误判一项结果变化，其他54条guard结果保持。证据 `.tmp/mechanism-r115-guard-replay.jsonl`，0新模型调用。
- 重放检查的是同一模型输出的拦截行为，不等于55项回答质量通过，也不证明新的生成始终会输出同一句。

## 实际链路与待办

对r111原始 `preference_change` 三轮完成新鲜HTTP基线/修改对照；近期历史正常开启，实际服务器Qwen3-8B-Instruct-AWQ，无LoRA，RAG和可选复核关闭，隔离SQLite，测试鉴权/排队。两组均3次新generation+3次新writer，全部HTTP200。所有远端写入限授权评测目录，生产未改，进程退出、SSH关闭。

修改组第二轮新鲜模型再次输出原先误判的“你的习惯吧”，本轮正常保留，guard无违规；第一轮无据“我记得你以前说过”仍被拦截。但第三轮出现质量失败：“我可能会推荐，但得看你想吃什么”，违背用户已经表达的不吃香菜。基线第三轮开头拒绝推荐，但后面又劝用户尝试，也不是完全合格。新鲜两组输出/历史不同，不据此声称统计意义的整体提升或锁定退化单因；本轮只证实固定输出误判已修，整段人物体验没有通过。

逐链路确认第三轮不是没有得到新信息：修改组新“不吃香菜”已写为active `preference_香菜`；最近用户历史、原话来源包均完整包含它。但读时的 `temporal_projection` 又把它标记为“时效未核实，不代表当前状态”，与旧“以前爱吃”的原话同时出现。guard因存在已注入memory ID而整体关闭用户偏好事实检查，最终只报generic_assistant_template，没有检测当前偏好违背。基线也有相同的时效降级，故不能把这一个因素直接宣称为两组回答差异的原因。下一轮应先做来源/时效投影与当前约束的受控消融，避免加入“香菜”特例。

证据 `.tmp/mechanism-r115-{baseline,nominal}-{traces.jsonl,manifest.json}`。实际存储把“不吃”归纳为“不喜欢”，还涉及行为限制与喜好不同的语义问题，不能通过直接把所有active都当无条件事实来处理。

更大的问题仍在：`has_relevant_memory` 或任意可抽取偏好会整体关闭偏好事实拦截，尚未逐项对应当前候选的对象、极性、时间和披露来源；原话依据没有同等表示。新型无据熟悉感（尤其姓名）也不属于现有偏好谓词检测覆盖。本轮不能宣称这些问题已解决。
