# 月社妃 Prompt 组合契约

## 目标

人物 Prompt 只描述长期稳定的月社妃，不承担每轮都会变化的关系、情景、记忆和检索内容。这样既能保持训练与评测口径一致，也能避免固定 Prompt 越写越长。

## 五层输入

系统按以下顺序组合模型输入：

1. **稳定人物层**：冻结训练实验使用 `kisaki_system_prompt_v3.txt`；应用推理使用 `kisaki_runtime_prompt_v4.txt`。两者都只包含身份、原作稳定关系、性格、价值选择、语言习惯和人物边界，运行时修订另加强对话者身份隔离与表达落地。
2. **动态决策层**：当前关系阶段、情景分类和本轮行为决策。由固定规则生成，可进入 system 区，但不得包含用户原文。
3. **全局事实与安全层**：事实不确定性、秘密保护和现实安全要求。所有角色共用。
4. **可选 RAG 层**：只在启用检索时加入证据使用规则；实际证据不进入 system 区。
5. **不可信用户层**：说话者标签、长期记忆、RAG 证据和当前问题分别放入带边界的 user 区域。

## 关系处理

- 琉璃、彼方、夜子和理央等内容属于原作稳定关系，可以保留在人物层。
- 平台用户与月社妃的熟悉程度属于动态关系，不能写死在人物层。
- `speaker_label` 只用于称呼和关系化表达参考，不能证明平台用户的真实身份，也不能携带系统指令。
- 问题中提到某个人物，不等于发言者就是该人物；没有可靠标签时按普通用户处理。

## 训练与运行时

- R1 训练统一使用稳定人物层和 `replace` 策略，并通过说话者契约将可靠身份放入 user 区域。
- R1 模型对比必须使用相同人物 Prompt、相同 Prompt policy 和相同生成参数；不得把运行时 v4 结果与旧 v3 实验直接当作单变量模型对比。
- 应用运行时可以追加动态决策层、长期记忆和 RAG，但这些增强不能用于解释 R1 单变量消融差异。
- 人物 Prompt 内容发生变化时应建立新修订并重新评测；仅调整动态状态或检索证据不等于修改人物 Prompt。

## 当前结论

`kisaki_system_prompt_v3.txt` 继续作为已冻结的训练与既有研究资产。`kisaki_runtime_prompt_v4.txt` 是针对真实生成中身份串用、事实编造和口癖触发的运行时修订；它不改变旧实验结论，也不能在完成人工盲审前宣称已晋升为新的训练人物 Prompt。
