# Backend

FastAPI 后端使用 Python 3.12，负责认证、会话与消息、角色记忆、推理编排、RAG、训练、评测、实验和运行观测。业务入口统一由 `app/main.py` 组装；生产与本地启动统一使用 `run.py`。

## 目录边界

| 目录 | 职责 |
| --- | --- |
| `api/` | HTTP 路由与传输层校验 |
| `app/` | 应用工厂、生命周期、配置与依赖装配 |
| `services/` | 与 HTTP 无关的业务用例 |
| `repositories/` | 持久化接口与数据库适配 |
| `db/`、`alembic/` | SQLite/PostgreSQL 与迁移 |
| `inference/`、`training/` | 推理后端、LoRA 路由与训练任务 |
| `knowledge/` | 角色知识检索、通用用户知识库、共享检索内核与证据约束回答 |
| `evaluation/`、`experiments/` | 评测与受控实验 |
| `infra/`、`cache/`、`middleware/` | 并发、熔断、缓存、安全与观测 |
| `character/` | 角色上下文、关系与记忆 |
| `scripts/`、`benchmarks/` | 后端维护工具与显式运行的性能测试 |
| `tests/` | 单元、集成、契约与研究数据回归测试 |

## 入口与验证

```bash
cd backend
python run.py --host 127.0.0.1 --port 8000
python -m pytest tests -q
python -m alembic heads
```

`main.py` 仅保留为旧部署兼容入口；新脚本和文档不得再依赖它。当前架构要求 `BACKEND_WORKERS=1`，因为幂等、会话锁和 nonce 状态仍是进程内状态。

认证的注册、登录和用户信息接口统一使用当前应用容器绑定的数据库；缺少容器明确失败，不能转用全局数据库。生产首次注册的用户计数和写入也在同一数据库完成。 管理员角色复核同样固定当前应用数据库，配置或读取故障返回 503 并保留原因；已验证 API 密钥沿用独立权限来源。

运行时数据库、模型、LoRA、日志、索引和密钥不属于源码目录，边界见 [`../docs/operations/SERVER_LAYOUT.md`](../docs/operations/SERVER_LAYOUT.md)。

## 知识检索边界

- `knowledge/multiscale_rag/` 是经过审核的作品知识生产入口。
- `knowledge/rag_helper.py` 与 `knowledge/vector_db.py` 服务用户管理的通用知识库。
- `knowledge/retrieval_core/` 是两类检索可复用的底层组件，不是独立服务。
- `knowledge/grounded_answer/` 负责证据约束生成、引用绑定和拒答。

聊天生成链路在检索置信度不足时采用角色化弃答：保留人物设定、动态上下文和所选 LoRA，
由模型自然表达不知道或无法确定。低置信度候选及其引用不会进入生成请求，系统指令禁止
猜测剧情、关系、原文和出处。返回仍标记 `abstained=true`、`answerMode=abstention`，
`citations` 为空；`modelInvoked=true` 表示尝试了表达生成，不代表成功回答了事实问题。
生成异常、非文本或空回复时明确失败，不返回固定弃答。
这一行为适用于聊天链路，不改变独立证据问答接口的弃答策略；提示词约束仍需通过真实模型评测验证。

独立 `/api/ask` 与 `/api/ask/stream` 共用语义检索准备结果，完整传递当前问题、历史对象绑定和来源域。未选域的首轮请求也经过当前提供商的来源规划和对象绑定；明确选域仍审核任务范围，并固定使用该知识域。未知域明确报错，正式业务全名不会按其中的短角色别名改成角色问题。独立接口目前只支持角色作品来源：合法域外问题明确弃答，混合角色／业务来源任务明确报错；聊天入口仍支持独立来源组合。

单字域问法词表已删除。登记别名在本次检索域内用于名称归一，名称对应按任务范围随证据传给聊天和独立回答模型，仅作指代对齐，不证明原作记载了别名来历或其他事实；名称字符串与原文都保持数据边界。名称边界不清的自然语言仍可能产生模型绑定错误，不通过截字或换来源掩盖。

检索或证据审核异常返回 HTTP 503，并保留异常原因供内部定位，不再进入回答生成。
模型管理器与 vLLM 共用这套策略；生成失败不自动切换模型提供商。

## 平台发送与重试

升级此版本时需同时更新 AstrBot 插件和后端，并执行 `python -m alembic upgrade head`
（在 backend 目录）。新增迁移 `008_integration_receipts` 保存消息处理及发送回执；
SQLite 本地初始化也支持创建该表。已有历史数据不会删除，旧去重表保留。

消息按平台、适配器、会话类型、会话、发送者和消息 ID 进行幂等处理。失败允许重试，
正在处理的重复请求不会再次生成；已生成但尚未确认发送的请求重用已保存回复。
插件等待平台 `send` 成功后调用 `/api/integrations/astrbot/delivery`，该接口使用与
消息入口相同的令牌和签名验证。未确认发送的回复不进入角色历史，人物记忆和关系更新
推迟到首次成功确认；重复确认不会重复更新。


网关失败通过 HTTP 状态明确返回：限流 429（含 Retry-After）、处理超时 504、队列/配置/数据库/生成故障 503；生成链路已有的 HTTP 错误保留，安全策略拒绝为 403，回执所有权变化为 409。故障不再变成 HTTP 200 的固定繁忙答复或群聊静默成功。失败会尝试释放生成回执；释放失败保留原错误，由租约到期处理。平台/会话显式关闭、正在处理的重复事件和已送达重复事件仍按业务状态返回，未确认的正常生成回复继续复用。插件已有 HTTP 错误处理会记录失败，私聊可显示明确的系统故障提示，不确认送达或标记事件完成。

已投递的语义记忆任务仅在明确的生成阶段暂时故障时自动重试，执行预算持久保存，最多三次。
容量满、调度器关闭和确定未开始的队列取消等待恢复，不消耗执行预算。永久错误、部分写入或
已开始但结果未知的遗留任务标记 blocked，保留实际回执供核对，不自动重放可能已经提交的修改。

这里的“已送达”表示平台适配器发送调用成功，不代表用户已读。确认失败时插件重试三次，
随后可在重复事件到达时再次确认；平台已接收但确认丢失、进程重启等情况下仍存在重复发送的
可能性，不承诺跨平台严格恰好一次。发送确认与人物状态更新不是跨系统事务，进程在确认后
立即退出时可能缺少一次记忆更新。无原生消息 ID 的事件使用事件级 ID，跨进程重新构造的事件
无法可靠识别为同一次消息。

构建角色知识索引：

```bash
python scripts/build_character_rag_index.py
```

完整的数据层级、配置和降级行为见
[`../docs/architecture/CHARACTER_KNOWLEDGE_RETRIEVAL.md`](../docs/architecture/CHARACTER_KNOWLEDGE_RETRIEVAL.md)。

模型提供商选择：非空 `MODEL_PROVIDER` 优先于数据库 `modelProvider`；缺失或非法值明确失败，不切换为 mock。mock 仅可在 development/test 环境显式启用，日志会标明模拟推理。模型配置数据库读取失败不会使用空配置继续运行。

配置读取统一使用按数据库实例隔离的进程内 TTL 快照（60 秒加少量抖动），不依赖 Redis，也没有 Redis 故障后的缓存切换。命中返回副本，过期后必须成功读取数据库；故障不使用过期数据或空配置继续。加载和失效共用一把锁，保存设置后的失效会等待旧加载结束，避免旧快照随后回填。当前仍要求 BACKEND_WORKERS=1；独立旧 bot 进程约一分钟内自行刷新，不提供跨进程即时失效。

OpenAI 兼容连接设置只由提供商统一解析：非空数据库字段优先，其次对应 OPENAI_COMPAT 环境变量，地址/模型缺省仍使用 DeepSeek 的现有默认值；空数据库字段重新按此优先级解析，不沿用上次的内存值。清空 API Key 且没有环境密钥时，生成明确失败。数据库读取失败不会转而使用环境值继续。

生成参数按每次调用的配置快照读取，沿用共享 TTL 缓存及配置接口的主动失效；不使用模块导入时的永久快照。OpenAI 请求在借用连接前固定本次地址、密钥和模型，运行时更新不改变已经开始的请求。配置保存后运行时刷新失败返回 503，并明确 configPersisted=true；提供商切换已发生时同时标记 providerSwitched=true，不声称整体成功。

OpenAI 兼容主答直接接收编译后的完整消息与采样参数，温度和输出上限不会被提供商再次读取的默认值覆盖；证据回答的编译温度限制有效传递。适配器保持非思考模式，不支持附加 LoRA 或非中性重复惩罚；DeepSeek 已弃用频率惩罚，非中性请求报错，其他兼容服务的标准 frequency_penalty 按请求传递。当前 DeepSeek 官方非思考接口的 top_p 固定为 1，聊天与独立知识问答采用中性默认值 1，显式其他值在调用前拒绝。依据：[官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)。

聊天回复缓存只用于无检索、无角色上下文、无附加 LoRA 的直接回答；检索与角色链路按当前证据重新执行。直接回复缓存绑定实际提供商状态、连接来源及凭据摘要，命中返回 cached_model_response 并明确 modelInvoked=false，不能记为新模型验证。缓存读取/结构错误明确失败，不转而生成；写入失败返回 503 并说明 modelInvoked/messageSaved 的实际部分结果。检索缓存及独立知识问答的版本缓存保留。

消息保存统一以数据库返回的有效 id 回执确认成功。异常、超时或无效回执在共享写入处返回 503/message_archive，不返回回复或继续角色记忆回写；缓存与新生成采用同一契约。错误明确 modelInvoked，并以 messageSaved=null 表示保存结果未确认：线程写入可能仍提交，不能宣称已经回滚，也不自动重试。内部生成 persist_message=false 保留不归档、不回写的语义。后台记忆处理已有的部分完成反馈保留。 回写回执必须包含完整字段；未确认、取消、未受理及版本冲突会显示明确提示，未知状态不能按成功处理。正常无变更和已接受的后台排队仍保留原语义，超时不表示已回滚。

回复缓存自身只有一份有界 LRU 数据和同一事件循环内的一把操作锁；不为未命中查询保存锁或索引，也不声称合并模型请求。请求身份由生成入口构建，旧独立哈希工具和未使用的空值模式已删除。容量必须为正整数，TTL 必须有限且非负；保留 ±10% 抖动，0 显式关闭该项写入并移除已有同项数据。过期使用单调时钟，读取不延长有效期；非法写入选项或 None 结果明确报错，保留已有有效结果。缓存模块导入/初始化失败中止应用配置，不隐藏为自动关闭缓存；管理接口及统计字段保留。

显式选择 LoRA 时，vLLM 必须成功查询全部配置实例的适配器目录，仅共同已加载的名称可用；查询/协议错误为 503，合法无匹配为 409，不忽略检查继续或切换默认适配器。基础模型不需要 LoRA 查询。注册角色的系统提示词缺失或为空会失败，不丢弃人物指令继续；未注册的自定义适配器仍可以没有附加提示词。无调用方的旧 default 降级解析工具已删除，兼容性报告和名称映射保留。

在线关键词 LoRA 分发已退出，明确的角色/适配器选择和当前激活设置继续保留；提到角色名不会切换适配器。管理页仅展示适配器检查，不再提供规则/意图路由开关。旧配置接口明确 routingAvailable=false，启用旧规则或未接入的意图路由返回 409；历史配置、离线评测源码及结果保留。知识检索继续使用当前 DeepSeek 语义模型，训练接口保留，未训练分类器不会自动接入。适配器列表读取或报告解析失败不显示为空列表；检查完成但未确认保存结果时明确返回部分完成错误。

数据库选择优先级为明确的 `USE_POSTGRESQL` → `DATABASE_URL` → 完整的 PostgreSQL 组件配置 → 本地 SQLite。显式布尔值、URL 类型或部分组件配置错误时启动失败；选择 PostgreSQL 后缺少依赖在所有环境都失败，不自动切换 SQLite。明确关闭 PostgreSQL 的开发/测试配置仍支持 SQLite，生产部署要求仍由启动校验约束。

启用调用记录的真实生成必须先完成计量保存，再归档消息；记录写入失败或超时返回 `model_invocation_record` 503，明确模型与存储的部分完成状态，不吞错成功。模型失败同时记录失败时保留两种异常原因，不自动补写；超时或取消不能证明线程事务已回滚。确定性答复、缓存重用和显式关闭计量的内部调用继续保留其实际来源。

云端主答使用既有并发容量，不再占用本地适配器互斥锁或清空本地适配器；本地适配器选择和生成仍完整互斥。每轮固定进入的提供商类型，模型分派前若类型已改变会失败，完成后的类型标签沿用本轮来源。超时、取消和异常继续释放并发容量，不重试或切换提供商。

每轮云端主答独立持有已解析的连接配置：缓存标识、实际请求、模型标签和计量均使用同一快照，同轮多次模型调用也不重新读取模型设置。设置更新从下一轮生效；不会把新模型回答写入旧模型缓存。请求实例继续使用已有共享连接池，无新增 HTTP 客户端资源。

## 就绪检查

`/health` 只表示进程响应；`/ready` 检查数据库和模型管理器当前选中的提供商，模型检查不能因关闭 vLLM 而跳过。
OpenAI 兼容服务使用与生成相同的配置和鉴权查询模型列表；Ollama 查询所选模型详情，llama.cpp 查询健康状态，vLLM 使用聊天链路的共享客户端。
鉴权、连接、解析或配置失败返回 503；模型不在列表、mock、尚未加载的 Transformers 模型也不报告就绪。Transformers 必须先完成模型预热，探测本身不会加载权重。
成功结果缓存 5 秒、失败 1 秒，并发请求共享一次探测；运行时模型切换最迟在当前缓存到期后反映。
检查不发送聊天请求，不消耗生成 token，不代表余额、回答质量、全部 LoRA 或可选 RAG 已通过验证。`details.rag=not_probed` 明确保留该边界。

动态上下文：显式关闭语义审核、清晰轮次无需审核和安全规则保护属于正常路径；需要执行的状态/策略审核失败、输入超出完整证据预算、递归审核或规则分析失败会停止本轮准备。聊天入口返回 503 并保留内部异常原因，不丢弃角色继续普通聊天。语义审核超时配置非法时明确报错。

历史、关系备忘录和已启用的记忆原文召回属于上下文准备的必要读取。正式数据库缺少接口或读取失败时异常传播到聊天入口，不以空记录继续；合法空查询、已删除来源和未启用原文召回仍保留正常语义。假想分支继续按明确的独立来源策略处理。

结构化长期记忆召回的数据库读取、精确来源版本/原文凭据读取与已启用的语义排序均为必需步骤；失败直接报错，不能改用空记忆、宽泛来源读取或词面排名。合法无匹配和显式关闭语义排序保留。向量形状错误、非有限值和零向量均拒绝。

证据选择审核：已启用的审核发生超时、模型错误、非法输出或完整输入超预算时直接失败；不返回空集合继续生成。正常无候选或模型完整分类后的主动弃选保持有效。超时必须处于 (0,120] 秒，候选超过 24 条明确报错；不静默截断候选或修改非法配置。

角色上下文准备统一通过 `recall_with_diagnostics` 读取结构化记忆。缺失接口或召回异常直接失败，不再改调旧接口或生成不可用诊断后继续；正常空记录与实际存储快照由召回服务提供。

后台记忆写入准备中的数据库、向量和遗忘原文候选读取失败会返回 failed，停止模型判断和结构化修改；完整输入超预算同样明确失败。原文可能已先保存，回执独立保留该结果。错误反馈记录阶段与异常类型，不泄露上游原始错误消息。


检索意图：聊天启用 useKnowledgeBase 后，由当前提供商执行一次完整语义任务规划，再据 public_knowledge/unresolved_source 依赖决定是否公共检索。当前不使用关键词规则或未训练的分类器。私人记忆、完整题设计算和纯聊天保持各自输入来源，不用公共检索补私人事实。规划超时、格式错误或输入超预算直接失败；不替换为规则或自动启用分类器。原 RAG_TASK_PLANNER_ENABLED 与 DYNAMIC_CONTEXT_SEMANTIC_REVIEW_ENABLED 不再控制此必要规划；后者仍控制动态上下文审核。关闭 useKnowledgeBase 可明确停用检索及其规划。分类器训练工具暂时保留，未来接入须单独验证。


## 动态语义与记忆来源

启用动态语义审核时，正式角色服务对每个非安全轮使用完整语义审核，直接采用
已通过结构与数值校验的模型状态。关键词得到的告别、致谢或关系修复假设不会
重新覆盖该结果。安全路径保持独立，审核失败直接终止准备；历史选择性评测
仍可显式使用原有规则辅助模式。

记忆版本替代或合并在同一事务中保留本次声明继续使用、且前版实际关联的
来源。来源键及原始作用域保持不变；缺失、歧义、已撤销或不属于前版的来源
使写入失败并回滚。来源编号及记忆中的来源列表本身不授予读取原话的权限。
已有历史记录不会自动补齐或重新授权。


通用向量索引的文档编号只接受整数或非空字符串，布尔值和小数不会被隐式转换成
另一个编号。合法整数、数字字符串、十六进制前缀及普通字符串沿用现有持久化
编码；编码失败明确报错，不返回空编号，也不改变编码方式来掩盖重复编号。


动态语义审核结果必须具有唯一的 `state` 顶层字段，状态恰好包含协议声明的十个
字段，三个信号字段使用对象。缺失封装、额外字段及信号列表明确报错，不猜测
字段含义。已有真实记录使用的完整 JSON 围栏格式继续支持。信息请求包括处理
用户已给出的材料，并与交互边界分别表达；单纯分享背景本身不构成处理请求。


长期记忆模型输出仅接受 `memories` 和可选的 `erase_source_ids` 顶层字段，
候选仅接受协议声明字段及仍有调用方的时间别名。未声明字段在任何写入前
整体拒绝；模型 JSON、集合、置信度、操作和文本类型协议错误使用
`MemoryResponseError`，回执标明 `invalid_model_response` 和固定字段路径，
不携带模型原文。空结果和低置信度仍是合法无变化；真实记录使用的数组、
完整围栏格式保留。删除来源的权限仍在执行边界独立验证。


记忆候选在业务筛选前检查写入字段：新增内容的操作必须有受支持的 `kind`
和长度不超过 48 的非空 `value`。缺失、未知或超长字段报协议错误，不因
低置信度、证据不足或已有目标而静默忽略或补猜。授权撤回、删除可仅指定
旧目标；现有 `user_fact` 输入契约继续经过独立证据检查。后续派生索引的
长度检查仍保留，避免归一化后的新值越界。


模型提交的 evidence 短引文超过 120 字时在业务筛选前报协议错误，不静默
当作无变化；这个上限不截断后续派生的完整用户原话观察。历史引文不再被
自动改写成当前原话，当前引文仍可用用户历史消歧 value。无变化回执以
`no_new_information` 表示空提取或无新操作，以 `no_eligible_memory` 表示
模型给出了候选但没有通过准入，不把后者当成已经理解并保存。


已进入限定校验的模型 qualifiers 若违反结构、字段唯一性、数量、值长度或
证据覆盖约定，抛出 `MemoryResponseError`，不再作为普通不保存结果。
回执提供固定字段 `qualifiers` 和安全的 `message` 原因说明；说明只来自
代码中的固定消息或已知字段模板，不包含模型原文。合法无限定、已有单项
上下文格式、实际引文限定及待确认标记的既有语义保留。


动态上下文使用已验证的封闭主状态词表，不把未知状态替换成日常标签或
日常回应目标。模型输出仍先经过语义协议校验；内部/自定义估计器违反
状态契约时，词表映射错误直接传播，停止本轮准备，不生成成功的默认上下文。
合法日常、安全状态和混合请求的目标保持原有语义。


上下文策略审核的 `required_strategies` 明确列出必做任务及其前缀顺序。
模型返回完整的1或2项选择；缺任务、顺序错误、不兼容时直接失败，不再
由后台补齐后截断策略，也不把改写后的结果标为模型的完整选择。安全路径
和两个任务已经占满槽位的确定性保护保持原样。


生产工厂在完整语义状态判断启用时，普通轮次只执行已有安全检查，
不再对当前消息及历史运行随后被模型覆盖的完整规则评分。只有已配置模型
完成并通过校验，状态才进入后续链路；模型错误直接终止。安全相关、空输入、
默认直接调用和明确关闭语义判断的路径保持原实现，没有新增关键词规则。

生产工厂在语义策略启用时，将常规轮次的可选策略交给模型，不再先运行随后
被覆盖的规则评分。中间基线标记 `pending_semantic`，审核失败仍直接终止，
不把基线当成成功的模型选择。安全相关信号、硬安全门、默认旧调用及显式
关闭语义策略的路径保持原实现；无效非安全主状态不再默认成日常。
已有 `profile.response_preferences` 作为可选倾向传入模型，不能覆盖必做任务
和边界。最终上下文编译器的独立保护继续执行。
